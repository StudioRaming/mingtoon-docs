モジュールとパフォーマンスコスト

このドキュメントを読むと インスペクターの マテリアルロード予測 の数字がどのように出されるのかを理解でき、重いアバターで何から削るかを根拠を持って判断できます。

この値はGPU msではありません

インスペクターもそう説明しています。

相対推定値であり、実際のGPU msではありません。画面占有率・オーバードロー・影響するライトの数によって異なります。

MingToonはこのプレビューから検証されたGPUパフォーマンス数値を公開していません。以下はマテリアル同士を比較するときの相対指標です。

スコア計算式​

ソースの計算式そのままです。

スコア = テクスチャサンプル
       + 深度サンプル × 3
       + max(パス数 − 1, 0) × 8
       + ALU指数
       + (追加ライトパスを使うと)        +12
       + (URP追加ライトなら)            +6
       + (透明オーバードロー危険)        +15
       + (画面深度を使うと)              +12
       + min(動的HSVG個数 × 2, 20)

ここで読むべきこと:

重み付けが示すこと
  1. パス1つが8点。 最初のパスは無料ですが、その次から付きます。アウトライン・追加ライト・透明プリパスが各1つずつです。
  2. 追加ライトパスは8 + 12 = 20点。 単一項目として最も高コストです。
  3. 深度サンプルはテクスチャサンプルの3倍。 さらに画面深度を使うと12点が追加されます。
  4. 透明オーバードロー危険15点。 半透明を乱用すると、ここに引っかかります。
  5. 動的HSVGは最大20点まで 積み重なります。

パスが増える条件​

条件パス +1
追加ライト受け取り + 追加ライト強度 どちらも0より大きい (Built-in)✅
アウトライン使用 + クラシックハル使用✅
サーフェスモードが透明系 + 透明深度プリパス✅

ここから読める観察​

観察実務的意味
グリッターのALU 36 — 単一モジュール最大ボロノイ計算が高コストです。きらめきが本当に必要なパーツだけに
アウトラインの追加パス 3アウトライン系が作れるパスは3つです
レイヤー系のテクスチャ 10~20レイヤー数を実際に使う分だけにするのが最大の節約
キャラクター高さのALU 1事実上無料です。節約する理由がありません
シャドウの深度 4深度予算の大半をシャドウが使います
バックライト・フロントライト ALU 4非常に安いです。リムライトの代わりにこちらを使う余地があります

重いときの削除順序​

スコア寄与が大きい順です。

  1. 追加ライト受け取りをオフにする (−20点前後) — キャラクターが主光だけで演出できるなら、最大の節約です。
  2. 半透明をカットアウトまたは不透明に変える (−15点) — 透明オーバードロー危険がなくなり、プリパスのパスも1つ減ります。
  3. 深度ベース効果をオフにする (−12点 + 深度サンプル × 3) — VRChat通常画面では、どうせ見えません。 → VRChat
  4. レイヤー数を実際の個数に減らす — 特にティア境界を超えるとコンパイル自体が削減されます。
  5. グリッターをオフにする — ALUが最大です。
  6. 動的HSVGを静的に焼く — アニメーションしないHSVGは定数に畳み込まれます。
アウトラインを無暗に削らないで

パス8点の節約になりますが、トゥーンルックの正体であり、深度なしで動作する数少ない手段です。上の1~5をまず検討してください。

動的HSVG​

動的HSVG N個はアニメーションされているか、スクリプトで変更される可能性があり、定数に畳み込めない色補正の個数です。

ビルド時最適化はアニメーションされない値をシェーダー定数として凍結し、演算を消します。アニメーションされる値はユニフォームのままです。 → ビルド時自動最適化

HSVGをアニメーションする予定がないなら、わざわざ揺らぐ値にしないでください。1個あたり2点、最大20点まで付きます。

複数マテリアルを一度に見る​

MingToonマネージャーの すべてのMingToonマテリアルを選択 または シーンのすべてのMingToonマテリアルを選択 で全部選択すると、平均と最悪値が一緒に出ます。

平均より最悪値を見てください

アバター全体が軽くても、マテリアル1つが 非常に重い なら、そのパーツが画面を大きく覆うときフレームが落ちます。最高 の横の等級をまず確認して、そのマテリアルを探して直してください。
