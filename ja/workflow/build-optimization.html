ビルド時の自動最適化

このドキュメントを読むと アップロード・ビルド時にMingToonが原本を保持しながら何を最適化し、失敗と復元をどう確認するか理解できます。

一行でまとめると​

自動最適化はデフォルトで有効です。VRChatアップロード、Warudo Modビルド、通常Playerビルドで出荷用コピーを軽量化し、作業用マテリアル・Rendererは編集可能な状態へ復元します。

手動Bakeは固定アセットを直接作る場合だけ使用してください。通常の配布は自動最適化で十分です。

実行される処理​

共通フロー：

  1. 出荷対象RendererとAnimationClipが参照するMingToonマテリアルを収集します。
  2. 実際に使う機能とアニメーション対象の値を解析します。
  3. 固定機能を定数へ畳み込んだ軽量シェーダーを生成するか、キャッシュから取得します。
  4. 出荷中だけマテリアルのシェーダーを軽量版へ交換します。
  5. プラットフォーム別の追加処理を実行します。
  6. 終了・失敗・ドメインリロード時に元の状態へ復元します。

生成シェーダーは編集用と同じShaderLab Properties契約を維持します。アニメーション対象のプロパティは動的なまま残り、Rendererへ現在割り当てられていなくてもAnimationClipだけが参照するマテリアルも収集します。

VRChatアバターで追加される処理​

  • Depth Availability = Autoをそのまま保持します。Force On / Force Offも作成者の指定値を維持し、アップロード時に深度ライトを含めるはマテリアル値を変更しない別オプトインです。
  • 顔ノーマルをアップロード用コピーMeshのUV7へベイクします。Face SDFがUV7を所有するか、テクスチャFace Area Maskが必要なRendererは、同じ結果を保つためLive経路を維持します。
  • プロジェクトで設定したベース・ノーマル・マスクなどスロット種別ごとのテクスチャ解像度上限をアップロード用コピーへ適用します。
  • VRC Light Volumesバリアントをアバターアップロードへ自動で含めます。
  • MingToonランタイムコンポーネントはIEditorOnlyとしてマークされます。exporter処理後の実際のbuild cloneでRuntimeComponentCount = 0か、別途検証する必要があります。

顔ノーマルのアップロード出力は、編集用メッシュベイクとは別の専用パスを使います。同じキャラクター・同じUVチャンネルでも、編集用Meshアセットを再利用または上書きしません。

アニメーション対象の値は変更しません​

解析器はAnimationClip、Animator Controller、コンポーネントのネスト・配列フィールドをたどります。ランタイム切り替えが必要な機能はInspectorでオプトインしないと、ベイク時に定数へ畳み込まれます。

例：

  • FX Animatorで深度エフェクトを切り替え
  • FXメニューでシャドウ投影を切り替え
  • VRC Quality Low / Mid / High

オプトインすると切り替え可能性を保持する代わりに、関連uniform分岐とコードが残ります。実際にアニメーションするマテリアルだけ有効にしてください。

復旧可能な失敗は分離し、致命的な失敗ではビルドを中止します​

マテリアル・Rendererの復元では、項目ごとに例外を分離します。一つが失敗しても後続項目の復元を続け、失敗した項目だけを次回復元用に残します。保存もMingToonが変更したアセットだけにSaveAssetIfDirtyを使うため、無関係なdirtyアセットを一緒に保存しません。

通常のマテリアル1つの解析・変換例外など復旧可能な失敗では、そのマテリアルを編集用シェーダーへ戻して警告を残し、残りの処理を続けます。

一方、BuildFailedException、共通定数の共通部分の算出失敗、復旧失敗など、結果の整合性を保証できないエラーではビルド全体を中止します。Consoleの原因を解消し、元データの復旧が完了したことを確認してから再ビルドしてください。

プラットフォーム別エントリーポイント​

VRChatフックはModular Avatar・VRCFuryなどのツールがマテリアルを処理した後の実際の最終状態を解析できるよう、遅い順序で実行されます。

VRChat深度Auto契約​

Autoはバインドされたカメラ深度テクスチャとVRChat Photo Camera状態をカメラごとに直接読み取ります。アップロードフックはこの値を書き換えないため、AutoはAutoのまま、Force On / Force Offは作成者が選んだ値のまま出荷されます。Force Onは、自動判定では検出できないホスト深度を作成者が保証する場合だけ使用してください。

アップロード時に深度ライトを含めるは別オプトインです。アップロード用コピーへシャドウを有効にしたDirectional Lightを追加し、カメラに実際のdepth bufferを生成させますが、マテリアルはAutoのままです。デフォルトはOFFで、パフォーマンスとワールド照明のコストがあります。→ VRChat深度ライト

ミラー安全遮断は別です。Force Onでもミラーが別カメラの深度を読まないよう深度モジュールを無効にします。→ VRChat深度

テクスチャ最適化​

MingToon Managerのテクスチャ最適化はプロジェクト全体の設定です。Scene・PrefabではなくEditor環境設定へ保存され、このプロジェクトから出荷するすべてのキャラクターへ適用されます。

スロット別の解像度上限​

ベース・ノーマル・MatCap・マスクなど、スロット種別ごとの最大解像度を決めます。アップロード用コピーだけをリサイズし、元のTextureImporterと原本ファイルは変更しません。

Reviewed Texture Rewrites On Build (Opt-In)​

デフォルトはOFFです。Surface/normal flattenとレビュー済みRGBA mask repackを許可します。readback、色空間、mip、プラットフォーム圧縮によってピクセルが変わる場合があるため、有効にした場合はbaked前後のキャプチャを比較してください。

このオプションがOFFでも、数学的にロスレスな重複サンプル・恒等マスクの削除は引き続き適用されます。

正しく適用されたか確認する​

  1. ConsoleのC#・シェーダーエラーを先に0件にします。
  2. MingToon Managerの準備状態を検査でキャッシュバージョン、生成シェーダー、原本変更の有無を確認します。
  3. ビルドログの候補・スワップ・深度処理・テクスチャ書き換え・顔ノーマルベイク数を確認します。
  4. StudioRaming/MingToonOptimizeReport.txtのマテリアル別結果を確認します。
  5. VRChatでは自分の画面・ミラー・Photo Cameraをそれぞれ確認します。

メニューオプション​

Tools > Studio Raming > MingToonの正式ビルドにはユーザー向けメニューだけが表示されます。

  • Optimize Shaders On Build — デフォルトON。自動シェーダー最適化を制御します。
  • Reviewed Texture Rewrites On Build (Opt-In) — デフォルトOFF。レビュー済みテクスチャ書き換えを許可します。
  • Clean Build Optimization Output — 生成シェーダーキャッシュを整理します。

Debug: Tint Optimized Shaders Red、バリアントダンプ・レコード、内部パフォーマンス計測メニューは正式パッケージには表示されません。MINGTOON_DEV開発ビルドでのみ使用できます。

Editorがビルド中に終了した場合​

シェーダースワップとテクスチャ書き換えはディスクジャーナルを使い、次回ドメインリロード時に復旧します。顔ノーマルのアップロードbakeはbuild clone破棄が通常終了経路で、存続する共有マテリアルがあれば元のfloat・keywordを対象ごとに復元して保存します。

Managerの状態が復元が必要のままならRestore After Interrupted Buildを実行し、Consoleの項目別失敗を確認してください。
