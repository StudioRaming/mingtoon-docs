変換ウィザード（セットアップウィザード）

このページはアバターや衣装をはじめて MingToon へ移す方のためのものです。 ウィザードが何を作り、画面ごとに何を選ぶかを順番に扱います。約 10 分かかります。

これは何ですか​

変換ウィザードは Inspector の中に開く案内画面です。 元を残したまま、別に編集できる MingToon のコピーを作ります。

ウィザードが作るもの:

  • 元の隣に新しいフォルダー <名前>_MingToon
  • そのフォルダーの中のプレハブ <名前>_MingToon.prefab とコピーしたマテリアル
  • シーンに置かれるコピー 1 つ。MingToon Manager はすでに付いています

元のマテリアルファイル、プレハブアセット、シーン上のオブジェクトの値は変更しません。 シーンにあった元のオブジェクトは、コピーを置いたあとに無効になります。

いつ使いますか​

  • アバターや衣装をはじめて MingToon へ移すとき。推奨の経路です
  • 元を残したまま結果を比べたいとき
  • すでに MingToon のアバターを独立したコピーとして分けたいとき

マテリアルを数個だけその場で変えたいときは手動変換を使います。 ウィザードのあとの調整は MingToon Manager で行います。

30 秒で試す​

  1. Hierarchy でアバターの最上位オブジェクトを右クリックします。
  2. MingToon > Convert to MingToon... を押します。
  3. Inspector の上部に MingToon のコピーを作成 の画面が開けば成功です。

開き方​

方法対象
Inspector の Add Component で MingToon Manager をはじめて付けたときそのオブジェクト
Hierarchy を右クリック MingToon > Convert to MingToon...選んだオブジェクト
メニュー GameObject > MingToon > Convert to MingToon... または GameObject > MingToon > Add MingToon Manager選んだオブジェクト
Project ウィンドウでプレハブを右クリック MingToon > Convert to MingToon... または MingToon > MingToon Managerプレハブアセット
Manager の開始タブのコピーを作成Manager が付いたオブジェクト
メニュー StudioRaming > MingToon > Open Manager SetupManager があればそれを選び、なければ確認ウィンドウのあとにウィザード
  • Add Component で自動的に開くのは、Manager をいま新しく付けたときだけです。シーンやプレハブを開いたときにすでにあった Manager や、Undo・Redo で戻った Manager では開きません。
  • Play モード中はウィザードが開かず、コピーも作りません。
  • Project ウィンドウでプレハブを複数選んで MingToon > MingToon Manager を押すと、プレハブごとにウィザードが別々に開きます。

画面の順番​

どの段階でも一番上は同じです。

  • タイトル行に MingToon と MingToon のコピーを作成、言語の選択（한국어 · English · 日本語）、? ヘルプがあります
  • 右上のウィザードをスキップを押すと、何も変換せずに元の Inspector へ戻ります。コピーを作ったあとはこのボタンがウィザードを閉じるに変わり、作ったコピーはそのまま残します
  • 段階の表示はメッシュ · 見た目 · MLC · 完了です。MLC がインストールされていなければ MLC の段階がなくなり、メッシュ · 見た目 · 完了になります

1. メッシュ​

カードが 3 枚あります。

カード何をするか
変換するオブジェクト対象のオブジェクトを変えられます。下に 変換する枠: N · 維持: N が出ます
顔のメッシュを入れてください顔のメッシュをドラッグして入れるか、一覧から選びます。顔がなければ空のままにします
体のメッシュを入れてください体・腕・脚の肌のメッシュを入れます。なければ空のままにします
  • 枠（スロット）は Renderer 1 つが持つマテリアルの 1 マスです。変換する枠 は MingToon に変わるマス、維持 はパーティクルのようにそのまま残すマスです
  • メッシュの欄はこの対象の中の Renderer だけを受け付けます。+ メッシュを追加で複数入れ、一覧メニューのクリアで外します
  • 顔のメッシュのマテリアルは Face、体のメッシュのマテリアルは Skin の役割になります。空のままなら、元のマテリアル自身が持つ顔フラグだけを読み、残りは Regular のままです。名前から顔を推測することはしません
  • 同じメッシュを顔と体の両方に入れると案内が出ます。次の画面のマテリアル一覧で、枠ごとに通常と顔を分けてください
  • 対象にすでに Manager の顔・スキン指定があれば、その値が最初から入っています
  • 変換できるマテリアルが 1 つもないと 対応するマテリアルがありません。上で対象を選び直してください。 が出て、次へがオフになります。再確認で一覧を読み直します

右下の次へを押します。

2. 見た目​

カード何をするか
ルックベーシックトゥーン・ハードトゥーン・ソフトトゥーンから 1 つ選びます。それぞれ 影の境界ふつう・境界くっきり・境界やわらか の説明が付いています
軽量 (Low)オンにすると深度エフェクトをオフにした軽いルックになります。オフなら深度エフェクトをオンにしたルックです
色調プリセット最初は 色調を選択… です。選ばなければ元の色をそのまま使います
変換するマテリアル · N変わる枠の一覧です。枠ごとに役割を決めます
そのまま維持する項目 · N折りたたまれています。変換しない枠の名前が出ます
  • 最初の選択はベーシックトゥーンで、軽量 (Low) はオフです
  • 変換するマテリアルの役割の一覧は、前の画面で選んだメッシュに応じて最初の項目が顔メッシュ・体メッシュ・元の設定に変わり、そのあとに通常と顔があります。枠の名前を押すと Hierarchy でその Renderer を示します。10 行を超えると一覧はスクロールします
  • 対象がすでにすべて MingToon なら すでに MingToon です。現在の見た目をコピーします。 が出て、ルックの選択と一覧は使いません
  • カードの下に 新しいフォルダーに保存します。元のファイルは変更されません。 という案内があります

戻るで戻るか、コピーを作成を押します。押すと次の順で進みます。

  1. 新しく <名前>_MingToon フォルダーを作ります。元がプレハブアセットならそのプレハブのあるフォルダーに、シーンのオブジェクトならそのシーンファイルのあるフォルダーに作ります。保存していないシーンなら Assets の直下です。同じ名前があれば番号の付いた新しい名前を使います
  2. 元を複製してプレハブの接続を切り、すべてのマテリアルをそのフォルダーに新しい .mat としてコピーします。変換しないマテリアルもコピーします
  3. コピーに Manager がなければ付け、選んだ顔・体のメッシュをそのコピーの Renderer へ移します
  4. 既存の変換をそのまま実行します。進行バーは マテリアルを変換中... → ルックプリセットを適用中... → 変換したマテリアルを整理して保存中... の順に変わります
  5. MLC がインストールされていて元に MLC の設定があれば、その中の照明のマテリアルグループをコピーの新しいマテリアルへ移します
  6. 新しいマテリアルが使うシェーダーバリアントを事前にコンパイルします。マテリアルが多いとこの段階は長くかかることがあります
  7. プレハブを <名前>_MingToon.prefab として保存します

ウィザードはメッシュチャンネル（UV4・UV7・UV8）のベイクをしません。必要なら Manager の見た目タブの輪郭・顔・高さの準備で行います。→ メッシュ UV ベイク

3. MLC（インストールされているときだけ）​

Ming Light Controller（MLC）は別売の製品です。インストールされていると、この段階が現れ、ゲーム内で照明を変えるメニューをコピーに追加するか尋ねます。インストールされていなければこの段階はなく、すぐ完了画面へ進みます。

カードのタイトルは**ゲーム内でも照明を調整しますか？**です。MLC 0.1.2 の自動調整を使う場合、画面は次のようになります。数字はすべて MLC が計算した値で、ウィザードは推定しません。

状態画面ボタン
コピーに MLC がない残りのパラメーター容量に合わせて照明メニューを選び、コピーに追加します。 の下に アバターの使用量 X / Y bits、照明メニュー +N bits · 合計 A / B bits、項目 a / b、容量に合わせて省く機能の数照明メニューを追加
コピーに MLC がすでにあるこのアバターにはすでに Ming Light Controller があります。コピーは設定をそのまま残します。この設定で完了
既存の設定が容量に入らない上の文の下に案内が出ます今の容量に合わせる（MLC が自分で合わせます）またはこの設定で完了
  • あとでを押すと MLC を追加せずに完了画面へ進みます
  • 使用量を読んでいる間は パラメーター使用量を確認しています… が出ます。再確認 / 詳細の中の再計算でもう一度測れます
  • 最小のメニューも入らないときは、どれだけ空ければよいかを示します。例: 最小の照明メニューも入りません。アバターのパラメーターを N bits 空けると追加できます。
  • アバターのパラメーター使用量を読めないときは、安全とはみなさず何も追加しません。アバターのパラメーター使用量を読めないため追加しません。Expression Parameters を確認してください。
  • 元に MLC の設定があれば、その照明のマテリアルグループをコピーの新しいマテリアルへ移します。移せなくても失敗にはならず、完了画面の警告として残ります
  • 追加した MLC の設定はコピーのプレハブにだけ保存されます。元には書き込みません

自動調整のない以前の MLC がインストールされている場合、このカードにはプリセットの一覧（現在の設定を維持 · 基本の照明調整 · パラメーターを節約 · 写真撮影 · エフェクト切替）が出ます。各項目の右に追加後の合計が出て、収まらない項目は容量不足として無効になります。おすすめの項目には · おすすめ が付きます。

MLC 自体は Ming Light Controller で扱います。

4. 完了​

タイトルは MingToon のコピーを作成しましたです。

  • シーンに置かれたコピー、変換した枠: N、プレハブのパスが出ます。MLC の段階を通った場合は MLC · 残りの容量に自動で合わせる または MLC · 現在の設定を維持 も出ます
  • 確認が必要な項目があれば 確認が必要な項目があります。下の変換結果をご確認ください。 が出ます。変換結果の詳細を開くとレポートが出ます。読み方は変換レポートの読み方にあります
  • Manager を開くを押すとウィザードが閉じ、コピーの MingToon Manager が選ばれます。続けて見た目タブでルックを整えてください

終わったあとにシーンで起きること​

元がコピーが置かれる場所元
シーンのオブジェクト元のすぐ次の兄弟の位置。同じ親、同じ位置・回転・スケール無効になります
Project ウィンドウのプレハブ現在開いているシーン。元のプレハブのルートの位置・回転・スケールを使いますそのまま
プレハブ編集画面の中のオブジェクト編集画面ではない、開いている通常のシーンそのまま
  • コピーを置くことと元を無効にすることは、1 回の Undo でまとめて戻ります。Undo の項目名は MingToon のコピーを配置 です
  • 作られたフォルダー、プレハブ、マテリアルのファイルは Undo では消えません。使わなければ自分で削除してください
  • シーンは保存しません。変更ありの印が付くだけなので、確認してから保存してください
  • 開いている通常のシーンが 1 つもないと コピーを置く通常のシーンがありません。シーンを開いてから完了してください。 が出ます。コピーのプレハブはすでにできているので、シーンを開いてからもう一度完了します

コピーと元が共有するもの​

項目コピーでは
マテリアルすべて新しいファイルとしてコピーします。以後の編集は元のマテリアルに届きません
メッシュ・テクスチャ・アニメーションのアセットコピーせず、元をそのまま参照します
Animator や VRC Avatar Descriptor などのコンポーネントコピーのオブジェクトにそのまま複製されます
プレハブの接続切って独立したプレハブとして保存します。元のプレハブをあとで直しても追従しません

失敗したとき​

元はどの場合もそのままです。コピーのプレハブを保存する前に失敗した場合は、今回作った新しいフォルダーだけを削除します。保存したあとの失敗（シーンへの配置など）はコピーを残します。赤い案内がウィザードの上部に出ます。下の表は画面に出る文です。

メッセージ意味と対処
Play モード中はコピーを作れません。Play を終了してからもう一度お試しください。Play を終了します。Play 中は 再生中はコピーを作成できません。再生を止めると続けられます。 も出ます
対象が変わりました。更新された一覧を確認してください。ウィザードを開いている間にマテリアルや Renderer が変わりました。新しく読んだ一覧を確認して、もう一度押します
対応するマテリアルがありません。対象を確認してください。対象が違っています。1 の段階で対象を選び直します
このアバターの顔メッシュを選んでください。 ・ このアバターの体メッシュを選んでください。選んだメッシュがこの対象の外にあります。対象の中のメッシュで選び直します
コピー用フォルダーを作成できません。書き込み可能か確認してください。元のあるフォルダーに書き込めません。書き込み権限を確認します
変換できませんでした。元はそのままです。理由はコンソールで確認してください。変換が失敗しました。Console の理由を先に読みます
元にスクリプト欠落（Missing）があるため、新しいプレハブを保存できませんでした。元の Missing スクリプトを整理してからもう一度お試しください。元はそのままです。元の Missing Script を削除するか再接続してから、最初からやり直します
新しいプレハブを保存できません。書き込み可能か確認してください。フォルダーの書き込み権限を確認します
コピーをシーンに配置できませんでした。元はそのままです。コピーのプレハブは残っています。シーンの状態を確認してもう一度完了します
処理を完了できませんでした。元はそのままです。詳細はコンソールで確認してください。それ以外の例外です。Console の例外の種類とメッセージを確認します
処理が中断されました。生成ファイルを確認してください。実行中にスクリプトのリロードがありました。作られたフォルダーを確認して最初からやり直します
この対象のウィザードはすでに開いています。その対象のウィザードを先に完了するか閉じます

警告として残るだけの場合:

  • 照明のマテリアルグループをコピーへ移せないと、照明のマテリアルグループをコピーへ移せませんでした。コピーの照明コンポーネントでマテリアルグループを確認してください。 がレポートに [MLC] として付き、完了画面に警告が出ます。コピーは作られます
  • 変換結果の lossy・unsupported の項目も同じ警告にまとまります

Missing Script のあるプレハブを Project ウィンドウで選ぶと、ウィザードは Inspector のインポーターのヘッダーの下に現れます。

知っておくべき制限​

  • このページはコードを基準に書かれていて、上の画面の順番と文はソースの実際の文字列です。画面のキャプチャはまだ入れていません
  • ウィザードはメッシュチャンネルのベイクとアップロードの準備をしません。アップロード前の点検は Manager と VRChat で行います
  • コピーには元のコンポーネントがそのまま複製されます。VRChat SDK が複製された Avatar Descriptor と Blueprint ID をどう扱うかは、このページが確認した範囲ではありません。アップロード前に SDK Builder ウィンドウで対象のアバターを自分で確認してください
  • ウィザードを再度実行するたびに新しいフォルダーとプレハブが作られます。以前の結果は削除されません
  • 進行中の画面はスクリプトのリロードのあとも続きますが、そのときコピーの作業が動いていた場合は、上の 処理が中断されました。 が出ます
