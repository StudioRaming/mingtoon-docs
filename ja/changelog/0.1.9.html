0.1.9

オープンベータ · 2026年9月9日

0.1.9​

今回のアップデートでは、変換時のルックと色調の選択、Manager の作業手順、ベイクの安定性、生成テクスチャの最適化に重点を置いています。

Manager とルック・色調の選択​

  • 作業を3つのタブに整理 — はじめに、外観・ベイク、最適化で構成しました。「はじめに」で変換対象を指定して変換し、「外観・ベイク」で既存の MingToon マテリアルのルックとベイクを調整します。「最適化」では自動処理とテクスチャ解像度の上限を設定します。上部のマテリアル選択と対象範囲は、3つのタブで共通です。

  • ルックと色調を別々に選択 — ルックプリセットの下に色調プリセットを追加しました。初期値はニュートラルです。ルックを適用してから、選んだ色調を適用します。従来の影色を上書きするチェックボックスは、この選択に置き換えました。

  • 既存の値を使用 — 元のマテリアルから変換した色を保持するには、色調プリセットで既存の値を使用を選んでください。以前の設定で影色の保持を選んでいた場合は、この選択へ引き継ぎます。別の色調プリセットを選ぶと、対象の色はそのプリセットの値に変わります。

  • 影バンドの保持 — 変換時に元のマテリアルから引き継いだ影バンドの強度・境界・幅・合成設定が、ルックプリセットの適用で上書きされないようにしました。色調プリセットの選択と、バンド設定の保持を分けて扱います。

  • 現在の MingToon マテリアルに再適用 — 変換対象がなく、編集用 MingToon マテリアルのみがある場合は、「はじめに」で選んだルックと色調をキャラクターの MingToon マテリアル全体に再適用できます。実行前に上書き対象を確認でき、Undo で元の値に戻せます。

  • メニューとコンポーネントの整理 — 製品メニューから開発用の診断項目を非表示にし、手動で追加する製品コンポーネントを MingToon Manager と Ming Light Controller を中心に整理しました。プロジェクト検証メニューは引き続き利用できます。

lilToon 変換​

  • 1番目・2番目の影の色調と強度 — 元の影の強度、境界、柔らかさを MingToon の設定に反映します。2番目の影のアルファと影全体の強度を合わせて反映し、強度が0でも2番目の影が残ったり、中間のアルファ値で薄くなりすぎたりする問題を修正しました。
  • 補助の影色 — 影色の統合が無効でも、ほかの影設定が白のままにならないよう、元の1番目の影色を引き継ぎます。元の2番目の影のアルファが0の場合は、2番目のバンドを有効にしません。
  • 処理できるマテリアルから変換 — 一部のマテリアルで変換が失敗しても、残りの処理を続けます。失敗したスロットは元のマテリアルを保持し、成功した変換結果は残します。選択したルックや色調などの後処理で発生した問題も結果に表示し、完了・除外・失敗を区別できます。
  • 透明マテリアル — 通常の透明マテリアルで、表示される表面のカットオフと深度処理用のカットオフを分け、アニメーションで変化する元のカットオフを保持する処理を強化しました。屈折マテリアルは従来の個別の変換経路を使用します。

影の計算方法が異なるため、すべての lilToon のルックがピクセル単位で一致するわけではありません。変換後はライティングとマスクを含め、実際の見た目も確認してください。

ベイク・変換の安定性​

  • VRChat SDKでのビルド後、編集用マテリアルに一時的なベイク済みシェーダーが残る場合がある問題を修正しました。
  • メインテクスチャが未設定のストラップなど、一部のアルファマスク付きマテリアルで、ベイク後に切り抜きの輪郭が変わる問題を修正しました。
  • ベイク後にマテリアルが白く表示される問題 — ベイク中に無効な発光が有効になり、マテリアル全体を白く覆うことがある問題を修正しました。発光の強度や色をアニメーションで制御している場合も、各マテリアルの有効・無効状態を保持します。
  • 発光が無効になったり状態が変わったりする問題 — 発光と2番目の発光レイヤーの使用状態がベイク結果へ正しく反映されるようにしました。使用中のレイヤーは保持し、無効なレイヤーが意図せず有効にならないようにします。
  • Glitter が別のマテリアルにも適用される問題 — 一部のマテリアルで Glitter を使うアバターを変換・ベイクすると、Glitter を無効にしたマテリアルにも効果が適用されることがある問題を修正しました。各マテリアルの Glitter 使用状態に従います。
  • Glitter マスクの安定性 — 手動ベイク後にマスクが適用されなかったり、後からマスクを有効にしたときに範囲制限が機能しなかったりする問題を修正しました。マスク反転とカラーマスクも保持します。
  • プリセットの選択的な適用 — 変換直後やプリセットを再適用したとき、現在使用中のモジュールと関連設定が、プリセットの無効値で上書きされないよう改善しました。プリセットのすべての値をマテリアル全体へ一括で上書きせず、保持すべき設定を残しながらルックを適用します。

パフォーマンスとその他の改善​

  • マテリアルごとに固定できる設定を活かしたベイク最適化を維持し、結果に影響しない不要なシェーダーバリアントを削減しました。
  • シェーダーの重複計算を整理 — ライティング方向と全体の色調整で繰り返していた計算を整理し、使用していないテクスチャレイヤーの不要な処理を減らしました。既存のルックとアニメーション制御を保持しながら、レンダリング負荷を下げることに重点を置いています。
  • ベイク・アップロード準備処理の改善 — マテリアルとキーワードの状態を確認・保存する処理の重複を減らしました。改善幅はアバター構成、使用機能、シェーダーキャッシュの状態によって異なります。
  • 遠距離での MatCap 表示を保持 — カメラから離れたときに MatCap による色や発光が消える問題を修正しました。
  • 保存・復元確認の強化 — ベイク中に保存が失敗したり作業が中断されたりした場合に、マテリアルの保存と復元の状態をより正確に確認するよう改善しました。

テクスチャの最適化​

  • 合成結果の解像度制限 — テクスチャレイヤーとノーマルレイヤーの合成、マスクのパッキング後に、生成結果へ解像度の上限を適用します。通常のマスクと、マテリアル編集中に生成するマスクパックの両方が、マスク解像度の設定に従います。
  • 元のインポート設定を保持 — 解像度制限や圧縮のために、元のテクスチャの最大サイズや圧縮設定は変更しません。制限なしでは合成結果のサイズを保持します。
  • 生成結果の圧縮と保存 — PC 用に合成したカラー・ノーマルテクスチャには圧縮を適用します。生成マスクはチャンネル値を保持するため可逆形式で保存し、マスク解像度の上限でサイズを抑えます。
  • キャッシュの再利用と復旧 — 同じ設定の生成結果を再利用するとき、不要な再書き込みとインポートを減らしました。設定や出力サイズが変わった場合は、既存のキャッシュをそのまま使用しません。出力先に由来を確認できないファイルがある場合、勝手に上書きや削除を行いません。
  • 新規インストール時の生成フォルダ — パッケージを初めて導入し、Assets/StudioRaming フォルダがないプロジェクトでも、マスクの生成先フォルダを作成できるよう修正しました。

自動ビルド・アップロードでテクスチャを再生成するには、「最適化」タブのビルド・アップロード時に自動最適化（全体共通）とアップロード時もテクスチャ再書き込み（オプトイン）を合わせて確認してください。容量の削減率と処理時間は実際のアバターでの検証後に確定するため、この文書ではまだ数値を掲載していません。

アニメーション判定と編集の安定性​

  • Animator 分析中の例外 — 不正または特殊な Animator 状態の読み取り中に例外が発生した場合、判定の失敗を知らせ、保守的に処理するよう強化しました。分析が不完全な状態で、アニメーションによって変わる値を固定してしまうことを防ぎます。
  • Scene ビューの深度表示の復旧 — 現在の Scene ビューに必要な深度表示を再度要求するよう改善しました。Play Mode と深度表示を抑制する設定は保持します。

Ming Light Controller 0.1.2​

  • 小数の Int 値と最終予算ゲート — インストールされた SDK が受け付ける場合は、0.5 のような小数の Int デフォルト値を保持します。ただし、整数として使う側で切り捨てや制限が行われる可能性を案内します。最終同期予算を超えた場合は、超過ビット数と削減方法を明示してビルドを停止します。
  • VRCFury の境界 — VRCFury の圧縮との完全な協調と、圧縮後の Inspector プレビューは次のバージョンへ延期します。この文書では、圧縮前の予測値とビルド時に再確認すべき範囲を区別します。

MLC は別パッケージです。MingToon 0.1.9 と併用する場合は、MLC も 0.1.2 に更新してください。対応する Unity は 2021.3 と 2022.3 です。VRChat へのアップロードには、インストールされた SDK が要求する Unity バージョンを使用してください。

更新後に確認すること​

  • すでに作成したベイク済みマテリアルへ修正を反映するには、編集用マテリアルへ復元してから再度ベイクしてください。VRChat にアップロード済みのアバターは再アップロードが必要です。
  • 白表示を避けるために発光強度を一時的に0にしていた場合は、更新後に希望する値へ調整してから再度ベイクしてください。
  • 以前のバージョンでプリセットを適用して変わった値は自動では復元されません。必要な設定を再調整するか、元のマテリアルから再度変換して結果を確認してください。
