0.1.13

正式版 · 2026年10月11日

これは正式版0.1.13の変更内容です。

要約​

更新後に黒くなる問題と、他のアバターツールとの併用時の問題を修正しました。

更新前の確認
  • バックアップ: 重要なプロジェクトは先にバックアップし、別コピーで確認してください。
  • 再ベイク: ジェネレーターバージョンが104になりました。既存のベイクは古いベイクとして表示されるため、復元してから再ベイクしてください。
  • 再アップロード: 変換済みのアバターは、新しいバージョンで再変換してから再アップロードすると反映されます。
  • マットキャップキャッシュ: マットキャップ生成キャッシュがテクスチャのサンプラー設定を区別するようになり、更新後に既存のマットキャップ生成キャッシュが1回再作成されます。
  • 初回起動: 更新後の初回起動でMingToonフォルダーを1回再インポートするため、時間がかかる場合があります。処理中はUnityを閉じないでください。

既定値と見た目の変更​

  • 深度ライトはVRChatアップロードでデフォルトオフで含まれ、自分とフレンドにだけオンになります。見る人の安全設定などでアニメーションが止められても、フレンド以外にはオフのままです。フレンド以外にも深度効果を見せるをオンにすると、従来どおり全員にオンになります。
  • NDMFを使うプロジェクトでは、アップロード準備をNDMFビルドの中で実行します。他のツールがアバターを変更した後の状態を基準に準備します。NDMFがないプロジェクトは従来どおりVRChat SDKのビルド段階で実行します。
  • VRC Light Volumes v3.0.0-dev.21に対応しました。v2ワールドもv3の経路で受け取ります。v2ワールドでは、ボリュームに焼き込まれたポイントライトの遮蔽が反映されなくなるため、壁の向こうのポイントライトが透けて見えることがあります。v3ワールドとLight Volumesのないワールドは変わりません。
  • 点光源の影ダイヤルをインスペクターから削除しました。

修正した問題​

  • 更新後にアバターが黒くなる、またはシェーダーエラーが出る問題を修正しました。更新されたシェーダーファイルがUnityに変更として認識されず、古いシェーダーと新しいファイルが混ざってコンパイルされることが原因でした。パッケージ内ファイルの時刻はバージョンごとに変わるようになりました。
  • インストール後のシェーダー準備でエディターを止めていた同期の待機ダイアログをなくしました。準備は使用中のレンダーパイプラインだけをコンパイルし、進行状況は画面右下のBackground Tasks表示に出ます。
  • Unity 2021.3の初期バージョン（例: 2021.3.18f1）にMingToonをインポートするとC#のコンパイルエラーが出る問題を修正しました。VRChat（2022.3）とWARUDO（2021.3.45f2）の環境には変化ありません。
  • AAO・LACなど他のツールが準備後にマテリアルを変更し、レシートが一致しなくてもアップロードを止めません。警告を出し、そのマテリアルは通常の経路で処理します。
  • フォルダー名が正確にlilToonでなくても（バージョン付きの名前など）、lilToonマテリアルを変換対象として認識します。
  • メッシュ交換時にブレンドシェイプの値を保持します。名前が一致しない場合は警告します。
  • 変換したコピーにMissing Scriptがあると変換が止まる問題を修正しました。Missing Scriptはコピーからのみ削除され、元のアバターは変更されません。プレハブの保存に失敗しても、変換後のオブジェクトと新しいマテリアルはシーンに残るので、結果画面の案内どおりシーンを保存してください。
  • マテリアルを切り替えるトグルアニメーションが、変換後もlilToonマテリアルを指していた問題を修正しました。アップロード用のビルドコピーで、クリップ内のマテリアル参照を変換後のMingToonマテリアルへ置き換えます。元のクリップとコントローラーは変更されず、Auto Optimizeのオン・オフどちらでも動作します。変換記録のないマテリアルや、1つの元に変換後マテリアルが複数ある場合は、触らずに警告します。 変換記録ができる前にウィザードで作ったコピーも、構造が同じなら同じ方法で置き換えます。
  • アップロード後の「Preserved a user keyword edit」という誤った警告が出て、一部のキーワードが元に戻らない問題を修正しました。
  • VRCFuryのBuild an Editor Test Copyを、d4rkAvatarOptimizerやTexTransToolと併用すると、コピーがビルド前のマテリアルに戻り、髪が描画されない、テクスチャがずれて見えるなどの問題が出ていたのを修正しました。
  • Test Copyや手動ベイクコピーが残っている間は、そのコピーが使うビルドファイルを削除しません。コピーを削除すると整理します。
  • 手動ベイクコピーが元のMingToonマテリアルの深度アンカー値を変更していた問題を修正しました。
  • d4rkAvatarOptimizerのWrite Properties as Static Valuesをオンにすると、d4rkが作ったMingToonシェーダーのコピーでコンパイルエラーが出る問題を修正しました。他のツールがMingToonシェーダーを書き換えたコピーを使う場合は、アップロード時に警告します。 そのコピーの見た目はMingToonでは保証できません。
  • TexTransToolのアトラス: MingToonのテクスチャごとにどのUVを使うかをTexTransToolに伝え、アトラス化の後もテクスチャがずれないようにしました。
  • メッシュを作り直すツールが、MingToonがメッシュに焼き込んだUVデータ（アウトラインなど）を消した場合、アップロード時に警告し、そのデータを使う効果を安全な値に戻します。
  • アップロードの最後にMingToonマテリアルが正しく残っているかを再検査します。他のツールがマテリアルやシェーダーを変更していた場合は、どのスロットかをコンソールに表示します。
  • 1つのオブジェクトにMingToonマテリアルが複数あるとき、上部の固定タブが崩れる問題を修正しました。固定タブと移動リストはエディターごとに動作します。
  • ビルドサマリーログの「depth availability promotion」という表記を「VRC Light Volumesをオンにしたマテリアル数」に直しました。
  • インストール時のウォームアップ後、最初の変換で余分なシェーダーをコンパイルしていた問題を修正しました。

Ming Light Controller 0.1.4​

Ming Light Controller 0.1.4 は 0.1.13 と同時に公開されます。MLC は別製品です。

  • NDMF 1.14 以降が入っている場合、Modular Avatar や FaceEmo など他のツールが追加したパラメーターも 予算・検証 パネルの予算に含まれます。
  • NDMF が報告しない同期メニュー項目も、パラメーター名で計算に含まれます。
  • NDMF による計算とアバターディスクリプターだけの計算が異なる場合、予算・検証 パネルに両方の数値を表示します。
  • 他のツールがパラメーターを追加する前にビルドが先に失敗することはありません。最終予算は、すべてのツールの実行後に再確認します。
  • 最終予算の超過メッセージには、特定のツール名を表示しません。
  • 以前のソースコード版 MLC から DLL パッケージへ更新すると、設定の Inspector は Unity の標準 Inspector の代わりに MLC のパネルを表示します。
  • マテリアルグループテンプレートは NaN や無限大の値を拒否します。
  • 0.1.2 または 0.1.3 から更新する場合は、unitypackage を既存のフォルダーに Import All で上書きします。設定は保持されます。

既知の制限​

  • MMDワールドで口だけが動かないという報告があります。原因は確定できておらず、深度ライトをオン・オフするFXレイヤーを、MMDワールドがオフにするFX 1・2番レイヤーの後ろに入れる防御的な修正を入れました。MMDワールドではまだ直接確認できていないので、同じ症状が続く場合は教えてください。
  • ライトとリムをオフにした状態で上を向くと肌が光るという報告があります。最新バージョンで再変換すると直る場合があります。
  • 他の人の視点で影がずれて見えるという報告があります。原因は確認中です。
  • 体のマテリアルスロットが消えるという報告があります。確認中です。
  • インストールや更新の直後にキャラクターがピンク色になる場合、ウォームアップ中のシェーダーコンパイルがUnityの制限時間を超えています。ProjectウィンドウでMingToonシェーダーを右クリックしてReimportすると戻ります。遅いPCで起こることがあり、自動復旧は次のバージョンで入れます。
  • 他のツールとの互換確認はPC（Windows）ビルドが基準です。VRCQuestToolsを付けたアバターもPCビルドに影響しないことを確認しました。Quest版の見た目は確認範囲外です。
  • VRMエクスポート（NDMF VRM Exporter）はVRMシェーダーに置き換わるため、MingToonの見た目は残りません。エクスポートがエラーなく終わることだけを確認しました。
  • TexTransToolのアトラスでは、タイリング・オフセット・スクロールのあるテクスチャはアトラスに入れず警告します。2×2のようなとても小さい単色テクスチャを使うマテリアルは、TexTransToolがアトラスの端に細く配置するため色がずれることがあります（lilToonマテリアルでも同じ）。そのようなマテリアルはアトラスの対象から外してください。
  • ManagerのPlayモードでビルドフックを実行は、Play中にアバターを直接変更することがあるのでオフにしておいてください。デフォルトはオフのままです。
