トラブルシューティング

症状をそのまま探してください。原因はほとんどの場合 1 つです。上位の値が 0 かオフだと、下位の値はすべて無視されます。

インストール · 変換 · 影 · デプスエフェクト · アウトライン · 顔 · VRChat · WARUDO · 性能 · ベイクと復元

どの値も効かない​

上から順に確認してください。

  1. 全エフェクトをオンにします。オフだとすべてのセクションが非アクティブです。
  2. 該当セクションのマスタートグルをオンにします。オフだと クイック設定 に (モジュールOFF) が付きます。
  3. 下の表で、その機能の上位の値を上げます。
見えないものまず確認する上位の値
ベースのティントティント合成強度
表面全体が透明すぎる、または不透明すぎるベースマップ全体の不透明度
デプスリムライト · デプスシャドウ全体幅、次に各モジュールの強度
PBR のハイライトと環境反射スペキュラー強度
追加のテクスチャレイヤーサーフェススタックレイヤー数
ノーマルマップのレイヤーノーマルレイヤー数
MatCap のレイヤーMatCapレイヤー数
影の境界の帯境界の幅、次に境界の強度
シャドウパターンパターン強度
顔のノーマル補正プロキシノーマル強度
顔領域マスクマスク強度。0 だとマテリアル全体を顔と見なします
PBR パックマスクのチャンネル設定パックマスクを使用
キャストシャドウの明るさと合成受信強度
アルファマスクサーフェスモードが不透明 (2000) だと、オンにしても見えません

インストール​

マテリアルがピンク色（マゼンタ）に見えます​

原因対処
レンダーパイプラインの不一致合うバックエンドのシェーダーに差し替えます
シェーダーモデル 4.5 に未達StudioRaming > MingToon > Validate Project を実行。PC のみ対応です
URP のバージョンが範囲外Unity 2021.3 + URP 12.x に合わせます
この場合はエラーメッセージが 1 つも出ません

SubShader が丸ごと脱落するため、ログは静かなままです。ピンク色が唯一の手がかりです。

Validate Project が Unity のバージョンを指摘します​

コードいつ出るか意味
MING-ENV-UNITY-VERSION (エラー)エディターが 2021.3 でも 2022.3 でもないとき対応していないストリームです
MING-VRC-UNITY-VERSION (警告)VRC SDK があるのに 2022.3 ではないときこのプロジェクトにはアバターのアップロード対応がありません
MING-ENV-BUILD-TARGET (エラー)ビルドターゲットがシェーダーモデル 4.5 を満たせないときAndroid・Quest・iOS・WebGL です。Windows に戻してください

2022.3.22f1 は正式対応のバージョンなので、何も指摘されません。 → Validate Project コード

レンダーパイプラインを変えたらマテリアルが全部壊れました​

切り替えダイアログで、プロジェクトの MingToon マテリアルを合うバックエンドへ一括で切り替えます。ダイアログを逃しても、マテリアルインスペクターの警告から再実行できます。

切り替えが止まる理由対処
マテリアルが他のアセットに含まれているサブアセットから抽出
マテリアルが読み取り専用パッケージ内にあるパッケージ外へコピー
マテリアルが読み取り専用、またはチェックアウトされていない読み取り専用の解除、またはチェックアウト

閉じているシーンと AssetBundle のマテリアルは検査できません。別途開いて切り替えてください。

変換​

変換後にルックが元と違います​

変換ログの lossy と unsupported の項目をまず読んでください。そのあと、マスクのチャンネルと反転、テクスチャの Tiling・Offset を比べます。AO、サーフェスモード、顔マテリアルの判定も元と合っているかを見ます。 → 変換レポートの読み方

変換やベイクが失敗します​

メッセージ対処
変換できるマテリアルスロットがありませんMingToon マネージャーの位置を確認し、子レンダラーを再検索
MingToon の元シェーダーが見つかりませんインストールが不完全です。パッケージを再インポート
生成したシェーダーをインポートできませんプロジェクトフォルダーの書き込み権限を確認して再試行
生成されたシェーダーにコンパイルエラーがありますMingToon のインクルードフォルダーが元のパスにあるかを確認
MingToon マネージャーが複数選択されています一度に 1 つだけ選択

影​

影が重なる場所だけ真っ黒です​

シャドウカラーセクションの統合シャドウを使用をオンにしてください。フォーム・キャスト・デプスの影が 1 色にまとまります。 → ライティングとシャドウ

オンにしたあと個別の影の色が効かなくなるのは正常です。値は残っているので、オフにすれば戻ります。

キャストシャドウがまだらです​

場所対処
服のしわと体全般セルフキャストシャドウ抑制をオンにし、セルフシャドウ・キャスターバイアスを 0.01 から 0.03 の間に
境界が階段状に角張る投影フェザーを使用をオンにし、投影フェザー半径・投影フェザー強度を調整
全体的にちらつく光源の shadow map 解像度、bias、cascade の順に確認
逆光で体の上にキャラクターの形が重なる逆光シルエット抑制をオンにします
フェザーは存在しない情報を復元できません

解像度の低い shadow map にそもそもなかったディテールは、柔らかくしても戻りません。

シャドウパターンがまったく出ません​

原因対処
パターン形状タイルを使用はオンなのにタイルのスロットが空空のスロットは白として読まれ、白はどんな濃度でも越えられません。同梱タイルを使ってください
パターン強度が 0上げます
適用対象が合っていないパターン適用対象を確認
点がトーンに反応せず、大きさが一定二値化された点の絵を入れています。タイルはしきい値マップである必要があります

暗いワールドでキャラクターが黒く潰れます​

ベースカラー保持、最終最小明るさ、間接光の持ち上げ、キャスト間接光補正を順に上げてください。明るいワールドで白く飛ぶ場合は最終最大明るさを下げます。

デプスエフェクト​

デプスリムライトやデプスシャドウが見えません​

原因対処
全エフェクトまたは深度エフェクトがオフインスペクターがオンにするボタンを表示します
全体幅が 0上げます
各モジュールの強度が 0上げます
サーフェスモードが透明 (3000)半透明 (2499) に変えます
カメラ深度への記録がオフオンにします
VRChat の通常画面アバターからは強制できません → VRChat
URPRenderer Feature のインストールと Depth Texture の有効化
WARUDODepth Bridge のインストール → Warudo

インスペクターに深度テクスチャが用意されていないという案内が出た場合は、その案内どおりに進めてください。SSAO 半径を上げても広がらない場合は、上限に達しています。範囲は 0.001 から 0.05m です。

インナーアウトラインだけ消えました​

Inner Depth Edgeを使用は インナーアウトライン セクションにあります。このセクションは スクリーン空間エフェクト グループの中にあります。

原因対処
インナーアウトラインに適用がオンで、頂点カラーが黒いトグルをオフにするか、圧力ソースを変えます
サーフェスモードが透明 (3000)半透明 (2499) に変えます
カメラ深度がない上の項目を参照

ノーマルアウトラインは深度がなくても描かれます。ノーマルアウトラインだけ見えるなら、深度の問題です。

髪が頬を突き抜けて見えます​

サーフェスモードを半透明 (2499) に変えてください。このモードはアルファ合成を使いながら深度も記録します。

透明深度プリパスは透明 (3000) 専用です。半透明 (2499) でオンにしても何も変わりません。

アウトライン​

ノーマルアウトラインが丸ごと消えました​

原因対処
頂点カラーが黒いのに圧力ソースが VertexRed圧力ソースを変えるか、頂点カラーを確認
圧力コントラストが 0圧力が完全に無視されます。上げてください
カラーマスクが 015 に戻します
アウトラインマスターがオフオンにします。インナーアウトラインもこのゲートを使います

アウトラインが角張った部分で途切れます​

ノーマルソースが VertexColorTS または UV8TS なのに、スムージングした輪郭線ノーマルをベイクしていないメッシュです。MeshNormal に変えてください。 → アウトライン平滑ノーマル UV8

シーンビューでアウトラインの太さを塗れません​

インスペクターが理由を文章で知らせます。メッセージごとの対処はシーンビューで直接塗るにあります。

塗ったら結果がおかしくなりました​

圧力ソースが Vertex Red でノーマルソースが VertexColorTS だと、同じチャンネルを上書きします。圧力ソースを Vertex Alpha に変えるか、アウトラインのノーマルを UV8 へ移してください。

他のオブジェクトまで一緒に変わった場合は、複数の Renderer が同じメッシュアセットを共有しています。メッシュを複製してその Renderer にだけ割り当ててから、塗り直してください。

顔​

顔マスクを塗ったのに効きません​

マスク強度が 0 だと、マスクを無視してマテリアル全体を顔と見なします。0 より大きく上げてください。マスクはテクスチャ、頂点ペイント、プロキシ、マテリアル全体の順に優先されます。 → フェイスシェーディング

顔に影が 1 つも出ません​

深度の可用性が Force Off だと、デプスシャドウは決して描かれません。顔用の自動補正は、顔から投影影を外しています。Face マテリアルの深度オフ時は投影影をオンにすると、深度がないときに投影影へ戻ります。

VRChat​

アップロードしたのに最適化がかかっていないようです​

  1. Unity のバージョンが 2022.3.22f1 かを確認します。2021.3 では VRChat のフックがコンパイルされません。
  2. Console に [MingToon] VRChat build hook compiled and registered. があるかを見ます。
  3. MingToon マネージャーの 最適化 タブで**ビルド・アップロード時に自動最適化（全体共通）**がオンかを見ます。
  4. プロジェクトフォルダーの隣の StudioRaming/MingToonOptimizeReport.txt を開きます。

→ きちんとかかったかを確認する

自分の画面では見えるのに、他人にはデプスエフェクトが見えません​

既定値がそうなっています。深度エフェクトは本人とフレンドにだけ見えます。マネージャーの はじめに タブの非フレンドにも深度エフェクトを表示をオンにすると、全員に見えます。ただし相手側の負荷が増えます。

ミラーで出ないのも意図した動作です。ミラーが他人のシルエットを影として使わないように遮断しています。 → 深度エフェクトがどこまで保証されるか

WARUDO​

WARUDO でデプスエフェクトが全部出ません​

Depth Bridge がインストールされていません。Playground のパスと .cs 拡張子、installed ログを確認してください。 → WARUDO Depth Bridge

メイン画面だけ正常で Spout・NDI の出力が異なる場合は、そのカメラの depth enabled for camera= ログを確認してください。ログがなければ、処理されていないカメラです。

性能​

作業中にインスペクターが重いです​

正常です。編集用のシェーダーは、すべての機能と最大レイヤー数を一度にコンパイルして保持します。そのおかげで、機能をオンにするたびにコンパイルを待たずに済みます。その代わり、Unity エディター内では同じマテリアルがビルド結果の約2倍の GPU 時間を使います（実測）。エディターのフレームレートやプロファイラーの数値でアバターの重さを判断しないでください。軽量化はビルドするときにだけ適用されます。

アバターが重すぎると言われます​

深度エフェクトをすべてオフにすると、深度ライトもビルドから自動で外れます。これがもっとも軽い経路です。 → VRChat 深度ライト

ベイクと復元​

baked マテリアルの復元ボタンが非アクティブです​

ベイクの Manifest が残っているかを確認してください。元の編集用マテリアルの GUID も生きている必要があります。ベイク以降、Renderer の階層とマテリアルスロットがそのままかも見ます。 → 手動 Bake と復元

ベイクのあとにオンにした機能が動きません​

ベイク時点でオフで、保存対象として検出されなかった機能はコードから削除されます。あとからスクリプトでオンにする値は、**ベイク除外（実行時変更）**として印を付けてください。

それでも解決しない場合​

公式 Discord サーバーのバグ報告チャンネルに、次の内容を一緒に残してください。

  1. Unity のバージョンと対象プラットフォーム (VRChat PC / WARUDO / 一般 Unity)
  2. レンダーパイプライン (BRP / URP 12.x)
  3. MingToon のバージョン
  4. Console ログの全文
  5. 再現手順
