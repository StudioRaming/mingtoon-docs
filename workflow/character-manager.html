밍툰 매니저

Manager로 처음 시작하기

컴포넌트 추가 → Face Mesh·Skin Mesh 지정 → 룩 프리셋 선택 → 색감 또는 기존값 선택 → 변환 → 빠른 설정.

Manager는 아바타 루트에 유지합니다. 재질 편집을 마친 뒤 VRC SDK 업로드 또는 WARUDO 모드 빌드를 실행하면 자동 최적화 베이크가 진행됩니다.

이 순서대로 따라 하기. MingToon으로 작업할 아바타 루트에 Manager를 항상 두세요. 의상만 편집할 때도 같습니다. Manager에서 업데이트도 확인합니다. VCC로 설치했다면 MingToon 업데이트는 VCC에서 진행합니다. Manager의 업데이트 안내를 이용할 때도 설치 경로를 먼저 확인하세요. 얼굴·맨살이 없는 의상은 해당 역할을 비워 두고 진행하세요.

Face SDF Studio는 아직 미발매인 제작 도구이며, 아래 온보딩에 필요하지 않습니다.

이 문서를 읽으면 아바타 하나를 처음부터 끝까지 — 변환 · 룩 · 메시 베이크 · 최적화 · 업로드 점검 — 한 컴포넌트에서 진행할 수 있습니다.

재질 하나씩이 아니라 아바타 단위 작업은 전부 여기서 합니다.

붙이기​

변환할 캐릭터의 루트 오브젝트를 선택하고

GameObject > Studio Raming > MingToon > Add MingToon Manager

Add Component에서 MingToon Manager를 찾아 붙여도 됩니다. 루트에 붙인 다음 변환을 진행하면 됩니다.

인스펙터 구성​

실제 작업 탭은 시작하기 · 룩·베이크 · 최적화 세 개입니다.

탭작업
시작하기Face/Skin 지정, Factory 룩과 색감 선택, 변환 또는 현재 재질에 재적용, MLC 진입, 빌드·업로드와 복구
룩·베이크변환용 룩과 재질 설정 프리셋 선택, 선택 범위 베이크·리베이크, 메시 채널과 세부 설정
최적화자동 최적화와 처리 옵션 확인

탭 위의 공통 재질 선택 행에서 역할별 MingToon 재질을 고릅니다. 이 행은 모든 탭에서 접근할 수 있습니다. 재적용할 때는 캐릭터 전체 / 선택한 재질만 범위도 확인하세요. 재질 설정 프리셋의 대상은 이 캐릭터의 MingToon 재질입니다. 설정에 전체 공통과 이 캐릭터가 구분되어 있으면 표시된 적용 범위를 따르세요.

상태 패널​

매니저를 열면 지금 상태가 먼저 보입니다. 새로고침으로 다시 셉니다.

얼굴 슬롯 N개 중 M개의 얼굴 모듈 키워드가 재질 값과 어긋나 있습니다. 이 상태로 베이크하면 얼굴 셰이딩이 빠집니다.

얼굴 모듈 동기화 버튼을 누르면 맞춰집니다. 베이크 전에 반드시 해소하세요.

최적화 범위가 오래됐다면

최적화 범위가 렌더러 N개 중 M개뿐입니다. 캐시가 오래되어 나머지는 최적화 없이 업로드됩니다.

의상을 붙이거나 뺀 뒤에는 하위 렌더러 다시 찾기를 눌러 주세요.

시작하기: 변환​

어떤 셰이더에서 옮길 수 있나​

lilToon 재질이 가장 완전하게 옮겨집니다. Standard, URP Lit 등 다른 셰이더도 변환할 수 있으며, 이 경우 베이스 색·텍스처·노멀·이미션·오클루전과 렌더 상태가 옮겨지고 나머지는 MingToon 기본값이 됩니다.

인스펙터가 어떤 규칙으로 읽는지 표시합니다 — 원본 스키마: lilToon 또는 원본 스키마: Unity 표준 재질 규칙.

변환되지 않는 슬롯​

일부 재질은 일부러 건드리지 않고 원본 그대로 둡니다.

계열
파티클 / VFX굴절 / 보석
퍼 / 쉘오디오 반응
플립북 / 스크롤 / 시간 애니메이션외곽선 전용 / 오버레이 / 보조 패스

MingToon이 그대로 옮길 수 없는 표현이기 때문입니다. 상태 패널의 변환 제외 개수로 확인할 수 있습니다.

전부 제외 대상이면 버튼이 아무 일도 안 합니다

읽을 수 있는 슬롯 N개가 모두 변환 제외 대상입니다. 가 뜨면 변환 버튼을 눌러도 바뀌는 것이 없습니다.

얼굴 · 피부 지정 — 가장 중요한 단계​

Auto는 이름으로 추측하지 않습니다

Auto는 원본 재질이 직접 가진 얼굴 플래그만 읽습니다.

따라서 플래그가 없는 셰이더에서 변환하면 전부 Regular로 남습니다. 얼굴로 쓸 슬롯은 직접 Face로 지정해야 합니다.

슬롯마다 Auto / Face / Skin / Regular 를 고정할 수 있고, 한 렌더러 안의 얼굴·눈·속눈썹도 따로 지정할 수 있습니다. 미리보기에 얼굴 셰이딩 · 피부 룩 · 일반 셰이딩 중 무엇이 적용될지 표시됩니다.

렌더러 단위로 한 번에 지정할 수도 있습니다.

  • 얼굴 렌더러 직접 지정
  • 피부 렌더러 직접 지정 — 여기 지정한 렌더러의 재질은 룩 프리셋의 Skin 값을 받습니다. 맨살 전용입니다.
  • 지정한 렌더러에 역할 표시
옷과 머리카락이 같은 렌더러에 있다면

피부 렌더러로 지정하면 옷까지 Skin 값을 받습니다. 변환한 뒤 슬롯별 목록에서 옷 슬롯을 Regular로 되돌리세요.

밍툰 매니저를 여러 개 선택하면

슬롯별 판정이 비활성화됩니다. 한 번에 하나만 선택하세요.

변환 시 룩 프리셋​

시작하기에서 Factory 룩을 먼저 고르고 색감 프리셋을 고릅니다. 처음 선택의 기본값은 Basic Toon과 Neutral이며, 기억된 선택이 있으면 그 선택이 표시될 수 있습니다. 룩을 적용하지 않는 None 항목은 없습니다.

적용 순서는 룩 → 색감입니다. 원본에 가까운 색감을 유지하려면 색감에서 Keep Existing Values를 선택합니다. 이 선택은 룩 적용을 생략하지 않습니다. 룩 적용 뒤 색감과 보존 대상인 원본 그림자의 밴드 강도·경계·너비·합성 값을 복원합니다. 모든 셰이더 동작이나 수치가 원본과 완전히 같아진다는 뜻은 아닙니다.

이미 변환했다면 시작하기의 현재 MingToon 재질에 적용하기를 누릅니다. 먼저 캐릭터 전체 또는 선택한 재질만 범위를 확인하세요. 현재 MingToon 재질이 없으면 적용할 대상이 없으므로 변환을 먼저 수행합니다.

Face·Skin·Common 역할에 맞는 룩 값이 적용되며, Surface 정체성과 얼굴 프록시 등 캐릭터별 보존 대상은 유지합니다. 표시되는 마지막 적용 프리셋은 이 에디터의 기록이며 재질의 영구 이력은 아닙니다.

일부 재질 변환이 실패하면 해당 원본 슬롯을 유지하고 가능한 다른 재질은 계속 처리합니다. 결과의 실패·제외·손실 항목을 읽고 남은 원본 슬롯을 확인하세요. 유효한 변환 뒤 룩·색감 적용만 실패한 경우에는 그 단계 이전의 변환 값을 유지하고 오류를 기록합니다. 성공한 재질이 있다는 사실을 전체 성공으로 해석하지 마세요.

함께 구울 메시 채널​

변환 직후 필요한 정적 채널만 굽습니다.

채널무엇을 위해
아웃라인 스무스 노멀 (UV8)각진 부분에서 아웃라인이 끊기지 않게
캐릭터 높이 그라데이션 (UV4)루트 기준 높이 그라데이션
이미 사용 중인 UV 채널 덮어쓰기소유권을 확인한 재변환에서만 사용

0.1.8의 얼굴 노멀은 편집 중 Live로 계산하므로 변환 단계에서 UV7을 기본 베이크하지 않습니다. VRChat 업로드 때 업로드 복사본에만 자동 베이크합니다. 텍스처 얼굴 영역 마스크 또는 Face SDF가 UV7을 소유하면 결과를 보존하기 위해 Live 경로를 유지합니다.

UV 채널 사용 현황에서 UV4·UV7·UV8의 소유권을 먼저 확인하세요. → 메시 UV 베이크

복구​

변환은 Renderer·Mesh·재질·Prefab override·dirty 상태를 영속 저널로 기록합니다. 각 영속 변경 직전에 계획 상태를 먼저 저장하므로, 변경 직후 에디터가 종료되는 구간도 복구할 수 있습니다. 저널은 ProjectSettings에 원자적으로 기록되고 손상된 주 파일은 백업에서 복구하며, 이전 버전의 Library 저널은 한 번만 이관합니다. 사용자가 나중에 바꾼 상태는 덮어쓰지 않고 보류하고, 자동 복구가 8회 실패하면 Tools > Studio Raming > MingToon > Advanced에서 다시 시도할 수 있습니다.

원본 머티리얼 복구는 현재 슬롯만 원본 재질로 되돌립니다. 변환 재질이나 메시 UV 베이크는 삭제하지 않습니다.

복원은 하나의 Undo 단계입니다

되돌리면 직전에 직접 수정한 내용까지 함께 사라질 수 있습니다.

변환 짝 검사로 변환 재질과 원본의 짝을 확인할 수 있습니다. 원본 기록이 없는 재질은 프로젝트 전체를 훑기 때문에 시간이 걸려서, 버튼을 눌렀을 때만 실행됩니다.

에디터 런타임 미리보기​

VRChat에는 실리지 않습니다

이 두 그룹은 에디터와 Warudo처럼 스크립트를 유지하는 환경에서만 동작합니다. VRChat에서는 컴포넌트가 IEditorOnly로 표시되지만 자동 삭제는 보장되지 않습니다. SDK 처리 뒤 실제 build clone에서 MingToon 런타임 컴포넌트가 0개인지 검증하고, 이 그룹의 런타임 결과를 아바타 외형으로 기대하지 마세요.

룩 프로필 사용 · 에디트 모드에서도 미리보기 · 룩 프로필

런타임 얼굴 방향​

머리 방향 전달을 켜면 머리 본의 방향을 셰이더에 넘겨 얼굴 셰이딩이 머리를 따라갑니다.

  • 머리 본 — 비우면 자동 판정
  • 머리 축 자동 판정 · 머리 로컬 정면 · 머리 로컬 위쪽
Warudo에서는 별도 Runtime Root가 필요하지 않습니다

Warudo 모드에서는 밍툰 매니저 컴포넌트가 그대로 유지됩니다. 별도 Runtime Root를 프리팹에 붙이지 마세요. 2D 림·2D 그림자·SSAO처럼 카메라 깊이가 필요한 효과는 캐릭터 컴포넌트가 아니라 전역 Playground 플러그인 MingToonWarudoDepthBridge.cs를 설치해야 합니다. → Warudo Depth Bridge

룩·베이크: 세부 설정​

룩·베이크에서 필요한 메시 채널과 대상 범위를 고르고 베이크·리베이크합니다. 변환 시 만들지 않은 채널이나 다시 계산할 채널을 확인하세요. 이미 채워진 채널에는 덮어쓰기를 켜지 않는 한 거부합니다.

캐릭터 높이 UV4와 아웃라인 스무스 노멀 UV8을 개별로 실행할 수 있습니다. 얼굴 노멀은 Live가 기본입니다. 예전 변환에서 _FaceNormalBaked가 남아 프록시 조정이 반영되지 않으면 얼굴 노멀 실시간으로 되돌리기를 실행하세요. 이 작업은 재질의 baked 플래그와 잘못된 Face SDF UV7 선택을 한 Undo 단계로 정리합니다. → 메시 UV 베이크

룩 / 얼굴​

시작하기에서 고른 룩과 색감은 현재 MingToon 재질에 적용하기로 다시 반영할 수 있습니다. 룩·베이크의 변환용 룩에서도 같은 재적용 기능을 사용합니다. 재질 설정 프리셋은 별도 종류이므로 대상과 함께 적용할 값을 확인하세요. 선택만 바꾸는 동작과 적용 버튼을 누르는 동작은 다릅니다.

얼굴 SDF​

빌드·업로드 준비​

최적화 / 베이크​

대부분의 경우 건너뛰어도 됩니다

VRChat 업로드와 Warudo 모드 빌드에서는 빌드 시 자동 최적화가 알아서 걸리고, 재질은 편집 가능한 상태로 남습니다.

경량 셰이더 베이크 (에디터 전용) · 애니메이션 가능 패스 보존 (안전)

텍스처 최적화는 프로젝트 전체 설정입니다

전체 공통으로 표시되는 옵션은 이 Unity Editor 환경의 모든 프로젝트와 캐릭터에 적용됩니다. 이 캐릭터로 표시되는 옵션과 구분해서 확인하세요. 원본 텍스처 변경 여부와 처리 대상은 현재 옵션 설명을 따릅니다.

→ 수동 Bake와 복원

VRChat 업로드 준비​

밍툰 매니저는 VRChat Expressions 메뉴·파라미터·FX를 설치하지 않습니다. Avatar Root에 Manager를 유지하면 변환·룩·최적화 상태를 점검하고, VRChat SDK가 만든 build clone에만 자동 최적화를 적용합니다. 기존 Expressions 구성이나 다른 툴의 메뉴는 그대로 두고 별도로 확인하세요.

  1. Avatar Root 아래의 MingToon Manager를 선택합니다.
  2. 하위 렌더러 다시 찾기를 눌러 현재 의상과 Renderer 범위를 갱신합니다.
  3. 준비 상태 검사와 VRChat 사전 점검을 실행하고 오류를 해결합니다.
  4. VRChat SDK Builder로 업로드합니다. 일반 경로에서는 수동 Bake를 먼저 실행할 필요가 없습니다.
  5. SDK가 만든 build clone에서 RuntimeComponentCount = 0인지 확인합니다. 이 진단값은 빌드 루트 아래의 저작용 MingToon 컴포넌트만 세며 SDK·런타임 컴포넌트 수는 세지 않습니다. Expressions 메뉴·파라미터·FX는 직접 작성했거나 별도 툴이 설치한 최종 결과를 확인하세요.
  6. 업로드 후 본인 화면·미러·Photo Camera를 각각 확인합니다.

문제가 있으면 문제 해결에서 Console 오류와 업로드 준비 검사를 먼저 확인하세요.

내보내기 / 검증​

업로드 준비 점검​

준비 상태 검사 — 계층과 Manifest를 모두 훑기 때문에 버튼을 눌렀을 때만 실행됩니다.

결과는 업로드를 막는 문제는 없습니다. 경고 N건. 또는 업로드를 막는 오류가 N건 있습니다. 로 나오고, 검사 범위(렌더러 · 재질 · 편집용 · 베이크됨)가 함께 표시됩니다. 각 항목의 위치 버튼으로 해당 오브젝트를 바로 찾아갈 수 있습니다.

깊이 Auto는 업로드에서 바뀌지 않습니다

Auto는 바인딩된 깊이 텍스처와 Photo Camera 상태를 직접 읽으며 업로드에서 Force On으로 승격되지 않습니다. 일반 화면 깊이가 필요하면 별도 옵트인 업로드 시 깊이 라이트 싣기의 비용을 확인하세요. → 빌드 시 자동 최적화

VRChat 사전 점검​

규칙 버전 · 검증된 Unity 가 표시되고, 아래를 검사합니다.

  • 없는 표준 프로퍼티 — fallback이 값을 이어받는 데 필요합니다. 폴백 프로퍼티 동기화로 갱신할 수 있습니다.
  • VRChat이 허용하지 않는 컴포넌트 개수

Quest / Android​

MingToon은 Quest(Android) 빌드를 지원하지 않습니다. Quest용 변형을 만들 계획이라면 아래 기능은 모두 빠진다고 보세요.

Quest에서 잃는 항목 — 아웃라인 N · 반투명 N · 깊이 효과 N 으로 실제 개수를 세어 줍니다.

스크립트 제거 점검​

MingToon 컴포넌트는 직접 지우지 마세요

저작 씬의 MingToon 컴포넌트는 직접 지우지 마세요. 매니저를 지우면 캐시된 렌더러 목록이 사라져 업로드 최적화가 범위를 잃습니다. 이 컴포넌트들은 IEditorOnly로 표시되지만 자동 삭제는 보장되지 않으므로, SDK 처리 뒤 실제 build clone에서 RuntimeComponentCount = 0인지 검증하세요. 이 값은 저작용 MingToon 컴포넌트 수이며 SDK·런타임 컴포넌트 전체 수가 아닙니다.

Warudo 모드는 스크립트를 유지하는 별도 규칙을 따릅니다. 이 패널은 검사만 합니다.

전체 흐름 요약​

아바타 루트에 Manager → Face/Skin 지정 → Factory 룩 → Neutral 또는 Keep Existing Values → 변환 또는 현재 MingToon 재질에 적용하기 → 결과·범위 확인 → 필요한 빠른 설정·메시 베이크 → SDK 업로드/WARUDO 빌드

이미 MingToon 재질이 있다면 재변환 없이 재적용할 수 있습니다. 업로드 전에는 실패·제외 슬롯, 선택 범위와 빌드 설정을 확인합니다.

Warudo로 내보낼 때 별도 Runtime Root는 필요하지 않습니다. 깊이 효과를 쓴다면 Warudo Depth Bridge를 Playground에 설치하세요.
