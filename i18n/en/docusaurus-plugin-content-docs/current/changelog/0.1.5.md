*Closed Beta · 2026-08-07*

## Check Before Upgrading

:::caution[A new material's `Base HSVG` hue now defaults to 0 instead of 0.02]
Materials made up to 0.1.4 keep their saved 0.02. If an untouched base map looked rotated by about seven degrees, set the hue back to 0 or use the property's right-click reset.
:::

:::caution[The factory look presets have been replaced]
`SoftCartoon` is gone; `Soft Toon`, `Hard Toon`, and `Rim Shadow` take its place, each with a `- Low` lightweight variant. Materials you already applied a preset to keep their values — only the list you can pick from changes.
:::

:::caution[The lilToon conversion mesh addressing rule changed]
The first conversion after updating rebakes the meshes once. From then on, pulling the same avatar into the scene again reuses what is already baked. → [Docs](/workflow/liltoon-conversion)
:::

## New Features

- **`SSAO (Screen Space Occlusion)`** — Re-reads the camera depth per pixel to darken necks, armpits, cloth folds, and where feet meet the floor. It is not a light and not a post-process pass, so it disappears silently wherever no depth exists. → [Docs](/guides/depth-effects#ssao-화면-공간-차폐)
- **`Shadow Color Map`** — Distributes the single unified-shadow colour through a UV map so hair and skin can hold different shadow colours. White is the neutral value, so turning it on alone changes nothing. → [Docs](/guides/light-and-shadow#그림자-컬러맵)
- **`Screen` added to the screentone's `Pattern Space`** — Locks the lattice to the viewport and lets the character slide underneath: the overprinted screentone or pop-art reading. It cannot bend or shimmer when the field of view or the camera angle changes. → [Docs](/guides/shadow-pattern#패턴-기준)
- **Glitter `Enable Shape Map`** — Replaces each particle's silhouette with a texture. Six shapes ship in `Textures/Glitter/`: Star, Bloom, Sparkle, Heart, Hex, and Flower. → [Docs](/guides/detail-maps#입자-모양-바꾸기)
- **Glitter `Rotation Randomize`** — Turns each particle to a different angle. Lower it to 0 to stand a directional shape such as a heart upright.
- **Glitter `Use Color Too`** — Reads one mask as full RGBA: alpha is the region and RGB tints the particles. It costs no extra texture read.
- **`Fresnel Rim View Strength`** — Chooses whether the view or the light decides where the rim sits. At 0 the rim stays put as the camera turns. → [Docs](/guides/rim#림이-카메라를-따라다니는-게-싫다면)
- **Create a look preset from a prefab** — Right-click a prefab in the Project window → `Studio Raming / MingToon / Create Look Preset From Prefab`. It pulls a Common · Face · Skin set out of a character you already finished shading.
- **VRChat Preview** — `Tools / Studio Raming / MingToon / VRChat Preview` switches the editor view to what an upload actually shows, with camera depth either absent or available. A scene-view banner stays up while it is on. → [Docs](/platforms/vrchat#깊이-효과가-어디까지-보장되나)

## Changes

- **`Shadow Pattern (Screentone)` is now its own tab.** No longer a group inside Shadow Color, it has its own master toggle, preset row, and copy/paste. → [Docs](/guides/shadow-pattern)
- **The screentone can be switched from in-game.** The authoring shader no longer compiles the module out, so `Enable Shadow Pattern` can be driven by an ordinary float animation or a VRChat expression menu.
- **`Rim / Added Light Maximum Multiplier` now defaults to 3 instead of 2.** The factory look presets were aligned to the same value; the rest of the Lighting Brightness Limits group is unchanged. → [Docs](/guides/light-and-shadow#라이팅--어두운-씬에서-검게-뭉칠-때)
- **Renamed to `Cast MingToon 2D Projected Shadow`** — the `...Caster` of 0.1.4. Behaviour is the same.
- **A look preset may make a material cheaper but never quietly dearer.** `- Low` presets still switch heavy modules off; only the direction that raises cost is blocked.

## Improvements

- **Less blue waiting when toggling a module.** The eight look modules that get toggled most (matcap, Fresnel rim, toon specular, backlight, front light, rim shade, emission, occlusion) are now compiled into the authoring shader up front, so toggling them recompiles nothing. The cost of a baked result is unchanged.
- **Lighting variants are compiled once, right after install.** Directional, point, spot, and vertex-light combinations you actually create while working are warmed ahead of time, so switching a light off or dropping a new one in no longer stalls. Run it again from `Tools / Studio Raming / MingToon / Warm up shader variants`.
- **lilToon conversion reuses meshes it already baked.** A single `(1)` suffix Unity appends to a copy gave the same avatar a new address every time, so everything was rebaked. → [Docs](/workflow/liltoon-conversion)
- **The depth mask is read once per fragment.** SSAO and the 2D shadow were reading the same texture at the same UV twice.
- **The `Shadow Interior Reflection` mask now has a keyword of its own,** dropping instructions and one texture sample on materials that do not use it. → [Docs](/guides/rim#그림자-내부-반사)

## Fixes

- **A material with `Cast MingToon 2D Projected Shadow` off turned dark all over** — the transparent depth prepass was gated on the same switch, and the disabled material's depth modules read what stood behind its own body, painting a rim and an inner edge across a whole pair of glasses. → [Docs](/guides/light-and-shadow#역광에서-몸에-캐릭터-모양-그림자가-겹칠-때)
- **Raising the screentone's `Pattern Edge Softness` printed marks on lit surfaces holding no shadow** — the blur is now bounded by the mark. At softness 0 the result is identical to before. → [Docs](/guides/shadow-pattern)
- **The screentone's `Overlay` was indistinguishable from `Recolor`** — the ink reached past the shadow. It is now confined to the shadow.
- **Toon specular went black on the `Screen` and `Overlay` blend modes** — an `[HDR]` colour or an intensity above 1 flipped the formula negative. `Hue` and `Color` had the same defect and were fixed with it. → [Docs](/guides/detail-maps#툰-스페큘러)
- **The face assist offsets ran even on materials with the 2D shadow switched off** — a material that inherited only the value from a preset lost its projected shadow on the face and received nothing in return. → [Docs](/guides/depth-effects#2d-그림자)
- **Inspector guidance corrections** — the `Cast MingToon 2D Projected Shadow` tooltip described the opposite of what the switch does, and turning unified shadow off can change the look in one step because each layer's stored colour returns, which is now warned about. Depth modules also say so when the material is absent from camera depth.

## Documentation

- The manual gained `Lighting Brightness Limits` and `Unified Shadow` sections in all three languages. Unified shadow is on by default and hides the per-layer shadow colours on a new material, and nothing said why.
- Three SSAO descriptions were corrected against the code: it is not multiplied with the occlusion map but joins after the toon band and the screentone taking whichever is darker, it scatters no per-pixel noise, and the far-distance fade begins at 75% of that value.
- The VRChat compatibility document's account of the face coordinate frame was corrected to the path that actually ships. → [Docs](/platforms/vrchat#깊이-효과가-어디까지-보장되나)
