*Open beta · 2026-09-07*

0.1.7 is the cumulative open-beta release after 0.1.6.

**Check before upgrading**

> ⚠️ **Coming from 0.1.6 or earlier, delete the whole `Assets/StudioRaming/MingToon` folder and import 0.1.7 fresh.** That is the official upgrade path. Importing over the old folder can leave scripts, shaders and generated files that no longer exist in 0.1.7, causing duplicate assemblies or compile errors. So many property names changed in this release that a value stored on a 0.1.6 material does not carry over — a name that is gone leaves the shader default in its place, the material keeps working without an error, and you dial it back in from the new defaults with no conversion or migration step. A saved Look Preset gets you back there quickly. Bake output — generated shaders, flattened textures and mask packs — has to be baked again as well. If you created presets or other user files directly under `Assets/StudioRaming/MingToon`, back them up outside that folder first; then delete only the old MingToon folder and import the new package. Materials, textures and prefabs stored elsewhere in the project are not part of this deletion. The separately distributed `MingLightController` folder is not part of it either.

> ⚠️ **The `_Ming` prefix was dropped from material property IDs. Animation curves must be re-bound.** Most property IDs that began with `_Ming` through 0.1.6 are now the unprefixed canonical name (`_MingBacklightColor` → `_BacklightColor`, `_MingGlitterDensity` → `_GlitterDensity`, `_MingAllEffectsEnabled` → `_AllEffectsEnabled`, about 670 in all). There is no automatic conversion. A value stored on a 0.1.6 material, and any animation curve pointing at `material._Ming...`, now names something the shader does not declare, so the value silently falls back to the shader default. Dial the materials back in from the new defaults as described above, and re-bind the animation curves to the new IDs. Presets and JSON documents written against the old IDs can simply be saved again from a current material. If you want a list of the materials, presets and animation clips still using an old ID, `StudioRaming/MingToon/Advanced/Migrate Project To Current Schema` validates and reports — it is not required for the upgrade, and it does not rewrite curves. Some `_Ming` names stay (`_MingVirtualLight*`, `_MingMaterialVersion`, `_MingUnifiedShadow*` and others), so do not strip the prefix everywhere.

> ⚠️ **Bake caches regenerate, and VRChat avatars must be re-uploaded.** The generated shader cache version moved up, which invalidates existing bake output. The next build rebakes it automatically — nothing to clean up by hand, but that one build takes longer. This release's MatCap optimisation only applies once you rebake. Shaders are bundled in the avatar asset bundle, so an avatar already uploaded must be uploaded again to receive this fix.

> ⚠️ **Face shading and shadow shape change on some materials.** In both cases the old behaviour was the bug. Shading that popped hard as the light crossed the centre of the face now moves across smoothly, and the face depth offset that was wrongly applied to the whole body on a unified material with the face region vertex-painted is gone.

> ⚠️ **Lighting defaults changed.** Nine lighting defaults, including `Scene Light Color Influence` and `Indirect Light Lift`, were retuned to match a real production setup, and `Enable Translucency` now defaults to off. This applies only to newly created materials and the factory presets; materials you already made are left untouched.

> **2D Rim Light gained `Scene Light Influence`.** It defaults to 1, so existing materials without a saved value may also show a darker rim inside a dark light volume. Set `Scene Light Influence` in `2D Rim Light` to 0 to disable this influence.

> ⚠️ **`Additional Light Energy Cap` is new. Point and spot lights are held back more than they used to be.** It caps the energy that additional lights such as point and spot add to the final surface brightness, and the shader default is 0.35 — the value at which a highlight under a strong coloured light keeps its colour instead of blowing out to white. It limits the brightness contribution only, so the additional light's colour still comes through as before. A value stored on a 0.1.6 material does not carry over, so on a project you deleted the folder from and imported fresh every material starts at that 0.35 default. If additional lights feel darker than before, raise `Additional Light Energy Cap` under `Lighting`.

> ⚠️ **`2D Shadow Bias` changed scale by 10x in this release.** 1 now means 10 cm, not 1 cm. A value stored on a 0.1.6 material does not carry over, so there is nothing to convert by hand - dial the value in again on the new scale. The bundled Soft Toon presets are stored on the new scale. The same pass removed the `Depth Blur` and `Light Pushback` rows: `Receiver Depth Pushback` now affects camera depth only.

> ⚠️ **Face SDF Studio and Mask Maker are no longer bundled from this release on.** Both tools are now separate products. Buy either one and drop it into the project, and the matching place in the inspector integrates with it exactly as before. Without it, that button becomes a notice — nothing else is affected.

> ⚠️ **VRChat Expressions menu authoring was split out of the MingToon core package.** The old installer UI was removed from the Manager. The separately sold `Ming Light Controller (MLC)` add-on now owns per-avatar menu, parameter and FX authoring. Without MLC, only the generated runtime menu is unavailable; the MingToon shader and the Build Depth Light choice still work normally. Menus, parameters and FX layers physically installed by an earlier release are not removed automatically, so clean them up by hand if you no longer want them.

> ⚠️ **The URP backend ships as a separate add-on.** The base package contains BRP and the shared core only. The URP shader and its Renderer Features are delivered separately as `MingToon_URP_Addon_0.1.7.unitypackage`, included in the paid distribution download. If you have been using MingToon in a URP project, import the base package first and the add-on after it. Installing the add-on on its own is not a supported configuration. In a project without the add-on the URP shader does not appear among the shader choices, while the shared editor features still compile and work. VRChat PC and Quest do not use URP, so neither is affected by the split (PC uses the BRP baked version, Quest the mobile conversion). The add-on targets WARUDO and general Unity projects on URP 12.x. The bundled `MingToon_URP_Addon.md` documents the install order and everything included.

### Cleanup of 0.1.6 Generated Assets and Automatic Updating of Converted Meshes

- The cleanup module included only in this version runs by itself, once per project, the first time the 0.1.7 editor code loads. It runs the same whether you imported over the old package or deleted the folder and imported fresh - 0.1.6 generated output lives in `Assets/StudioRaming/MingToonGenerated/Shaders`, not inside `Assets/StudioRaming/MingToon`, so deleting the MingToon folder leaves it behind. The module picks only the obsolete 0.1.6-style fixed profiles it can prove MingToon generated, redirects the baked materials using that exact profile to the current canonical BRP/URP shader, and then deletes the profile. That is what prevents a Missing Shader. It does not change any material values beyond the shader reference, original/editable materials, or foreign shaders/assets in other folders. If the current BRP/URP shader it would redirect to is unavailable or has errors, it keeps the profile and reports that in the Console.
- Old parameters are not translated to the new layout, so the look may change. To obtain the correct current-version look, convert the original/editable materials again and then Bake.
- By default, MingToon Manager saves editable materials and generated Mesh assets together in a `MingToon` folder beside the original Model/FBX. If you specify a conversion output folder, both use that folder.
- MingToon-owned Mesh assets previously stored in the global `MingToonGenerated/Meshes` folder are moved beside their original source during the next conversion, while preserving their GUID, `.meta`, and Renderer references.
- When a Model/FBX with the same GUID is overwritten, reimported, or moved, its registered generated Mesh assets are automatically rebaked after import completes. Mesh assets that can be safely reused are updated in place, preserving their GUIDs and Renderer references.
- MingToon does not overwrite assets automatically when the Renderer scope has changed, the source Mesh cannot be identified unambiguously, or the user has made conflicting edits to the generated Mesh's geometry, colors, or UVs. Check the warning and convert again in MingToon Manager.

**New features**

### 1. `Enable Emission Layer 2`

- A second emission map, so different areas can glow in different colours. The two layers are added, so each area keeps its own colour. Off by default.

### 2. `Map Alpha Masks Intensity`

- Uses the emission map's alpha channel as a per-pixel intensity mask. The alpha is already read along with the colour, so it costs no extra texture read. Present on both emission layers.

### 3. Copy and paste material settings

- Copy and paste buttons were added to the inspector's top bar. Paste comes in five variants — `Paste All`, `Paste Values Only (No Textures)`, `Paste Textures Only`, `Paste Keywords Only` and `Paste Render Queue Only` — so you can carry settings across while leaving each material's own textures in place. Undo (Ctrl+Z) works.

### 4. `Quick Settings` card and color Gamma

- The controls that take effect across the whole material are gathered in one place at the top of the inspector, `Unified Shadow Color` among them.
- `Gamma` was added to Unified Shadow and SSAO tone controls, Normal Outline Color, and Inner Outline Color. It adjusts only the value axis, preserving hue and saturation; 1 preserves the existing look. Outline opacity and width are unchanged.

### SSAO (Screen Space Occlusion)

- The `SSAO` tab in the Depth group settles into the form this release ships. Coming straight from 0.1.6 the tab itself is new to you. It reads screen depth to find where objects meet and darkens only those places; unlike an occlusion map it is applied after the toon bands and the screentone, so it never stair-steps a shadow edge. **It is off by default, so no existing material changes.**
- The units and ranges moved since the module was first described. `SSAO Radius` is 0.001-0.03 (default 0.005), and what was described as a fade range is now called `Contact Falloff`: a multiple of `SSAO Radius` rather than metres (0.25-4, default 1). `SSAO Bias` is likewise a ratio of `SSAO Radius` rather than absolute metres (0.4 = 40% of the radius). Being a ratio of the radius, the look follows along when the camera distance or the radius changes. The far distance is no longer an SSAO-only row: it merged into `Shared Fade Distance` (default 200), which the 2D shadow uses as well. Do not carry figures over from an older release.
- Like every other depth module it needs the camera depth texture. It disappears silently where depth is unavailable, switches off with `All Effects` and with the `Depth Effects Master`, and is off on the VRC Low quality tier. The Build Depth Light also counts an SSAO-enabled avatar as a depth-module user.
- The cost is paid per visible fragment, not once per material. The depth group's `Shared Quality` sets the depth samples per pixel (Low 4, Standard 8, High 16), and `Shared Fade Distance` is the control that ends the cost — a character past that distance takes zero samples, which makes lowering it the surest optimisation in a crowded scene. Both rows are shared with the 2D shadow, so neither can be adjusted for one module alone.
- `Visibility in Cast Shadow` and `Visibility in 2D Shadow` set how much of the occlusion is still drawn inside each shadow. Manual section `3-10. SSAO` documents every control.

### 2D Shadow: one silhouette sheet and its depth response

- The 2D shadow is now one silhouette sheet. The front object's silhouette is shifted away from the light and that one sheet is read, then pushed farther the more the front object floats off the receiver - what rests on the surface stays at the width and only what floats moves out, which is what reads as depth.
- The shadow is judged against the receiver's own tangent plane, so the marks the face's and body's own curvature used to leave are gone while the shadow of bangs almost touching the forehead survives.
- The `2D Shadow` tab settles on these controls: `Shadow Width`, `Shadow Intensity`, `Depth Stretch`, `Depth Curve`, `Depth Falloff`, `Softness`, `Blur`, `2D Shadow Bias`, `Receiver Depth Pushback` and `Suppress Backlit Silhouette`.
- `Depth Stretch` (default 1) is what creates the depth. At 1 an object floating 10 cm away lands its shadow 10 cm past the width; at 0 nothing is pushed and the sheet is read at the width only. `Depth Curve` sets the shape of that push and `Depth Falloff` how strong a far-floating object's shadow stays.
- The further the camera looks down at the character, the shorter `Depth Stretch` eases and the thinner the stretched part gets. The push is a screen direction, so looking down used to leave the shadow reading as a long smear; a side-lit shadow pushed across the screen is untouched. There is no control for it; it is automatic.
- That shortening now reaches materials using `Face Fixed Direction` as well. The face was exempt until now, on the grounds that it pins its shadow direction to the head, so with the camera looking down at it only the bangs shadow kept its full length while the body's shadow at the same angle shortened correctly. What is pinned is the **direction** the shadow points, not its length, so the direction still follows the head and only the length now shortens with the camera angle. The stretched part and the part at the width shorten together, so how a side-facing surface fades out is exactly what it was.
- The length never collapses to nothing. A floor keeps the shadow axis defined, and at that floor the shadow is 2% of the `Shadow Width` you set - a size no one sees.
- `Blur` is applied last, to the finished shadow, and its radius comes from that value in metres alone. Only then is the sheet read five times - the centre read plus a four-tap rotating disc.
- The inside of the shadow is painted solid in the shadow colour you chose. On a material using the unified shadow a fully covered area comes out exactly the colour of the form shadow's core, and the `Shadow Boundary` band lands only on an edge softened by Blur or by depth.
- The quality and distance rows merged into two shared controls in the depth group, `Shared Quality` and `Shared Fade Distance`. `Shared Quality` sets SSAO's sample count only; the 2D shadow ignores the tier and reads a fixed handful - one at the width, four votes, one sheet read, and with Blur on that sheet read becomes five, ten at most.
- SSAO now exposes `Color Purity` (0-10, default 1), `Color Brightness` and `Color Gamma`; default purity 1 preserves the composed color. The old `SSAO Saturation` name is not a shader property.
- Manual section `3-11. 2D Shadow: one silhouette sheet and its depth response` documents each control.

### `Backlight Blend Mode` and `Front Light Blend Mode`

- You can now choose how the backlight and the front light mix their color into the surface: Normal, Multiply, Add, Hue, Screen, Color or Overlay - the same list the other rim modules use. The `Blend Opacity` (0-1) added beside it lowers the effect's presence without touching its color or intensity.
- Both default to `Add` at opacity 1. That combination is the same expression as the previous direct addition, so this entry alone changes nothing.
- Outside `Add`, `Backlight Intensity` and `Front Light Intensity` act as how much is mixed in rather than a brightness multiplier. Hue and Color cannot hold a hue above a luminance of 1 and drift to gray there, so use `Add` or `Screen` when you want the layer to burn.

### `Re-bake meshes now`

- A button was added at the bottom of `Setup` > `1 · Convert` > `Mesh Channels To Bake` in the Manager. Press it after editing the source FBX and it rebakes only the channels ticked above - outline normals, face normals, character height.
- Materials and look values are not touched. Running the conversion again to get the meshes back would rewrite both, and re-applying a look preset over hand-tuned values is exactly what this button avoids. The scope selector above the group picks `Every mesh on this character` or `Selected objects only`.
- It is disabled when there is no target mesh, no channel ticked, or the output folder is not valid.

### lilToon 2.3.4 conversion fidelity and the shared UV router

- The lilToon 2.3.4 material path was remapped for HSVG, alpha masks, outline width and vertex pressure, rim direction and backface conditions, MatCap mask channels, reflection color, and toon specular. The report now warns only for values that cannot be represented; equivalent defaults and empty no-op masks are not counted as failures.
- Main Color, 2nd and 3rd layers and their independent masks are imported. The 2nd and 3rd layers become MingToon stacking layers so their color, mask and blend conditions remain independent.
- The base surface, alpha mask, ten stacking layers, emission layers 1 and 2, and their masks share one UV router. UV0-UV3, Tiling/Offset, scrolling, rotation around the center, rotation speed, and sprite-sheet columns, rows, frame count and playback speed use the same implementation.
- lilToon decal position, size and rotation; single-image versus tiled display; left/right restriction; copy, flip and mirror modes; and sprite-sheet animation are converted. Atlas textures that move like an animated image are supported; this release does not include a video-file decoder.
- UV routing is compiled only into a generated shader that uses it. A material that uses the default UV and static textures does not pay the extra routing or atlas work.
- Automatic rewriting of old material-property curves inside AnimationClips, and Fur, Gem and refraction conversion, are outside this release.

### Conversion report cleanup

- Conversion results are grouped as source-and-result pairs instead of one long paragraph per material. Each pair prints both material paths under `Source:` and `Converted:`, states how the two were matched under `Resolution:`, and then splits what could not be carried across into two lists, `Core mismatches` and `Explicit losses`. Expand the `Last Conversion Result` panel for that detail, and `Copy All` takes the whole report in one action.
- `Resolution` is one of `Matched by provenance`, `Matched by unique name`, `Ambiguous name; review required` and `Source missing`. The first two mean the pair is settled; the last two mean you have to check which original the material came from yourself.
- UV, decal, emission, alpha and outline settings that are immediately visible on clothing are converted as far as the destination can represent them instead of being left as warnings. Only features without a rendering path in this release, such as Fur, Gem and refraction, remain as `Explicit losses`.
- A warning now sits under `Direct Face Renderer` and `Direct Skin Renderer`. It counts the MingToon materials on those named renderers that are not marked with that role yet - so many face, so many skin - and points at the `Mark Roles on the Named Renderers` button right below it. Without the role mark a look preset cannot route its face and skin values to those materials and they end up painted with the regular ones, and until now nothing on screen said so. It counts exactly what the button marks, so when the warning goes the marking is done. It appears in all three languages.

### Per-avatar Ming Light Controller settings (separately sold add-on)

- The VRChat lighting and look-control menu generator was separated from the MingToon core package into a separately sold add-on named `Ming Light Controller (MLC)`. MingToon updates and avatar-menu authoring can now be managed independently, and users who do not need a runtime menu do not need to install the add-on.
- A `Ming Light Controller Settings` component now stores the expression profile, the attachment mode and the per-feature adjustments on the avatar root. Those values used to live in the window alone, so the last avatar you touched decided the next one's setup and nothing survived a script recompile. Two characters in one project can now carry different menus and parameter budgets.
- Add it by right-clicking a prefab in the Project window and choosing `MingToon` > `Ming Light Controller`, or from the button in the Attachment window. Only the entries you actually changed are recorded, so returning one to the catalog default removes its record. It holds authoring intent only and does nothing at run time.

### `Performance Distance` — the heavy modules switch off outright with distance

- Two rows joined the bottom of the `Master Adjust` tab: `Performance Distance (m)` (default 10) and `Performance Distance Scale` (default 1). The camera distance is split into near, mid and far bands against the product of the two, and whole modules are cut as the camera moves away.
- Within 0.4x of that product (4 m by default) nothing changes at all. Past it (4-10 m by default) the four camera-depth modules, PBR, matcap layers 2 and up, normal layers 2 and up, stack layers 3 and up, glitter, screen tone and the shadow interior reflection switch off, and the sample-count tiers step down once. Beyond 10 m what remains is base colour, the first form shadow, the cast shadow, outlines, emission, rim shade and the face SDF.
- It is combined with the existing `VRC Quality Tier` by taking the lower of the two. Mid caps where quality tier Mid does and far where Low does, so a material already set to Low stays Low however close the camera gets.
- The band is decided per object - the renderer's origin against the camera - so every pixel of a character takes the same one. It switches at the threshold; the gradual disappearance is still `Shared Fade Distance`'s job.
- The scale is what the separately sold MLC add-on drives from an in-game radial: turn it down to 0 in a crowded instance to pin the avatar to its cheapest state, raise it for photos to keep the near look further out. Neither row folds into a baked constant, so both keep working after upload.
- The defaults change no look. What you see up close is unchanged; only distant avatars get cheaper.

### `Surface Mode` option names tidied up

- The four `Surface Mode` options were renamed to carry their render queue: `Opaque (2000)`, `Cutout (2450)`, `Semi-Transparent (2499)` and `Transparent (3000)`. 0.1.6's `Transparent · Outline Depth Ready` is `Semi-Transparent (2499)`. Only the names changed — each mode's render state, queue and stored value are as they were — so no existing material looks different.
- The difference between the two transparent modes is now spelled out in the option's own description. `Semi-Transparent (2499)` uses alpha blending and writes depth as well. At render queue 2499 it lands in the camera depth texture, so it is the mode to be on if you want `2D Shadow`, `2D Rim Light` or `Inner Outline` on a transparent surface. Because it has depth, it suits a surface where the far side must not cover the near one, such as double-sided hair.
- `Transparent (3000)` is standard alpha blending. It writes no depth and draws back to front, so overlapping layers sharing one material — body, underwear and skirt — show through each other instead of erasing one another. It is also the side for a surface that has to blend with other transparent objects, glass among them. In exchange it stays out of the camera depth texture, so the three modules above are unavailable. Both modes can keep their outlines.

### `Two-Sided Dual Pass`

- `Two-Sided Dual Pass` was added to `Surface Rendering`. It draws the far side of a surface whose `Visible Faces` is `Off (Double-Sided)` in its own pass, before the near side. The per-triangle sawtooth where a skirt flap folds across itself disappears, and the far side blends through by alpha.
- The cost is one vertex pass and one SetPass. Pixel cost is unchanged — a double-sided surface was already shading both facings.
- It can be switched on independently of `Surface Mode`. It is off by default, so no existing material looks different.

### `Transparent Depth Prepass` — an outline no longer shows through a transparent material

- A `Transparent (3000)` material writes no depth while it draws colour, so its outline showed through the surface toward the camera. Turning on `Transparent Depth Prepass` under `Surface Rendering` draws one more depth-only pass and rejects that outline.
- `Semi-Transparent (2499)` writes depth itself and does not need it, so the option only takes effect on `Transparent (3000)`.
- If a back-side outline still shows through a fold seen edge-on, raise `Outline Reject Margin (Slope)` and `Outline Reject Margin (Constant)` a little at a time. Both default to 0, and overdoing it erases the silhouette outline along with it.

### `Alpha Fades` — make a surface disappear with distance or with angle

- An `Alpha Fades` area was added to `Alpha & Cutout`. `Enable Distance Fade` fades the surface out by how far it is from the camera. Use it to keep your own head or accessories out of your own view in first person, or to make something disappear as it gets further away. The near side is set by `Near - Fully Gone At` and `Near - Fully Visible At`, the far side by `Far - Starts Fading At` and `Far - Fully Gone At` (in metres); equal values in a pair give a hard switch at that distance.
- `Enable Fresnel Alpha` varies transparency with how squarely the surface faces the camera. `Opacity Facing Camera` and `Opacity At Silhouette` decide the direction between them, which is why there is no mode to pick. It reads the mesh's own facing rather than a normal map, so it follows the silhouette.
- Both are off by default, and the ranges you get the moment you switch one on hide nothing, so set the distances and the opacities yourself. An `Opaque (2000)` `Surface Mode` hides the result.
- Two caveats. `Transparent Depth Prepass` does not account for the fade, so a place the fade emptied can keep occluding the semi-transparency behind it. And a surface faded away still casts its shadow — the shadow is drawn from the light, not the camera, and that pass has no camera distance to measure. When you fade something out completely at distance, switch the renderer's shadow settings off with it.

### `Gradation LUT` and `Hue Rotation Space`

- `Gradation LUT` was added to `Base Surface`. It re-maps the Base Map's colours through per-channel R/G/B ramps. Assign a horizontal ramp texture to `Gradation LUT` and import it as sRGB. `Gradation Strength` sets how far the ramp result is mixed over the source colour. It is off by default, and off reads no ramp texture at all.
- `Hue Rotation Space` was added in the same place. It picks which space the base map's HSVG hue (H) rotates in. `OKLab` turns the hue while holding lightness and chroma steady, so moving a skin or hair colour stays predictable; `HSV` is the behaviour you have had so far.
- **An existing material picks its space automatically from the HSVG values it has stored.** A material already dialled in under HSV stays on `HSV` and its colour does not change. Use `OKLab` when you rotate a hue from scratch.

### Shared Build Depth Light for VRChat and WARUDO

- New Managers enable the preference by default, but builds carry the light only when the Depth master and at least one actual depth effect are enabled.
- Avatars with no depth features omit it automatically; authors targeting a world or host that supplies depth can turn it off manually.
- VRChat and WARUDO use the same setting and decision, while the scene, source prefab, and material values are preserved after the build.
- The generated depth light is carried as `Not Important` (`ForceVertex`), so it does not render a shadow map or ForwardAdd. This is measured in the editor; the actual VRChat client remains unverified. Existing uploads must be re-uploaded to receive it.

**Changes**

### 5. VRChat Expressions menu authoring moved to the MLC add-on

- The whole VRChat Expressions install block is gone from the Manager: `Non-Destructive Modular Avatar Install`, the Full/Lightweight choice behind `Use Full Control Menu`, `Place Directly In Expressions Root`, the install button, and the bulk button that switched `Use VRC Runtime Controls` and `Switch Shadow Projection From FX` on or off across every material on the character.
- The MingToon core package no longer builds Expressions menus, parameters or FX layers directly on an avatar. That role moved to the separate `Ming Light Controller (MLC)` product. Without MLC only automatic menu generation is unavailable; you can still drive the same properties with a menu and animations you author yourself.
- Anything installed by an earlier release stays on the avatar. The path that used to remove it is gone as well, so clean it up by hand if you no longer want it.
- The material's `Use VRC Runtime Controls` and `VRC Quality Tier` are still in the inspector. MLC can connect them to an avatar menu, or you can author the required menu and animations yourself without MLC.
- The clean-up is finished within this release: the old installer sources (`MingVrcVirtualLightExpressionInstaller`, `MingVrcVirtualLightContract`, `MingVrcModularAvatarBridge`) and the Manager install-panel strings are gone from the package too. The properties that `Use VRC Runtime Controls` keeps live through the bake, and the shader properties themselves, are unchanged; MLC drives them.

### Leftover installer API removed (breaking)

- **`MingToonManager`'s public `UseModularAvatarVrcIntegration`, `VrcFullExpressionMenu` and `VrcMenuAtExpressionsRoot` properties and the three serialized fields behind them are gone.** They are leftovers from the built-in VRChat installer removed above, and nothing in this release reads them. Whatever a scene or prefab had stored disappears with them, but the installer itself is gone, so neither behaviour nor look changes. A user script referencing those properties will fail to compile; remove the reference.
- The same pass deleted `MingVrcDepthAvailabilityPolicy` from the package. The type held one boolean and one sentence, and nothing read either. The ship-time depth decision is still made by `MingVrcDepthLightPolicy` and the build depth light path, so behaviour is unchanged.

### 6. Three PBR-related sections moved out into their own `PBR` group

- `PBR Surface`, `Toon Specular` and `Region Mask` were mixed into the character group and are now a separate one. It sits after `Character` and before `Depth Effects`. Values and defaults are unchanged.

### 7. Inspector sections and Fresnel regions cleaned up

- The top-level `Rim` group is now `Stylized Lighting`, reflecting that it also contains Front Light and Shadow Interior Reflection.
- The lighting controls moved into a `Shadow` section inside `Basic Settings`, ordered `Form Shadow` → `Cast Shadow` → `Shadow Color` → `Shadow Pattern`.
- The rim family reads `Rim Light` → `Rim Shade` → `Front Light` → `Backlight` → `Shadow Interior Reflection`, and the depth family `Depth Effects Master` → `2D Rim Light` → `2D Translucency` → `2D Shadow` → `Inner Outline`.
- Fresnel-style regions now share `Width`, `Softness`, and `Invert Area`. Width 0 is none and 1 makes the whole domain available. Softness changes only the feather ratio inside that support without moving its outer boundary; Width 1 with Softness 1 is a full-domain gradient rather than a solid fill.
- Rim Light and Shadow Interior Reflection now call their former `Light Direction Influence` control `Light-Side Emphasis`, matching its actual brightness role. The old 0.5 floor on the opposite side is removed, so rotating the resolved main or Virtual Light produces an immediate response. Rim placement remains under `View Alignment`.
- Front Light is now separate from the Fresnel family and uses a dedicated circular cap whose `Area Size` closely tracks projected radius. It directly exposes `Area Size` and `Softness`; `Light Direction Influence` and the new `View Direction Influence` independently weight the main-light and camera directions. At a View value of 0, camera orbit leaves the cap locked to the light axis. A low-cost `Highlight Core Size/Intensity` reuses the same radius. Size 1 makes the full front available while Softness remains active across it. Fresnel area inversion is not used.
- The former Front Light `Border`, `AreaInvert`, `Directivity`, and `ViewStrength` properties were removed without automatic conversion. The new view control uses `_FrontLightViewDirectionInfluence` rather than reviving the old ID. New defaults and factory presets were authored for the correct mechanism; at the time of this entry the material property schema was 15 and the preset schema 10. Later changes in the same release took the material property schema to 17, which is the figure this release ships.
- The five former Power/Falloff values were also removed without migration instead of remaining as hidden compatibility storage. Backlight keeps its serialized `Border` and displays `Width = 1 - Border` in the inspector.
- `2D Rim Light` gained an optional Fresnel region. It multiplies the existing 2D Rim Light result, and disabling it reproduces the previous output exactly. Invert Area bypasses only the geometric silhouette guard that would erase the camera-facing selection; depth comparison and material masks remain active.

### 8. The `Performance Cost` meter shows the post-bake figure by default

- The number may read lower than before without you changing anything. The material did not change, the yardstick did. What actually uploads is the baked shader, so that is the headline figure now. The figure for the material you are editing is still there under the detail breakdown.

### 9. A notice on the `Overlay` + `Depth2D` combination

- Leaving `Pattern Style` on `Overlay` and switching `Pattern Target` to `Depth2D` now shows a notice. `Overlay` prints line work over finished shading, so it only works on the form shadow; on 2D it falls back to `Recolor`. That has always been the case, but nothing said so.


### Projection Feather reworked, with automatic conversion

- `Cast Edge Feather Quality` went from five kernels to three: `Light3Tap`, `Standard5Tap` and `High9Tap`, all one method now — a centre tap plus a golden-angle disc rotated per pixel by noise. The old per-kernel radius caps (8/20/48 px) went with them, so all three tiers honour the full slider range.
- `Projection Feather Radius` was re-based from screen pixels onto the same camera-stable world width the 2D Rim Light uses. The range went from 0-400 (default 60) to 0-20 (default 3.5).
- **Both saved values convert automatically when the material is opened.** The value you see is converted, not reset. Quality maps as `Premium25Tap` and `SoftBilinear9Tap` → `High9Tap`; `Fast5Tap`, `Smooth13Tap` and `StableVogel5Tap` → `Standard5Tap`; `DerivativeEdgeAA1Tap` → `Light3Tap`. The radius converts from the pixel reach each retired tier could actually produce.
- **The number in each name is the per-pixel read count.** It is the one centre read the shader already holds plus 2, 4 or 8 disc taps, and the disc reads the main directional light's shadow map only. It never reads the camera depth texture, so this control cannot bring a depth prepass along with it.
- **The disc taps got cheaper on URP.** With the project's soft shadows on, every disc tap used to unfold a 5x5 filter of its own, taking the per-pixel shadow-map reads to 36 at `Standard5Tap` and 72 at `High9Tap`. Each disc tap is now one hardware comparison, so it is 4 and 8. The disc is itself the filter that softens the edge, so laying a filter over it was doing the same job at nine times the price. The centre tap uses the filtered shadow value URP has already computed, so the softness of soft shadows stays. A setup on screen-space shadows was one fetch per tap to begin with and is unchanged, and Built-in is unchanged. The edge can come out very slightly crisper.
- **The `Performance Cost` meter counts this feather now.** Until now the module read as 0 on the meter, so it could not be put beside the 2D shadow, whose per-pixel reads were counted honestly. Turning the feather on and off now actually moves the number. It follows the same convention as every other module - counted only while `Shadow Projection` and `Projection Feather` are on and the radius and strength are above 0 - and the tap count is the 2, 4 or 8 of the tier you picked. Shadow-map reads are counted apart from depth reads, so the depth-prepass entry does not rise by mistake.

### `2D Depth Rim` is now labelled `2D Rim Light`

- Everything the inspector showed as `2D Depth Rim` or `Depth Rim` is now labelled `2D Rim Light`. Sub-entries follow the same head, so `2D Depth Rim Mask` becomes `2D Rim Light Mask`, and names that were missing the prefix, such as `Depth Rim Backlight Boost`, gain it.
- This entry is a label change only. No 2D Rim Light material property was renamed - `_DepthRimEnabled`, `_DepthRimMask`, `_DepthRimWidth` and the rest keep their identifiers - so this rename by itself needs no rebinding. A separate property-ID canonicalization does ship in this release, though: read the `_Ming` prefix item in the upgrade warnings above.

### One behaviour for every button that needs a separately sold add-on

- Buttons that need Mask Maker, Face SDF Studio, or Ming Light Controller stay visible and stay clickable without the add-on. Clicking one opens the manual page for that feature, which is also where the purchase link lives.
- Each spot used to behave differently. The mask authoring button and the vertex paint start buttons were greyed out, so the reason was only visible on hover, and the Face SDF button raised a dialog and left you where you started.
- `Master Adjust` and `Virtual Light` follow a different rule, because they are places that write values rather than buttons. Without Ming Light Controller the rows MLC owns - the `Everything That Adds Light`, `Of Those, Only The Silhouette`, `Every Shadow` and `Final Output` groups, plus the `Virtual Light` group - are not drawn. No lock notice, no greyed-out control, nothing in their place: a control you cannot commit a value with is not worth showing.
- The `Performance Distance` group at the bottom of the `Master Adjust` tab works without the add-on, so it is always drawn. In a project without MLC it is the only group left on that tab.
- Either way, values already stored on the material stay where they are and the shader keeps reading them. Installing MLC brings the rows back in the same place.

### Cast shadow reception rebuilt

- How a cast shadow darkens a surface was rewritten. Shadow attenuation now multiplies the direct-light term only, and the ambient (SH) light is added back on top as a floor. `Cast Indirect Lift`, which was dead in Unified Shadow mode, works again, so a cast shadow no longer punches to black in a brightly lit environment. In a scene with no ambient it adds nothing.
- **Materials on Unified Shadow, the shipping default, get brighter cast shadows in a scene with ambient light.** The old opacity reduction used by Layer mode is replaced by the same additive floor.
- The point at which `Suppress Backlit Silhouette` starts erasing the cast shadow now follows the form shadow's effective boundary instead of a fixed angle. The new `Backlit Suppression Offset` (0-1, default 0.25) sets how far past that boundary, toward the dark side, the erase begins; half of `1st Shadow Blur` is added on top, so the cast shadow's fade-out edge always hides inside the form shadow. It sits under `Advanced` on the `Cast Shadow` tab, directly below `Suppress Backlit Silhouette`. Materials with the form shadow off keep the old fixed window.
- The caster push behind `Suppress Self Cast Shadow` now fades automatically under backlight to protect the contact silhouette, and applies to directional lights only. Only materials with that toggle on are affected, and the bias is not applied under spot or point lights.

### The face-only self-surface suppression row folded into one `Receiver Depth Pushback`

- The face-only self-surface suppression row that sat on the `Face` tab is gone. One value now does that job - `Receiver Depth Pushback` on the `2D Shadow` tab - and the face and the body share it. It pushes the camera depth this material writes backward to cut self-surface artifacts; `2D Shadow` and `SSAO Enabled` read it, while the light shadow map is left unchanged.
- It works regardless of `Face 2D Shadow Assist`. It used to apply only while the assist was on, so with the assist off, which is the shipping default, the slider visible in the inspector was silently dead and angular chunks of shadow were left along the nose ridge. It now takes effect whenever `All Effects` and the `Depth Effects Master` are on and either `2D Shadow` or `SSAO Enabled` is on.
- A view-facing weight was added. Only relief turned toward the camera - the nose, the cheeks, the brow - is pushed back and loses its self-artifacts, while grazing surfaces such as the underside of the jaw keep their true depth, so the chin-to-neck shadow keeps its separation.
- **Open your materials and check `Receiver Depth Pushback` on the `2D Shadow` tab.** Use it on receiving face and body materials only and keep casters such as hair and clothing at 0. A new material defaults to 0, and the bundled factory looks use 0.01 on the face slot alone.
- **The slider's ceiling came down from 1 to 0.1.** 0.1 is 10 cm, and that is where the effect ends: the gap the 2D shadow judges front-from-back with clamps at 10 cm and the SSAO radius is far smaller, so a value above it never changed a pixel. The slider now ends where the effect ends, the same tidying this release did to the `2D Shadow Bias` scale. The range anyone actually used - 0 by default, 0.01 on the factory face - is untouched, so nothing looks different. A material holding a value above 0.1 draws the same result, and moving the slider once settles it at the new ceiling.

### Face correction and the cast shadow now coexist

- The exclusion that removed the cast shadow inside the face area while `Face 2D Shadow Assist` was on is gone. Turning the assist on used to make scene shadows vanish from the face alone; the cast shadow and the 2D shadow now both draw there.
- The frontal-light self-shadow the exclusion was hiding is cancelled at its source instead. On Built-in the face's shadow-map entry is peeled along the light by the same amount, over the same area, under the same conditions as the camera-depth push (directional lights only), so the self comparison cannot succeed by construction. External casters such as a hand or a hat keep their true depths and land on the face normally. URP samples the shadow map at the rasterized position and never had the artifact.
- The inspector warning that had lost its basis - `Face 2D Shadow Assist requires Shadow Projection` and the `Enable Shadow Projection` button beside it - was removed. Picking `2D Shadow (Face Corrected)` under `Shadow Mode` no longer forces `Shadow Projection` on either; that choice leaves the projection master alone.

### `Added Light Brightness Maximum` re-based on HDR semantics

- The value now reads like an HDR intensity. It is an **absolute ceiling on the final output peak** with every additive effect included: at 1 the layers brighten up to just under a bloom threshold of 1 and never trip it, at 1.1 the bloom picks them up. It used to be a multiple of the base color's brightness applied to the whole final color, which erased glitter and rims outright on black clothing, and raising it released the scene light along with them and blew out to white.
- The same value now **limits the scene-light intensity that drives those effects.** At 1 only intensity up to 1 reaches rims, backlight, front light, translucency, MatCaps, emission and glitter; at 3, up to 3. That is what stops those layers burning white under a high-intensity directional light.
- **The stored number is unchanged but its meaning is not, so brightness changes.** The picture moves toward additive effects staying visible on black clothing, and toward being held back under strong lighting. Turning `Bound Added Light Too` off removes both limits.
- Exposure of the scene light itself still belongs to `Maximum Final Brightness`, as before.

### Color purity ceilings raised to 10

- SSAO gained `Color Purity` (0-10, default 1), `Color Brightness` and `Color Gamma`; purity 1 preserves the composed color. The Unified Shadow `Chroma` slider still spans 0-10. The old `SSAO Saturation` name is not a shader property.
- The `Color Purity` on Rim Light, Backlight, Front Light, Shadow Interior Reflection, 2D Rim Light and 2D Translucency shares the same 0-10 range. 0 is grayscale, 1 is the composed color as-is, and above 1 oversaturates.
- Only the ceiling moved, so a stored value means what it meant before and the look is unchanged.

### Menu paths tidied up

- The MingToon menu moved out from under `Tools` to a top-level `StudioRaming > MingToon`. Paths written as `Tools / Studio Raming / MingToon …` elsewhere in this document are under the new root now.
- Every context menu is under a single `MingToon` root: `MingToon > Add MingToon Manager` and `MingToon > Create Look Preset From Character` in the Hierarchy, `MingToon > MingToon Manager`, `MingToon > Ming Light Controller` and `MingToon > Create Look Preset From Prefab` in the Project window.
- Right-clicking a prefab in the Project window and choosing `MingToon > MingToon Manager` attaches the Manager without opening the prefab in a scene. It handles a multiple selection, and imported model roots such as an FBX are skipped with the reason stated.
- Ming Light Controller moved to `StudioRaming > Ming Light Controller > Open` and `> Avatar Attachment`. The same path used to be both a leaf and a submenu, which hid the main window.

### `Face Proxy Depth` removed

- The experimental `Face Proxy Depth` feature is gone. It was compiled out by default in both shaders with no way to switch it on, so nothing renders differently.
- Its four properties left the shaders, so the material property schema moved to 15 and the generated shader cache version moved up with it. Later changes in the same release raised both numbers further, so this entry alone does not decide either one. What this release finally ships is material property schema 17 and generated shader cache version 66; `Release/MingToon_ReleaseManifest.json` is the authority. The re-bake described above covers this too.

### `VRChat Preview` removed

- The `Tools / Studio Raming / MingToon / VRChat Preview` menu documented in 0.1.5 is gone. Its three surfaces - `Authoring`, `VRChat - no camera depth`, `VRChat - camera depth available` - are no longer available and nothing replaces them. The menu path did not move, so there is nothing to look for.
- To check whether depth is actually being supplied, set `Depth Sampling` > `Depth Availability` to `Diagnostic` in the material inspector; it paints the detection state on screen.

### Point and spot lights now reach `Rim Light`

- The colour and intensity of additional lights - point and spot - are added thinly into the Fresnel rim. Until now the rim answered the main light alone, so a silhouette edge stayed the main light's colour even in a scene lit from the side by a coloured lamp. **A material with `Enable Fresnel Rim` on gets a different edge colour in a scene with additional lights.**
- How much is added is bound to `Rim Light`'s colour and `Blend Opacity`, so several lights together still do not blow out to white. Nothing is added on a material with `Enable Fresnel Rim` off or `Intensity` at 0, and the whole thing drops out in `Performance Distance`'s far band. It reads no extra texture.
- On URP the Fresnel rim used to take additional lights twice; it now matches BRP. Both backends multiply by the main light and add the additional ones, one way only. **A URP material gets a different rim colour in a scene with additional lights.**

### The factory looks' `Rim Light` > `Color Purity` default is now 1

- The value stored in the bundled presets came down from 10 to 1. When the purity ceiling was widened to 0-10 the preset values were saved pinned to that ceiling, so applying a factory look pushed the rim colour into oversaturation. 1 means the composed colour as-is, the same as the shader default.
- It takes effect only when you apply a preset again. A value already stored on a material you made is left alone.

### A material's version no longer blocks presets and JSON

- Applying a Look Preset, saving a preset and applying a JSON document all work regardless of the version stored on the material. Those three paths used to refuse an older material with an error telling you to run the project migration first. That check, the error and the dialog that offered to run the migration are all gone.
- The official path from 0.1.6 is to delete the `Assets/StudioRaming/MingToon` folder and import 0.1.7 fresh. So many property names changed that old values do not carry over, so dial your materials back in from the new defaults and use a Look Preset if you want to get there faster. Bake output has to be baked again too. Nothing in the product requires the migration any more.

- The workspace bar has five tabs. `Optimize` contains texture optimization and per-type resolution caps; automatic build and play-mode hooks are configured in `Upload`. `Analyze` in `Optimize` produces four suggestions for this avatar: bake materials with identical settings as one, fold uniform textures into constants, pack mask textures together, and switch off modules that have no effect. All are off by default. Choices are remembered per avatar in this computer's user settings.

### `Transparent Draw Order` in the Manager

- `Transparent Draw Order` was added to `3 · Details` on the Manager's `Look & Bake` tab. Transparent parts are drawn in order of distance from the camera, but an avatar's skinned meshes usually share one large bounds, so every part reports the same distance. Sorting Order alone then decides, and parts left on the same value are tied — which is how a ribbon ends up behind the blouse it belongs on top of.
- `Find Parts With Undecided Order` collects the groups distance cannot separate, listed per shared material. Order them yourself with ▲▼ in the list; up is behind, down is in front.

### The bake removes more textures and draw calls

- Matcap layers that only add and carry no mask are merged into a single map at bake time; the layer count and its keyword come down with them.
- A texture slot that is empty, or whose texels are all one colour, folds into a constant - the sample and the binding disappear together.
- A material with outlines authored off no longer submits the outline hull pass, as long as nothing animates its outline properties. That is one pass fewer per slot.
- `Depth Effect Mask` and `Outline Width Mask` join the existing mask pack, two textures fewer.
- All of it needs a rebake to apply.

### VRC Light Volumes turn on automatically for an upload

- `VRC Light Volumes (Test)` is an in-editor preview toggle. A VRChat avatar upload turns the module on regardless of the value, reading the Light Volumes the world placed instead of Unity light probes, and the value stored on the material is restored once the upload finishes. In a world without volumes it falls back to probes and the picture is unchanged.

- Development console logs are stripped from the C# sources that go into the package. 27 lines - shader warm-up progress, internal bake tags and the like - no longer appear.

### A warning on a material left holding bake-only MatCap values

- Switching a baked material's shader back to the editable one by hand leaves the MatCap atlas values behind with no per-layer maps. The `MatCap Layers` tab now opens with a yellow warning at the top: "This material still carries the bake-only MatCap atlas values, so the MatCap layers look empty. Use the original material, or bake it again."
- There is no automatic repair, because guessing the maps back would be inventing content. Restore the recorded editable material or bake again. Restore, cleanup, the backend swap and migration all leave a baked copy's shader alone, so no normal path raises this warning.

### The validator catches a material with a performance distance of zero

- When `Performance Distance (m)` times `Performance Distance Scale` is 0, the material renders at its lightest tier at every distance and the camera-depth effects, PBR, the extra matcap and normal layers, toon specular, glitter and screen tone never draw. The validator now reports that as `MING-MAT-PERF-DISTANCE-ZERO`.

Everything else keeps compiling behind the Progress window on the same asynchronous job, which is not gated on editor focus.

### 18. Upload and conversion recovery is now interruption-safe

- The VRChat face-normal bake isolates build-only Face slots with temporary materials. It does not mutate the scene's original Meshes and materials or materials shared by another avatar.
- For each face-normal optimization build root, it first records the original Mesh and material slots of every Renderer that has a Mesh. Recovery restores even non-Face Renderer Meshes replaced by a later upload conversion, and resumes journal and temporary-material ownership recovery across script reloads or editor restarts.
- Regular conversion records Renderers, Meshes, materials, Prefab overrides, and dirty state before each mutation. Its journal is written atomically under `ProjectSettings`; a backup repairs a damaged primary file, and an older `Library` journal is migrated once. After eight failed automatic recovery attempts, retry from the Advanced menu or inspect the pending work before discarding only the recovery journal.

### `Startup recovery is incomplete` repeated on every editor start

- When a build was interrupted and its material was deleted afterwards, the recovery could never complete - yet it retried on every domain reload and printed a fresh red error each time, so it appeared on every script recompile and every entry into Play mode.
- The first attempt now waits for the import to finish, and only records whose material is gone from the project are dropped, once, with their names. Only after three failed attempts does it name the materials still waiting and what to do about them, in a single warning, and then it stays quiet. A recovery failure during a build or an upload still stops the build as before.

### Four precision and backend-mismatch fixes in the normal and depth math

- On a pixel where normal layers were stacked inverted and at full strength, the math could overflow and drop the whole normal stack. The same limit in the direction vectors the 2D Shadow and the 2D Rim Light use is fixed with it.
- Where the tangent is near zero, BRP and URP built different tangent frames, and the 2D Shadow's depth-placement fallback pointed forward on one backend and backward on the other. Both now use the same expression on both.
- The first two are defensive fixes that only surface on a GPU that really runs half precision; the last two were a BRP/URP result difference that showed on PC as well. Verified through the shader compile gate; not verified in a live render.

### Regions could not be taken back out in the `One Slot / Tiled Regions` window

- Unticking a region and applying left the slot it had already written in place, so a region applied once could not be removed with the tool. Apply now writes all four slots, and a region left off is actually removed from the material.
- **The window does not read the material's current values.** Applying an empty window over a material whose stack, normal or MatCap slots are already filled clears those slots, so set the window's regions up before applying. Undo (Ctrl+Z) works.

### Turning `Gradation LUT` on did nothing

- The module's shader keyword was declared on neither BRP nor URP, so switching it on applied no ramp and the whole thing dropped out of the compile. It works now.
- **A material that already had `Gradation LUT` on looks different.** The ramp that was ignored until now is applied to the base colour. Switch the row off if you need the old picture.
- On a material using UV scrolling, rotation or atlas animation, Built-in alone skipped the ramp; that is fixed with it.
- It needs a rebake to apply.

### `Render Disabled` could not switch the transparent depth prepass off

- `Render Disabled (do not draw this material)` now blocks the screen draw and removes depth/shadow passes at the vertex stage on both Built-in and URP. Hidden materials no longer write camera depth or the light shadow map, so they do not cast 2D shadows, SSAO contact, or projected shadows. Older hidden materials are healed on next selection or project migration.

### Creating a look preset from a prefab saved unrelated work with it

- `MingToon > Create Look Preset From Prefab` in the Project window wrote every unsaved change in the project to disk at save time. It now saves only the preset asset it actually created or overwrote.

### The face proxy Scene view preview was never built

- The preview read its own temporary material, decided there was no face, and never built the data to draw the normal lines from at all. It now judges from the original material's values.

### lilToon conversion left the emission channel settings at their old values

- The conversion wrote the emission map and mask fresh but left `Channel Source`, `Invert Source Colors` and the blend mask's channel and inversion at the pre-conversion material's values, so either emission layer could come out different from the original. The conversion now resets those values with the rest.

### Ming Light Controller — a configuration with a Photo Look Bit pinned was refused at install

- A configuration that locked a `Photo Look Bit` to a fixed value was refused at the install step with a "no target binding" error. Fixed.

### Preserve a map changed manually while Face SDF auto refresh is pending

- If you connect an external or shared Face SDF map while Face SDF Studio has an automatic refresh waiting, it checks the connection again just before applying the older automatic job so that job does not overwrite your map.

### Verify material references when cleaning up 0.1.6 generated profiles

- The cleanup checks every material contained in one asset file and changes it to the current shader. It first checks that the material can be saved, then reads the saved reference again after the change. If it cannot save or verify the result, it leaves the existing generated profile and keeps the cleanup incomplete.

### Disable automatic camera settings without overwriting later settings

- Turning off automatic camera settings in the Inspector removes the settings that automation applied. When you use an existing post-processing layer, it does not overwrite the layer mask and volume trigger settings you changed later.

### A compile failure was recorded as a completed warmup

- The shader variant's compilation errors are checked after it is warmed up. A variant with an error is not recorded as ready, and the failure reason is reported.

### Reuse the same mask pack after restarting the Editor

- When the original mask and settings saved in the project match, the same mask pack is reused after reopening the Editor. Existing packs are neither deleted nor renamed, so the first application of this change can create one new pack.

### Baked shaders of materials with an alpha mask or region mask failed to compile

- The baked profile of a material that uses an alpha mask or a region mask failed to compile on D3D11, so the build hook left that material on the editable shader for the upload. That put every variant of the editable shader into the avatar bundle and made the upload about five minutes longer.
- Avatars that are already uploaded need a re-upload to receive this fix.

### NullReferenceException in the conversion completion dialog

- When no mesh channel was checked and the mesh bake was skipped, the conversion itself finished but building the completion dialog title threw a NullReferenceException. Fixed.

### Stale NDMF clone records kept blocking the VRChat build

- Recovery records for the clone materials NDMF creates under `Packages/nadena.dev.ndmf/__Generated/` and deletes after the build stayed in the journal, so every later VRChat build failed with `Material recovery is incomplete`. The missing-material check now looks at the file on disk instead of the GUID mapping alone, and such records are cleared at the next recovery with a single warning.
- A project already stuck in this state is cleaned up automatically on the first build or editor restart after updating.

### Look presets overwrote the stencil values

- The lilToon conversion carries the source stencil unit across (Ref, Comp, Pass and so on), but the factory look applied right after it held the shader defaults (Ref 0, Always, Keep), so the stencil that eye overlays and hidden-mesh masks rely on went back to 0 on every converted material. Re-applying a look did the same. Fixed.
- Both stencil units (surface and outline, 14 properties) are now neither captured into nor written by a preset. Materials converted earlier need a re-conversion or the stencil values set back by hand.
