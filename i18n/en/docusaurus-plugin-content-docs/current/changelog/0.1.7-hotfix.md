*0.1.7 hotfix · the package version stays 0.1.7*

:::info[How to read a hotfix]
A hotfix is the same 0.1.7 package uploaded again without a version bump. Download it again from BOOTH and overwrite `Assets/StudioRaming/MingToon`. To see which round your package contains, check the entries in `Docs/PATCH_NOTES_0.1.7.md` inside the package. New rounds are always added at the top of this page.
:::

## Hotfix 1 — 2026-09-07 (round 1)

**After updating**

- A project whose VRChat build was stuck on `Material recovery is incomplete` cleans itself up after one editor restart following the overwrite.
- lilToon-converted materials that rely on stencil (eye overlays, hidden-mesh masks) need a re-conversion or the stencil values set back by hand.
- No re-upload is needed.

### Stale NDMF clone records kept blocking the VRChat build

- Symptom — after one build of an avatar that uses NDMF, every later VRChat build failed with `Material recovery is incomplete`.
- Fix — recovery records for the clone materials NDMF creates under `Packages/nadena.dev.ndmf/__Generated/` and deletes after the build stayed in the journal. The missing-material check now looks at the file on disk instead of the GUID mapping alone, and such records are cleared at the next recovery with a single warning.

### Look presets overwrote the stencil values

- Symptom — the lilToon conversion carries the source stencil unit across (Ref, Comp, Pass and so on), but the factory look applied right after it held the shader defaults (Ref 0, Always, Keep), so the stencil that eye overlays and hidden-mesh masks rely on went back to 0. Re-applying a look did the same.
- Fix — both stencil units (surface and outline, 14 properties) are now neither captured into nor written by a preset.
