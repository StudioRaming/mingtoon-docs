*Closed Beta · 2026-08-09*

## Check Before Upgrading

:::caution[VRChat avatars must be re-uploaded]
**After this update, VRChat avatars must be re-uploaded for fixes to take effect.** Shaders are bundled in the avatar asset bundle, so previously uploaded avatars continue using the old shader.
:::

## Bug fixes

- **Avatar white-out from upload optimization defect is gone** — Fixed a defect where upload optimization (baking) was forcefully enabling disabled modules. Before, you could turn `Use Emission` off but get full-screen emission with a default white map, or have modules like `2D Shadow Mask` work despite being disabled. This was the root cause behind reports of avatars "glowing white" in mirrors or cameras without post. → [Docs](/workflow/build-optimization)
  - Already-generated baked shaders are regenerated, so **avatars must be re-uploaded** to receive this fix.
- **Depth effects normalize inside mirrors** — Fixed 2D Shadow and Depth Rim slipping and failing to follow the body as the player looks around inside a VRChat mirror. → [Docs](/guides/depth-effects#플랫폼별-깊이-확보)
  - The mirror camera does not render its own depth texture, but the player camera's depth buffer was still bound, so the shader was reading a stranger's silhouette. Now depth-related modules automatically disable inside mirrors.
  - The meaning of `Depth Availability` changes slightly. `Force On` now means "enable even when the host cannot report it, **but exclude mirrors**".
- **Proper shading in matte worlds and Disable Pixel Lights mirrors** — Fixed avatar shading collapsing into pale flatness in worlds without a realtime directional light or in Disable Pixel Lights mirrors.
  - Now the ambient probe synthesizes a key light (direction and colour) so proper shading holds everywhere. Worlds with a directional light are unchanged.
- **lilToon conversion now enables the toggles of transferred data** — When converting a lilToon material that had the `PBR Surface Use`, `Emission Use`, `Surface Stack Use`, `Outline Master`, or `Classic Hull` toggles on, the values were received but the modules came out disabled. This is fixed. → [Docs](/workflow/liltoon-conversion)
  - If lilToon's `_UseReflection` (reflection) was on, MingToon's `Use PBR Surface` now comes out on as well. Materials that glowed from colour alone without an emission texture are now reproduced as-is. Stack layer 2 and 3 data is received. Outlines receive direction and thickness correctly.
  - `Hull Thickness` default values now take what the author set. lilToon's behavior of enabling thickness to 1 on materials that had no outline no longer occurs.
- **Outlines are correct with `Normal Source` set to `VertexColorTS`** — Fixed outlines shifting diagonally wholesale when `Normal Source` is set to `VertexColorTS` but the mesh has no vertex colours. Now it falls back to mesh normals and behaves as the tooltip describes. → [Docs](/guides/outline#노멀-아웃라인)
- **Single part without tangents breaking face and height bakes is fixed** — Fixed conversion failing all three stages (outline, face, height) at once if a mesh lacked tangents or normals. Now only that renderer is skipped and the console names which mesh.
- **Meshes shared by multiple renderers are properly combined in bake** — When the same mesh was shared by N renderers, baking used to create N copies. Now an asset is created per source mesh and all renderers share it.
- **Conversion no longer overwrites user model UV8 without confirmation** — Conversion was erasing the original model's UV8 regardless of the `Overwrite Existing Channel` option. Now it skips and reports if the option is off.
- **Outline UV8 bake no longer rejects already-baked characters** — Fixed the bake rejecting the entire character if any submesh already had UV8. Now MingToon skips its own baked UV8, rejects only the original user model's UV8, and names which mesh. → [Docs](/guides/mesh-bakes#아웃라인-스무스-노멀-uv8)
- **`Unified Shadow Color Map` toggle works in all modes** — Turning `Unified Shadow Color Map` off now reliably disables it in any compile mode. Previously, cases existed where this row would not work if global compilation mode was on.
- **Importing into a world-building project no longer breaks with a compile error** — Fixed placing MingToon or a converted avatar into a VRChat world project (no Avatars SDK) breaking the whole project with a `VRCExpressionsMenu` compile error (CS0246). The expression menu installer is avatar-upload-only, so it now compiles away automatically in world projects.
- **Material selection no longer shows only outline** — Found and fixed the root cause of the rendering defect where selecting or editing a material in Unity 2022 erases the base and leaves only the outline. No matter how long you wait for compilation in environments where this recurred, it no longer appears. → [Docs](/guides/texture-modules#마스크-세부-설정)
  - Layer masks (Surface Stack, Normal, Matcap) are now internally auto-composited into unified textures. Mask placement per slot and all adjustments—channel selection, inversion, remap—are unchanged; the number of textures the GPU reads is reduced, making rendering lighter. Composited masks are auto-generated and shared in `MingToonGenerated/MaskPacks`; no manual management needed.
- **Conversion now preserves your selected look preset** — Fixed the first conversion defaulting to the top preset (Hard Toon) even when you had selected a different one. Chosen presets now persist across script reloads and object re-selections.
- **Look presets no longer touch converted layer content** — Fixed layer content carried over from conversion—matcaps, normal layers, surface stack—being disabled or reset to Add blend when a look preset was applied. → [Docs](/workflow/character-manager#1--변환)
  - Look presets now handle only look properties (shadows, rims). Layer content owned by the character (enabled state, blend mode, intensity) is left alone. Only tab-specific presets can modify those values.
- **VRChat build hook registration log now displays** — Fixed the `[MingToon] VRChat build hook compiled and registered.` guidance log from the manual not appearing in user environments. It now prints once per editor session, so you can verify the upload optimization hook is active. → [Docs](/workflow/build-optimization#제대로-걸렸는지-확인하기)

## Working experience — no more compile waits

- **Inspector toggles no longer wait for shader recompilation** — Seven inspector toggles—`Use Glitter Mask`, `Use Mask` (shadow reflection), `2D Shadow Mask`, `Depth Rim Mask`, `Inner Edge Mask`, `Use Area Mask`, `Use 2nd Shadow`—no longer freeze the inspector during shader recompilation (2–6 seconds per toggle) when turned on or off.
  - Layer dropdowns behave the same way. You can change values instantly without waiting for compilation.
  - The `Base Tint After HSVG` row behaves the same way. The feature is now controlled by a float branch instead of a keyword, so it applies immediately when toggled.
  - The `Face Shading Module` toggle (switching face/regular roles) also applies instantly without recompiling, like every other toggle.
  - The authoring shader keeps the related keywords always on, and the actual on/off is decided by a float value, so the rendered image does not change at all. Inspector defaults and bake behaviour remain the same.
  - To achieve this, the `Compile All Modules While Authoring` setting now defaults to on. One line of guidance appears in the console when it first activates; if unwanted, you can turn it off in the MingToon inspector's bulk edit panel. Keeping it on during build and upload carries no cost to the output — unnecessary keywords are automatically pruned.
- **Shader compilation completes once, at package install** — When you import the package, install compilation runs immediately (cancellable progress bar). Parallel compilation finishes the initial setup in minutes; afterward, no compile window pops up during conversion, material selection, or editing. "Wait once at install" is this version's compile model.
  - The combinations your converted materials use—cutout, matcaps/normals/stack enabled—are pre-compiled at install time. Saved state and display state always match, so selecting a material never changes the render combination.
  - Warm-up state is recorded in `Library/StudioRaming/MingToon.warmup`. It auto-invalidates if shader source, Unity version, or graphics API changes, triggering a re-warm. Cancellations record the stopping point, so the next run picks up from there.
  - Manual menus are also preserved. `Tools > Studio Raming > MingToon` offers `Warm up shader variants` (install plan), `Warm up selected materials`, `Verify warm-up`, `Warm-up status`, `Measure warm-up cache effect`.
- **Conversion progress is now shown per step** — The stretch after pressing convert that only showed "Hold on (busy)" now shows a per-step progress bar (converting materials → look preset → mesh bakes).
  - When conversion completes, per-step timing is logged to the console in one line, so a slow conversion immediately names which step is responsible.
- **Outline UV8 bake alerts when needed and states scope and result in advance** — When `Normal Source` is `UV8TS` (the default) but the mesh has no UV8, a warning message and bake button appear at the top of MingToon Manager. Nothing renders on a character with mismatched conditions. → [Docs](/guides/mesh-bakes#아웃라인-스무스-노멀-uv8)
  - Above the bake button it shows "where new meshes will be created, the original FBX is untouched, and how many renderers will be processed". The result message also reports how many vertices were left with mesh normals due to missing tangents.
- **Project-wide material keyword cleanup menu added** — A new menu `Tools > Studio Raming > MingToon > Heal Material Keywords (Project)` has arrived. It syncs the saved keywords and pass state of all MingToon materials in the project to match the inspector values. After confirming before run, changed files are backed up to `TempBackups/MingToonKeywordHeal/`, cancellation works, and the result is logged as one line to the console.

## Features added and removed

- **Reads indirect light from VRC Light Volumes worlds (off by default)** — A new row `VRC Light Volumes` has been added. On worlds using VRC Light Volumes, the avatar's `Indirect Light Correction` and shadow tones follow the room's Light Volume instead of the Unity probe. Built-in shader only.
  - It defaults to off. Turning it on is safe: environments without a Light Volume fall back to the probe, so the picture never changes or breaks anywhere.
- **`Depth Availability` gains a Diagnostic mode** — A fourth option called `Diagnostic` has been added to `Depth Availability`. When reporting depth effects bleeding across an entire avatar in VRChat, this mode lets you diagnose which depth texture the shader is actually reading by tinting it solid. → [Docs](/guides/depth-effects#플랫폼별-깊이-확보)
  - The colour key is as follows: black means no depth texture, red means the texture exists but is not from this screen's buffer (different size or mirror), yellow means it exists and the size matches, and the blue channel means the host is reporting depth availability directly. This mode is **diagnostic only and should be used only when reporting bugs**, not for regular use.
- **Shadow Color Map rows added to bulk edit panel** — The rows `Use Shadow Color Map` and `Color Map Amount` now appear in the bulk edit panel. They already worked in the regular inspector, and adding them to bulk edit lets you select multiple materials and set these values at once. → [Docs](/guides/bulk-editing#일괄-설정-패널)
- **Missing Depth Fallback (Fresnel fallback) removed** — The feature where `Depth Rim` automatically fell back to Fresnel Rim when depth data was absent has been removed. The depth module now silently disables if no depth data exists. Materials that were using Fresnel Rim will lose that rim. → [Docs](/guides/depth-effects#깊이-림-2d-림)
- **Outlines are much lighter** — Outline (classic hull) pixel cost is cut to roughly one-third. Outlines now render with only base map colour and lighting response; the body's shadow pattern, cast shadows, and depth effects are no longer re-drawn over the outline. → [Docs](/guides/outline#아웃라인-색이-조명을-따라가게)
  - `Outline Include Shading` is kept but changes behavior. When on, a lightweight contrast band following the body's form shadow colour is applied to the outline, rather than duplicating the entire body shading as before. Thick outlines keep their contrast impression while cost drops.
