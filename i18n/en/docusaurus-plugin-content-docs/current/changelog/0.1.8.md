*Open Beta · 2026-09-08*

## 0.1.8 {#v018}

[Permanent link: 0.1.8 patch notes](/changelog/0.1.8#v018)

### Major fixes and usability improvements

- **First-upload time** — Improved the excessive time required for uploads. User measurements report a 3–50% improvement for a first upload; results vary by environment.
- **White VRC-baked characters** — In the VRC bake path, emission layers are now composed sequentially over the current lit result instead of overwriting it, addressing characters turning white after a bake and upload. Emission masks, shadow visibility, `Normal`/`Multiply` blending, map RGB/alpha, and surface alpha are retained. Re-bake and re-upload existing baked materials to receive this change.
- **Fallback path distinction** — The change that forces the fallback emission alias (`_EmissionColor`) to black shipped separately in the 0.1.7 HotFix1 release. This 0.1.8 fix covers emission composition in the regular MingToon bake/render path. Re-bake and re-upload baked materials created before 0.1.7 HotFix1.
- **Ming Light Controller 0.1.1** — BRP-only projects no longer fail because a missing URP shader was validated during upload. MLC now validates each installed MingToon backend and reports an error only when neither backend is installed. Authorized transient IDs for NDMF build clones stay in memory and never rewrite the source avatar or project files. The menu's Saturation control binds to MingToon's `Output Master Saturation`. MLC is a separate package; update it after installing MingToon.
- **Recovery when an older Assets installation conflicts** — Only when the older Assets-based installation conflicts with the new installer and installation fails, first move any `.mat`, texture, or preset files saved directly inside `Assets/StudioRaming/MingToon` elsewhere, then delete only that MingToon folder and import again. Do not delete `MingLightController` or the entire `StudioRaming` folder. This cleanup is needed once when migrating from the older Assets installation and is not repeated for later VPM updates.
- **Conversion stability** — Fixed lilToon conversion changing SSAO color purity, disabling emission masks, or changing mask data through compression.
- **Upload texture rewrites (opt-in)** — The default `LosslessOnly` texture bake policy never rewrites authored texels. Enable `Reviewed Texture Rewrites On Build (Opt-In)` on `Optimize` only with `Optimize On Build / Upload (Applies To Everything)` enabled to flatten `Texture Layers` and `Normal Layers` before upload and pack loose masks into RGBA. Color-space conversion, regenerated mips, or platform compression can change pixels, so compare target-platform captures before and after baking; the widened pack also includes `Width Mask` on the `Outline` tab.
- **Manager controls** — Update status and installed/latest versions now fit in two rows at about one third of the previous height, with `Check`, `Update`, and `Notes` in one place.
- **Installation and update paths** — Import the DLL unitypackage downloaded from BOOTH to install the required MingToon package automatically without an additional install button. This is the VCC/VPM-based path introduced in this release. Unity then checks for new versions at startup and shows a notice for versions that have neither been installed nor skipped. The user must click the `Update` button in the notice to install; if Unity is playing, compiling, or building, it waits and checks again after reload. Restarting Unity does not install a version automatically. `Skip` applies only to that version, and the next new version is announced again. Users who installed through VCC continue to maintain and update it manually through VCC.
- **Existing asset preservation** — Existing 0.1.7 installations and inventories are recognized; package updates touch only managed files and preserve existing materials, scenes, prefabs, and Unity-created `package.json.meta` files.

### New features

- **Color Presets** — Use the `Color Presets` panel to save and apply the full Shadow Color tab (bands, chroma, brightness, and color map), rim/depth tints, and HSVG. The seven factory palettes are `Neutral`, `Warm Tone 1`, `Warm Tone 2`, `Cool Tone 1`, `Cool Tone 2`, `High Saturation`, and `Low Saturation`. Textures outside the preset's targets, render state, and keywords stay intact; presets apply to multiple selected materials and support Undo.
- **Band and rim color controls** — Quick settings expose overall saturation and emission intensity, while `SSAO Color`, `Rim Shade Color`, and shadow-band colors can be set directly. A `Rim Shade Color` blend opacity of 0 preserves the existing `1st Shadow Color`.
- **Output Master Saturation** — Applies to the final output: 0 is grayscale, 1 is the baseline, and values above 1 strengthen chroma while preserving brightness.
- **Per-layer UV selection** — Choose `UV Source` (UV0–UV3) independently for each normal layer and `Mask UV Source` separately for its mask. With both at UV0 (the default), the UV-router variant is not compiled.

### Changes

- **Language display** — Installation and update messages select Korean, Japanese, or English for other system languages; Manager labels continue to follow the Inspector language selection.
- **Conversion output** — Converted materials retain emission-map RGB/alpha and emission-mask RGBA data, including surface-alpha blending for transparent materials. Per-layer normal `UV Source` and mask `Mask UV Source` (UV0–UV3) choices are copied as well.

### Improvements

- **Shader baking** — Identical requests are grouped to reduce duplicate work during repeated bakes while preserving existing generated output and state.
- **Generated-output recovery** — Interrupted bakes now recover without leaving partial files that can poison the next generated-shader cache.
- **Outline normal stability** — Replaced the outline normal's object-scale-sensitive geometric correction with finite, scale-invariant handling and an authored-direction fallback for degenerate or non-finite geometry.

### Documentation

- Manager `Notes` opens the latest localized documentation, while the current and latest versions remain visible together.

### Updating from an earlier version

Back up your project, then move any personal materials, textures, or presets out of `Assets/StudioRaming/MingToon`. For an older Assets-based installation, delete only that MingToon folder before importing the new installer. Do not delete `MingLightController` or the entire `StudioRaming` folder. This cleanup is only for migration from the older installation method, not for every subsequent VPM update.
