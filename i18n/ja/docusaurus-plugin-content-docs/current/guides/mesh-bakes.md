# メッシュUVベイク

**このドキュメントを読むと** UV4・UV7・UV8の所有権と、0.1.7のLive顔ノーマル・アップロード専用bakeを区別できます。

| チャンネル | ユーザー用データ |
|---|---|
| **UV8** | アウトラインスムースノーマルと任意の筆圧値 |
| **UV7** | Face SDFのBaked Front座標。顔ノーマルのアップロードpayloadが同じチャンネルを一時使用する場合があります |
| **UV4** | キャラクタールート基準の高さ |

:::danger[既存チャンネルを確認してください]
UVチャンネルには別のシェーダー・ツール・モデル制作者が入れたデータがある場合があります。`上書き`は所有権を確認した場合だけ有効にしてください。MingToon Managerの`UVチャンネル使用状況`にUV4・UV7・UV8が表示されます。
:::

## アウトラインスムースノーマル（UV8） {#아웃라인-스무스-노멀-uv8}

同じ位置の頂点ノーマルを平均してUV8へ保存します。ハードエッジでハルアウトラインが割れる問題を軽減します。UV8.wには任意で線幅の強弱値も入ります。

### 手順

1. MingToon Managerの`3 · 詳細設定`で`アウトラインスムースノーマルUV8`を開きます。
2. 状態パネルで対象・共有Mesh・既存UV8を確認します。
3. 編集済みノーマルを持つ髪・スカートなら`ノーマルを編集したモデル用に計算`を検討します。
4. 既存UV8の所有権を確認した場合だけ上書きを有効にします。
5. キャラクター全体のUV8 bakeを実行します。

`ノーマルソース = UV8TS`がデフォルトなので、bake後にマテリアル側で変更する項目はありません。`筆圧ソース = OutlineNormalUV8`ならUV8.wも幅へ反映されます。

タンジェントのないパーツはそのUV8段階だけをスキップし、他のUV4・顔段階まで一緒に失敗させません。必要なパーツはModel Importerでtangentを生成してから再実行してください。

### ノーマルを編集したモデルの場合 {#노멀을-편집한-모델용으로-계산}

`ノーマルを編集したモデル用に計算`を有効にすると、球・円柱から転送したシェーディングノーマルではなくMesh面からアウトライン方向を再計算します。シェーディングノーマル自体は変更しません。

## Live顔ノーマルとUV7 {#얼굴-프론트뷰-노멀-uv7}

0.1.7から顔プロキシノーマルのリアルタイム合成は、編集中にシェーダーがリアルタイム計算します。プロキシの中心・半径・Sphere/Cylinder/Capsule形状・軸・高さ・プロキシノーマル強度を変えると、別途Meshをbakeせず即時反映されます。

### VRChatアップロード時

VRChatアップロードフックは、顔ノーマル最適化の対象となる各build rootで、**Meshを持つ全Rendererの元Meshとマテリアルスロットを先にジャーナルへ記録**します。顔ベイクの後に実行されるアップロード変換はFace以外のRendererのMeshも置換できるため、Faceスロットだけの記録では元の配置を完全に戻せません。

Faceスロットはトランザクション専用の一時マテリアルで分離し、そのコピーだけに顔ノーマルpayloadをUV7へ作成します。シーンの元Mesh・マテリアルや、別アバターが共有するマテリアルは変更しません。アップロード終了後はジャーナル全体から元の配置へ復元し、スクリプトリロードやEditor再起動を挟んでも復旧を続けます。アップロード後にユーザーが対象を変更した場合はその新しい状態を上書きせず、後の再試行まで保留します。

次のRendererでは結果を保つためアップロードbakeをスキップし、Liveシェーダー経路を維持します。

- Face SDFが`Baked Front UV7`を使い、UV7を所有している
- テクスチャFace Area Maskが有効で強度が0より大きい
- 1つのRendererにある複数のFaceスロットが、異なるプロキシ形状・ランタイム顔フレームを使っている
- ソースMeshのUV7がMingToon以外のデータですでに埋まっている

### 古い顔ノーマルbakeを戻す

旧バージョンの`_FaceNormalBaked`が残り、プロキシを動かしても画面が変化しない場合は、MingToon Managerの`顔ノーマルをリアルタイムへ戻す`を実行してください。

この操作は次を行います。

- baked floatとkeywordを無効化
- tangent-normal payloadをFace SDF座標として誤読しないよう、`顔マップ座標`をBase UVへ戻す
- Meshバイト自体は変更しない
- 全マテリアルを1つのUndo段階へ記録し、変更したアセットだけを保存

次回の通常conversionは元Meshから作り直すため、読み取られない古いUV7 payloadも自然に除外されます。

### Face SDF用Baked Front UV7

Face SDFでUV7はノーマルではなく**正面投影座標**です。別製品のFace SDF Studioがインストールされている場合は、SceneViewの正面を基準に複製MeshのTEXCOORD6へベイクします。

1. 顔を正面へ合わせます。
2. Studioで`Baked Front UV7`を選択します。
3. 複製Meshをベイクして対象Rendererへ適用します。
4. MingToonマテリアルの`顔マップ座標`が同じモードか確認します。

Base UVで作ったSDFにはUV7は不要です。→ [顔SDF](/guides/face-sdf)

## キャラクター高さ（UV4） {#캐릭터-높이-uv4}

キャラクター全体のルート基準高さを、すべてのMeshのUV4.xへ保存します。上半身と下半身が別Meshでも1つの連続した軸を共有します。

### 手順（MingToon Manager）

1. `3 · 詳細設定`の`キャラクター高さUV4`を開きます。
2. 既存UV4と対象Rendererを確認します。
3. 所有権を確認した場合だけ上書きを有効にします。
4. キャラクター全体のUV4 bakeを実行します。
5. 子階層のMingToonマテリアルへ高さ設定を一括適用します。

マテリアルInspectorからも、選択マテリアルを使う開いたキャラクターを探して実行できます。複数マテリアルが同じキャラクターを参照していても、キャラクターごとに1回だけ処理します。

## ベイクするチャンネルの選び方

| 状況 | 選択 |
|---|---|
| アウトラインがハードエッジで割れる | UV8 |
| Face SDFが正面投影座標を必要とする | UV7 |
| 高さグラデーションを使う | UV4 |
| 編集中に顔ノーマルプロキシを確認する | bakeしない — Live |
| VRChatの顔ノーマル最適化 | 直接bakeしない — アップロードフック |
