# Ming Light Controllerを使う

> このページはMLCを初めて導入する方のためのものです。
> ゲーム内メニューで明るさと色を変えられるようにします。15分ほどかかります。

## これは何ですか {#ming-light-controller란}

Ming Light Controller（MLC）は別のアドオンです。MingToon BRP本体とは別にインストールします。

シェーダーのルックを作る作業はMingToonで行います。装着者がゲーム内で変えられる項目を選ぶ作業はMLCで行います。

| 製品 | 役割 |
|---|---|
| **MingToon BRP本体** | マテリアルの描画、インスペクターとマネージャー、ビルド最適化 |
| **Ming Light Controller** | アバターごとの調整設定と、ゲーム内表情メニューの生成 |

## 始める前の準備

- MingToonマテリアルを持つアバター
- VRChat Avatars SDK
- NDMF — アバターのコピーに何かを付け足してくれる共通フレームワークです
- 既存のメニュー・FXがあるアバターなら、Modular Avatarまたは対応するVRCFury

MLCはこれらの依存関係を自動インストールしません。

## 30秒でオンにしてみる

1. アバターのルートにMLCコンポーネントを追加します。
   `GameObject > Studio Raming > Ming Light Controller > Add or Configure Component`
2. **クイックスタート** で開始プリセットを選び、プロファイルを自動（Auto）にしておきます。 **適用** を押します。
3. **メニュー構成** で使う項目をオンにし、メニューの位置を決めます。
4. **予算・検証** で合計と生成可否を確認します。

予算の画面に赤いエラーがなければ成功です。
赤いエラーが残っている場合は [Playモードとアップロードで確認すること](#설치-확인) を見てください。
エラーを解決してからPlayモードでメニューが開くか確認し、アップロードします。

プリセットを選ぶことと **適用** を押すことは別です。適用したあとも各項目を直せますし、Undoで元に戻せます。

## 連携方式を選ぶ

連携方式は、MLCが作ったメニューをアバターにどう付けるかを決めます。

| 方式 | いつ使うか |
|---|---|
| **Modular Avatar** | 既存のメニュー・FXがあるアバター。最も安全です |
| **VRCFury** | 対応providerがインストールされているとき |
| **Direct Descriptor** | 既存のFX・メニュー・パラメーターが **空の** コピーにのみ |
| **Standalone** | アバターにメニューを付けません。これだけを選ぶとゲーム内で調整できません |

`自動（Auto）` は上から順に探し、使えるものを選びます。VRCFuryを選んだのに対応providerがない場合はエラーを表示します。黙って別の方式に切り替えることはありません。

:::caution[Write Defaultsは既存のFXを一括変更しません]
MLCが作るステートは、Write Defaultsがオフの状態で作成されます。
Modular Avatar連携ではアバター側の方式に合わせるよう要求するため、最終結果はご自身で確認してください。
:::

## プロファイルと予算 {#파라미터-프로필}

VRChatのアバターは、同期に使えるビット数が決まっています。プロファイルはそのビットの使い方を決めます。

| プロファイル | 選ぶ基準 |
|---|---|
| **Auto** | 現在の設定と予算を見て、まずSmoothを検討します。足りなければCompactに切り替えます |
| **Smooth** | 連続調整の精度を優先します。ビットをより多く使います |
| **Compact** | ビットを減らします。その代わり調整の段階が粗くなります |

同期ビットとパラメーター項目数は別々の上限です。ビットが少ないからといって、項目数も少ないとは限りません。

コストは有効な機能と保存・同期の設定、他のコンポーネントによって変わります。文書の固定値ではなく、 **予算・検証** パネルの現在の計算値で判断してください。

:::caution[未確認は使用可能の確定ではありません]
他のコンポーネントのコストを読み取れない場合、全体の予算は保証できません。
MLCの推定値が表示されても、アバター全体が上限内という意味ではありません。
:::

## メニュー構成 {#루트-메뉴-구성}

推奨する構成は次の7つです。出発点であり、追加したり外したりすれば最終的な構成は変わります。

`Reset` · `Final Output` · `Hue/Saturation` · `Photo Looks` · `Virtual Light` · `Master Adjust` · `Performance`

各項目について3つを決めます。

- **使用（Enabled）** — この機能をメニューに入れます。
- **保存（Saved）** — 次にアバターを着たときに値を保持します。
- **同期（Synced）** — 他の人にも見えます。予算を使います。

### コマンドは押したときに実行されます

Resetやパフォーマンスプリセットのようなコマンドは、ボタンを押したときに一度実行されるイベントです。連続調整の項目のように、固定値や復元値を指定するものではありません。

以前の設定に誤ったコマンドの固定値が残っていると、警告と **コマンド値設定の修復** ボタンが表示されます。Undoで元に戻せます。

## インストールすると開くMingToonの機能 {#설치하면-열리는-mingtoon-기능}

MingToonインスペクターのマスター調整・仮想ライトの編集UIと、マネージャーのMLC設定への入口が開きます。ボタンがロックされたままの場合は、Consoleのコンパイルエラーとアドオンのインストール状況を確認してください。

## MLCなしでもできること {#mlc-없이도-되는-것}

ライティング・影・リム・深度エフェクト・アウトラインの描画は、MLCなしですべて動作します。マテリアルに保存されたマスター調整の値も描画され続け、編集UIだけが表示されなくなります。

深度テクスチャの確保とビルドポリシーはMingToonマネージャーが所有します。MLCを削除してもビルドの動作は変わりません。 → [VRChat深度ライト](/platforms/vrchat#vrchat-깊이-라이트)

## Playモードとアップロードで確認すること {#설치-확인}

:::note[元のアバターには設定だけを保存します]
実際のメニュー・パラメーター・FXは、Playモードやアップロード用のコピーで作られます。
編集中に元のアバターにGeneratedフォルダーができないのは正常です。
:::

アップロード前に、メニューが開くこと、調整の向き、初期値、Resetの動作を確認してください。

| 症状 | 確認すること |
|---|---|
| メニューが出ない | Playモードのプレビューオプション、選んだ連携方式、SDK・NDMFのコンパイル状況 |
| Direct Descriptorが中断される | 既存のメニューやFXがあります。Modular Avatarに切り替えてください |
| 外部コストが未確認 | 合計が確定したものとは見なさないでください |
| コマンドの固定値エラー | 該当するコマンドの修復ボタンで整理します |

エディターでのテストだけでは、実際のクライアントにおける2人のユーザー間の同期までは検証できません。 → [現在の制限とリリース](/limitations)

## 配布と価格

MLCはオープンベータ期間中のみ無料で配布し、Early Accessのリリースから有料で販売します。無料配布にはMingToonの商用ライセンスは含まれず、ファイルの共有と再配布は禁止します。

対応シェーダーは現在MingToonのみです。lilToonとPoiyomiは今後対応予定で、MLCはシェーダーを変換するツールではありません。
