# モジュールとパフォーマンス負荷

マテリアルの負荷表示は、**アップロード時のベイク後を基準にした相対的な推定値**です。内訳を開き、アップロード後の推定値と現在編集中の値を分けて確認します。

## 負荷パネルの読み方 {#부하-예상-패널-읽기}

| 表示 | 読み方 |
|---|---|
| アップロード後の負荷 | 新規MingToonマテリアルを同じ方法でベイクした負荷が1.0倍 |
| 編集中の負荷 | 編集用シェーダーの推定値。アップロード後とは異なる場合があります |
| 選択の平均 / 最大 | マテリアルの平均と最高等級。アバター全体の合計ではありません |
| 無条件読み / 深度 / 命令 / ドロー | 負荷要因の推定。GPUプロファイラーの測定値ではありません |
| テクスチャ枚数 / MB | テクスチャメモリの推定。描画速度とは別に確認します |

:::note[倍率はフレーム時間の比率ではありません]
モデルは特定のBRPベンチマークに合わせたものです。画面占有率、重なり、ライト、GPU、レンダーパイプラインで実際の負荷は変わります。2倍という表示は、アバター全体やゲームの描画時間が2倍になる意味ではありません。
:::

## 推定に含まれるもの

現在のモデルは編集状態とベイク後の予測状態を分け、命令、常に実行されるテクスチャ読み、レジスター使用、パスなどを考慮します。以前の固定重みの加算式や点数の区切りは現在の表示に対応しません。

レイヤー数と実行条件を合わせて見ます。最大数のスロットが存在しても、すべてが毎ピクセル読まれるとは限りません。一方、強度が0でも、アニメーションや実行時制御のためにコードを残す場合があります。

カメラ深度を得るためのシーン全体の処理は、マテリアル倍率にすべて含まれていません。最初に深度効果を有効にしたときの変化は実際のシーンで比較します。

## 重いときの確認順序

1. カメラ、距離、照明を固定して基準画面を保存します。
2. 主な負荷要因を読み、不要なレイヤーや効果をひとつずつ無効にします。
3. 広い透明面が重なる場合はオーバードローを確認します。見た目が許す場合にだけ不透明やカットアウトへ変更します。
4. ライトが多い場面では追加ライトの受け取りを比較します。照明表現も変わります。
5. 必要な輪郭と影を保ちながら深度効果とアウトラインを比較します。VRChatでもカメラ構成によって深度が提供される場合があります。
6. 同じ条件で実際のビルドを測定します。推定等級が下がっただけでは高速化を確定できません。

## 動的HSVG

アニメーションや実行時スクリプトで動かす色調整はベイク後も動作する必要があります。アニメーション解析とベイク除外を確認します。定数化やテクスチャ書き換えは、それぞれの安全条件を満たした場合に適用されます。
