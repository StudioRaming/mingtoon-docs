# モジュールとパフォーマンスコスト

**このドキュメントを読むと** インスペクターの `マテリアルロード予測` の数字がどのように出されるのかを理解でき、重いアバターで何から削るかを根拠を持って判断できます。

:::warning[この値はGPU msではありません]
インスペクターもそう説明しています。

> 相対推定値であり、実際のGPU msではありません。**画面占有率・オーバードロー・影響するライトの数によって異なります。**

MingToonはこのプレビューから検証されたGPUパフォーマンス数値を公開していません。以下は**マテリアル同士を比較するときの相対指標**です。
:::

---

## ロード予測パネルを読む {#부하-예상-패널-읽기}

`マテリアルロード予測`

```text
[軽い]  選択 8個 平均 42 / 最高 118
テクスチャコスト 14 · 深度コスト 2 · 予想ドロー 3 · ALU指数 31
メインコスト: 画面深度サンプル · 追加ライトパス
```

| 表示 | 意味 |
|---|---|
| **等級** | 下の4段階 |
| `選択 N個 平均 X / 最高 Y` | 複数のマテリアルを選択すると平均と**最悪値**を一緒に表示します |
| `テクスチャコスト` | テクスチャサンプル数 |
| `深度コスト` | 画面深度サンプル数 |
| `予想ドロー` | このマテリアルが作るパス数 |
| `ALU指数` | 演算量の相対値 |
| `メインコスト` | スコアを大きく上げた項目 |

### 等級の境界

| 等級 | スコア |
|---|---|
| **軽い** | 0 – 34 |
| **通常** | 35 – 84 |
| **重い** | 85 – 149 |
| **非常に重い** | 150以上 |

---

## スコア計算式

ソースの計算式そのままです。

```text
スコア = テクスチャサンプル
       + 深度サンプル × 3
       + max(パス数 − 1, 0) × 8
       + ALU指数
       + (追加ライトパスを使うと)        +12
       + (URP追加ライトなら)            +6
       + (透明オーバードロー危険)        +15
       + (画面深度を使うと)              +12
       + min(動的HSVG個数 × 2, 20)
```

ここで読むべきこと:

:::tip[重み付けが示すこと]
1. **パス1つが8点。** 最初のパスは無料ですが、その次から付きます。アウトライン・追加ライト・透明プリパスが各1つずつです。
2. **追加ライトパスは8 + 12 = 20点。** 単一項目として最も高コストです。
3. **深度サンプルはテクスチャサンプルの3倍。** さらに画面深度を使うと12点が追加されます。
4. **透明オーバードロー危険15点。** 半透明を乱用すると、ここに引っかかります。
5. **動的HSVGは最大20点まで** 積み重なります。
:::

### パスが増える条件

| 条件 | パス +1 |
|---|---|
| `追加ライト受け取り` + `追加ライト強度` どちらも0より大きい (Built-in) | ✅ |
| アウトライン使用 + `クラシックハル使用` | ✅ |
| サーフェスモードが透明系 + `透明深度プリパス` | ✅ |

## モジュール別コスト

ソースのモジュールカタログに宣言されている値です。順序はシェーダー内の実行順序です。

| モジュール | テクスチャ | 深度 | 追加パス | ALU |
|---|---:|---:|---:|---:|
| 基本サーフェス | 0 | 0 | 0 | 0 |
| テクスチャレイヤー | **20** | 0 | 0 | 8 |
| ノーマルレイヤー | **10** | 0 | 0 | 8 |
| ライティング | 0 | 0 | **1** | 7 |
| シャドウ | 0 | **4** | 0 | **12** |
| PBRサーフェス | 2 | 0 | 0 | **12** |
| MatCapレイヤー | **10** | 0 | 0 | 9 |
| エミッション | 1 | 0 | 0 | 3 |
| オクルージョン | 1 | 0 | 0 | 2 |
| リム (深度リム含む) | 2 | 1 | 0 | 7 |
| バックライト | 0 | 0 | 0 | 4 |
| フロントライト | 0 | 0 | 0 | 4 |
| グリッター | 0 | 0 | 0 | **36** |
| シャドウ内部リフレクション | 1 | 0 | 0 | 8 |
| キャラクター高さグラデーション | 1 | 0 | 0 | **1** |
| フェイスシェーディング | 6 | 1 | 0 | 8 |
| アウトライン | 4 | 2 | **3** | 10 |

:::note[この値はモジュールの**最大値**です]
テクスチャレイヤーの20は、10レイヤーをすべて使い、各々にマスクまで付けたときの上限です。実際のスコアはマテリアルで実際に有効になっているものだけをカウントします。
:::

### ここから読める観察

| 観察 | 実務的意味 |
|---|---|
| **グリッターのALU 36** — 単一モジュール最大 | ボロノイ計算が高コストです。きらめきが本当に必要なパーツだけに |
| **アウトラインの追加パス 3** | アウトライン系が作れるパスは3つです |
| **レイヤー系のテクスチャ 10~20** | レイヤー数を実際に使う分だけにするのが最大の節約 |
| **キャラクター高さのALU 1** | 事実上無料です。節約する理由がありません |
| **シャドウの深度 4** | 深度予算の大半をシャドウが使います |
| **バックライト・フロントライト ALU 4** | 非常に安いです。リムライトの代わりにこちらを使う余地があります |

## 重いときの削除順序

スコア寄与が大きい順です。

1. **追加ライト受け取りをオフにする** (−20点前後) — キャラクターが主光だけで演出できるなら、最大の節約です。
2. **半透明をカットアウトまたは不透明に変える** (−15点) — 透明オーバードロー危険がなくなり、プリパスのパスも1つ減ります。
3. **深度ベース効果をオフにする** (−12点 + 深度サンプル × 3) — VRChat通常画面では、どうせ見えません。 → [VRChat](/platforms/vrchat#깊이-효과가-어디까지-보장되나)
4. **レイヤー数を実際の個数に減らす** — 特に[ティア境界](/internals/shader-structure#레이어-티어-키워드)を超えるとコンパイル自体が削減されます。
5. **グリッターをオフにする** — ALUが最大です。
6. **動的HSVGを静的に焼く** — アニメーションしないHSVGは定数に畳み込まれます。

:::tip[アウトラインを無暗に削らないで]
パス8点の節約になりますが、トゥーンルックの正体であり、**深度なしで動作する数少ない手段**です。上の1~5をまず検討してください。
:::

## 動的HSVG

`動的HSVG N個`は**アニメーションされているか、スクリプトで変更される可能性があり、定数に畳み込めない**色補正の個数です。

ビルド時最適化はアニメーションされない値をシェーダー定数として凍結し、演算を消します。アニメーションされる値はユニフォームのままです。 → [ビルド時自動最適化](/workflow/build-optimization#애니메이션되는-값은-건드리지-않습니다)

**HSVGをアニメーションする予定がないなら**、わざわざ揺らぐ値にしないでください。1個あたり2点、最大20点まで付きます。

## 複数マテリアルを一度に見る

`MingToonマネージャー`の `すべてのMingToonマテリアルを選択` または `シーンのすべてのMingToonマテリアルを選択` で全部選択すると、**平均と最悪値**が一緒に出ます。

:::tip[平均より最悪値を見てください]
アバター全体が軽くても、マテリアル1つが `非常に重い` なら、そのパーツが画面を大きく覆うときフレームが落ちます。`最高` の横の等級をまず確認して、そのマテリアルを探して直してください。
:::
