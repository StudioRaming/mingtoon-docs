# 変換レポートを読む

**このドキュメントを読むと** lilToon変換後、コンソールに出力される項目をコード別に解釈でき、どの部分を手動で修正する必要があるかが正確に分かります。

変換直後、このような行が表示されます。

```text
MingToon変換完了: スロット12個、マテリアル8個、損失・未サポート機能5件。元のマテリアルはそのまま保存されました。
```

**`損失・未サポート機能` の件数が0でない場合は、以下を参照してください。**

---

## 深刻度レベル 4段階

| 深刻度 | 意味 | 対応 |
|---|---|---|
| `Information` | 情報。変換は意図通りに実行されました | 読んでスキップしても構いません |
| **`Lossy`** | 変換しましたが **結果が異なる可能性があります** | 実際のモデルで確認が必要です |
| **`Unsupported`** | **変換できません** | 手動で再作成するか、スキップします |
| `Error` | 変換失敗 | 処置が必要です |

集計に含まれるのは `Lossy` · `Unsupported` · `Error` の3つです。

---

## イシューコード一覧

### 近似 — 変換しましたが計算式が異なります

| コード | 何が近似されたか | 確認する項目 |
|---|---|---|
| `SourceDefaultsReplaced` | 元のデフォルト値がMingToonのデフォルト値に置き換わりました | 元のマテリアルがデフォルト値に依存するルックの場合は見た目が変わります |
| `ShadowApproximation` | 影の計算式が異なります | [フォームシャドウの境界・明度](/guides/light-and-shadow#1-형태-그림자-경계--가장-먼저)を再調整してください |
| `OutlineApproximation` | アウトライン幅・色計算が異なります | 幅モードと圧力ソースを確認してください |
| `RimApproximation` | リム計算式が異なります | [リムシェード](/guides/rim) |
| `AlphaApproximation` | アルファ処理が異なります | サーフェスモードとアルファカットオフ |
| `UvApproximation` | UV変形が異なります | テクスチャST |
| `ValueClamped` | 値がMingToonの範囲に制限されました | 元のマテリアルが範囲外の値を使用していました |

:::caution[近似は「間違い」ではありません]
異なるシェーダーは計算式と機能の意味が同じではありません。変換は**相互運用ツール**であり、数学的な複製ではありません。近似項目は**目視で確認し、値を調整してください**というシグナルです。
:::

### ベイク必須 — ランタイムで再現不可能

| コード | 元の機能 | 代替案 |
|---|---|---|
| `AnimatedUvRequiresBake` | UVスクロール/回転アニメーション | テクスチャを事前ベイクするか、アニメーションで再現します |
| `DecalRequiresBake` | デカール | テクスチャレイヤーとして再配置します |
| `DissolveRequiresBake` | ディゾルブ | アルファマスク+アニメーションで再現します |
| `SecondEmissionRequiresBake` | 第2エミッション | エミッションマップにマージしてベイクします |
| `EmissionMaskRequiresBake` | エミッションマスク | エミッションマップにマージしてベイクします |

:::tip[この5つはすべて「テクスチャとして事前ベイクすれば解決」という意味です]
ランタイムで計算していたものを静的テクスチャに変更すれば、ほとんどの場合視覚的に同じように再現できます。アニメーションが必要な場合は、AnimationClipに移してください。
:::

### 未サポート — 変換不可能

| コード | 意味 |
|---|---|
| `SpecialSurfaceUnsupported` | 元のマテリアルの特殊サーフェス(ファー、ゼリーなど)はMingToonに対応がありません |
| `AudioLinkUnsupported` | AudioLink連動はサポートされていません |
| `FeatureUnsupported` | その他の未サポート機能。メッセージに名前が記載されます |

### アセット・判定

| コード | 意味 | 処置 |
|---|---|---|
| `MissingTextureSkipped` | 元のマテリアルが参照していたテクスチャがプロジェクトにありません | テクスチャを復旧して再変換してください |
| `FaceClassification` | 顔判定結果レポート | 以下を参照 |
| `ConversionFailed` | 該当マテリアルの変換失敗 | メッセージを確認してください |

## 顔判定 — Autoは推測しません

:::danger[Autoは元のマテリアルの顔フラグのみを読みます]
インスペクターがそのまま説明しています。

> Auto は **元のマテリアルが直接持つ顔フラグのみ** を読みます。**名前で推測しないため** 、フラグがないシェーダーは引き続きRegularのままで、顔として使用するスロットは **直接 Face として指定する必要があります。**

つまり **lilToonのように顔フラグを持つシェーダーから変換する場合のみ、Autoが顔を検出できます。** StandardやURP Litから変換すると、すべて `Regular` になります。
:::

名前ベースの推測を排除したのは意図的な変更です。名前が `Face` だからといって必ずしも顔ではなく、 `Body` に顔が混在している可能性もあるのに対し、推測が外れる場合のコストが正しい場合よりもはるかに大きいからです — 顔シェーディングが不適切なメッシュに適用されると、原因を特定するのが困難です。

### 判定根拠の表示 {#판정-근거-표시}

| 表示 | 意味 | 信頼度 |
|---|---|---|
| オブジェクト/レンダラー指定 | ユーザーが `顔レンダラー直接指定`·`スキンレンダラー直接指定` で指定 | ✅ |
| マテリアル直接指定 · マテリアルスロット指定 | ユーザーがスロット単位で固定 | ✅ |
| 元のマテリアルの顔フラグ | 元のシェーダーが顔と表示 | ✅ |
| グローバル変換モード | 一括適用 | ⚠️ |
| 一般的なデフォルト値 | フラグがないためRegularのまま | ⚠️ **確認が必要** |

### 役割3種類

| 役割 | プレビュー | 受け取るプリセット値 |
|---|---|---|
| `Face` | 顔シェーディング | 顔用 |
| `Skin` | スキンルック | スキン用 — **素肌のみ** |
| `Regular` | 一般的なシェーディング | 共通 |

→ [MingToonマネージャー](/workflow/character-manager#얼굴--피부-지정--가장-중요한-단계)

## 元のマテリアル追跡 (provenance)

変換マテリアルは **元のマテリアルのGUIDをインポーターのuserDataに記録** します。 `元のマテリアル復元` はこれで動作します。

記録が破損する場合:

| 監査メッセージ | 意味 | 結果 |
|---|---|---|
| `importer userData written by another tool` | 別のツールがすでにuserDataを使用しているため、**データを破損しないようにGUIDを記録しませんでした** | `元の復元` 使用不可 |
| `Source material name is ambiguous; reconvert once to stamp its GUID.` | 名前だけでは元のマテリアルを特定できません | 1回再度変換するとGUIDが記録されます |
| `The source material could not be resolved.` | 元のマテリアルが見つかりません | 元のマテリアルが削除・移動されました |

復旧結果に `正確な元のGUIDがないか、元のマテリアルが見つからないスロット: N個` として集計されます。

:::tip[他のツールと一緒に使用する場合]
MingToonは **他のツールのuserDataを上書きしません。** その代わり、追跡機能を放棄します。元のマテリアル復元が必要な場合は、変換前にそのツールがuserDataを使用しているかを確認してください。
:::

## 監査表 (audit)

変換監査はタブ区切り表を生成します。

```text
source  converted  resolution  face  surfaceMode  renderQueue  cull
        surfaceLayers  normalLayers  matcapLayers  occlusion  passes
        keywords  mismatches  losses
```

| 列 | 確認する項目 |
|---|---|
| `resolution` | 元のマテリアルをどのように見つけたか |
| `face` | 顔判定の結果 |
| `surfaceMode` · `renderQueue` · `cull` | レンダー状態が元と一致しているか |
| `surfaceLayers` ·
ormalLayers` · `matcapLayers` | レイヤーが何個に変換されたか |
| `passes` · `keywords` | コンパイルされるコードの形状 |
| `mismatches` | 元と異なる項目 |
| `losses` | 損失項目 |

`renderQueue differs: expected ...` が表示される場合、サーフェスモードが元と異なる設定になっています。

---

## 変換後の必須確認事項

レポートを読んだ後 **実際のモデルで** 確認してください。インスペクターのプレビュー球では判断できません。

1. **マスクチャンネル選択と反転** — 最も頻繁に間違える場所
2. **テクスチャST** (Tiling / Offset)
3. **AO**
4. **サーフェスモード** — 特に髪がカットアウトで変換されたか
5. **顔スロット判定** — 上記の判定根拠表を参照
6. **レイヤー数** — 元のマテリアルの2nd/3rd表面が何層のレイヤーで変換されたか
