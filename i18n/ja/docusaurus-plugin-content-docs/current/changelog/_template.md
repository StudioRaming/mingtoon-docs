■ 新しいバージョンを作る — `node scripts/new-patch-note.mjs 0.1.11`

  このコマンドが韓国語・英語・日本語の3ファイルを作成し、frontmatterを計算して埋めます。
  手作業で作らないでください。sidebar_positionを間違えるとバージョンの順序が逆になります。
  タイトル下の最初の行の日付は、実際の公開日に自分で書き換えてください。

■ 必ず守ること

  1. 3言語を常に一緒に埋めます。韓国語だけを書くと、残りは韓国語にフォールバックします。
  2. 以下のセクションの順序を守ります。該当しないセクションはまるごと削除します。
     順序は、一行まとめ、アップデート前の確認、新機能、変わった既定値とルックの変化、
     修正された問題、既知の制限、下部のリンクです。
  3. 各項目はユーザーに見える変化から書き始めます。
     キャッシュ・計算の共有・コード整理のように画面に結果が出ない変更は書きません。
       悪い例: 繰り返し計算の削減 — 再利用できるライティング・ノーマル計算を共有し…
       良い例: 同じアバターを再ベイクするときの待ち時間が短くなります。
  4. `新機能`の項目はインスペクターのラベルから書き始めます。ラベルがなければ新機能ではありません。
  5. `修正された問題`は症状として書きます。
       悪い例: 復元の安定性を改善
       良い例: ベイクを中止するとマテリアルが編集用に戻らない問題
  6. 性能の変化は数字なしで書きません。数字がない場合は「体感の差は環境によって異なります」だけを付けます。
  7. 免責の段落を本文の間に挟みません。`既知の制限`にまとめます。
  8. UIラベルはインスペクターの文言そのままを太字で、バッククォートはメニューパスとファイル名にだけ使います。
     ラベルの正本: MingToonソースの Editor/InspectorUx/MingInspectorText.cs
  9. アンカーは韓国語の原文のまま3言語に使います。存在しないアンカーを使うとビルドが失敗します。
 10. Admonitionはv3構文のみ使います。`:::warning[タイトル]` — 角括弧は必須。
     `:::warning`は上部の「アップデート前の確認」1つだけに使います。
 11. 1文60字以内、1ページ80行以内、絵文字は禁止。

    node scripts/check-translations.mjs ja
