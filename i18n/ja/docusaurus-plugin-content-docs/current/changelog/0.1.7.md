*オープンベータ · 2026-09-07*

0.1.7 は 0.1.6 以降の累積変更をまとめたオープンベータリリースです。

**アップグレード時の確認事項**

> ⚠️ **0.1.6 以前から上げる場合は、`Assets/StudioRaming/MingToon` フォルダーをまるごと削除してから 0.1.7 を新規インポートしてください。** これが公式のアップグレード手順です。古いフォルダーへ上書きすると、0.1.7 で廃止されたスクリプト・シェーダー・生成ファイルが残り、アセンブリの重複やコンパイルエラーの原因になります。今回の版でプロパティ名が大きく変わったため、0.1.6 のマテリアルに保存されていた値は引き継がれません — 無くなった名前の位置にはシェーダーの既定値が入り、マテリアルはエラーなくそのまま動作しますので、変換やマイグレーションなしで新しい既定値から調整し直してください。ルックプリセットを保存してあれば、それで素早く戻せます。ベイク成果物（生成シェーダー・フラット化テクスチャ・マスクパック）も焼き直しが必要です。`Assets/StudioRaming/MingToon` 内へ直接作成したプリセットやユーザーファイルがある場合は先にフォルダー外へバックアップし、古い MingToon フォルダーだけを削除してから新しいパッケージをインポートしてください。プロジェクト内の別の場所にあるマテリアル・テクスチャ・プレハブは削除対象ではありません。別製品として配布される `MingLightController` フォルダーも削除対象に含まれません。

> ⚠️ **マテリアルプロパティIDから `_Ming` プレフィックスが外れました。アニメーションカーブの再設定が必要です。** 0.1.6 まで `_Ming` で始まっていたプロパティIDの大半が、プレフィックスなしの正本名になりました（`_MingBacklightColor` → `_BacklightColor`、`_MingGlitterDensity` → `_GlitterDensity`、`_MingAllEffectsEnabled` → `_AllEffectsEnabled` など約670件）。自動変換はありません。0.1.6 のマテリアルに保存されていた値と、`material._Ming...` を指すアニメーションカーブは、シェーダーが宣言していない名前になるため、値が静かにシェーダー既定値へ戻ります。マテリアルは上記の手順どおり新しい既定値から調整し直し、アニメーションカーブだけを新しいIDへ再設定してください。旧IDで保存したプリセットとJSONは、現在のマテリアルから保存し直せば済みます。旧IDを使っているマテリアル・プリセット・アニメーションクリップの一覧が必要な場合は、`StudioRaming/MingToon/Advanced/Migrate Project To Current Schema` が検証と報告だけを行います — アップグレードに必須ではなく、カーブの書き換えもしません。`_MingVirtualLight*`・`_MingMaterialVersion`・`_MingUnifiedShadow*` のように残る名前もあるため、プレフィックスを一括削除しないでください。

> ⚠️ **ベイクキャッシュが再生成され、VRChat アバターは再アップロードが必要です。** 生成シェーダーのキャッシュバージョンが上がり、既存のベイク出力が無効になります。次のビルドで自動的に再ベイクされるため手作業は不要ですが、その1回だけ時間がかかります。今回の版のマットキャップ最適化は再ベイクしてから適用されます。シェーダーはアバターのアセットバンドルに同梱されるため、すでにアップロード済みのアバターは再アップロードしないとこの修正が反映されません。

> ⚠️ **顔の陰影と影の形が変わるマテリアルがあります。** どちらも従来の挙動がバグだったケースです。光が顔の中央を通るときに陰影が硬く飛んでいたのが滑らかに切り替わり、頂点ペイントで顔領域を指定した統合マテリアルで体全体に誤って適用されていた顔の深度オフセットがなくなります。

> ⚠️ **ライティング関連の既定値が変わりました。** `シーン照明色の影響`・`間接光の持ち上げ` を含むライティング項目9つの既定値を実運用のセットアップに合わせ、`透過光を使用` は既定でオフになりました。新規作成するマテリアルとファクトリープリセットにのみ適用され、すでに作成済みのマテリアルの値には手を加えません。

> **2Dリムライトに `Scene Light Influence` を追加しました。** 既定値は1なので、この値を保存していない既存マテリアルでも、暗いライトボリューム内ではリムが暗くなる場合があります。この影響を無効にするには、`2Dリムライト` の `Scene Light Influence` を0に設定してください。

> ⚠️ **`追加ライトの明るさ上限` が新しく追加されました。ポイント・スポットライトが以前より抑えられます。** ポイント・スポットなどの追加ライトが最終的な表面の明るさに加えるエネルギーの上限で、シェーダーの既定値は 0.35 です。強い色ライトの下でもハイライトが白飛びせず色味が残る値です。明るさの寄与だけを制限するため、追加ライトの色の反映はそのままです。0.1.6 のマテリアルに保存されていた値は引き継がれないため、フォルダーを削除して新規インポートしたプロジェクトでは、どのマテリアルもこの既定値 0.35 から始まります。追加ライトが以前より暗く感じる場合は、`ライティング` の `追加ライトの明るさ上限` を上げてください。

> ⚠️ **`2Dシャドウバイアス` の尺度が今回の版で10倍変わりました。** 1 が 1cm ではなく 10cm を意味するようになりました。0.1.6 のマテリアルに保存されていた値は引き継がれないため、手で換算するものはなく、新しい尺度で調整し直してください。同梱の Soft Toon プリセットは新しい尺度で保存されています。同じ整理で `Depth Blur` と `Light Pushback` の項目は無くなり、`受信面プッシュバック`（Receiver Depth Pushback）はカメラ深度だけに適用されます。

> ⚠️ **Face SDF Studio と Mask Maker は今回の版から同梱されません。** 2つのツールは別製品として分離されました。個別に購入してプロジェクトに入れれば、インスペクターの該当箇所で以前と同じように連携します。無い場合はそのボタンが案内に変わるだけで、他の機能には影響しません。

> ⚠️ **VRChat Expressions メニュー作成機能は MingToon 本体から分離されました。** Manager の旧インストール UI は削除され、別売アドオン `Ming Light Controller (MLC)` がアバターごとのメニュー・パラメーター・FX 構成を担当します。MLC がなくても、自動生成されるランタイムメニューだけが使えないだけで、MingToon シェーダーとビルド深度ライトの選択機能はそのまま動作します。以前の版で実際にインストールしたメニュー・パラメーター・FX レイヤーは自動削除されないため、不要なら手作業で整理してください。

> ⚠️ **URP バックエンドが別アドオンとして分離されました。** 基本パッケージには BRP と共用コアだけが入ります。URP シェーダーと Renderer Feature は、有料配布のダウンロードに含まれる `MingToon_URP_Addon_0.1.7.unitypackage` として別途提供します。これまで URP プロジェクトで MingToon を使っていた場合は、基本パッケージを先にインポートしてから続けてアドオンをインポートしてください。アドオンだけを単独で入れる構成はサポートしません。アドオンのないプロジェクトでは URP シェーダーが選択肢に表示されず、共用のエディター機能はそのままコンパイルされ動作します。VRChat PC・Quest は URP を使わないため、この分離の影響を受けません（PC は BRP ベイク版、Quest はモバイル変換版）。アドオンの対象は WARUDO と一般 Unity の URP 12.x 環境です。詳しいインストール手順と収録内容は同梱の `MingToon_URP_Addon.md` を参照してください。

### 0.1.6 生成物の整理と変換 Mesh の自動更新

- このバージョンにのみ含まれる整理モジュールは、0.1.7 のエディターコードが最初に読み込まれたときに、プロジェクトごとに一度、自動で実行されます。上書きインポートでも、フォルダーを削除して新規インポートした場合でも同じように実行されます — 0.1.6 の生成物は `Assets/StudioRaming/MingToon` ではなく `Assets/StudioRaming/MingToonGenerated/Shaders` にあるため、MingToon フォルダーを削除しても残るからです。このモジュールは、MingToon が生成したと証明できる 0.1.6 方式の古い固定プロファイルだけを選び、そのプロファイルを使っている baked マテリアルのシェーダー参照を現行の BRP/URP シェーダーへ切り替えてから、プロファイルを削除します。これにより Missing Shader を防ぎます。シェーダー参照以外のマテリアル値、元のマテリアル・編集用マテリアル、外部/他フォルダーのシェーダーアセットは変更しません。切り替え先の現行 BRP/URP シェーダーが見つからないかエラー状態の場合は、プロファイルをそのまま残して Console に報告します。
- 古いパラメーターを新しい構造へ変換しないため、見た目は変わる場合があります。現行バージョンの正しい見た目が必要な場合は、元のマテリアル・編集用マテリアルを再度変換してから Bake してください。
- MingToon Manager のデフォルト変換では、編集用マテリアルと生成 Mesh を元の Model/FBX の隣にある `MingToon` フォルダーへ一緒に保存します。変換出力フォルダーを直接指定した場合は、両方ともそのフォルダーを使用します。
- 以前のグローバル `MingToonGenerated/Meshes` にあった MingToon 所有の Mesh は、次回の変換時に元のファイルの隣へ移動し、GUID と `.meta`、Renderer 参照を維持します。
- 同じ GUID の Model/FBX が上書き・再インポート・移動された場合、インポート完了後に登録済みの生成 Mesh を自動的に再ベイクします。安全に再利用できる Mesh は同じアセット内で更新し、GUID と Renderer 参照を維持します。
- Renderer の範囲が異なる場合、元の Mesh の識別が曖昧な場合、またはユーザーが生成 Mesh の形状・色・UV を競合する形で編集した場合は、自動的に上書きしません。警告を確認し、Manager で再度変換してください。

**新機能**

### 1. `発光レイヤー2を使用`

- 2枚目の発光マップが追加され、部位ごとに異なる色で発光させられます。2つのレイヤーは加算されるため、各部位の色はそのまま残ります。既定はオフです。

### 2. `マップのアルファを強度マスクに`

- 発光マップのアルファチャンネルをピクセル単位の強度マスクとして使います。アルファは色と一緒にすでに読み込まれているため、テクスチャの読み取りは増えません。2つの発光レイヤーのどちらにもあります。

### 3. マテリアル設定のコピー＆ペースト

- インスペクター上部のバーにコピー・ペーストのボタンが追加されました。ペーストは `すべて貼り付け`・`値のみ貼り付け（テクスチャ除く）`・`テクスチャのみ貼り付け`・`キーワードのみ貼り付け`・`レンダーキューのみ貼り付け` の5種類に分かれており、テクスチャはマテリアルごとに残したまま設定だけを移せます。元に戻す (Ctrl+Z) が効きます。

### 4. `クイック設定` カードとカラーガンマ

- マテリアル全体にすぐ効く項目をインスペクター最上部の一か所にまとめました。`統合シャドウカラー` を含みます。
- 統合シャドウとSSAOの彩度・明度調整、ノーマルアウトライン色、インナーアウトライン色に `ガンマ` を追加しました。明度軸だけを調整して色相と彩度を維持し、1は従来の見た目を保ちます。アウトラインの不透明度と幅は変わりません。

### SSAO（スクリーンスペースオクルージョン）

- 深度グループの `SSAO` タブが、この版で出荷する形にまとまりました。0.1.6 から直接上がった場合、このタブ自体が初めて表示されます。画面深度から物体が接している場所を見つけ、そこだけを暗くするモジュールです。オクルージョンマップと違い、トゥーンバンドとスクリーントーンを通過したあとに乗るため、影の境界を階段状にしません。**既定はオフなので、既存マテリアルの絵は変わりません。**
- 値の単位と範囲が最初に紹介したときから変わりました。`SSAO 半径` は 0.001〜0.03（既定 0.005）で、以前フェード範囲として案内していた項目は `接触減衰` へ名前が変わり、メートルではなく `SSAO 半径` の倍数（0.25〜4、既定 1）になりました。`SSAO バイアス` も絶対メートルではなく `SSAO 半径` に対する比率です（0.4 = 半径の40%）。半径比率のため、カメラ距離や半径を変えても見た目がそのまま追従します。消失距離は SSAO 専用の項目ではなくなり、2Dシャドウと共用の `共通フェード距離`（既定 200）にまとまりました。以前の版の数値をそのまま持ち込まないでください。
- 他の深度モジュールと同様にカメラ深度テクスチャが必要です。深度がない環境では静かに消え、`全エフェクト` と `深度エフェクトマスター` をオフにすると一緒にオフになり、VRC品質ティア Low でもオフになります。ビルド深度ライトも、SSAOをオンにしたアバターを深度モジュール使用として扱います。
- 費用はマテリアルごとに一度ではなく、画面に見えるフラグメントごとに発生します。深度グループの `共用品質` がピクセルあたりの深度サンプル数を決め（Low 4・Standard 8・High 16）、`共通フェード距離` が費用を切る項目です — この距離より遠いキャラクターはサンプル数が0になるため、群衆シーンではこの値を下げるのが最も確実な最適化です。2項目とも2Dシャドウと共用の値なので、片方だけを個別に調整することはできません。
- `キャストシャドウ内の表示量`・`2Dシャドウ内の表示量` で、それぞれの影の中でSSAOをどれだけ重ねるかを個別に決めます。各項目の詳細はマニュアル `3-10. SSAO` を参照してください。

### 2Dシャドウ: 一枚のシルエットと深度反応

- 2Dシャドウが一枚のシルエットに整理されました。前面オブジェクトのシルエットをライトと反対方向へずらしてその一枚を読み、前面オブジェクトが受信面から浮いている分だけその一枚をさらに遠くへ押し出します — 接しているものは幅の位置にそのまま、浮いているものだけが遠くへ動き、それが奥行きとして読み取れます。
- 影の判定を受信面自身の接平面基準で行うため、顔や体の自己曲率が残していた跡が消え、額にほぼ接した前髪の影はそのまま残ります。
- `2Dシャドウ` タブの項目は次に整理されました: `影の幅`・`影の強さ`・`深度伸び`・`深度カーブ`・`深度フェード`・`ソフトネス`・`ブラー`・`2Dシャドウバイアス`・`受信面プッシュバック`・`逆光シルエット抑制`。
- 奥行きは `深度伸び`（既定1）が作ります。1なら10cm浮いたオブジェクトの影が幅から10cm先に落ち、0では押さずに幅の位置だけを読む均一な一枚になります。`深度カーブ` がその押し出しの形を、`深度フェード` が遠くに浮いたオブジェクトの濃さを決めます。
- カメラが見下ろすほど `深度伸び` が短くなり、伸びた部分が薄くなります。押し出しが画面上の方向のため、見下ろすと影が長く伸びて見えていたのを抑えたもので、横から差す光で画面横方向へずれる影はそのままです。調整項目はなく自動です。
- この短縮が `顔の固定方向` を使うマテリアルにも適用されます。これまで顔は「影の方向を頭に固定する」という理由で長さの補正から外れており、そのためカメラが顔を見下ろすと前髪の影だけが全長を保ち、同じ角度の体の影とずれていました。固定されるのは影が向く**方向**であって長さではないので、方向はそのまま頭に追従し、長さだけがカメラ角度に応じて一緒に縮むようになりました。伸びた部分と幅の位置が同じ比率で縮むため、側面の薄まり方は以前と同じです。
- 長さが 0 まで潰れることはありません。影の軸が消えないよう最小値が入っており、その位置での影は指定した `影の幅` の 2% の幅として残ります — 目には見えない大きさです。
- `ブラー` は描き終えた影に最後に適用され、半径はこの値（メートル）だけで決まります。このときだけ一枚を中心1回＋回転ディスク4回の計5回読みます。
- 影の内側は指定した影色でしっかり塗られます。統合シャドウを使うマテリアルでは完全に覆われた場所がフォームシャドウの中心とまったく同じ色になり、`影の境界` の色帯はブラーや深度で柔らかくなった縁にだけ乗ります。
- 品質と距離の項目は深度グループの `共用品質`・`共通フェード距離` の2つにまとまりました。`共用品質` はSSAOのサンプル数だけを決め、2Dシャドウはこの段階に関係なく固定の少数だけ読みます — 幅1回＋投票4回＋一枚1回、ブラーを有効にするとその一枚が5回になり、最大10回です。
- 各項目の説明はマニュアル `3-11. 2D シャドウ：一枚のシルエットと深度反応` を参照してください。

### `バックライトの合成モード`・`フロントライトの合成モード`

- バックライトとフロントライトの色を表面へどう混ぜるかを選べるようになりました。Normal・Multiply・Add・Hue・Screen・Color・Overlay の7種類で、ほかのリム系と同じ一覧です。同時に追加された `ブレンド不透明度`（0〜1）は、色と強度はそのままに存在感だけを抑えます。
- 既定値はどちらも `Add`、不透明度1です。この組み合わせは従来の直接加算と式が同じなので、この項目だけでは見た目は変わりません。
- `Add` 以外のモードでは `バックライト強度`・`フロントライト強度` が明るさの倍率ではなく混ざる度合いとして働きます。Hue と Color は輝度が1を超えると色を保てず灰色へ寄るため、強く飛ばす表現には `Add` か `Screen` を使ってください。

### `今すぐメッシュだけ再ベイク`

- Manager の `準備` > `1 · 変換` > `同時にベイクするメッシュチャンネル` の一番下にボタンが追加されました。元のFBXを修正したあとに押すと、アウトラインノーマル・顔ノーマル・キャラクター高さのうち上でオンにしたチャンネルだけを焼き直します。
- マテリアルとルック値には触れません。メッシュを取り戻すために変換をやり直すと手で合わせた値がプリセットで上書きされますが、このボタンはメッシュだけを書き直します。範囲は同じグループの上にあるセレクタで `このキャラクターのすべてのメッシュ` か `選択したオブジェクトのみ` を選びます。
- 対象メッシュがない、オンにしたチャンネルがない、出力フォルダーが無効、のいずれかでは無効になります。

### lilToon 2.3.4 変換精度と共通 UV ルーター

- lilToon 2.3.4 マテリアルを基準に、HSVG、アルファマスク、アウトライン幅と頂点圧力、リム方向と裏面条件、MatCap マスクチャンネル、反射色、トゥーンスペキュラーを再マッピングしました。表現できない値だけを警告し、同じ結果になる既定値と空の無効マスクは失敗として数えません。
- Main Color、2nd、3rd と各独立マスクを取り込みます。2nd・3rd は MingToon のスタッキングレイヤーへ移し、色・マスク・合成条件を個別に維持します。
- ベース表面・アルファマスク・10枚のスタッキングレイヤー・発光レイヤー1/2と各マスクが同じ UV ルーターを使います。UV0〜UV3、Tiling/Offset、スクロール、中心回転、回転速度、スプライトシートの列・行・フレーム数・再生速度を同じ実装で処理します。
- lilToon デカールの位置・サイズ・回転、単一表示／繰り返しタイル、左右制限、複製・反転・ミラー、スプライトシートアニメーションを変換します。アニメ画像のように動くアトラステクスチャは対応しますが、動画ファイルを再生するデコーダーは含みません。
- UV ルーティングは、それを使う生成シェーダーにだけ組み込まれます。既定 UV と静止テクスチャだけのマテリアルは追加のルーティング・アトラス演算を負担しません。
- AnimationClip 内の旧マテリアルプロパティカーブの自動書き換え、Fur、Gem、屈折変換は今回の版に含まれません。

### 変換結果レポートの整理

- 変換結果をマテリアルごとの長文ではなく、元と結果の組ごとにまとめて表示します。組ごとに `元:` と `変換後:` で両マテリアルのパスを示し、`解決方法:` でどう対応付けたかを明らかにしたうえで、移せなかった内容を `主要な不一致` と `明示的な損失` の2つの一覧に分けて記載します。`直近の変換結果` パネルを開くとこの詳細が出て、`すべてコピー` でレポート全体を一度に取り出せます。
- `解決方法` は `出所記録で接続`・`一意の名前で接続`・`名前が重複して確認が必要`・`元を見つけられない` の4つのいずれかです。前の2つは組み合わせが確定したもので、後の2つはどの元マテリアルから出たのかを自分で確認する必要があるものです。
- 衣装で一目で分かる UV・デカール・発光・アルファ・アウトライン設定は警告だけで終わらせず、変換先で表現できる範囲まで実際の値を移します。Fur・Gem・屈折のように今回の版にレンダー経路がない機能だけを `明示的な損失` として残します。
- `顔Rendererを直接指定`・`肌Rendererを直接指定` の下に警告が1つ増えました。指定した Renderer 上の MingToon マテリアルのうち、まだその役割が付与されていないものを顔いくつ・肌いくつと数えて知らせ、すぐ下の `指定したRendererに役割を付与` ボタンを指し示します。役割の付与がないとルックプリセットが顔・肌の値を分けて送れず、そのマテリアルだけが通常の値で塗られるのですが、これまでその事実が画面のどこにも出ていませんでした。数える基準はボタンが実際に付与する対象と同じなので、警告が消えれば付与は完了です。3言語すべてで表示されます。

### アバターごとの Ming Light Controller 設定（別売アドオン）

- VRChat 用のライティング・ルック操作メニュー生成機能を MingToon 本体から分離し、`Ming Light Controller (MLC)` という別売アドオンにしました。MingToon 本体の更新とアバターメニューの作成を独立して管理でき、ランタイムメニューが不要なユーザーはアドオンを導入する必要がありません。
- `Ming Light Controller Settings` コンポーネントが追加され、表現プロファイル・アタッチ方式・機能ごとの調整をアバターのルートに保存します。以前はこれらがウィンドウの中にしか残らず、最後に触ったアバターの設定が次のアバターを決め、スクリプトを再コンパイルすると消えていました。1つのプロジェクトの2キャラクターが別々のメニューとパラメーター予算を持てます。
- プロジェクトウィンドウでプレハブを右クリックして `MingToon` > `Ming Light Controller` を選ぶか、Attachment ウィンドウのボタンから追加します。実際に変更した項目だけが記録されるため、カタログ既定値へ戻すと記録も消えます。オーサリング情報のみを保持し、実行時の動作はありません。

### `パフォーマンス距離` — 離れると重いモジュールをまとめてオフに

- `マスター調整` タブの最下部に `パフォーマンス距離 (m)`（既定 10）と `パフォーマンス距離倍率`（既定 1）の2項目が追加されました。カメラとの距離が2つの積を基準に近・中・遠の3区間に分かれ、離れるほど重いモジュールが丸ごとオフになります。
- 積の 0.4 倍より内側（既定 4m）はこれまでとまったく同じです。その外側（既定 4〜10m）では深度効果4モジュール・PBR・マットキャップ2層以上・ノーマル2層以上・スタック3層以上・グリッター・スクリーントーン・影の内部反射がオフになり、サンプル数上限が1段階下がります。10m より外では基本色・フォームシャドウ1段・影の投影・アウトライン・エミッション・リムシェード・顔SDFだけが残ります。
- 既存の `VRC品質ティア` とは低い方が採用されます。中距離が Mid、遠距離が Low と同じ上限なので、品質ティアを Low にしてある場合は近づいても Low のままです。
- 判定はオブジェクト単位（レンダラー原点とカメラの距離）なので、1キャラクターのすべてのピクセルが同じ区間になります。しきい値で一度に切り替わり、徐々に薄くなるフェードは従来どおり `共通フェード距離` が担当します。
- 倍率は別売アドオン MLC がゲーム内のラジアルで操作します。人が多い場所では 0 に下げて常に最も軽い状態にし、写真を撮るときは上げて近距離の見た目を広く使います。2項目ともベイクで定数に畳まれないため、アップロード後も動作します。
- 既定値では見た目は変わりません。近くで見る絵はそのままで、遠くにいるときだけ軽くなります。

### `サーフェスモード` の選択肢名を整理

- `サーフェスモード` の4つの選択肢が、レンダーキュー番号を併記する名前に変わりました: `不透明 (2000)`・`カットアウト (2450)`・`半透明 (2499)`・`透明 (3000)`。0.1.6 の `透明・アウトライン用深度書き込み` が `半透明 (2499)` です。名前だけの変更で、各モードのレンダーステート・キュー・保存された値はそのままなので、既存マテリアルの絵は変わりません。
- 2つの透明モードの違いを選択肢の説明に記載しました。`半透明 (2499)` はアルファ合成を使いながら深度も書き込みます。レンダーキュー 2499 のためカメラ深度テクスチャに入り、透明なサーフェスで `2Dシャドウ`・`2Dリムライト`・`インナーアウトライン` を使うにはこのモードである必要があります。深度を持つため、両面の髪のように毛束の内側が外側を覆ってはいけないサーフェスに向いています。
- `透明 (3000)` は標準のアルファ合成です。深度を書き込まず奥から手前の順で描くため、1つのマテリアルを共有する体・インナー・スカートのような重なった層が互いを消さずに透けて見えます。ガラスのように他の透明オブジェクトと混ざる必要があるサーフェスもこちらです。その代わりカメラ深度テクスチャに入らないため、上記の3モジュールは使えません。どちらのモードもアウトラインは維持できます。

### `両面デュアルパス`

- `サーフェス描画` に `両面デュアルパス` が追加されました。`表示する面` が `OFF（両面）` のサーフェスの裏面を、表面より先に別パスで描きます。スカートの裾が自分に重なる部分にできていた三角形のギザギザが消え、裏面がアルファどおりに透けます。
- コストは頂点パス1回と SetPass 1回です。ピクセルコストは変わりません — 両面設定はすでに表裏の両方をシェーディングしていました。
- `サーフェスモード` とは無関係にオンにできます。既定はオフなので、既存マテリアルの絵は変わりません。

### `透明深度プリパス` — 透明マテリアルのアウトラインが突き抜けません

- `透明 (3000)` のマテリアルは色を描くときに深度を書き込まないため、アウトラインが表面を突き抜けて手前に透けていました。`サーフェス描画` の `透明深度プリパス` をオンにすると、深度だけを書き込むパスをもう1回描いてそのアウトラインを取り除きます。
- 自分で深度を書き込む `半透明 (2499)` には不要なので、`透明 (3000)` でのみ動作します。
- 折り目など斜めに見える面で背面のアウトラインがまだ透ける場合は、`アウトライン遮蔽マージン (傾き)`・`アウトライン遮蔽マージン (固定)` を少しずつ上げてください。どちらも既定値は0で、上げすぎるとシルエットのアウトラインまで消えます。

### `アルファフェード` — 距離と角度で表面を消します

- `アルファとカットアウト` に `アルファフェード` の領域が追加されました。`距離フェードを使用` はカメラからの距離に応じて表面を消します。一人称で自分の頭やアクセサリーが視界を塞がないようにしたり、遠ざかるほど消したい場合に使います。近距離側は `近距離・完全に消える距離` と `近距離・完全に見える距離`、遠距離側は `遠距離・薄れ始める距離` と `遠距離・完全に消える距離` で指定し（単位はメートル）、一組の2つの値を同じにするとその地点で切り替わります。
- `角度フェードを使用` は表面がカメラを向いている度合いに応じて透明度を変えます。`正面の不透明度` と `輪郭の不透明度` の2つの値が方向を決めるため、別途モードを選ぶ項目はありません。ノーマルマップではなくメッシュ自体の向きを見るため、シルエットに沿います。
- どちらも既定はオフで、オンにした直後の既定範囲は何も隠さないため、距離と不透明度を自分で指定する必要があります。`サーフェスモード` が `不透明 (2000)` だと結果は見えません。
- 注意点が2つあります。`透明深度プリパス` はフェードを反映しないため、フェードで消えた場所が背後の半透明を隠し続けることがあります。そしてフェードで消えても影はそのまま残ります — 影はカメラではなくライトから描くもので、そのパスには測れるカメラ距離がありません。遠距離フェードで完全に消す場合は、レンダラーの影設定も一緒にオフにしてください。

### `グラデーションLUT` と `色相回転の方式`

- `基本サーフェス` に `グラデーションLUTを使用` が追加されました。ベースマップの色を R・G・B チャンネルごとのランプで再マッピングします。`グラデーションLUT` には横方向のランプテクスチャを割り当て、sRGB でインポートしてください。`グラデーション強度` で元の色と混ぜる比率を決めます。既定はオフで、オフの場合はランプテクスチャを読み込みません。
- 同じ場所に `色相回転の方式` が追加されました。ベースマップ HSVG の色相 (H) をどの空間で回すかを選びます。`OKLab` は明度と彩度を保ったまま色相だけを回すため、肌や髪の色を移す際の結果が予測しやすく、`HSV` はこれまでの方式です。
- **既存のマテリアルは、保存されている HSVG の値から自動的に方式が決まります。** すでに HSV で色を合わせてあるマテリアルは `HSV` のまま残り、色は変わりません。新しく色相を回すときだけ `OKLab` を使ってください。

### VRChat・WARUDO 共通のビルド深度ライト

- 新しい Manager では既定でオンですが、深度マスターと実際の深度エフェクトが1つ以上有効な場合だけビルドへ載せます。
- 深度機能を使わないアバターでは自動除外され、深度を供給するワールド・ホスト専用なら手動でオフにできます。
- VRChat と WARUDO は同じ設定・判定を使い、ビルド後もシーン・元のPrefab・マテリアル値を保持します。
- 生成される深度ライトは `Not Important`（`ForceVertex`）として載り、シャドウマップと ForwardAdd を描きません。これはエディター実測であり、実際の VRChat クライアントでは未検証です。既存のアップロードへ適用するには再アップロードが必要です。

### 5. VRChat Expressions メニュー作成を MLC アドオンへ分離

- Manager の VRChat Expressions インストール項目を丸ごと削除しました。`Modular Avatarで非破壊インストール`、フル／軽量メニューを選ぶ `フル調整メニューを使用`、`Expressionsルートに直接配置`、インストールボタン、そしてこのキャラクターの全マテリアルで「VRCランタイム操作を使う」と「FXメニューでシャドウ投影を切り替え」をまとめてオン・オフしていたボタンがすべてなくなりました。

- 以前の版でインストールした項目はアバターにそのまま残ります。削除する経路も一緒になくなったため、不要なら手作業で整理してください。
- マテリアルの「VRCランタイム操作を使う」と `VRC Quality Tier` はインスペクターに残っています。MLC でアバターメニューへ接続するか、MLC を使わず必要なメニューとアニメーションを自分で用意できます。
- 同じ版内で整理を完了し、旧インストーラーのソース（`MingVrcVirtualLightExpressionInstaller`・`MingVrcVirtualLightContract`・`MingVrcModularAvatarBridge`）と Manager インストールパネルの文言もパッケージから削除しました。マテリアルの「VRCランタイム操作を使う」がベイクで保持するプロパティ一覧とシェーダープロパティはそのままで、MLC がそれらを駆動します。

### インストーラーの残存 API を削除（breaking）

- **`MingToonManager` の public プロパティ `UseModularAvatarVrcIntegration`・`VrcFullExpressionMenu`・`VrcMenuAtExpressionsRoot` と、対応する直列化フィールド3個を削除しました。** 上で分離した内蔵 VRChat インストーラーの残りで、この版にはこれらを読むコードが一つもありません。シーンやプレハブに保存されていた値は失われますが、インストーラー自体が存在しないため、動作にも見た目にも影響はありません。これらのプロパティを参照するユーザースクリプトはコンパイルエラーになるので、その参照を削除してください。
- 同じ整理で `MingVrcDepthAvailabilityPolicy` もパッケージから削除しました。ブール値1つと案内文1つだけを持ち、読み手のいなかった型です。出荷時の深度判断は従来どおり `MingVrcDepthLightPolicy` とビルド深度ライトの経路が担当するため、動作は変わりません。

### 6. PBR 関連の3セクションを独立した `PBR` グループへ分離

- `PBR サーフェス`・`トゥーンスペキュラー`・`領域マスク` がキャラクターグループに混ざっていたものを独立したグループに分けました。位置は `キャラクター表現` の次、`深度ベースエフェクト` の前です。値と既定値はそのままです。

### 7. インスペクターのセクションとフレネル領域を整理

- リム以外にフロントライトと影の内部反射も含む最上位 `リム` グループを `スタイライズドライティング` に改名しました。
- ライティング項目は `基本設定` 内の `シャドウ` セクションに移り、`フォームシャドウ`→`キャストシャドウ`→`シャドウカラー`→`シャドウパターン` の順になりました。
- リム系は `リムライト`→`リムシェード`→`フロントライト`→`バックライト`→`影内部リフレクション`、深度系は `深度エフェクトマスター`→`2Dリムライト`→`2D透過光`→`2Dシャドウ`→`インナーアウトライン` の順です。
- フレネル系の領域を `Width`・`Softness`・`Invert Area` に統一しました。`Width` 0はなし、1は領域全体を使用できます。`Softness` は外側境界を動かさず、選択したWidth内の減衰比率だけを変えます。Width 1・Softness 1は単色塗りではなく全範囲のグラデーションです。
- リムライトと影内部リフレクションの旧 `ライト方向の影響` は、実際の輝度動作に合わせて `光源側の強調` としました。反対側に残っていた0.5の輝度底を除去し、メイン／Virtual Lightを回すと明るい側がすぐ切り替わります。リム位置は別の `視線基準` で調整します。
- フロントライトをフレネル系から分離し、画面上の半径に近く動く専用の円形キャップへ作り直しました。`領域サイズ`・`柔らかさ` を直接調整し、`光源方向の影響` と新しい `視線方向の影響` で主光源とカメラ方向の重みを個別に設定できます。視線値を0にすると、カメラを回してもキャップは主光源軸に固定されます。同じ半径を再利用する低コストの `ハイライト中心サイズ/強度` も追加しました。フレネル用の領域反転は使いません。
- 以前のフロントライト `Border`・`AreaInvert`・`Directivity`・`ViewStrength` は自動変換せず削除しました。新しい視線制御は旧IDを復活させず `_FrontLightViewDirectionInfluence` を使います。正しい新規既定値とFactory Presetで再構成し、この項目の時点でマテリアルプロパティSchemaは15、Preset Schemaは10になりました。同じ版の以降の変更でマテリアルプロパティSchemaは17まで上がり、この版が出荷する値は17です。
- 以前の `Power/Falloff` 互換値5個も、非表示の互換ストレージとして残さず、自動移行なしで削除しました。バックライトは直列化済み `Border` を維持し、Inspectorでは `Width = 1 - Border` と表示します。
- `2Dリムライト` に任意のフレネル領域を追加しました。既存の2Dリムライト結果へ乗算され、無効時は従来の出力と完全に同じです。`Invert Area` ではカメラ正面側を消していた幾何シルエットガードだけを迂回し、深度比較とマテリアルマスクは維持します。

### 8. `パフォーマンス負荷` メーターがベイク後の値を既定で表示

- 何もしていないのに数字が以前より低く見えることがあります。マテリアルが変わったのではなく、基準が変わりました。実際にアップロードされるのはベイクされたシェーダーなので、その値が代表の数字になりました。編集中のマテリアルの値は詳細項目にそのままあります。

### 9. `Overlay` + `Depth2D` の組み合わせに案内を表示

- `パターン方式` を `Overlay` にしたまま `パターン適用対象` を `Depth2D` に変えると案内が出ます。`Overlay` は仕上がった陰影の上に線を重ねる方式のためフォームシャドウでのみ動作し、2D では `Recolor` に下がります。以前からの挙動ですが、何の表示もありませんでした。


### 投影境界フェザーの刷新と自動変換

- `キャスト境界フェザー品質` の選択肢が5つから3つになりました。`Light3Tap`・`Standard5Tap`・`High9Tap` の3段階で、中心1タップと黄金角ディスクタップをピクセルごとのノイズ回転で混ぜる一つの方式に統一されています。旧方式ごとの半径上限（8/20/48px）もなくなり、3段階すべてがスライダーの全範囲をそのまま使います。
- `投影フェザー半径` の単位が画面ピクセルから、2Dリムライトと同じカメラ補正ワールド幅に変わりました。範囲は 0〜400（既定60）から 0〜20（既定3.5）になりました。
- **マテリアルを開くと保存済みの2つの値が自動変換されます。** 値がリセットされたのではなく、新しい単位へ換算されたものです。品質の対応は `Premium25Tap`・`SoftBilinear9Tap` → `High9Tap`、`Fast5Tap`・`Smooth13Tap`・`StableVogel5Tap` → `Standard5Tap`、`DerivativeEdgeAA1Tap` → `Light3Tap` です。半径は各段階が実際に出せたピクセル幅を基準に換算します。
- **名前の数字がそのままピクセルあたりの読み取り回数です。** すでに読んである中心 1 回にディスク 2・4・8 回を足した値で、ディスクはメインディレクショナルライトのシャドウマップだけを読みます。カメラ深度テクスチャは読まないため、この項目のために深度プリパスが増えることはありません。
- **URP でディスクタップが軽くなりました。** プロジェクトのソフトシャドウが有効だと、ディスクタップごとに 5×5 のフィルターがもう一度展開され、ピクセルあたりのシャドウマップ読み取りが `Standard5Tap` で 36 回、`High9Tap` で 72 回まで増えていました。いまは各ディスクタップがハードウェア比較 1 回だけなので 4 回・8 回です。ディスク自体が境界をぼかすフィルターなので、その上にフィルターを重ねるのは同じ仕事を 9 倍の値段でしていたことになります。中心タップは URP がすでに計算したフィルター済みの影の値をそのまま使うため、ソフトシャドウの柔らかさは残ります。スクリーンスペースシャドウを使う構成はもともとタップあたり 1 回だったので変わらず、Built-in も変わりません。境界がごくわずかにくっきりする場合があります。
- **`パフォーマンス負荷` メーターがこのフェザーを計算に入れます。** これまでこのモジュールはメーター上で 0 と出ていたため、ピクセルあたりの読み取りが正直に数えられていた 2D シャドウと並べて比較できませんでした。いまはフェザーをオン・オフするとメーターの数字が実際に動きます。他のモジュールと同じ規約に従い、`影の投影` と `投影境界フェザー` がオンで半径と強度が 0 より大きいときだけ数え、タップ数は選んだ段階の 2・4・8 を使います。シャドウマップの読み取りは深度読み取りと分けて数えるため、深度プリパスの項目が誤って増えることはありません。

### `2D深度リム` の表示名を `2Dリムライト` に変更

- インスペクターで `2D深度リム`・`深度リム` と表示していた名前を `2Dリムライト` に統一しました。`深度リムマスク` などの下位項目も `2Dリムライトマスク` に揃い、`2D` が付いていなかった名前にも接頭辞を付けました。
- この項目は表示名だけの変更です。2Dリムライト系のマテリアルプロパティ名は一つも変更していないため（`_DepthRimEnabled`・`_DepthRimMask`・`_DepthRimWidth` などはそのまま）、この名称変更を理由とした再設定は不要です。ただし本バージョンには別途プロパティIDの正規化が含まれるため、上のアップグレード警告にある `_Ming` プレフィックスの項目を必ず確認してください。

### 別売アドオンが必要なボタンの動作を統一

- Mask Maker・Face SDF Studio・Ming Light Controller が必要な箇所は、アドオンがなくてもボタンがそのまま表示され、クリックできます。クリックするとその機能を説明するマニュアルページへ移動し、購入経路もそのページにあります。
- 以前は箇所ごとに異なっていました。マスク作成ボタンと頂点ペイント開始ボタンはグレーアウトしてカーソルを乗せないと理由が分からず、Face SDF ボタンはダイアログを出すだけでその場に留まりました。
- ただし `マスター調整` タブと `バーチャルライト` は、ボタンではなく値を書き込む場所なので規則が異なります。Ming Light Controller がない場合、MLC が担当する行 —`光を足すもの全部`・`そのうち輪郭に出るものだけ`・`影全部`・`最終出力` の4グループと `バーチャルライト` グループ— は描画しません。ロック案内もグレーアウトしたコントロールも残さず、その場所には何も描画しません。アドオンなしでは値を確定できない死んだコントロールを見せないためです。
- `マスター調整` タブ最下部の `パフォーマンス距離` グループは MLC と無関係に動作するため、アドオンがなくても常に表示されます。MLC のないプロジェクトでこのタブに残るのはこのグループだけです。
- いずれの場合も、マテリアルに保存された値はそのまま残り、シェーダーは引き続きその値を読みます。MLC を導入すれば、同じ場所に行が戻ります。

### キャストシャドウの受光構造を刷新

- キャストシャドウが暗くなる仕組みを作り直しました。影の減衰は直接光の項にのみ乗算し、環境光（SH）はその上に加算の下限として足されます。統合シャドウモードで死んでいた `キャスト間接光補正` が生き返り、環境光の明るいシーンでキャストシャドウが黒く抜けなくなります。環境光のないシーンでは何も加算しません。
- **統合シャドウ（出荷時の既定）のマテリアルは、環境光のあるシーンでキャストシャドウが以前より明るくなります。** レイヤーモードで使われていた旧来の減免式も、この加算の下限に置き換わりました。
- `逆光シルエット抑制` がキャストシャドウを消し始める位置が、固定角度からフォームシャドウの実効境界の追従へ変わりました。新しい `キャスト抑制オフセット`（0〜1、既定0.25）がその位置を暗い側へどれだけ押し込むかを決め、実際の押し込み量には `1段目の影のぼかし` の半分が加わるため、キャストシャドウの消え際が常にフォームシャドウの内側に隠れます。`キャストシャドウ` タブの `詳細設定` の中、`逆光シルエット抑制` のすぐ下にあります。フォームシャドウをオフにしたマテリアルは従来の固定ウィンドウのままです。
- `セルフキャストシャドウ抑制` のキャスター押し出しが逆光時に自動的に弱まり接地シルエットを守るようになり、ディレクショナルライトにのみ適用されます。このトグルをオンにしたマテリアルだけが対象で、スポット・ポイントライトの下ではバイアスがかかりません。

### 顔専用の自己面抑制の行が `受信面プッシュバック` ひとつに統合されました

- `顔` タブに別途あった顔専用の自己面抑制の行を廃止しました。同じ働きをする値は `2Dシャドウ` タブの `受信面プッシュバック` ひとつになり、顔と体が共有します。このマテリアルが書き込むカメラ深度を後ろへ押して自己面の汚れを減らします。カメラ深度（`2Dシャドウ`・`SSAOを使用` が読みます）だけに適用され、ライトシャドウマップは変えません。
- `顔2D影アシスト` とは無関係に動作します。以前はアシストがオンのときだけ効いたため、出荷時の既定であるアシストオフの状態ではインスペクターに見えているスライダーが黙って死んでおり、鼻の稜線に角張った影の塊が残っていました。今は `全エフェクト` と `深度エフェクトマスター` がオンで、`2Dシャドウ` か `SSAOを使用` のどちらかがオンであればそのまま効きます。
- 視野角の重み付けが加わりました。カメラを向いたレリーフ（鼻・頬・額）だけが後ろへ押されて自己汚れが消え、斜めに寝た面（顎の下）は実際の深度を保つため、顎から首へ落ちる影の分離はそのまま残ります。
- **マテリアルを開いて `2Dシャドウ` タブの `受信面プッシュバック` の値を確認してください。** 影を受ける顔・体のマテリアルにだけ使い、影を落とす髪・衣装は0にするのが基準です。新規に作成するマテリアルの既定値は0で、同梱のファクトリールックは顔スロットにだけ0.01を使います。
- **スライダーの上限が1から0.1へ下がりました。** 0.1は10cmで、そこが効果の終わる地点です — 2Dシャドウが前後を判定する間隔は10cmで頭打ちになり、SSAOの半径はそれよりはるかに小さいため、それを超える値はどのピクセルも変えていませんでした。スライダーを効果の終わる位置で終わらせたもので、今回の版の `2Dシャドウバイアス` の尺度整理と同じ整理です。実際に使われていた範囲（既定0、ファクトリーの顔0.01）はそのままなので絵は変わりません。マテリアルに0.1より大きい値が保存されていても結果は同じで、スライダーを一度動かせば新しい上限に収まります。

### 顔補正とキャストシャドウが共存します

- `顔2D影アシスト` が顔領域からキャストシャドウを除外していた排他をなくしました。アシストをオンにすると顔だけシーンの影が消えていたのはこの排他で、今は顔にもキャストシャドウと2Dシャドウの両方が落ちます。
- 排他が隠していた正面光での自己影は、原因の側で解消しました。Built-in では顔のシャドウマップ記録を、カメラ深度の押し出しと同じ量・同じ領域・同じ条件でライト方向へ一緒に押し出し（ディレクショナルライト限定）、自己比較が構造的に成立しないようにしています。手や帽子などの外部キャスターは本来の深度を保つため、顔に正常に落ちます。URP はシャドウマップをラスタライズ位置で直接読むため、もともとこの問題はありません。
- 根拠を失ったインスペクターの警告（`顔用2Dシャドウ補正にはShadow Projectionが必要です` と、その横の `Shadow Projectionをオンにする` ボタン）を削除しました。`影の方式` で `2D影（顔補正）` を選んだときに `シャドウ投影` を強制的にオンにしていた動作もなくなり、この選択は投影マスターに触れません。

### `追加光の最終明度上限` の意味を再設計

- この値が HDR 強度のように読まれるようになりました。加算効果まで含めた**最終出力ピークの絶対上限**で、1ならブルームしきい値1に掛からない範囲までしか明るくならず、1.1ならブルームが乗ります。以前はベース色の明るさの倍率として最終色全体を押さえていたため、黒い服ではグリッターやリムが丸ごと消え、上限を上げるとシーンライトまで解放されて白飛びしていました。
- 同じ値が**加算効果に入るライト強度も制限します。** 1なら強度1まで、3なら3までがリム・バックライト・フロントライト・透過光・マットキャップ・エミッション・グリッターに反映されます。強度の大きいディレクショナルライトの下でこれらが白く飛んでいたのは、この制限で収まります。
- **保存された数値はそのままでも意味が変わったため、明るさは変わります。** 黒い服でも加算効果が見える方向へ明るくなり、強い照明の下では以前より抑えられます。`リム・追加光にも上限` をオフにすると両方の制限が解除されます。
- シーンライト自体の露出は従来どおり `最終最大明るさ` の担当です。

### 色純度の上限が10に

- SSAO に `色純度`（0〜10、既定値1）、`色の明るさ`、`色のガンマ` を追加しました。純度1は合成色を保ちます。以前の文書にある `SSAO 彩度` というプロパティ名は実際のシェーダーにはありません。
- リムライト・バックライト・フロントライト・影内部リフレクション・2Dリムライト・2D透過光の `色純度` も同じ0〜10の範囲です。0は無彩色、1は合成された色そのまま、1を超えると過彩度になります。
- 上限を広げただけなので、保存された値の意味は変わらず見た目も変わりません。

### Manager に `透明パーツの描画順`

- Manager の `外観・ベイク` タブの `3 · 詳細` に `透明パーツの描画順` が追加されました。透明パーツはカメラからの距離順に描画されますが、アバターのスキンメッシュは通常1つの大きな共有バウンズを使うため、すべてのパーツが同じ距離として報告されます。すると順序は Sorting Order の値だけで決まり、値が同じパーツ同士は順序が定まらず、リボンが服の後ろに回り込むといった問題が起きます。
- `順序が未定のパーツを検索` を押すと、距離で区別できない組み合わせを共有マテリアルごとに探し出します。一覧の ▲▼ で順序を直接指定し、上が奥・下が手前です。

### パフォーマンス距離が0のマテリアルをバリデーターが検出します

- `パフォーマンス距離 (m)` × `パフォーマンス距離倍率` が0の場合、すべての距離で最も軽いティアで描画され、深度効果・PBR・マットキャップ2層以上・追加のノーマルレイヤー・トゥーンスペキュラー・グリッター・スクリーントーンは描画されません。バリデーターがこの状態を `MING-MAT-PERF-DISTANCE-ZERO` として報告するようになりました。
- エラーではなく警告です。0は正当な作者値であり、MLC がゲーム内で倍率を下げていく側の端でもあるため、意図して0にしているマテリアルはそのままで問題ありません。そうでない場合は `マスター調整` タブの `パフォーマンス距離倍率` を上げるよう案内します。

### 18. アップロード・変換の中断復旧を強化

### エディタを起動するたびに `Startup recovery is incomplete` エラーが繰り返されていた問題

- ビルドが中断されたあとにそのマテリアルが削除されると復旧は永久に完了できないのに、ドメインリロードのたびに再試行して赤いエラーを新たに出していました。スクリプトの再コンパイルやプレイモードへの入り直しのたびに出ていたのはこれが原因です。
- 今は最初の試行はインポートの完了を待ち、プロジェクトから消えたマテリアルの記録だけを名前とともに一度整理します。3回で戻せなかった場合にのみ、どのマテリアルが残っているかと対処方法を警告1行で知らせ、その後は静かになります。ビルド・アップロード中の復旧失敗は従来どおりビルドを止めます。

### ノーマル・深度計算の精度とバックエンド不一致 4件

- ノーマルレイヤーを反転かつ最大強度で重ねたピクセルで計算があふれ、ノーマルスタックが丸ごと消えることがあった問題を修正しました。2Dシャドウと2Dリムライトが使う方向ベクトルの同じ限界も併せて修正しています。
- タンジェントがほぼ0のピクセルで BRP と URP が異なるタンジェントフレームを作っていた点と、2Dシャドウの深度配置のフォールバックが一方は前を、もう一方は後ろを向いていた点を、両バックエンドで同じ式に揃えました。
- 前の2件は half 精度を実際に使う GPU でのみ現れる予防的な修正で、後の2件は PC でも出ていた BRP・URP の結果の違いです。シェーダーコンパイルゲートで確認しており、実機レンダーでの検証は行っていません。

### `1スロット/タイル領域` ウィンドウで領域を取り消せなかった問題

### コンパイル失敗をウォームアップ完了として記録していた問題

- シェーダーバリアントをウォームアップした後にコンパイルエラーを確認します。エラーのあるバリアントは準備完了として記録せず、失敗した理由を知らせます。

### エディター再起動後も同じマスクパックを再利用

- プロジェクトに保存された元のマスクと設定が同じなら、エディターを開き直しても同じマスクパックを再利用します。既存のパックは削除も名前変更もしないため、この変更を最初に適用すると新しいパックが1つ生成される場合があります。

### アルファマスク・領域マスクを使うマテリアルのビルド用シェーダーがコンパイルに失敗していた問題

- アルファマスクや領域マスクを使うマテリアルのベイク済みプロファイルが D3D11 でコンパイルに失敗し、ビルドフックがそのマテリアルを編集用シェーダーのままアップロードしていた問題を修正しました。編集用シェーダーの全バリアントがアバターバンドルに入り、アップロードが約5分長くなっていた原因です。
- すでにアップロード済みのアバターは、再アップロードするとこの修正が反映されます。

### 変換完了ダイアログの NullReferenceException

- メッシュチャンネルを選ばずメッシュベイクをスキップした変換で、変換自体は完了しているのに完了ダイアログのタイトル生成で NullReferenceException が出ていた問題を修正しました。
