## 0.1.8 {#v018}

[固定リンク: 0.1.8 パッチノート](/changelog/0.1.8#v018)

### 主な修正と使いやすさの改善

- **初回アップロード時間** — アップロードに過度に時間がかかる問題を改善しました。ユーザー計測では初回アップロードを基準に 3～50% 速くなったと報告されており、環境によって異なります。
- **VRC ベイク後の白表示** — VRC ベイク経路で、発光レイヤーが既存のライティング結果を上書きせず現在の結果へ順番に合成されるようにしました。ベイク後のアップロードでキャラクターが白く見える問題に対応し、発光マスク、シャドウの可視性、`Normal`/`Multiply` ブレンド、マップの RGB/アルファ、表面アルファを保持します。既存の baked マテリアルに反映するには再ベイクして再アップロードしてください。
- **フォールバック経路の区別** — フォールバック発光 alias（`_EmissionColor`）を黒に固定する変更は 0.1.7 HotFix1 に含まれる別の修正です。今回の 0.1.8 修正は通常の MingToon ベイク・レンダリング経路の発光合成を対象とします。0.1.7 HotFix1 より前に作成した baked マテリアルは再ベイクして再アップロードしてください。
- **Ming Light Controller 0.1.1** — URP シェーダーが未導入の BRP 専用プロジェクトで、存在しない URP を検証してアップロードが中断される問題を修正しました。MLC はインストール済みの MingToon バックエンドだけを検証し、どちらも導入されていない場合だけエラーにします。NDMF ビルドクローン用の承認済み一時 ID はメモリ内だけで使い、元のアバターやプロジェクトファイルを書き換えません。メニューの彩度は MingToon の `Output Master Saturation` に接続します。MLC は別パッケージのため、MingToon の導入後に更新してください。
- **旧 Assets インストールが競合した場合の復旧** — 旧 Assets 方式のインストールが新しいインストーラーと競合してインストールに失敗した場合だけ、`Assets/StudioRaming/MingToon` 内に直接保存した `.mat`、テクスチャ、プリセットを先に別のフォルダーへ移し、その MingToon フォルダーだけを削除して再度インポートしてください。`MingLightController` や `StudioRaming` フォルダー全体は削除しないでください。この整理は旧 Assets インストールからの移行時に一度だけ必要で、その後の VPM 更新ごとに繰り返しません。
- **変換の安定性** — lilToon 変換で SSAO の色の純度が変わったり、発光マスクが無効になったり、マスクデータが圧縮で変化したりする問題を修正しました。
- **アップロード時のテクスチャ書き換え（オプトイン）** — 既定の `LosslessOnly` テクスチャベイクポリシーは作成済みテクセルを書き換えません。`Optimize` の `Reviewed Texture Rewrites On Build (Opt-In)` を同じグループの `Optimize On Build / Upload (Applies To Everything)` と一緒に有効にした場合だけ、アップロード直前に `Texture Layers` と `Normal Layers` を各 1 枚へ平坦化し、個別マスクを RGBA パックします。色空間、再生成ミップ、プラットフォーム圧縮によりピクセルが変わる可能性があるため、対象プラットフォームのベイク前後のキャプチャを比較してください。拡張されたパックには `Outline` タブの `Width Mask` も含まれます。
- **Manager の操作** — 更新状態と現在・最新バージョンを 2 行にまとめ、パネルの高さを以前の約 3 分の 1 にしました。同じ場所で `確認`・`更新`・`更新履歴` を使えます。
- **インストールと更新の経路** — BOOTH から入手した DLL unitypackage を初回インポートすると、追加のインストールボタンなしで必要な MingToon パッケージを自動インストールします。今回導入した VCC・VPM ベースの経路です。その後は Unity 起動時に新しいバージョンを自動確認し、未インストールかつスキップしていないバージョンの通知を表示します。通知でユーザーが「更新」ボタンを押した場合にのみインストールし、Unity が再生・コンパイル・ビルド中の場合は待機して再読み込み後にもう一度確認します。Unity を再起動しただけでは自動インストールせず、「スキップ」はそのバージョンだけに適用され、次の新しいバージョンでは再び通知します。VCC からインストールしたユーザーは、これまでどおり VCC から手動で維持・更新します。
- **既存アセットの保持** — 既存の 0.1.7 インストールとインベントリを認識し、パッケージが管理するファイルだけを更新します。既存のマテリアル・シーン・プレハブと Unity が生成した `package.json.meta` は保持されます。

### 新機能

- **カラー・プリセット** — `カラー・プリセット` パネルでシャドウ色タブ全体（バンド・色の純度・明度・カラーマップ）、リム・深度のティント、HSVG を保存して選択したマテリアルに適用できます。標準パレットは `Neutral`、`Warm Tone 1`、`Warm Tone 2`、`Cool Tone 1`、`Cool Tone 2`、`High Saturation`、`Low Saturation` の 7 種です。プリセット対象以外のテクスチャ、レンダー状態、キーワードは維持され、複数の選択マテリアルへの適用と Undo に対応します。
- **バンドとリムの色調整** — クイック設定で全体の彩度と全体の発光強度を調整し、`SSAO Color`、`Rim Shade Color`、シャドウバンドの色を直接設定できます。`Rim Shade Color` のブレンド不透明度を 0 にすると、従来どおり `1st Shadow Color` を引き継ぎます。
- **最終出力の彩度** — `Output Master Saturation` は最終出力全体に適用されます。0 はグレースケール、1 は基準値、1 より大きい値は明るさを保ったまま彩度を強めます。
- **レイヤーごとの UV 選択** — 各ノーマルレイヤーで `UV Source`（UV0～UV3）を選び、マスクは `Mask UV Source` で個別に指定できます。両方が既定の UV0 の場合、UV ルーターのバリアントはコンパイルされません。

### 変更

- **言語表示** — インストール・更新メッセージはシステム言語に合わせて韓国語・日本語・その他の言語では英語を選択し、Manager のラベルはインスペクターの言語選択に従います。
- **変換結果** — 変換したマテリアルで発光マップの RGB/アルファと発光マスクの RGBA を保持し、透明マテリアルの表面アルファブレンドも反映します。ノーマルレイヤーごとの `UV Source` とマスクの `Mask UV Source`（UV0～UV3）も引き継ぎます。

### 改善

- **シェーダーベイク** — 同一のリクエストをまとめて処理し、繰り返しベイク時の重複作業を減らしながら既存の生成結果と状態を保持します。
- **生成結果の復旧** — ベイクが中断しても不完全なファイルを残して次の生成シェーダーキャッシュを壊さないよう、復旧処理を強化しました。
- **アウトラインノーマルの安定性** — オブジェクトスケールに依存する幾何学的補正を、有限値でスケールに依存しない処理に置き換え、退化したジオメトリや非有限値には作成方向のフォールバックを使います。

### ドキュメント

- Manager の `更新履歴` から最新のローカライズ済みドキュメントを開けます。現在のバージョンと最新バージョンも同時に確認できます。

### 旧バージョンからの更新

プロジェクトをバックアップし、`Assets/StudioRaming/MingToon` 内に直接保存した自作マテリアル・テクスチャ・プリセットを別のフォルダーへ移してください。旧 Assets 方式のインストールでは、その MingToon フォルダーだけを削除してから新しいインストーラーをインポートします。`MingLightController` や `StudioRaming` フォルダー全体は削除しないでください。この整理は旧方式からの移行時だけに必要で、その後の VPM 更新ごとに繰り返す必要はありません。
