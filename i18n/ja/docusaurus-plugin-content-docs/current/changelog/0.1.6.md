*クローズドベータ・2026-08-09*

## アップグレード時の確認事項

:::caution[VRChat アバターの再アップロードが必要]
**このアップデート後、VRChat アバターを再アップロードして修正を反映させる必要があります。** シェーダーはアバター アセット バンドルに含まれているため、既にアップロード済みのアバターは古いシェーダーを使い続けます。
:::

## バグ修正

- **アップロード最適化の欠陥でアバターが真っ白になる現象がなくなります** — アップロード最適化（ベイク）時に無効化されたモジュールが強制的にオンになっていた欠陥を修正しました。以前は `エミッションを使用` をオフにしても既定の白いマップで全体が発光したり、`2D シャドウマスク` のようなモジュールがオフのままなのに動作する現象が起こっていました。これが鏡やポストプロセスのないカメラでアバターが「真っ白に光る」という報告の根本原因でした。→ [ドキュメント](/workflow/build-optimization)
  - 既に生成されたベイクシェーダーは再生成されるため、この修正を適用させるには **アバターを再アップロードする必要があります**。
- **鏡の中で深度エフェクトが正常化されます** — VRChat 鏡の中で `2D シャドウ` と `深度リム` がプレイヤーが頭を動かすたびに体に追従せずスリップしていた問題を修正しました。→ [ドキュメント](/guides/depth-effects#플랫폼별-깊이-확보)
  - 鏡カメラは自分の深度テクスチャをレンダリングしないのに、プレイヤーカメラの深度バッファが常にバインドされているためシェーダーが他人のシルエットを読んでいました。これからは鏡の中では深度関連モジュールが自動的に下がります。
  - `深度可用性` の意味が少し変わります。`Force On` は これからは「ホストが報告できない場合まで有効にする、**ただし鏡は除く**」を意味します。
- **無光ワールドと Disable Pixel Lights 鏡でコントラストが正常になります** — リアルタイム平行光がないワールドや Disable Pixel Lights 鏡でアバターのコントラスト構造が崩れて蒼白に見える問題を修正しました。
  - これからはアンビエントプローブからキーライト（方向と色）を合成して、どこでも正常なシェーディングを維持します。平行光があるワールドでは変化がありません。
- **lilToon 変換が移してきたデータのトグルがオンになるようになりました** — lilToon の `PBR サーフェスを使用`、`エミッションを使用`、`サーフェススタックを使用`、`アウトラインマスター`、`クラシックハル` トグルがオンになっていたマテリアルを変換するときに、値は受け取ったのにモジュールがオフのままになっていた問題を修正しました。→ [ドキュメント](/workflow/liltoon-conversion)
  - lilToon の `_UseReflection`（反射）がオンになっていれば MingToon の `PBR サーフェスを使用` もオンで出力されます。エミッションテクスチャなしで色だけで発光していたマテリアルも正確に再現されます。スタックの 2 段・3 段レイヤーデータも受け取ります。アウトラインは方向と太さを正確に受け取ります。
  - `ハル太さ` の既定値もアーティストが設定した値を受け取ります。lilToon ではアウトラインがなかったマテリアルまで太さ 1 でオンになる現象がなくなります。
- **`法線ソース` を `VertexColorTS` に設定するとアウトラインが正常になります** — アウトラインの `法線ソース` を `VertexColorTS` に選びながらメッシュに頂点カラーがないときアウトラインが対角線方向に全体的にずれていた問題を修正しました。これからはメッシュ法線に下り、ツールチップの説明どおり動作します。→ [ドキュメント](/guides/outline#노멀-아웃라인)
- **接線のないパーツ 1 つが顔・高さベイクまで壊していたのが修正されます** — 変換中にメッシュに接線や法線がない場合アウトライン、顔、高さの 3 段階が一度に失敗していたのを修正しました。これからはそのレンダラーだけをスキップしてどのメッシュかをコンソールに知らせます。
- **複数のレンダラーが共有していたメッシュがベイクで正しく統合されます** — 同じメッシュを N 個のレンダラーが共有しているときベイクが複製 N 個を別々に作っていたのを修正しました。これからはソースメッシュごとに 1 つのアセットを作り、すべてのレンダラーがそれを共有します。
- **変換がユーザーモデルの UV8 を確認なしに上書きしていたのが修正されます** — 変換が元のモデルの UV8 を `既存チャンネルの上書き` オプションと関係なく削除していました。オプションがオフの場合は これからはスキップして報告します。
- **アウトラインUV8ベイクが既にベイク済みのキャラクターを拒否しなくなりました** — サブメッシュの 1 つでも UV8 を持つとキャラクター全体が失敗していたのを修正しました。これからは MingToon がベイクした UV8 はスキップし、ユーザーモデルの元の UV8 だけを拒否して、どのメッシュかを名前で知らせます。→ [ドキュメント](/guides/mesh-bakes#아웃라인-스무스-노멀-uv8)
- **`Unified Shadow Color Map` トグルすべてのモードで動作するようになりました** — `Unified Shadow Color Map` をオフにするとこれからはどのコンパイルモードでも確実にオフになります。以前は広域コンパイルモードがオンになっていると この行が動作しない場合がありました。
- **ワールド制作プロジェクトへのインポートがコンパイルエラーで壊れる問題を修正** — アバター SDK のない VRChat ワールドプロジェクトに MingToon や変換済みアバターを入れると、`VRCExpressionsMenu` のコンパイルエラー（CS0246）でプロジェクト全体が壊れていた問題を修正しました。エクスプレッションメニューのインストーラーはアバターアップロード専用機能のため、ワールドプロジェクトでは自動的にコンパイル対象から除外されます。
- **マテリアルを選択するとアウトラインだけが見える現象が根本的になくなります** — Unity 2022 プロジェクトでマテリアルを選択または編集するとベースが消えてアウトラインだけが残る現象の根本原因を見つけて修正しました。コンパイルをいくら待っても再発していた環境でも、これからは表示されません。→ [ドキュメント](/guides/texture-modules#마스크-세부-설정)
  - これを実現するためにレイヤーマスク（サーフェススタック・ノーマル・マットキャップ）が内部的に統合テクスチャに自動合成されます。マスクをスロットごとに配置する使用法とチャンネル選択・反転・リマップなどすべての調整値は変わらず、GPU が読むテクスチャ数が削減されてレンダリングも軽くなります。合成版は `MingToonGenerated/MaskPacks` フォルダに自動生成・共有されるため、直接管理する必要がありません。
- **変換するときに選択したルックプリセットがそのまま適用されます** — プリセットを選んでも最初の変換でリスト上部のプリセット（ハード トゥーン）が適用される問題を修正しました。スクリプト再読み込みやオブジェクト再選択後も選択したプリセットが保持されます。
- **ルックプリセットが変換で移してきたレイヤーコンテンツに触れません** — 変換が移してきたマットキャップ・ノーマルレイヤー・サーフェススタックがルックプリセット適用と一緒に無効になったり、合成モードが全て `Add` に変わったり乗算マットキャップが光るという問題を修正しました。→ [ドキュメント](/workflow/character-manager#1--변환)
  - ルックプリセットは これからは影・リムのような「ルック」だけを扱い、キャラクターが持つレイヤーコンテンツ（有効性・合成モード・強度を含む）はそのままにします。対応するタブ用に保存したタブプリセットだけがその値を変更できます。
- **VRChat ビルドフック登録ログが実際に表示されます** — マニュアルで案内された `[MingToon] VRChat build hook compiled and registered.` 確認ログがユーザー環境で表示されない問題を修正しました。これからはエディターセッションごとに 1 回コンソールに表示され、アップロード最適化フックが生きているかすぐ確認できます。→ [ドキュメント](/workflow/build-optimization#제대로-걸렸는지-확인하기)

## 作業体験 — コンパイル待ちの解消

- **インスペクタートグルがもはやシェーダーコンパイルを待ちません** — `グリッターマスク使用`、`マスク使用`（シャドウリフレクション）、`2D シャドウマスク`、`深度リムマスク`、`内部エッジマスク`、`エリアマスク使用`、`2 次シャドウ使用` など、インスペクターの 7 個のトグルをオンにしてオフにするときにインスペクターが止まっていたシェーダー再コンパイル（トグルあたり 2～6 秒）がなくなりました。
  - レイヤードロップダウンも同様です。コンパイル待機なしにすぐに値を変更できます。
  - `Base Tint After HSVG` 行も同様です。キーワードの代わりに float 分岐で制御するようになったため、トグルの瞬間にすぐ適用されます。
  - `Face Shading Module` トグル（顔／通常の役割切り替え）も他のトグルと同様、再コンパイルなしで即座に適用されます。
  - オーサリングシェーダーで関連キーワードは常にオンのままで、実際の on/off は float 値で決定されるため、描かれる画像はまったく変わりません。インスペクター既定値とベイク動作も同じです。
  - このため `Compile All Modules While Authoring` 設定が既定でオンに変わりました。最初にオンになるときコンソールに 1 行のお知らせが表示され、望まなければ MingToon インスペクターの一括編集パネルで無効にできます。オンのまま構築・アップロードしても不要なキーワードは自動的にクリーンアップされるため、成果物に負担がかかりません。
- **シェーダーコンパイルがパッケージのインストール時に一度に完了します** — パッケージをインポートするとインストールコンパイルが直ちに実行されます（キャンセル可能な進捗バー表示）。並列コンパイルで初めてのインストールが数分で完了し、その後の変換・マテリアル選択・編集中にコンパイルウィンドウが表示されたりアウトラインだけが見える待機区間がありません。「待機はインストール時に 1 回」がこのバージョンのコンパイルモデルです。
  - 変換結果が使う組み合わせ（カットアウト、マットキャップ・ノーマル・スタックがオンの状態を含む）までがインストール時点で事前にコンパイルされます。マテリアルを選択しても描く組み合わせが変わらないよう保存状態と表示状態が常に一致します。
  - ウォームアップ状態は `Library/StudioRaming/MingToon.warmup` に記録されます。シェーダーソースや Unity バージョン、グラフィックス API が変わると自動的に無効化されて再コンパイルされ、キャンセルされた地点から次の実行が引き継がれます。
  - 手動メニューも維持されます。`Tools > Studio Raming > MingToon` の `Warm up shader variants`（インストール計画）、`Warm up selected materials`、`Verify warm-up`、`Warm-up status`、`Measure warm-up cache effect`。
- **変換の進捗状況がステップごとに表示されます** — 変換ボタンを押した後「Hold on (busy)」だけが表示されていた区間にステップごとの進捗バー（マテリアル変換 → ルックプリセット → メッシュベイク）が表示されます。
  - 変換完了時にステップごとの所要時間がコンソール 1 行で記録され、変換が遅い場合どのステップが原因かすぐ確認できます。
- **アウトラインUV8ベイクが必要なときに知らせ、範囲と結果を事前に明記します** — `法線ソース` が `UV8TS`（既定値）なのにメッシュに UV8 がない場合、MingToon Manager の最上部に警告メッセージとベイクボタンが表示されます。条件に合わないキャラクターには何も描かれません。→ [ドキュメント](/guides/mesh-bakes#아웃라인-스무스-노멀-uv8)
  - ベイクボタン上に「どこに新しいメッシュを作り、元の FBX は変更せず、何個のレンダラーを処理するか」を表示します。結果メッセージには接線がなくてメッシュノーマルで残る頂点数も報告します。
- **プロジェクト全体のマテリアルキーワード整理メニューが追加されます** — `Tools > Studio Raming > MingToon > Heal Material Keywords (Project)` メニューが新しくできました。プロジェクトのすべての MingToon マテリアルの保存済みキーワードとパス状態をインスペクター値と一致させます。実行前に確認後、変更ファイルは `TempBackups/MingToonKeywordHeal/` にバックアップされ、キャンセルできて、結果はコンソール 1 行に記録されます。

## 機能の追加・削除

- **VRC Light Volumes ワールドの間接光を読みます（既定はオフ）** — `VRC ライトボリューム` という新しい行が追加されました。VRC Light Volumes を使用するワールドでアバターの `間接光補正` とシャドウティントが Unity プローブの代わりにルームの Light Volume に従うようになります。Built-in シェーダーにのみ適用されます。
  - 既定値はオフです。オンにしても Light Volume がない環境ではプローブに戻るため、どこでも画像が変わったり壊れたりしません。
- **`深度可用性` に診断モードを追加** — `深度可用性` に `Diagnostic` という 4 番目の選択肢が追加されました。VRChat で深度エフェクトがアバター全体に広がる現象を報告するときに、このモードでシェーダーが実際に読む深度テクスチャを単色で塗って診断できます。→ [ドキュメント](/guides/depth-effects#플랫폼별-깊이-확보)
  - 色判読表は以下のとおりです。黒は深度テクスチャなし、赤はテクスチャがあるが画面のバッファが異なる（サイズが異なるか鏡）、黄色はあってサイズも正しい、青チャンネルはホストが直接深度可用を報告することを意味します。このモードは **バグ報告時のみの診断用** なので、一般的な使用には適していません。
- **一括編集パネルにシャドウカラーマップ 2 行が追加されます** — `シャドウカラーマップを使用` と `カラーマップ適用量` の 2 行が一括編集パネルに表示されます。一般的なインスペクターでは既に描かれていたものが一括編集にも追加され、複数のマテリアルを選択して 1 度にこれらの値を設定できるようになります。→ [ドキュメント](/guides/bulk-editing#일괄-설정-패널)
- **Missing Depth Fallback（フレネル フォールバック）機能が削除されます** — 深度がないとき `深度リム` がフレネルリムに自動フォールバックされていた機能が削除されました。深度モジュールは これからは深度データがなければ静かに無効になるようになります。Fresnel Rim を使っていたマテリアルはその対応するリムが消えます。→ [ドキュメント](/guides/depth-effects#깊이-림-2d-림)
- **アウトラインがはるかに軽くなります** — アウトライン（クラシック ハル）のピクセルコストが約 1/3 に削減されました。アウトラインは これからはベースマップの色と照明応答だけで描かれ、本体のシャドウパターン・投影された影・深度エフェクトをアウトライン上に再び描きません。→ [ドキュメント](/guides/outline#아웃라인-색이-조명을-따라가게)
  - `Outline Include Shading` は維持されますが動作が変わります。オンにすると本体のフォームシャドウ色に従う軽いコントラストバンドがアウトラインに適用され、以前のように本体シェーディング全体を複製することはありません。太いアウトラインのコントラスト印象は維持しながらコストだけ下がります。
