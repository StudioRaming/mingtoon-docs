*0.1.7 ホットフィックス1 · 2026年9月7日 · パッケージバージョンは0.1.7のまま*

## 一行まとめ

顔プロキシ・ステンシル・フォールバック発光・ビルドのブロックを修正した0.1.7の再配布です。

:::warning[アップデート前の確認]
- 入手方法: 同じ0.1.7のパッケージを再度ダウンロードして上書きするだけです。
- 再アップロード: `エミッションを使用`が有効なマテリアルを使うアバターのみ、再アップロードしてください。
- そのマテリアルは再変換するか、Managerの`フォールバックプロパティを同期`を一度押してください。
- 再変換: ステンシルを使うlilToon変換マテリアルは、再変換するかステンシルの値を手動で戻してください。
- 顔プロキシは上書きするだけで済みます。シーンを開けばすぐ反映されます。
:::

:::info[ホットフィックスの読み方]
バージョン番号を上げずに、同じパッケージを再度公開した修正です。
何次まで含まれているかは、パッケージ内の`Docs/PATCH_NOTES_0.1.7.md`で確認します。
:::

:::note[現在は]
0.1.7当時のインストール先は`Assets/StudioRaming/MingToon`でした。
0.1.8からは`Packages/com.studioraming.mingtoon`です。 → [インストール](/getting-started/installation)
:::

## 修正された問題

- 顔プロキシを調整しておくと、シーンの保存・再生・リロードのたびに元のノーマルへ戻る問題。
- これからは編集マテリアルで、シェーダーがプロキシのノーマルを直接計算します。リアルタイムとベイクが同じ式です。
- Root BoneのあるSkinned Mesh Rendererで、`プロキシ領域マスク`の中心が顔からずれる問題。
- アウトラインのないlilToonマテリアルを変換すると、アウトラインだけがステンシルマスクを無視する問題。
- 前髪の間から透けるようにした目が、表面は透けるのに線だけ髪に隠れていました。
- これからは、元にアウトラインがなければ、アウトラインが表面のステンシル値を引き継ぎます。
- フォールバックシェーダーに落ちたアバターが、アウトラインだけを残して白く表示される問題。
- フォールバック用の発光色は、これからは常に黒です。MingToonシェーダー自体のエミッションはそのままです。
- NDMFアバターを一度ビルドすると、すべてのVRChatビルドが`Material recovery is incomplete`でブロックされる問題。
- これからはマテリアルの消失を実際のファイルの有無で判定し、残った記録は次回の復元時に整理します。
- 変換直後に適用されるファクトリールックプリセットが、元のステンシル値を0に戻す問題。
- ステンシルの2ユニット（表面・アウトライン、14項目）は、これからはプリセットに保存も適用もされません。

## 既知の制限

- ビルドがブロックされていたプロジェクトは、上書き後にエディターを一度再起動すると整理されます。
- 新しい次数が出ると、このページの最上部に追加されます。
