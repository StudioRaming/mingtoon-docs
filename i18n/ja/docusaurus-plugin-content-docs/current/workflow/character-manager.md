# MingToon マネージャー

**このドキュメントを読むと** アバター1体を最初から最後まで — 変換・ルック・メシュベイク・最適化・アップロード点検 — 1つのコンポーネントで行えます。

マテリアル1つずつではなく **アバター単位の作業** はすべてここで行います。

## 装着

変換するキャラクターの **ルートオブジェクト** を選択して

`GameObject > Studio Raming > MingToon > Add MingToon Manager`

Add Componentから `MingToon Manager` を探して装着することもできます。**ルートに装着してから変換を進めてください。**

## インスペクター構成

| ステップ | 実行する処理 |
|---|---|
| **1 · 変換** | 別のシェーダー → MingToon、顔/肌の判定、メッシュチャンネルのベイク |
| **2 · セットアップ** | 対象範囲、エディターランタイムプレビュー、ランタイム顔方向 |
| **3 · 詳細設定** | 個別メッシュベイク等 |
| **ルック / 顔** | ルックプリセットの適用 |
| **最適化 / ベイク** | 軽量シェーダーのベイク |
| **書き出し / 検証** | アップロード準備点検・VRChat事前チェック・Quest点検 |

上部には **よく使う機能** と **ステータスパネル** が常に表示されます。

## ステータスパネル {#상태-패널}

マネージャーを開くと現在のステータスが最初に表示されます。`更新` で再度スキャンしてください。

| 表示 | 意味 |
|---|---|
| `MingToon N · 変換可能 N · 変換除外 N · その他 N` | マテリアル構成 |
| `シェーディング状態` — `編集用 N · ベイク済み N` | どのマテリアルがベイク済みか |
| `顔スロット` | 下記を参照 |
| `ビルド・アップロード時に自動最適化` | フックが有効か |
| `最適化範囲` | 下記を参照 |

:::danger[顔モジュールのキーワードがずれていた場合]
`顔スロット N個中、M個の顔モジュールキーワードがマテリアル値とずれています。この状態でベイクすると顔シェーディングが失われます。`

`顔モジュールを同期` ボタンを押すと修正されます。**ベイク前に必ず解決してください。**
:::

:::caution[最適化範囲が古い場合]
`最適化範囲がレンダラー N個中 M個だけです。キャッシュが古いため、残りは最適化なしでアップロードされます。`

衣装を付けたり外したりした後は、`子レンダラーを再検索` を押してください。
:::

## 1 · 変換 {#1--변환}

### どのシェーダーから移行できるか

**lilToon マテリアルが最も完全に移行されます。** Standard、URP Lit等の別のシェーダーからも変換できますが、この場合ベースカラー・テクスチャ・法線・エミッション・オクルージョンとレンダ状態が移行され、残りはMingToonの既定値になります。

インスペクターがどのルールで読み込むかが表示されます — `元スキーマ: lilToon` または `元スキーマ: Unity標準マテリアル規則`。

### 変換されないスロット {#변환되지-않는-슬롯}

一部のマテリアルは **意図的に手を付けずに元のまま保ちます。**

| カテゴリー | |
|---|---|
| パーティクル / VFX | 屈折 / 宝石 |
| ファー / シェル | オーディオ連動 |
| フリップブック / スクロール / 時間アニメーション | アウトライン専用 / オーバーレイ / 補助パス |

MingToonがそのまま移行できない表現だからです。ステータスパネルの `変換除外` 数で確認できます。

:::caution[すべてが除外対象の場合はボタンは何もしません]
`読み込めるスロット N個がすべて変換除外対象です。` が表示される場合、変換ボタンを押しても変わりません。
:::

### 顔・肌の指定 — 最も重要なステップ {#얼굴--피부-지정--가장-중요한-단계}

:::danger[Autoは名前で推測しません]
`Auto` は **元のマテリアルが直接持つ顔フラグのみ** を読みます。

したがって **フラグのないシェーダーから変換すると、すべてが `Regular` のままになります。** 顔に使うスロットは **直接 `Face` に指定する必要があります。**
:::

スロットごとに `Auto` / `Face` / `Skin` / `Regular` を固定できて、1つのレンダラー内の顔・目・まつげも個別に指定できます。プレビューに `顔シェーディング` · `肌ルック` · `通常シェーディング` のどれが適用されるかが表示されます。

レンダラー単位で一度に指定することもできます。

- `顔Rendererを直接指定`
- `肌Rendererを直接指定` — ここに指定したレンダラーのマテリアルはルックプリセットの **肌値** を受けます。**素肌専用** です。
- `指定したRendererに役割を付与`

:::caution[服と髪が同じレンダラーにある場合]
肌レンダラーとして指定すると、服も肌値を受けます。変換後、スロット別一覧で **服スロットを `Regular` に戻してください。**
:::

:::note[MingToonマネージャーを複数選択した場合]
スロット別の判定は無効になります。**一度に1つだけ** 選択してください。
:::

### 変換時のルックプリセット

変換と同時にルック値を埋めます。

:::danger[プリセットは約500個の値を上書きします]
`プリセットは変換直後のマテリアルの数値と色約500個を一度に上書きします。変換前に編集した値がある場合は、適用しない を選んでください。`
:::

顔と判定されたマテリアルには顔用、肌と判定されたマテリアルには肌用、その他には共通値が入ります。SDFフレーミング・ベイク結果・テクスチャ有無のように **キャラクターごとに異なる値はプリセットに含まれません。**

`このエディターで最後に適用したプリセット` が表示されるため、後で何を適用したか確認できます。

### 同時にベイクするメッシュチャンネル {#함께-구울-메쉬-채널}

変換直後、チェックされたチャンネルが自動的にベイクされます。

| チャンネル | 何のために |
|---|---|
| `アウトライン平滑ノーマル (UV8)` | 角張った部分でアウトラインが途切れないように |
| `顔フロントビューノーマル (UV7)` | 顔の影が鼻・眉上で汚れないように |
| `キャラクター高さグラデーション (UV4)` | 高さベースの色グラデーション |
| `使用中のUVチャンネルを上書き` | **再変換する時だけ** オンにしてください |

既定値のままで変換すると自動的にベイクされます。→ [メッシュUVベイク](/guides/mesh-bakes)

:::caution[UV7は2つで共有できません]
`UV7は顔ノーマルベイクと顔SDF投影で一緒に使われます。どちらか1つだけが所有できるため、SDFを使う予定ならば顔ノーマルベイクはオフにしてください。`
:::

`UVチャンネルの使用状況` に `UV4 · UV7 · UV8` がそれぞれ空いているか使用中かが表示されます。

### 復旧

`元のマテリアルを復元` は **現在のスロットだけ** を元のマテリアルに戻します。変換されたマテリアルやメッシュUVベイクは削除しません。

:::caution[復元は1段階のUndo分です]
元に戻すと、**直前に直接編集した内容まで一緒に消える可能性があります。**
:::

`変換ペアを検査` で変換されたマテリアルと元の対応を確認できます。元の記録がないマテリアルはプロジェクト全体を調べるため時間がかかるので、**ボタンを押したときだけ** 実行されます。

## 2 · セットアップ

| 項目 | 実行する処理 |
|---|---|
| `対象範囲` · `非アクティブを含む` | ここまでをこのキャラクターと見なすか |
| `子レンダラーを再検索` | 衣装を変更した後に実行 |
| `すべてのMingToonマテリアルを選択` | [一括編集](/guides/bulk-editing)に渡す |
| `顔＋肌のみ選択` · `共通のみ選択` | 役割別に選んで選択 |

### エディターランタイムプレビュー

:::caution[VRChatに実装されません]
`このグループはエディターやWarudoのようにスクリプトを保持する環境でのみ動作します。VRChat アップロード時はこのコンポーネントが削除されるため、ここで作った結果はアバターに実装されません。`
:::

`ルックプロファイルを使用` · `編集モードでもプレビュー` · `ルックプロファイル`

### ランタイム顔方向

`頭の向きを送出` をオンにすると、頭ボーンの向きがシェーダーに渡され、顔シェーディングが頭に追従します。

- `頭ボーン` — 空欄の場合は自動判定
- `頭の軸を自動判定` · `頭のローカル前方` · `頭のローカル上方`

:::note[Warudoへのエクスポート時は別のコンポーネントが必要です]
この設定はエディター・Warudo環境用です。**Warudoモードでビルドするときは、`WARUDO Runtime Root` を別に装着する必要があります。** → [Warudo](/platforms/warudo#내보내기-전-필수--warudo-runtime-root)
:::

## 3 · 詳細設定

`個別メッシュベイク` — 1段階の変換のチェックボックスをオフにしたか、そのベイクが失敗した場合だけ必要です。既に埋められたチャンネルには、`上書き` をオンにしない限り拒否します。

`キャラクター高さUV4` · `アウトライン平滑ノーマルUV8` · 顔フロントビューノーマルを個別に実行できます。→ [メッシュUVベイク](/guides/mesh-bakes)

## ルック / 顔

変換されたマテリアルにルックプリセットを適用します。

まだ変換前の場合、`まだMingToonマテリアルがありません。2段階の変換を先に実行すれば、ここでルックプリセットを適用できます。` が表示されます。

### 顔SDF

`正面SDF TEXCOORD6 (Unity UV7)ベイカーを開く`

:::note[別パッケージです]
`Face SDF Bakerがインストールされていません。` が表示された場合、Studio Ramingの **別のエディターパッケージ** をインストールする必要があります。
:::

→ [顔SDFオーサリング](/guides/face-sdf)

## 最適化 / ベイク

:::tip[ほとんどの場合スキップできます]
VRChat アップロード と Warudoモードビルドでは、[ビルド時の自動最適化](/workflow/build-optimization)が自動的に機能し、マテリアルは編集可能な状態のままです。
:::

`軽量シェーダーベイク（エディター専用）` · `アニメーション可能パスを保持（安全）`

:::caution[テクスチャ再書き込みは2か所に分かれています]
`下のチェックはこのパネルから直接実行するベイクにのみ適用されます。` アップロード時に自動で実行される側は `アップロード時もテクスチャ再書き込み（オプトイン）` で、`Tools > Studio Raming > MingToon` メニューから復元できます。
:::

→ [手動ベイクと復元](/workflow/bake-and-restore)

## 書き出し / 検証 {#내보내기--검증}

### アップロード準備の点検 {#업로드-준비-점검}

`準備状態を検査` — 階層とManifestを両方調べるため、**ボタンを押したときだけ** 実行されます。

結果は `アップロードを妨げる問題はありません。警告 N件。` または `アップロードを妨げるエラーが N件あります。` で出力されて、検査範囲（`レンダラー・マテリアル・編集用・ベイク済み`）が一緒に表示されます。各項目の `位置` ボタンで対応するオブジェクトをすぐに見つけられます。

主要な診断項目:

| 分類 | 項目 |
|---|---|
| **ベイク** | ベイクManifestがない・Manifestに記録がない・古いGeneratorバージョン・ベイク後に元が変わった・ベイクの元マテリアルが見つからない |
| **ベイク文脈** | キャラクター依存追跡の古いバージョン・ベイク後にアニメーションまたはルックプロファイルが変わった・ベイク時のマネージャーが見つからない |
| **生成シェーダー** | なし・記録と異なる・コンパイルエラー |
| **コンポーネント** | MingToonランタイムコンポーネントがある・スクリプトが失われたコンポーネントがある |
| **顔SDF** | SDF用UVがない・SDFテクスチャがない・準備済みだが顔モジュールがオフ |
| **その他** | ホストの深度テクスチャが必要・古い名前にバインドされたアニメーション |

`プロジェクト設定を検査` で [プロジェクトを検証](/reference/validator) もここで実行できます。

:::note[深度昇格のお知らせ]
`アップロード時、マテリアル N個の深度使用が Autoから強制的にオンに変わります。VRChat アバターではAutoは決してオンにならないためです。` → [ビルド時の自動最適化](/workflow/build-optimization#vrchat-깊이-자동-승격)
:::

### VRChat 事前チェック

`ルールバージョン・検証済みUnity` が表示されて、以下を検査します。

- **不足している標準プロパティ** — フォールバックが値を引き継ぐために必要です。`フォールバックプロパティを同期` で更新できます。
- **VRChatが許可しないコンポーネント** の数

→ [VRChat互換性ルール](/internals/vrc-rules)

### Quest / Android

`MingToonはQuest（Android）ビルドをサポートしていません。` Quest向けのバリアントを作る予定なら、**下の機能はすべて欠落していると考えてください。**

`Questで失われる項目` — `アウトライン N・半透明 N・深度エフェクト N` で実際の数を数えてくれます。

### スクリプト除去点検

:::danger[MingToonコンポーネントを直接削除しないでください]
`MingToonランタイムコンポーネントはVRChat アップロードで自動的に削除されるため、直接削除しないでください。このマネージャーを削除するとキャッシュされたレンダラー一覧が消えて、アップロード最適化がその範囲を失います。`

Warudoモードはスクリプトを保持 する別のルールに従います。このパネルは検査するだけです。
:::

## フロー全体のまとめ

```text
ルートにMingToonマネージャーを装着
        ↓
1 · 変換      顔/肌スロット指定 → ルックプリセット → UV8/UV7/UV4を同時にベイク → 変換
        ↓     損失レポートを読む
2 · セットアップ      衣装を変えたらレンダラーを再検索
        ↓
ルック / 顔     マテリアル別にルックを調整（ルック作成ドキュメント）
        ↓
最適化        通常スキップ — ビルド時の自動最適化で十分
        ↓
検証          準備状態を検査 → VRChat事前チェック → アップロード
```

Warudoにエクスポートする場合、ここに [WARUDO Runtime Root](/platforms/warudo#내보내기-전-필수--warudo-runtime-root) ステップが追加されます。
