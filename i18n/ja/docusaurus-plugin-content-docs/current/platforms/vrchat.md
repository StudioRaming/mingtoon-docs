# VRChat

**このドキュメントを読むと、** VRChat PC アバターに MingToon をアップロードする手順と、深度効果がどこまで保証されるのかが分かります。

VRChat PC は MingToon の **主要なターゲット** です。

:::caution[現在の状態]
クローズドベータ基準では、VRChat PC は **手動検証対象であり、リリース認証は完了していません。** アップロード前に以下のチェックリストを直接実行してください。

VRChat **Quest** は MingToon の直接的な実行対象ではありません。→ [対応環境](/platforms/compatibility#vrchat-quest)
:::

## Unity バージョン

:::danger[2022.3.22f1]
現行 VRChat SDK の基準です。MingToon の VRChat ビルドフック と VRChat ランタイムは `UNITY_2022_3_OR_NEWER` 条件下でのみコンパイルされるため、**2021.3では、このコードはまったく存在しません。** アップロードはされますが、自動最適化も深度昇格も適用されません。

Warudo 用の 2021.3.45f2 プロジェクトと **同じプロジェクトを使用することはできません。** ターゲット別に分けてください。
:::

## アップロード チェックリスト

1. **ビルド フック確認** — スクリプト リロード後、Console に `[MingToon] VRChat build hook compiled and registered.` があることを確認します。ない場合、最適化はまったく適用されません。
2. **アップロード準備確認を実行** — MingToon マネージャーの `準備状態チェック`。→ [準備状態チェック](/workflow/character-manager#내보내기--검증)
3. **アップロード** — [ビルド時の自動最適化](/workflow/build-optimization)が自動的に適用されます。**手動ベイクは不要です。**
4. **SDK Builder で最終検証**
5. **インゲーム確認** — 自分の画面・ミラー・Photo Camera を **それぞれ** 確認します。

## MingToon コンポーネントは削除しないでください

:::danger[直接削除すると最適化範囲が失われます]
MingToon ランタイム コンポーネントは **VRChat アップロード時に自動的に削除されます。** 手動で削除する必要はありません。

**MingToon マネージャーを削除すると、キャッシュされたレンダラー リストが一緒に失われ、アップロード最適化がその範囲を失います。** 最適化されない材質がそのままアップロードされます。
:::

MingToon 以外のスクリプトが残っている場合、それはクリーンアップの対象です。MingToon マネージャーの `VRChat 事前チェック` が **VRChat が許可していないコンポーネント** を数えて、通知します。

:::note[Warudo は反対です]
Warudo モードは **スクリプトを保持する** 別のルールに従います。→ [Warudo](/platforms/warudo#스크립트-정책이-vrchat과-다릅니다)
:::

## 深度効果がどこまで保証されるか {#깊이-효과가-어디까지-보장되나}

深度リム・2D シャドウ・内部 2D 境界は、カメラ深度テクスチャを読み取ります。VRChat ではこれは **ワールド権限** です。

| 状況 | 深度 | 根拠 |
|---|---|---|
| **Photo Camera 有効時** | ✅ | 公式契約。ホストが `_VRChatCameraMode` を 0 以外の値で渡します |
| **ワールドが Screen Camera depth を有効にしている場合** | ✅ | ワールド/Udon が `VRCCameraSettings` でリクエスト |
| **通常プレイヤー画面 (デフォルト)** | ❌ | アバターは強制できません |
| **ミラー・ストリーム・handheld preview 内部パス** | ⚠️ | 同じ結果は保証されません |

:::danger[深度を有効にする正規の経路はワールド側です]
Screen Camera 設定はワールド/Udon 側の権限です。アバターがこの設定を変えることはできません。
参考: [VRC Camera Settings (公式ドキュメント)](https://creators.vrchat.com/worlds/udon/vrc-graphics/vrc-camera-settings/)

アバターにライトを載せて深度パスを誘発する**オプトインの回避策**はありますが、コストを負担するのは他人です。下を読んだうえで判断してください。 → [VRChat 深度ライト](#vrchat-깊이-라이트)
:::

### VRChat 深度ライト (デフォルト オフ) {#vrchat-깊이-라이트}

VRChat ではアバターがカメラ設定を変えられないため、深度を読む画面エフェクト（`2Dデプスリム` · `2Dデプスシャドウ`）が写真カメラ以外で消えます。**アバターにライトを1つ実装すると**、カメラが深度を描画するようになり、これらのエフェクトがオンになります。

MingToon マネージャーの `VRChat 深度ライト` グループで `アップロード時に深度ライトを載せる`をオンにすれば大丈夫です。**デフォルト値はオフです。**

- オンにすると、**VRChat アップロード本にのみ**ライトが1つ追加されます。シーンと Warudo ビルドはそのままです。
- マテリアルの`深度の可用性` 値は変わりません。`Auto`がみずから深度を見つけます。 → [深度の可用性](/guides/depth-effects#깊이-가용성)

:::danger[コストを先に読んでください]
1. このライトは、**あなたを見ているすべての人のフレーム**で、ワールド全体を1回分多く描く深度パスを追加します。コストはあなたではなく、その人たちが払います。
2. **ミラーの中では動作しません。** ミラーに映る深度は別のカメラのものなので MingToon がわざと消します。
3. VRChat の**アバター安全設定がこのライトをオフにする可能性があり**、そうなるとエフェクトも一緒に消えます。
4. ライトが1つ増えて**アバター パフォーマンスランクが下がり**、ピクセルライトの枠を1つ占めてワールドの実際の照明が押し出される可能性があります。
:::

オンにしないのがデフォルト値である理由がここにあります。深度なしでもシルエットが立つようにする方を先に検討してください。

### ビルド時に自動的に処理されること {#빌드-시-자동으로-처리되는-것}

アバター アップロード時に、MingToon は `Depth Availability` が `Auto` である材質を `Force On` に昇格させます。

`Auto` は「ホストが深度があると言ったら信じる」という意味ですが、そう言う `MingDepthTextureProvider` が `IEditorOnly` であるため、アップロード時に削除され、VRChat ではその信号は決して到達しません。昇格がないと、**深度が実際にあるワールドでも 2D 効果が消えます。**

`Force On` / `Force Off` で直接指定された値は上書きされません。

:::note[昇格されてもミラーは例外です]
`Force On` は「ホストが報告できない場合までオンにする、**ただしミラーは除外**」を意味します。ミラーカメラは自分の深度を描画しないため、その中では深度モジュールが自動的に下がります。 → [深度の可用性](/guides/depth-effects#깊이-가용성)
:::

詳細: [ビルド時の自動最適化](/workflow/build-optimization#vrchat-깊이-자동-승격)

### 深度なしでもシルエットが立つようにする

通常プレイヤー画面では、深度がないと仮定してルックを確定する方が安全です。**深度が不要な手段** で基盤を敷いておきます。

| 手段 | ドキュメント |
|---|---|
| **法線アウトライン** | [アウトライン](/guides/outline) |
| **リムライト・リムシェード** | [リム](/guides/rim) |
| **形状シャドウ・シャドウ投影** | [ライティングとシャドウ](/guides/light-and-shadow) |
| **シャドウパターン (形状シャドウに適用)** | [シャドウパターン](/guides/shadow-pattern) |

深度ベース効果は **Photo Camera でより良く見えるボーナス** として扱う方が現実的です。

## その他のビルド ツールと共に使用する場合

MingToon の VRChat フックは `callbackOrder = 2000` で遅延実行されます。Modular Avatar や VRCFury が自分のコールバック内で材質を再度書き換え **た後に** 分析するためです。特別な設定は不要です。

## ライティングを制御できないという前提

ワールドごとにライティングは大きく異なります。以下を高めに設定すると、どのワールドでもキャラクターが崩れません。

| 項目 | 理由 |
|---|---|
| `ベースカラー保持` (シンプルモード: ベースカラー保持) | 暗いワールドでオリジナルアート色を保持 |
| `最終最小輝度` | 黒つぶれしないように |
| `最終最大輝度` | オーバーエクスポーザー ワールドで白飛びしないように |
| `シーンライト色の影響` を低めに | カラーライト ワールドでキャラクターが着色されないように |
| リムの `シーンライト影響` を低めに | どこでもリムが一定になるように |

→ [ライティングとシャドウ](/guides/light-and-shadow#라이팅--어두운-씬에서-검게-뭉칠-때)

## VRChat + URP

サポートされていません。BRP 製成版に切り替えてください。

## 知っておくべきこと

**ハードウェア要件** — MingToon はシェーダー モデル 4.5 を必要とします。これを満たさない環境では、材質がマゼンタでレンダリングされ、その他のエラー メッセージは表示されません。→ [対応環境](/platforms/compatibility#하드웨어-요구-사항-필수)

**Validate Project** — 2022.3.22f1 では、Unity バージョン関連のエラーや警告は表示されません。逆に **2021.3 プロジェクトに VRC SDK が含まれている場合**、`MING-VRC-UNITY-VERSION` 警告で「アバター アップロード サポートなし」と通知します。→ [Validator コード](/reference/validator)
