# Warudo

**このドキュメントを完了すると、** Warudo モードでフェイスシャドウと深度エフェクトが正常に表示されるよう、エクスポートできるようになります。

:::caution[現在の状態]
Warudo は **テスト対象であり、実装の検証がまだ完了していません。**
:::

## 推奨バージョン

| 項目 | 値 |
|---|---|
| Unity | **2021.3.45f2** |
| Warudo Mod SDK | **0.14.3.10** |
| レンダーパイプライン | Built-in (BRP) |

:::danger[VRChat プロジェクトと共存できません]
VRChat は Unity **2022.3.22f1**、Warudo は **2021.3.45f2** です。両方に対応する同一プロジェクトはないため、ターゲット別に分けてください。
:::

## エクスポート前の必須設定 — WARUDO Runtime Root {#내보내기-전-필수--warudo-runtime-root}

**このステップを省略すると、フェイスシャドウと深度エフェクトが表示されません。**

Warudo は **エディタースクリプトを含めて渡すことができません。** したがって、実行時にカメラの深度と頭の方向をシェーダーに渡す必要があります。その役割を果たすのが `MingToonWarudoRoot.cs` です。

### 手順

1. 付属の **`MingToonWarudoRoot.cs` ファイルをキャラクターモードフォルダに配置します。**
   アバターアセットと **同じフォルダ** に置く必要があります。一緒にビルドされるためです。
2. キャラクター **ルートオブジェクト** にコンポーネントをアタッチします。
   `Add Component → Studio Raming / MingToon / WARUDO Runtime Root`
3. そのままモドをビルドしてエクスポートします。

<!-- SCREENSHOT: モドフォルダの MingToonWarudoRoot.cs とアタッチされたコンポーネント -->

:::note[設定はほぼ変更不要です]
頭の骨は自動で検出されます — ヒューマノイド `Head` をまず確認し、なければ `Head` / `J_Bip_C_Head` という名前で検索します。

自動検出が失敗した場合は、`Head Bone` フィールドに直接指定してください。
:::

### 何が渡されるのか

このコンポーネントは毎フレーム、シェーダーに以下を渡します。

| 渡す値 | 用途 |
|---|---|
| カメラ `DepthTextureMode.Depth` | 深度リム・2D シャドウ・内部 2D 境界 |
| ビューカメラ位置/行列 (VR は左右の眼それぞれ) | スクリーン空間計算 |
| 頭の前方・上方・頭の中心 (ワールド空間) | フェイスシェーディング方向 |

MingToon エディター実行時（`MingToonManager` など）に **依存しない独立ファイル** です。したがってソースファイル 1 つだけをモドフォルダに配置すれば十分です。

### 症状から原因を特定

| 症状 | 原因 |
|---|---|
| **フェイスシャドウが動かず固定されている** | コンポーネントをアタッチしていないか、頭の骨が見つからない |
| **深度リムや 2D シャドウがまったく表示されない** | `.cs` ファイルがモドフォルダにない |

:::info[今後変更される予定です]
Warudo 側で **カメラ深度をトグルで有効にできるアップデートが計画** されています。そのアップデートが適用されたら、このコンポーネントなしで深度エフェクトが使用できるようになります。

**それまでは上記の手順が必要です。**
:::

## ビルド

`Warudo > Build Mod` を実行すると、[ビルド時の自動最適化](/workflow/build-optimization) が自動的に適用されます。追加の設定は不要です。

:::note[なぜ個別のフックが必要か]
`Warudo/Build Mod` は UMod 自体のパイプライン（`ModToolsUtil.StartBuild`）を使用するため、Unity のビルドコールバック（`IPreprocessBuildWithReport`）は **呼び出されません。** したがって以前は、モドが最適化されていないマテリアルで静かにエクスポートされていました。今では、UMod の拡張ポイントにプロセッサーとポストプロセッサーを登録して処理します。
:::

### ビルド範囲

モドビルドは、シーン全体ではなく **ビルド対象プリファブのみを最適化** します。シーン全体をスキャンすると、作成者が開いたまま関係のないマテリアルまで置き換わり、実際にビルドされるプリファブがシーンにない場合は完全に見落とされる可能性があるためです。

ビルド後、Console で `MING_WARUDO_BUILD` ログと最適化サマリーを確認してください。

## スクリプトポリシーが VRChat と異なります {#스크립트-정책이-vrchat과-다릅니다}

| | VRChat | Warudo |
|---|---|---|
| MingToon 実行時コンポーネント | アップロード時に **自動削除** | **保持されます** |
| 実行時データの供給 | ホスト (Photo Camera・ワールド) に依存 | **`WARUDO Runtime Root` が直接供給** |

Warudo はスクリプトを保持する環境なので、[MingToon マネージャー](/workflow/character-manager) の **エディター実行時プレビュー**（ルックプロファイルなど）もここでは実際に機能します。

## 知っておくべきこと

- Unity バージョンを **2021.3.45f2** に合わせてください。Mod SDK の基準線です。
- シェーダーモデル 4.5 の要件はここでも同じです。→ [対応環境](/platforms/compatibility#하드웨어-요구-사항-필수)
- シーン照明をコントロールできない演出の場合は、`ベースカラー保持` と `最終最小明るさ` を上げておいてください。→ [照明とシャドウ](/guides/light-and-shadow#라이팅--어두운-씬에서-검게-뭉칠-때)
- 複数のカメラを使用する構成 (メイン + 出力) の場合は、各カメラの深度エフェクトを個別に確認してください。
