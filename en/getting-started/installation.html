Installation

When you finish this page, you have a Unity project with MingToon installed and no errors. It takes about 15 minutes.

Before you start​

  • Unity Hub, a Unity version from the table below, and a backup of the project you will work on
  • VRChat SDK3 (Avatars) if you target VRChat

1. Match the Unity version​

TargetUnity
VRChat PC2022.3.22f1
Warudo2021.3.45f2
General Unity2021.3 LTS

Use 2022.3.22f1 if you target VRChat. The MingToon VRChat build hook only compiles on 2022.3 or later. A 2021.3 project has no upload optimization at all. One project cannot cover both VRChat and Warudo, so split them.

2. Install the package​

Choose VCC or BOOTH on the official download page.

To install with VCC:

  1. Press Add to VCC on the download page.
  2. Confirm the repository in VCC.
  3. Open Manage Project for the target project.
  4. Add MingToon and open Unity.

To install with the BOOTH installer:

  1. Download the installer .unitypackage from the BOOTH product.
  2. Import it in Unity with Assets > Import Package > Custom Package.
  3. Stay connected to the internet and wait. The installer downloads the core automatically.

If you installed with VCC, update in VCC as well. Upgrade MingToon under Manage Project > Manage Packages of the target project. The BOOTH installer tells you about new versions when you open Unity.

Either way, StudioRaming > MingToon > Update opens the MingToon Update window. Opening the window checks the latest information automatically and shows the current and candidate versions. There is one Update button. It becomes available for an installable candidate and also handles checking or refreshing a failed installation. Candidates depend on the configured release source and installation state. A version lower than an installed development or preview build is not offered as a new update. The changelog shows only the language selected in the MingToon Inspector. Headings, lists, emphasis, code, and links are rendered from Markdown.

Back up your Unity project before updating. Beta builds may change the UI, features, and appearance, so we recommend converting a new copy from the original materials after updating. Keep the previous copy while comparing the new result. Upload the avatar again to apply the update to an uploaded avatar.

3. Wait for the first compile to finish​

When you first add or upgrade MingToon, Unity recompiles the scripts. MingToon then prepares shader combinations needed for the first view in the current environment. This does not compile every lighting, shadow, instancing, or upload variant.

  1. Both new installations and updates show MingToon warm-up in the foreground. Cached work is skipped. Cancel closes the wait window and continues the remaining preparation in the background.
  2. Open a material after it finishes. Combinations outside the prepared set may still compile on their first draw.

This work starts in one of three cases.

  • When the project has no MingToon compile record. That is the first time you add it, and when you have deleted the Library folder
  • When the import of a .unitypackage with MingToon in its name finishes. This is the BOOTH installer route
  • When MingToon arrives through VCC (VPM) or changes version and Unity finishes registering the package. This route was added in 0.1.12

The compile record is kept in the project's Library/StudioRaming/MingToon.warmup file. Valid records and Unity's actual pass cache let MingToon skip compile requests for combinations already prepared. The record must match conditions such as shader source, Unity version, and graphics API. Changed source or an unprepared pass causes the required combinations to be prepared again. This cache belongs to the current project. It does not remove the first compile on another PC or in a new project.

Cancel on the progress bar closes only the bar. The compile moves to a Unity Progress item and keeps going, and you see its progress and cancel in the status bar at the bottom right of the editor. If you cancel there, what was finished until then stays recorded. The remaining variants are compiled by Unity the first time that shader is drawn, so the editor can stall for a moment.

No compile time is promised

Compile time varies a lot with the PC and the number of Unity shader compilers, so this page gives no time. Cache verification in a development build and new-install/update acceptance of a public package are separate steps. New-install and update verification of the final distribution files with foreground update warm-up is in progress. We do not promise zero compilation or a fixed percentage reduction in first-install time.

4. Check that the shader arrived​

Select one material and open the shader list at the top of the Inspector. You are fine if StudioRaming/MingToon/MingToon BRP is there. The URP shader is not included in this BRP open beta.

5. Check the VRChat integration​

This applies only to VRChat targets. After the reload finishes, the Console must contain the line below.

[MingToon] VRChat build hook compiled and registered.

If this line is missing

The VRChat build hook is not present. Uploading will not run the automatic optimization.

6. Validate the project​

Run StudioRaming > MingToon > Validate Project from the menu. If the build target cannot meet shader model 4.5, you get a MING-ENV-BUILD-TARGET error. Continuing in that state makes materials render magenta (pink). If the editor is 2021.3 and the VRC SDK is present, you get a MING-VRC-UNITY-VERSION warning.

Check that it worked​

  • The Console has no red errors.
  • The shader list contains StudioRaming/MingToon/MingToon BRP.
  • The build hook log is present if you target VRChat.
  • Validate Project reports no errors.

If any of the four does not match, go to Troubleshooting.

If you upgraded from an earlier version​

If “Unable to remove the file to be replaced” appears when starting an update from 0.1.11, follow the older-version update error guidance to check the state and retry. Do not keep repeating the installation if the same error persists.

Right after the update, the first compile progress bar can appear again. On an avatar that already has Manager, the Setup Wizard does not open by itself after an update. The bake cache is rebuilt once. There is nothing to delete by hand, but the next build or upload takes that much longer. A VRChat avatar must be uploaded again for this version to apply. The shader ships with the avatar. The conditions are in VRChat.

Optional: Post Processing Stack v2​

MingToon works fully without PPv2. This is for scene checks and capture.

  1. Install PPv2 3.4.0.
  2. Add UNITY_POST_PROCESSING_STACK_V2 manually to Player Settings > Scripting Define Symbols.
  3. Wait until Unity finishes recompiling.
  4. Run StudioRaming > MingToon > Create or Repair BRP PPv2 Global Volume.

If you skip step 2, the menu in step 4 does nothing.
