# 모듈과 성능 비용

**이 문서를 읽으면** 인스펙터의 `머티리얼 부하 예상` 숫자가 어떻게 나오는지 알고, 무거운 아바타에서 무엇부터 끌지 근거를 갖고 판단할 수 있습니다.

:::warning 이 값은 GPU ms가 아닙니다
인스펙터도 그렇게 말합니다.

> 상대 예상치이며 실제 GPU ms가 아닙니다. **화면 점유율·오버드로우·영향 조명 수에 따라 달라집니다.**

MingToon은 이 preview에서 검증된 GPU 성능 수치를 공개하지 않습니다. 아래는 **재질끼리 비교할 때의 상대 지표**입니다.
:::

---

## 부하 예상 패널 읽기

`머티리얼 부하 예상`

```text
[가벼움]  선택 8개 평균 42 / 최고 118
텍스처 비용 14 · 깊이 비용 2 · 예상 드로우 3 · ALU 지수 31
주요 비용: 화면 깊이 샘플 · 추가광 패스
```

| 표시 | 의미 |
|---|---|
| **등급** | 아래 4단계 |
| `선택 N개 평균 X / 최고 Y` | 여러 재질을 선택하면 평균과 **최악값**을 함께 보여 줍니다 |
| `텍스처 비용` | 텍스처 샘플 수 |
| `깊이 비용` | 화면 깊이 샘플 수 |
| `예상 드로우` | 이 재질이 만드는 패스 수 |
| `ALU 지수` | 연산량 상대값 |
| `주요 비용` | 점수를 크게 올린 항목 |

### 등급 경계

| 등급 | 점수 |
|---|---|
| **가벼움** | 0 – 34 |
| **보통** | 35 – 84 |
| **무거움** | 85 – 149 |
| **매우 무거움** | 150 이상 |

---

## 점수 계산식

소스의 계산식 그대로입니다.

```text
점수 = 텍스처 샘플
     + 깊이 샘플 × 3
     + max(패스 수 − 1, 0) × 8
     + ALU 지수
     + (추가광 패스를 쓰면)      +12
     + (URP 추가광이면)          +6
     + (투명 오버드로우 위험)    +15
     + (화면 깊이를 쓰면)        +12
     + min(동적 HSVG 개수 × 2, 20)
```

여기서 읽어야 할 것:

:::tip 가중치가 말해 주는 것
1. **패스 하나가 8점.** 첫 패스는 공짜지만 그 다음부터 붙습니다. 아웃라인·추가광·투명 프리패스가 각각 하나씩입니다.
2. **추가광 패스는 8 + 12 = 20점.** 단일 항목 중 가장 비쌉니다.
3. **깊이 샘플은 텍스처 샘플의 3배.** 게다가 화면 깊이를 쓰면 12점이 더 붙습니다.
4. **투명 오버드로우 위험 15점.** 반투명을 남발하면 여기서 걸립니다.
5. **동적 HSVG는 최대 20점까지만** 누적됩니다.
:::

### 패스가 늘어나는 조건

| 조건 | 패스 +1 |
|---|---|
| `추가 광원 받기` + `추가 광원 강도` 둘 다 0보다 큼 (Built-in) | ✅ |
| 아웃라인 사용 + `클래식 헐 사용` | ✅ |
| 표면 모드가 투명 계열 + `투명 깊이 선기록` | ✅ |

## 모듈별 비용

소스의 모듈 카탈로그에 선언된 값입니다. 순서는 셰이더 내 실행 순서입니다.

| 모듈 | 텍스처 | 깊이 | 추가 패스 | ALU |
|---|---:|---:|---:|---:|
| 기본 표면 | 0 | 0 | 0 | 0 |
| 텍스처 레이어 | **20** | 0 | 0 | 8 |
| 노멀 레이어 | **10** | 0 | 0 | 8 |
| 라이팅 | 0 | 0 | **1** | 7 |
| 그림자 | 0 | **4** | 0 | **12** |
| PBR 표면 | 2 | 0 | 0 | **12** |
| 맷캡 레이어 | **10** | 0 | 0 | 9 |
| 이미션 | 1 | 0 | 0 | 3 |
| 오클루전 | 1 | 0 | 0 | 2 |
| 림 (깊이 림 포함) | 2 | 1 | 0 | 7 |
| 백라이트 | 0 | 0 | 0 | 4 |
| 프런트 라이트 | 0 | 0 | 0 | 4 |
| 글리터 | 0 | 0 | 0 | **36** |
| 그림자 내부 반사 | 1 | 0 | 0 | 8 |
| 캐릭터 높이 그라데이션 | 1 | 0 | 0 | **1** |
| 페이스 셰이딩 | 6 | 1 | 0 | 8 |
| 아웃라인 | 4 | 2 | **3** | 10 |

:::note 이 값은 모듈의 **최대치**입니다
텍스처 레이어의 20은 10 레이어를 전부 쓰고 각각 마스크까지 붙였을 때의 상한입니다. 실제 점수는 재질에서 실제로 켜진 것만 셉니다.
:::

### 여기서 읽히는 것

| 관찰 | 실무 의미 |
|---|---|
| **글리터의 ALU 36** — 단일 모듈 최대 | 보로노이 계산이 비쌉니다. 반짝임이 꼭 필요한 파츠에만 |
| **아웃라인의 추가 패스 3** | 아웃라인 계열이 만들 수 있는 패스가 셋입니다 |
| **레이어 계열의 텍스처 10~20** | 레이어 수를 실제 쓰는 만큼만 두는 것이 가장 큰 절감 |
| **캐릭터 높이의 ALU 1** | 사실상 공짜입니다. 아껴 쓸 이유가 없습니다 |
| **그림자의 깊이 4** | 깊이 예산의 대부분을 그림자가 씁니다 |
| **백라이트·프런트 라이트 ALU 4** | 매우 쌉니다. 림 라이트 대신 이쪽을 쓸 여지가 있습니다 |

## 무거울 때 끄는 순서

점수 기여가 큰 것부터입니다.

1. **추가 광원 받기를 끈다** (−20점 내외) — 캐릭터가 주광만 받아도 되는 연출이면 가장 큰 절감입니다.
2. **반투명을 컷아웃이나 불투명으로 바꾼다** (−15점) — 투명 오버드로우 위험이 사라지고 프리패스 패스도 하나 줄어듭니다.
3. **깊이 기반 효과를 끈다** (−12점 + 깊이 샘플 × 3) — VRChat 일반 화면에서는 어차피 안 보입니다. → [VRChat](/platforms/vrchat#깊이-효과가-어디까지-보장되나)
4. **레이어 수를 실제 개수로 줄인다** — 특히 [티어 경계](/internals/shader-structure#레이어-티어-키워드)를 넘기면 컴파일되는 코드 자체가 줄어듭니다.
5. **글리터를 끈다** — ALU가 가장 큽니다.
6. **동적 HSVG를 정적으로 굽는다** — 애니메이션되지 않는 HSVG는 상수로 접힙니다.

:::tip 아웃라인은 함부로 끄지 마세요
패스 8점을 아끼지만 툰 룩의 정체성이고, **깊이 없이 동작하는 몇 안 되는 수단**입니다. 위 1~5를 먼저 검토하세요.
:::

## 동적 HSVG

`동적 HSVG N개`는 **애니메이션되거나 스크립트로 바뀔 수 있어 상수로 접을 수 없는** 색 보정의 개수입니다.

빌드 시 최적화는 애니메이션되지 않는 값을 셰이더 상수로 굳혀 연산을 지웁니다. 애니메이션되는 값은 유니폼으로 남습니다. → [빌드 시 자동 최적화](/workflow/build-optimization#애니메이션되는-값은-건드리지-않습니다)

**HSVG를 애니메이션할 계획이 없다면** 굳이 흔들리는 값으로 두지 마세요. 개당 2점씩, 최대 20점까지 붙습니다.

## 여러 재질을 한 번에 보기

`MingToon Manager`의 `모든 MingToon 재질 선택`이나 `씬의 모든 MingToon 머티리얼 선택`으로 전부 선택하면 **평균과 최악값**이 함께 나옵니다.

:::tip 평균보다 최악값을 보세요
아바타 전체가 가벼워도 재질 하나가 `매우 무거움`이면 그 파츠가 화면을 크게 덮을 때 프레임이 떨어집니다. `최고` 옆의 등급을 먼저 확인하고, 그 재질을 찾아 손보세요.
:::
