# 모듈과 성능 비용

머티리얼 부하 표시는 **업로드 후 베이크된 재질의 상대 부하 예상치**입니다. 값을 낮추기 전에 펼친 내역에서 비용이 큰 항목과 현재 작업 중 수치를 구분하세요.

## 부하 예상 패널 읽기 {#부하-예상-패널-읽기}

| 표시 | 읽는 방법 |
|---|---|
| 업로드 후 부하 | 새 MingToon 재질을 같은 방식으로 베이크한 비용을 1.0배로 두는 예상치 |
| 작업 중(에디터) 부하 | 현재 편집용 셰이더의 예상치. 업로드 수치와 다를 수 있습니다 |
| 선택 평균 / 최고 | 여러 재질의 평균과 가장 높은 등급. 최고값을 아바타 전체 비용으로 해석하지 마세요 |
| 무조건 텍스처 읽기 / 깊이 / 명령어 / 드로우 | 비용의 원인을 찾는 추정 내역. GPU 프로파일러 측정값은 아닙니다 |
| 텍스처 개수 / MB | 텍스처 메모리 예상치. 렌더링 속도와 별도로 봅니다 |

:::note[배율은 프레임 시간의 배수가 아닙니다]
코드의 모델은 특정 BRP 벤치마크 프로필에 맞춰져 있습니다. 화면 점유율, 겹침, 광원, GPU, 렌더 파이프라인에 따라 실제 비용이 바뀝니다. 2배라고 표시돼도 아바타 전체나 게임 프레임 시간이 2배가 되는 뜻은 아닙니다.
:::

## 예상치에 포함되는 것

현재 모델은 편집 상태와 베이크 예상 상태를 나누고, 명령어·항상 실행되는 텍스처 읽기·레지스터 사용·패스 등의 영향을 계산합니다. 예전의 고정 가중치 합산 점수와 등급 경계 표는 현재 표시를 설명하지 못합니다.

레이어는 사용 개수와 실행 조건을 함께 봅니다. 최대 슬롯이 있다는 이유만으로 모든 텍스처를 매 픽셀 읽는다고 계산하면 안 됩니다. 반대로 강도가 0인 것만으로 코드가 사라진다고 볼 수도 없습니다. 런타임 제어나 애니메이션을 위해 남기는 값이 있기 때문입니다.

카메라 깊이를 확보하는 씬 전체 비용은 재질 배율에 모두 포함되지 않습니다. 깊이 효과를 처음 켰을 때의 변화는 실제 씬에서 비교하세요.

## 무거울 때 확인하는 순서

1. 같은 카메라·거리·조명에서 기준 화면을 저장합니다.
2. 내역의 주요 비용을 보고 필요 없는 레이어나 효과를 하나씩 끕니다.
3. 투명 표면이 넓게 겹치면 오버드로우를 확인합니다. 표현이 허용할 때만 불투명이나 컷아웃으로 바꿉니다.
4. 추가 광원이 많은 장면에서는 추가 광원 받기를 비교합니다. 조명 표현도 함께 바뀝니다.
5. 깊이 효과와 아웃라인은 원하는 실루엣·그림자를 보존하는 범위에서 비교합니다. VRChat에서도 카메라 구성에 따라 깊이가 제공될 수 있습니다.
6. 실제 빌드 결과를 같은 조건에서 측정합니다. 낮아진 예상 등급만으로 개선을 확정하지 마세요.

## 동적 HSVG

애니메이션 또는 런타임 스크립트로 바꾸는 색 보정은 베이크 후에도 동작해야 합니다. 애니메이션 분석과 베이크 제외 설정을 확인하세요. 정적 값의 상수화나 텍스처 재작성은 해당 최적화의 조건을 만족할 때만 적용됩니다.
