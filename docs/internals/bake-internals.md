# 베이크가 제거하는 것

**이 문서를 읽으면** 베이크와 빌드 최적화가 무엇을 기준으로 코드를 지우는지 알고, "왜 이 재질만 최적화가 안 됐지"에 스스로 답할 수 있습니다.

---

## 두 단계로 나뉩니다

```text
1) 애니메이션 의존성 분석      무엇을 건드리면 안 되는가
        ↓
2) 기능 집합(FeatureSet) 산출  코드 모양이 어떻게 되는가
        ↓
   구조 프로파일이 같은 재질끼리 생성 셰이더를 공유
```

---

## 1단계 — 애니메이션 의존성 분석

> 이 분석기는 **클립·컨트롤러·재질을 절대 다시 쓰지 않습니다.** 읽기만 합니다.

무엇을 훑나:

| 대상 | 비고 |
|---|---|
| `AnimationClip`의 재질 프로퍼티 커브 | |
| `Animator`에 할당된 컨트롤러 | |
| **컴포넌트의 중첩·배열 직렬화 필드에 들어 있는 컨트롤러 참조** | 아래 참고 |
| `AnimationClip`의 오브젝트 참조 커브가 지정하는 재질 | 의상 토글 |

:::danger[VRChat 아바타에서 특히 중요한 부분]
아바타/익스포터 컴포넌트가 소유한 컨트롤러도 찾습니다. **VRChat Avatar Descriptor의 Playable Layer**가 결정적인 경우입니다 — 그 컨트롤러들은 Animator에 할당되어 있지 **않을 수 있지만**, 업로드 후에는 재질 커브가 실제로 실행됩니다. 따라서 반드시 보존 대상에 들어가야 합니다.

MingToon은 VRChat SDK에 컴파일 타임 의존성을 걸지 않고 이걸 찾아냅니다.
:::

### 여러 루트가 같은 재질을 쓸 때

여러 계층이 하나의 공유 재질을 참조하면 각 보고서를 **합집합**으로 합칩니다.

> 먼저 나온 것을 채택하는 방식은 안전하지 않습니다. 뒤에 오는 루트가, 앞선 루트에서는 정적이던 프로퍼티를 애니메이션할 수 있기 때문입니다.

### 분석이 실패하면

**"애니메이션이 없다"로 취급하지 않습니다.** 보수적 실패 표식을 만들어 해당 루트 아래 모든 재질에 병합하고, 파괴적·상수화 작업을 전부 건너뜁니다.

Console에 이렇게 남습니다.

```text
[MingToon] Animation analysis failed for {루트}; leaving its materials editable.
```

리포트에는 `SKIPPED: animation dependency analysis failed` 로 기록됩니다.

### 프로퍼티 이름 정규화

Renderer 재질 애니메이션 경로를 셰이더 프로퍼티 이름으로 바꿉니다. **컴포넌트 채널(`.r`, `.x` 등)은 제거하고 `_ST` 같은 타일링/오프셋 접미사는 유지**합니다.

즉 색의 R 채널만 애니메이션해도 그 색 전체가 동적으로 남습니다.

### Keep Editable — 사람이 직접 지정

`이 그룹 전체 베이크 제외`로 표시한 항목은 리포트에 접혀 들어갑니다.

:::note[두 목록 모두에 들어갑니다]
베이크의 두 절반이 서로 다른 목록을 읽기 때문입니다.
- **텍스처 베이커** → `AlwaysPreservedPropertyNames`
- **기능 분석기** → 셰이더 스트립 판단용 목록

애니메이션되지는 않지만 나중에 스크립트로 바꿀 값에 쓰세요.
:::

---

## 2단계 — 기능 집합 (FeatureSet)

재질의 **구조적 스냅샷**입니다.

:::tip[무엇이 들어가고 무엇이 빠지는가]
- **들어감** — 표면 모드, 컬 모드, 각 모듈의 on/off, 레이어 개수, 합성 모드, 얼굴 여부, SDF 사용 여부, 백엔드 ID
- **일부러 빠짐** — **수치 룩 값과 텍스처 에셋 identity**

그래서 **코드 모양이 같은 재질들이 하나의 생성 셰이더를 공유**합니다. 텍스처와 색이 달라도 상관없습니다.
:::

### 마스크 항등 비트

`OptionalWhiteMaskIdentityBits`는 "이 마스크는 수학적으로 흰색(=항등)"임을 증명한 결과를 비트로 담습니다.

| 비트 | 대상 |
|---|---|
| 0 | 프레넬 림 마스크 |
| 1 | 그림자 내부 반사 마스크 |
| 2–6 | 맷캡 마스크 01–05 |
| 7 | 림 셰이드 마스크 |

**항등이 증명되면 그 마스크의 텍스처 샘플이 통째로 사라집니다.** 손실이 전혀 없는 최적화입니다.

### 동적 상태

`AllEffectsDynamic` 같은 플래그는 **그 값이 애니메이션된다**는 뜻입니다. 동적인 항목은 상수로 접히지 않고 유니폼으로 남습니다.

---

## 3단계 — 구조 프로파일과 상수 교집합

같은 **구조 프로파일**(생성 셰이더의 코드 모양)을 갖는 재질들끼리만 상수를 교집합합니다.

```text
프로파일 A: 재질 3개  →  공유 수치 상수 12개
프로파일 B: 재질 5개  →  공유 수치 상수 4개
```

:::note[왜 프로파일 단위로 나누나]
lilToon 식의 상수화를 그대로 하면, 값이 다르거나 애니메이션되는 재질 하나가 **이웃 재질들의 안전한 상수까지 막아 버립니다.**

프로파일을 나누면, 값이 다른 재질은 그 프로파일 안에서 유니폼으로 남고, **코드 모양이 다른 재질은 이웃의 상수화를 방해하지 못합니다.**
:::

프로파일 식별에는 `MaterialConstants`가 의도적으로 제외됩니다 — 상수 자체가 프로파일을 가르면 순환이 됩니다.

`CanonicalLiteral`은 이미 불변 HLSL 표현식이라 **에디터 로케일에 프로파일 identity가 좌우되지 않습니다** (소수점 표기가 지역마다 다른 문제를 피합니다).

---

## 무엇이 실제로 제거되나

| 대상 | 조건 |
|---|---|
| 사용하지 않는 **패스** | 해당 기능이 꺼져 있고 애니메이션되지 않음 |
| 프레넬 림 · 2차 형태 그림자 · 깊이 효과 · 깊이 림 · 2D 그림자 | 위와 동일 |
| 비활성 **텍스처 모듈** 연산 | |
| **레이어 수를 초과하는** 슬롯 연산 | 티어 경계를 넘으면 코드가 실제로 줄어듭니다 |
| 항등이 증명된 마스크의 **텍스처 샘플** | |
| 정적 수치의 **연산** | 상수로 접힘 |

아웃라인은 **직접 렌더링되는 헐**과 **카메라 깊이를 읽는 내부 2D 경계**만 지원하며, 화면 합성용 별도 런타임은 쓰지 않습니다.

---

## 텍스처 최적화

기본값은 **`LosslessOnly`** 입니다. 원본 텍스처의 texel을 **다시 쓰지 않습니다.**

| 손실 없는 증명 | 내용 |
|---|---|
| depth mask 항등 | `optimized depth-mask(-1 sample)` |
| PBR/AO 공유 샘플 | 같은 Texture 객체 · 같은 UV 식일 때 `pbr/ao(-1 shared sample)` |

`ReviewedHighQuality`(또는 빌드 메뉴의 `Reviewed Texture Rewrites On Build`)를 켜면 추가로:

| 재작성 | 위험 |
|---|---|
| surface flatten | 픽셀이 달라질 수 있음 |
| normal flatten | 픽셀이 달라질 수 있음 |
| 일반 RGBA mask repack | 슬롯을 공유 텍스처로 합침. **셰이더 샘플 수는 줄지 않음** |

:::danger[픽셀이 달라지는 이유]
imported texture readback · color space · mip 재생성 · 플랫폼 압축. baked 전후 캡처를 직접 비교해야 합니다.
:::

### 실패하면 정확히 되돌립니다

텍스처 최적화 전에 **재질의 프로퍼티 블록 전체를 스냅샷**합니다. 손실 없는 증명조차 숨은 구조 플래그를 바꾸기 때문입니다.

스냅샷은 **디스크에 저장**되므로 에디터가 빌드 도중 죽어도 복구됩니다.

실패 시 동작:

1. 해당 재질만 정확히 롤백 → `Texture baking failed and was rolled back exactly for {재질}`
2. 롤백이 불완전하면 전체 복구 시도
3. 그것도 실패하면 **빌드를 중단**합니다 (`BuildFailedException`)

---

## 왜 이 재질만 최적화가 안 됐나

리포트(`StudioRaming/MingToonOptimizeReport.txt`)와 Console을 보세요.

| 기록 | 원인 |
|---|---|
| `SKIPPED: animation dependency analysis failed` | 분석 실패. 보수적으로 편집 상태 유지 |
| `SKIPPED: {메시지}` | 그 재질에서 예외 발생. 빌드는 계속 진행 |
| 아무 줄도 없음 | 대상으로 수집되지 않음 — 씬/프리팹 범위 밖이거나 이미 생성 셰이더 위에 있음 |

:::note[이미 스왑된 재질은 건너뜁니다]
편집용 MingToon 재질만 대상입니다. 수동 베이크로 만들어진 재질이나 이전 빌드에서 복원되지 않은 재질은 그대로 둡니다.
:::

## 수집 범위

| 상황 | 범위 |
|---|---|
| 플레이어 빌드 | **씬**을 훑습니다. 씬이 곧 빌드이기 때문 |
| Warudo 모드 빌드 | **빌드 대상 프리팹**만 |

:::danger[호스트가 프리팹 하나를 빌드할 때 씬을 훑으면 안 되는 이유]
측정된 한 모드 빌드에서, 프리팹이 쓰는 재질은 7개인데 **작업자가 열어 둔 재질 41개가 스왑**됐습니다. 게다가 그 프리팹이 씬에 없으면 **정작 출하되는 것만 최적화되지 않은 채로** 나갑니다.
:::
