## 핫픽스 1 — 2026-09-07 (1차)

**업데이트 후 해야 할 것**

- 얼굴 프록시는 덮어쓰기만 하면 됩니다. 씬을 열면 편집 재질의 프록시 노멀이 바로 셰이더로 계산됩니다. 재업로드는 필요 없습니다.
- 아웃라인 없는 lilToon 원본에서 변환한 재질이 스텐실을 쓰고 있다면 다시 변환하거나 `아웃라인` > `스텐실 설정`을 표면 값과 맞춰 주세요.
- `이미션 사용`이 켜진 재질은 다시 변환하거나 Manager의 `폴백 프로퍼티 동기화`를 한 번 누른 뒤 재업로드해야 VRChat 폴백이 검정이 됩니다.
- VRChat 빌드가 `Material recovery is incomplete`로 막혀 있던 프로젝트는 덮어쓴 뒤 에디터를 한 번 재시작하면 자동으로 정리됩니다.
- 스텐실(눈 오버레이·숨김 마스크)을 쓰는 lilToon 변환 재질은 다시 변환하거나 스텐실 값을 직접 되돌려 주세요.
- 재업로드는 필요 없습니다.

### 얼굴 프록시 노멀이 씬에서 자꾸 풀리던 문제

- 증상 — 프록시를 조정해 두면 씬 저장·플레이 모드·리로드·검증 때마다 원본 노멀로 되돌아갔고, 그동안 인스펙터가 미리보기 클론을 가리켜 편집이 원본 재질에 남지 않았습니다.
- 조치 — 임시 UV7 미리보기 메시·재질로 바꿔치기하던 방식을 버리고, 편집 재질에서는 셰이더가 프록시 노멀을 직접 계산합니다. 업로드본은 종전대로 프록시 설정대로 구워지고 그 재질에서는 실시간 계산이 컴파일에서 빠집니다. 실시간과 베이크는 같은 수식입니다.
- 함께 고침 — Root Bone이 있는 Skinned Mesh Renderer에서 `프록시 영역 마스크` 중심이 얼굴에서 어긋나던 문제. 셰이더가 보는 오브젝트 공간이 루트 본(대개 Hips) 공간이라 생긴 것으로, 에디터가 렌더러마다 보정값을 넣어 줍니다.

### 아웃라인 없는 lilToon 재질을 변환하면 아웃라인이 스텐실 마스크를 무시하던 문제

- 증상 — 앞머리 사이로 비치게 스텐실을 건 눈이 표면은 비치는데 아웃라인만 머리카락에 가려졌습니다. lilToon의 아웃라인 없는 변형은 아웃라인 스텐실 값을 쓰지 않은 채 갖고 있고, 변환 후 밍툰이 그리는 아웃라인이 그 중립 값을 받았습니다.
- 조치 — 원본에 아웃라인이 없으면 아웃라인이 표면 스텐실 단위를 물려받습니다. 원본이 아웃라인을 그리면 종전처럼 자기 값을 유지합니다.

### VRChat 폴백 셰이더에서 이미션이 아바타 전체를 하얗게 덮던 문제

- 증상 — 셰이더가 차단되거나 로드에 실패해 폴백으로 떨어진 아바타가 아웃라인만 남긴 채 하얗게 나왔습니다. 폴백용 `_EmissionColor`에 `이미션 사용`이 켜진 재질의 틴트×세기가 들어갔고, VRChat 폴백 셰이더는 이미션 맵이 없으면 그 색을 표면 전체에 더합니다.
- 조치 — 폴백 alias의 이미션 색은 항상 검정입니다. MingToon 셰이더 자체의 이미션은 그대로입니다.

### NDMF 생성 클론의 레코드가 남아 VRChat 빌드가 계속 막히던 문제

- 증상 — NDMF를 쓰는 아바타를 한 번 빌드한 뒤부터 모든 VRChat 빌드가 `Material recovery is incomplete`로 실패했습니다.
- 조치 — NDMF가 빌드 후 지우는 `Packages/nadena.dev.ndmf/__Generated/` 클론 머티리얼의 복구 레코드가 저널에 남던 것이 원인입니다. 머티리얼 소실 판정을 GUID 매핑이 아니라 실제 파일 존재로 바꿨고, 그런 레코드는 다음 복원 시점에 경고 한 줄과 함께 정리됩니다.

### 룩 프리셋이 스텐실 값을 덮어쓰던 문제

- 증상 — lilToon 변환은 원본의 스텐실 값(Ref·Comp·Pass 등)을 그대로 가져오는데, 변환 직후 적용되는 팩토리 룩 프리셋이 셰이더 기본값(Ref 0·Always·Keep)을 들고 있어 눈 오버레이·숨김 마스크용 스텐실이 전부 0으로 되돌아갔습니다. 룩 프리셋을 다시 적용할 때도 같았습니다.
- 조치 — 스텐실 두 단위(표면·아웃라인, 14개 항목)는 이제 프리셋에 캡처되지도 적용되지도 않습니다.
