*오픈 베타 · 2026-09-07*

0.1.7은 0.1.6 이후 누적 변경을 정리한 오픈 베타 릴리즈입니다.

**업그레이드 시 확인할 것**

> ⚠️ **0.1.6 이하에서 올라올 때는 `Assets/StudioRaming/MingToon` 폴더를 통째로 지우고 0.1.7을 새로 임포트하세요.** 이것이 공식 업그레이드 경로입니다. 이전 폴더 위에 덮어쓰면 0.1.7에서 없어진 스크립트·셰이더·생성 파일이 남아 중복 어셈블리나 컴파일 오류를 만들 수 있습니다. 이번 판에서 프로퍼티 이름이 대폭 바뀌었기 때문에 0.1.6 재질에 저장돼 있던 값은 이어지지 않습니다 — 없어진 이름 자리에는 셰이더 기본값이 들어가고 재질은 오류 없이 그대로 동작하므로, 별도 변환이나 마이그레이션 없이 새 기본값에서 다시 잡으면 됩니다. 룩 프리셋을 저장해 두었다면 그것으로 빠르게 되돌릴 수 있습니다. 베이크 산출물(생성 셰이더·플래튼 텍스처·마스크 팩)도 다시 구워야 합니다. `Assets/StudioRaming/MingToon` 폴더 안에 직접 만든 프리셋이나 사용자 파일이 있다면 먼저 폴더 밖으로 백업하고, 기존 MingToon 폴더만 삭제한 뒤 새 패키지를 임포트하세요. 프로젝트의 다른 위치에 둔 재질·텍스처·프리팹은 삭제 대상이 아닙니다. 별도 제품인 `MingLightController` 폴더도 이 삭제 대상에 포함되지 않습니다.

> ⚠️ **재질 프로퍼티 ID에서 `_Ming` 접두어가 빠졌습니다. 애니메이션 커브를 다시 연결해야 합니다.** 0.1.6까지 `_Ming`으로 시작하던 프로퍼티 ID 대부분이 접두어 없는 정본 이름이 됐습니다(`_MingBacklightColor` → `_BacklightColor`, `_MingGlitterDensity` → `_GlitterDensity`, `_MingAllEffectsEnabled` → `_AllEffectsEnabled` 등 약 670개). 자동 변환은 없습니다. 0.1.6 재질에 저장돼 있던 값과 `material._Ming...`을 가리키는 애니메이션 커브는 이제 셰이더가 모르는 이름이 되어, 값이 조용히 셰이더 기본값으로 돌아갑니다. 재질은 위 안내대로 새 기본값에서 다시 잡고, 애니메이션 커브만 새 이름으로 다시 연결하세요. 옛 이름으로 저장해 둔 프리셋과 JSON은 현재 재질에서 다시 저장하면 됩니다. 옛 이름을 쓰는 재질·프리셋·애니메이션 클립의 목록이 필요하면 `StudioRaming/MingToon/Advanced/Migrate Project To Current Schema`가 검사·보고만 해 줍니다 — 업그레이드에 필수가 아니고, 커브를 고쳐 주지도 않습니다. `_MingVirtualLight*`·`_MingMaterialVersion`·`_MingUnifiedShadow*`처럼 남아 있는 이름도 있으니, 접두어를 일괄로 지우지 마세요.

> ⚠️ **베이크 캐시가 다시 생성되고, VRChat 아바타는 재업로드해야 합니다.** 생성 셰이더 캐시 버전이 올라가 기존 베이크 산출물이 무효가 됩니다. 다음 빌드에서 자동으로 다시 구워지므로 손댈 것은 없지만 그 한 번은 시간이 더 걸립니다. 이번 판의 맷캡 최적화는 다시 구워야 적용됩니다. 셰이더는 아바타 에셋번들에 동봉되므로 이미 올라간 아바타는 재업로드해야 이번 수정을 받습니다.

> ⚠️ **얼굴 음영과 그림자 모양이 달라지는 재질이 있습니다.** 둘 다 기존 동작이 버그였던 경우입니다. 빛이 얼굴 정중앙을 지날 때 음영이 딱딱하게 튀던 것이 부드럽게 넘어가고, 버텍스 페인트로 얼굴 영역을 지정한 통합 재질에서 몸 전체에 잘못 적용되던 얼굴 깊이 오프셋이 사라집니다.

> ⚠️ **조명 관련 기본값이 바뀌었습니다.** `씬 조명 색상 영향`·`간접광 보정`을 비롯한 조명 항목 9개의 기본값을 실사용 세팅에 맞췄고, `투과광 사용`은 기본 꺼짐이 됐습니다. 새로 만드는 재질과 팩토리 프리셋에만 적용되며, 이미 만들어 둔 재질의 값은 건드리지 않습니다.

> **2D 림라이트에 `씬 조명 영향`이 추가됐습니다.** 기본값은 1이므로 이 값을 저장하지 않은 기존 재질도 어두운 라이트 볼륨에서는 림이 함께 어두워질 수 있습니다. 이 영향을 끄려면 `2D 림라이트`의 `씬 조명 영향`을 0으로 설정하세요.

> ⚠️ **`추가광 밝기 상한`이 새로 생겼습니다. 포인트·스폿 조명이 예전보다 눌립니다.** 포인트·스폿 같은 추가광이 최종 표면 밝기에 더하는 에너지의 상한이며, 셰이더 기본값은 0.35입니다. 강한 색광 아래에서 하이라이트가 흰색으로 날아가지 않고 색이 남는 값입니다. 밝기 기여만 제한하므로 추가광의 색 반영은 그대로입니다. 0.1.6 재질에 저장돼 있던 값은 이어지지 않으므로, 폴더를 지우고 새로 임포트한 프로젝트에서는 모든 재질이 이 기본값 0.35에서 시작합니다. 추가광이 예전보다 어둡게 느껴진다면 `라이팅`의 `추가광 밝기 상한`을 올리세요.

> ⚠️ **`2D 그림자 바이어스`의 척도가 이번 판에서 10배 달라졌습니다.** 이제 1이 1cm가 아니라 10cm를 뜻합니다. 0.1.6 재질에 저장돼 있던 값은 이어지지 않으므로 손으로 환산할 것은 없고, 새 척도에서 다시 잡으면 됩니다. 동봉된 Soft Toon 프리셋은 새 척도로 저장돼 있습니다. 같은 정리로 `Depth Blur`와 `Light Pushback` 항목은 없어졌고, `수신면 밀기`(Receiver Depth Pushback)는 카메라 깊이에만 적용됩니다.

> ⚠️ **Face SDF Studio와 Mask Maker가 이번 판부터 동봉되지 않습니다.** 두 도구는 별도 제품으로 분리됐습니다. 따로 구매해 프로젝트에 넣으면 인스펙터의 해당 자리에서 예전과 똑같이 연동됩니다. 없으면 그 버튼이 안내로 바뀔 뿐, 다른 기능에는 영향이 없습니다.

> ⚠️ **VRChat Expressions 메뉴 제작 기능은 밍툰 본체에서 분리됐습니다.** Manager의 기존 설치 UI는 제거됐고, 이제 별매 애드온 `Ming Light Controller (MLC)`가 아바타별 메뉴·파라미터·FX 구성을 담당합니다. MLC를 설치하지 않으면 런타임 메뉴만 만들어지지 않을 뿐, 밍툰 셰이더와 빌드 깊이 라이트 선택 기능은 그대로 작동합니다. 이전 판에서 실제 설치해 둔 메뉴·파라미터·FX 레이어는 자동으로 지우지 않으므로 필요 없으면 직접 정리하세요.

> ⚠️ **URP 백엔드가 별도 애드온으로 분리됐습니다.** 기본 패키지에는 BRP와 공용 코어만 들어갑니다. URP 셰이더와 Renderer Feature는 유료 배포 다운로드에 포함된 `MingToon_URP_Addon_0.1.7.unitypackage`로 따로 제공됩니다. 지금까지 URP 프로젝트에서 밍툰을 쓰고 있었다면 기본 패키지를 먼저 임포트한 뒤 애드온을 이어서 임포트하세요. 애드온만 단독으로 넣는 구성은 지원하지 않습니다. 애드온이 없는 프로젝트에서는 URP 셰이더가 선택지에 나타나지 않으며, 공용 에디터 기능은 그대로 컴파일되고 동작합니다. VRChat PC·Quest는 URP를 쓰지 않으므로 이 분리의 영향을 받지 않습니다(PC는 BRP 베이크본, Quest는 모바일 변환본). WARUDO와 일반 Unity의 URP 12.x 환경이 애드온 대상입니다. 자세한 설치 순서와 포함 항목은 동봉 문서 `MingToon_URP_Addon.md`를 보세요.

### 0.1.6 생성물 정리와 변환 Mesh 자동 갱신

- 이번 버전에만 들어 있는 정리 모듈이 0.1.7 에디터 코드가 처음 로드될 때 프로젝트당 한 번 스스로 돕니다. 덮어썼든 폴더를 지우고 새로 임포트했든 똑같이 돕니다 — 0.1.6 생성물은 `Assets/StudioRaming/MingToon`이 아니라 `Assets/StudioRaming/MingToonGenerated/Shaders`에 있어서, MingToon 폴더를 지워도 그대로 남기 때문입니다. 이 모듈은 MingToon이 생성했다고 증명되는 0.1.6 방식의 낡은 고정 프로필만 골라, 그 프로필을 쓰는 baked 재질의 셰이더 참조를 현재 BRP/URP 셰이더로 바꾼 뒤 프로필을 삭제합니다. 그래서 Missing Shader 상태가 되지 않으며, 셰이더 참조 외의 재질 값, 원본·편집용 재질, 다른 폴더의 셰이더 에셋은 수정하지 않습니다. 바꿔 넣을 현재 BRP/URP 셰이더를 찾을 수 없거나 오류 상태면 프로필을 그대로 두고 콘솔에 보고합니다.
- 예전 파라미터를 새 구조로 변환하지는 않으므로 룩은 달라질 수 있습니다. 현재 버전의 정확한 룩이 필요하면 원본·편집용 재질을 다시 변환한 뒤 Bake하세요.
- MingToon Manager의 기본 변환은 편집용 재질과 생성 Mesh를 원본 Model/FBX 옆 `MingToon` 폴더에 함께 저장합니다. 변환 출력 폴더를 직접 지정하면 둘 다 그 폴더를 사용합니다.
- 기존 전역 `MingToonGenerated/Meshes`에 있던 MingToon 소유 Mesh는 다음 변환 때 원본 옆으로 이동하며 GUID와 `.meta`, Renderer 참조를 유지합니다.
- 같은 GUID의 Model/FBX가 덮어쓰기·재임포트·이동되면, 임포트가 끝난 뒤 등록된 생성 Mesh를 자동으로 다시 굽습니다. 안전하게 재사용할 수 있는 Mesh는 같은 에셋 안에서 갱신해 GUID와 Renderer 참조를 유지합니다.
- Renderer 범위가 달라졌거나 원본 Mesh 식별이 모호하거나 사용자가 생성 Mesh의 형상·색·UV를 충돌되게 편집한 경우에는 자동 덮어쓰지 않습니다. 경고를 확인하고 Manager에서 다시 변환하세요.

**새 기능**

### 1. `발광 레이어 2 사용`

- 두 번째 발광 맵이 생겨 부위마다 다른 색으로 발광시킬 수 있습니다. 두 레이어는 더해지므로 각 부위의 색이 그대로 남습니다. 기본값은 꺼짐입니다.

### 2. `맵 알파를 세기 마스크로`

- 발광 맵의 알파 채널을 픽셀별 세기 마스크로 씁니다. 알파는 색상과 함께 이미 읽히므로 텍스처를 더 읽지 않습니다. 두 발광 레이어 모두에 있습니다.

### 3. 재질 설정 복사·붙여넣기

- 인스펙터 상단 바에 복사·붙여넣기 버튼이 생겼습니다. 붙여넣기는 `전체 붙여넣기`·`값만 붙여넣기 (텍스처 제외)`·`텍스처만 붙여넣기`·`키워드만 붙여넣기`·`렌더 큐만 붙여넣기` 다섯 가지로 나뉘어, 텍스처는 재질마다 다르게 두고 설정만 옮기는 작업이 한 번에 됩니다. 되돌리기(Ctrl+Z)가 듣습니다.

### 4. `빠른 설정` 카드와 색 감마

- 재질 전체에 바로 듣는 항목들을 인스펙터 맨 위 한 자리에 모았습니다. `통합 그림자 색상`을 포함합니다.
- 통합 그림자와 SSAO의 순도·명도 조정, 노멀 아웃라인 색상, 이너 아웃라인 색상에 `감마`가 추가됐습니다. 밝기 축만 조절해 색조와 순도를 유지하며, 1은 기존 룩을 유지합니다. 아웃라인의 불투명도와 폭은 바뀌지 않습니다.

### SSAO (화면 공간 차폐)

- 깊이 그룹의 `SSAO` 탭이 이 판의 최종 형태로 정리됐습니다. 0.1.6에서 바로 올라온 프로젝트에서는 이 탭 자체가 처음 보입니다. 화면 깊이로 물체가 맞닿은 자리를 찾아 그 자리만 더 어둡게 만드는 모듈이며, 오클루전 맵과 달리 툰 밴드와 스크린톤을 통과한 뒤에 얹히므로 그림자 경계를 계단지게 만들지 않습니다. **기본값은 꺼짐이므로 기존 재질의 그림은 달라지지 않습니다.**
- 값의 단위와 범위가 처음 소개했을 때와 달라졌습니다. `SSAO 반경`은 0.001~0.03(기본 0.005)이고, 예전에 페이드 범위로 안내한 항목은 `접촉 감쇠`로 이름이 바뀌어 미터가 아니라 `SSAO 반경`의 배수(0.25~4, 기본 1)가 됐습니다. `SSAO 바이어스`도 절대 미터가 아니라 `SSAO 반경`에 대한 비율입니다(0.4 = 반경의 40%). 반경 비율이라 카메라 거리나 반경을 바꿔도 룩이 그대로 따라옵니다. 소멸 거리는 SSAO 전용 항목이 아니라 2D 그림자와 함께 쓰는 `공용 소멸 거리`(기본 200)로 합쳐졌습니다. 예전 판의 수치를 기억하고 있다면 그대로 옮기지 마세요.
- 다른 깊이 모듈과 같이 카메라 깊이 텍스처가 필요합니다. 깊이가 없는 환경에서는 조용히 사라지고, `전체 효과`과 `깊이 효과 마스터`를 끄면 함께 꺼지며, VRC 품질 티어 Low에서도 꺼집니다. 빌드 깊이 라이트도 SSAO를 켠 아바타를 깊이 모듈 사용으로 인정합니다.
- 비용은 재질당 한 번이 아니라 화면에 보이는 프래그먼트마다 냅니다. 깊이 그룹의 `공용 품질`이 픽셀당 깊이 샘플 수를 정하고(Low 4 · Standard 8 · High 16), `공용 소멸 거리`가 비용을 끊는 항목입니다 — 이 거리 밖의 캐릭터는 샘플 수가 0이 되므로 군중 씬에서는 이 값을 줄이는 것이 가장 확실한 최적화입니다. 두 항목은 2D 그림자와 함께 쓰는 공용 값이라 한쪽만 따로 조절할 수 없습니다.
- `캐스트 섀도우 안 표시량`·`2D 섀도우 안 표시량`으로 각 그림자 안에서 SSAO를 얼마나 더 얹을지 따로 정합니다. 자세한 항목 설명은 매뉴얼 `3-10. SSAO`를 보세요.

### 2D 그림자: 한 장의 실루엣과 깊이 반응

- 2D 그림자가 실루엣 한 장으로 정리됐습니다. 앞 물체의 실루엣을 조명 반대 방향으로 밀어 그 한 장을 읽고, 앞 물체가 수신면에서 떠 있는 만큼 그 한 장을 더 멀리 밀어냅니다 — 붙어 있는 것은 폭 자리에 그대로, 떠 있는 것만 더 먼 자리에 맺혀 앞뒤가 읽힙니다.
- 그림자 판정을 표면의 접평면 기준으로 하므로, 얼굴·몸의 자기 곡률이 그림자로 오인되던 자국이 사라지고 이마에 거의 닿은 앞머리 그림자는 그대로 남습니다.
- `2D 그림자` 탭 항목이 다음으로 정리됐습니다: `그림자 폭`·`그림자 강도`·`깊이 늘림`·`깊이 커브`·`깊이 옅어짐`·`소프트니스`·`블러`·`2D 그림자 바이어스`·`수신면 밀기`·`역광 실루엣 억제`.
- 거리감은 `깊이 늘림`(기본 1)이 만듭니다. 1이면 10cm 떠 있는 물체의 그림자가 폭에서 10cm 더 멀리 맺히고, 0이면 폭 자리에서만 읽는 균일한 한 장이 됩니다. `깊이 커브`가 그 밀림의 모양을, `깊이 옅어짐`이 멀리 뜬 물체의 진하기를 정합니다.
- 카메라가 캐릭터를 내려다볼수록 `깊이 늘림`이 짧아지고 늘어난 부분이 옅어집니다. 화면 위에서 미는 방식이라 내려다볼 때 그림자가 길게 늘어져 보이던 것을 줄인 것으로, 화면 옆으로 밀리는 측광 그림자는 그대로입니다. 조절 항목은 없고 자동입니다.
- 이 단축이 `얼굴 고정 방향`을 쓰는 재질에도 적용됩니다. 지금까지 얼굴은 그림자 방향을 머리에 고정한다는 이유로 길이 보정에서 빠져 있었고, 그래서 카메라가 얼굴을 내려다볼 때 앞머리 그림자만 전체 길이를 유지해 같은 각도의 몸 그림자와 어긋났습니다. 고정되는 것은 그림자가 향하는 **방향**이지 길이가 아니므로, 이제 방향은 그대로 머리를 따라가고 길이만 카메라 각도에 따라 함께 줄어듭니다. 늘어난 부분과 폭 자리가 같은 비율로 줄어들기 때문에 옆면의 옅어지는 정도는 예전과 같습니다.
- 길이가 0으로 무너지지는 않습니다. 그림자 축이 사라지지 않도록 최소값이 걸려 있고, 그 자리에서 그림자는 지정한 `그림자 폭`의 2% 너비로 남습니다 — 눈에 보이지 않는 크기입니다.
- `블러`는 다 그려진 그림자에 마지막으로 적용되고 반경은 이 값(미터)만으로 정해집니다. 이때만 한 장을 중심 1회 + 회전 디스크 4회, 모두 5회 읽습니다.
- 그림자 안쪽은 지정한 그림자 색으로 꽉 차게 칠해집니다. 통합 그림자를 쓰는 재질에서는 완전히 덮인 자리가 형태 그림자의 중심과 똑같은 색이 되고, `그림자 경계` 색 띠는 블러나 깊이로 부드러워진 가장자리에만 얹힙니다.
- 품질·거리 항목은 깊이 그룹의 `공용 품질`·`공용 소멸 거리` 두 개로 합쳐졌습니다. `공용 품질`은 SSAO의 샘플 수만 정하고, 2D 그림자는 이 단계와 무관하게 고정된 소수만 읽습니다 — 폭 1회 + 투표 4회 + 한 장 1회, 블러를 켜면 그 한 장이 5회가 되어 최대 10회입니다.
- 항목별 설명은 매뉴얼 `3-11. 2D 그림자: 한 장의 실루엣과 깊이 반응`을 보세요.

### `백라이트 합성 모드`·`프런트 라이트 합성 모드`

- 백라이트와 프런트 라이트의 색을 표면에 어떻게 섞을지 고를 수 있습니다. Normal·Multiply·Add·Hue·Screen·Color·Overlay 일곱 가지로, 다른 림 계열과 같은 목록입니다. 함께 생긴 `블렌드 불투명도`(0~1)는 색과 강도는 그대로 두고 존재감만 줄입니다.
- 기본값은 둘 다 `Add`, 불투명도 1입니다. 이 조합은 예전의 직접 가산과 수식이 같으므로 이 항목만으로는 룩이 달라지지 않습니다.
- `Add`가 아닌 모드에서는 `백라이트 강도`·`프런트 라이트 강도`가 밝기 배수가 아니라 섞이는 정도로 작동합니다. Hue와 Color는 휘도가 1을 넘으면 색을 지키지 못하고 회색으로 수렴하므로, 세게 태우는 표현에는 `Add`나 `Screen`을 쓰세요.

### `지금 메쉬만 다시 베이크`

- Manager의 `준비` > `1 · 변환` > `함께 구울 메쉬 채널` 맨 아래에 버튼이 생겼습니다. 원본 FBX를 고친 뒤 눌러 아웃라인 노멀·얼굴 노멀·캐릭터 높이 중 위에서 켠 채널만 다시 굽습니다.
- 재질과 룩 값은 건드리지 않습니다. 메시를 되찾으려고 변환을 다시 돌리면 손으로 맞춘 값이 프리셋으로 덮이지만, 이 버튼은 메시만 새로 씁니다. 굽는 범위는 같은 그룹 위쪽에서 `전체 메쉬`나 `선택한 오브젝트만`으로 정합니다.
- 대상 메시가 없거나, 켠 채널이 없거나, 출력 폴더가 유효하지 않으면 비활성입니다.

### lilToon 2.3.4 변환 정밀도와 공용 UV 라우터

- lilToon 2.3.4 재질을 기준으로 HSVG, 알파 마스크, 아웃라인 폭·버텍스 압력, 림 방향·뒷면 조건, 맷캡 마스크 채널, 반사 색, 툰 스페큘러를 다시 매핑했습니다. 정확히 옮길 수 없는 값만 경고하고, 실제로 같은 결과인 기본값과 빈 마스크는 실패로 세지 않습니다.
- 메인 색, 2nd, 3rd와 각 독립 마스크를 가져옵니다. 2nd·3rd는 밍툰 스태킹 레이어로 옮겨 색·마스크·합성 조건을 따로 유지합니다.
- 메인 표면·알파 마스크·스태킹 레이어 10장·발광 레이어 1/2와 각 마스크가 같은 UV 라우터를 씁니다. UV0~UV3, Tiling/Offset, 스크롤, 중심 회전, 회전 속도, 스프라이트 시트의 열·행·프레임 수·재생 속도를 한 수식으로 처리합니다.
- lilToon 데칼의 위치·크기·회전, 한 장만 표시/반복 타일, 좌우 제한, 복제·반전·대칭과 스프라이트 시트 애니메이션을 변환합니다. 움짤처럼 움직이는 아틀라스 텍스처는 지원하지만 동영상 파일을 재생하는 디코더는 포함하지 않습니다.
- UV 라우팅은 사용하는 재질의 생성 셰이더에만 들어갑니다. 기본 UV와 정지 텍스처만 쓰는 재질은 추가 라우팅·아틀라스 연산을 부담하지 않습니다.
- AnimationClip 안의 옛 재질 프로퍼티 커브 자동 재작성, Fur, Gem, 굴절 변환은 이번 판에 포함되지 않습니다.

### 변환 결과 보고서 정리

- 변환 결과를 재질별 긴 문장 대신 원본·결과 한 쌍 단위로 묶어 보여줍니다. 쌍마다 `원본:`과 `변환 결과:`로 두 재질의 경로를 찍고 `연결 방식:`으로 둘을 어떻게 짝지었는지 밝힌 뒤, 옮기지 못한 내용을 `핵심 불일치`와 `명시적 손실` 두 목록으로 나눠 적습니다. `최근 변환 결과` 패널을 펼치면 이 상세가 나오고, `전체 복사`로 보고서 전체를 한 번에 가져갈 수 있습니다.
- `연결 방식`은 `출처 기록으로 연결`·`고유 이름으로 연결`·`이름이 겹쳐 확인 필요`·`원본을 찾지 못함` 넷 중 하나입니다. 앞의 둘은 짝이 확정된 것이고, 뒤의 둘은 어느 원본에서 나온 재질인지 직접 확인해야 하는 것입니다.
- 의상에서 바로 티가 나는 UV·데칼·발광·알파·아웃라인 항목은 경고만 남기지 않고 가능한 범위까지 실제 값으로 옮깁니다. Fur·Gem·굴절처럼 이번 판의 렌더 경로가 없는 항목만 `명시적 손실`로 남습니다.
- `얼굴 렌더러 직접 지정`·`피부 렌더러 직접 지정` 아래에 경고가 하나 생겼습니다. 지정한 렌더러 위에 있는 밍툰 재질 중 아직 그 역할로 표시되지 않은 것을 얼굴 몇 개, 피부 몇 개로 세어 알려 주고, 바로 아래 `지정한 렌더러에 역할 표시` 버튼을 가리킵니다. 역할 표시가 없으면 룩 프리셋이 얼굴·피부 값을 따로 보내지 못해 그 재질만 일반 값으로 칠해지는데, 지금까지는 그 사실이 화면 어디에도 드러나지 않았습니다. 세는 기준은 버튼이 실제로 표시하는 대상과 같으므로, 경고가 사라지면 표시가 끝난 것입니다. 3개 국어 모두 나옵니다.

### Ming Light Controller 아바타별 설정 (별매 애드온)

- VRChat용 조명·룩 제어 메뉴 생성기를 밍툰 본체에서 떼어 `Ming Light Controller (MLC)`라는 별매 애드온으로 만들었습니다. 밍툰 본체 업데이트와 아바타 메뉴 구성을 서로 독립적으로 관리할 수 있고, 런타임 메뉴가 필요 없는 사용자는 애드온을 설치하지 않아도 됩니다.
- `Ming Light Controller Settings` 컴포넌트가 생겨 표현 프로필·부착 방식·기능별 조정을 아바타 루트에 저장합니다. 예전에는 이 값들이 창 안에만 남아 마지막으로 만진 아바타의 설정이 다음 아바타를 결정했고, 스크립트를 다시 컴파일하면 사라졌습니다. 이제 한 프로젝트의 두 캐릭터가 서로 다른 메뉴와 파라미터 예산을 가질 수 있습니다.
- 프로젝트 창에서 프리팹을 우클릭해 `MingToon` > `Ming Light Controller`를 고르거나 Attachment 창의 버튼으로 붙입니다. 직접 바꾼 항목만 기록되므로 카탈로그 기본값으로 되돌리면 기록도 사라집니다. 저작 정보만 담고 런타임 동작은 없습니다.

### `성능 거리` — 멀어지면 무거운 모듈을 한 번에 끕니다

- `마스터 조정` 탭 맨 아래에 `성능 거리 (m)`(기본 10)과 `성능 거리 배율`(기본 1) 두 항목이 생겼습니다. 카메라와의 거리가 두 값의 곱을 기준으로 근·중·원 세 구간으로 나뉘고, 멀어질수록 무거운 모듈이 통째로 꺼집니다.
- 곱한 값의 0.4배 안쪽(기본 4m)은 지금까지와 완전히 같습니다. 그 바깥(기본 4~10m)에서는 깊이 효과 네 모듈·PBR·맷캡 2층 이상·노멀 2층 이상·스택 3층 이상·글리터·스크린톤·그림자 내부 반사가 꺼지고 샘플 수 상한이 한 단계 내려갑니다. 10m 밖에서는 기본 색·형태 그림자 1단·그림자 투영·아웃라인·이미션·림 셰이드·얼굴 SDF만 남습니다.
- 기존 `VRC 품질 티어`와 낮은 쪽이 적용됩니다. 중거리가 Mid, 원거리가 Low와 같은 상한이므로 품질 티어를 Low로 내려 뒀다면 가까이 가도 Low 그대로입니다.
- 판정은 오브젝트 단위(렌더러 원점과 카메라 거리)라 한 캐릭터의 모든 픽셀이 같은 구간을 씁니다. 경계에서 한 번에 바뀌며, 점진적으로 옅어지는 소멸은 지금까지대로 `공용 소멸 거리`가 담당합니다.
- 배율은 별매 애드온 MLC가 인게임 라디얼로 조절합니다. 사람이 많은 곳에서는 0으로 내려 항상 가장 가벼운 상태로 두고, 사진을 찍을 때는 올려 근거리 룩을 넓게 씁니다. 두 항목은 베이크에서 상수로 접히지 않으므로 업로드 후에도 계속 동작합니다.
- 기본값은 기존 룩을 바꾸지 않습니다. 가까이서 보는 그림은 그대로이고, 멀리 있을 때만 가벼워집니다.

### `표면 모드` 선택지 이름 정리

- `표면 모드`의 네 선택지가 렌더 큐 번호를 함께 표시하도록 이름이 바뀌었습니다: `불투명 (2000)`·`컷아웃 (2450)`·`반투명 (2499)`·`투명 (3000)`. 0.1.6의 `투명 · 아웃라인용 깊이 기록`이 `반투명 (2499)`입니다. 이름만 바뀌었고 각 모드의 렌더 상태·큐·저장된 값은 그대로이므로, 기존 재질의 그림은 달라지지 않습니다.
- 두 투명 모드의 차이를 선택지 설명에 적었습니다. `반투명 (2499)`는 알파 합성을 쓰면서 깊이도 기록합니다. 렌더 큐 2499라 카메라 깊이 텍스처에 들어가므로, 투명한 표면에서 `2D 그림자`·`2D 림라이트`·`이너 아웃라인`을 쓰려면 이 모드여야 합니다. 깊이를 가지므로 양면 머리카락처럼 가닥 안쪽이 바깥을 덮으면 안 되는 표면에 맞습니다.
- `투명 (3000)`은 표준 알파 합성입니다. 깊이를 기록하지 않고 뒤에서 앞 순서로 그리므로, 한 재질을 공유하는 몸·속바지·치마처럼 겹친 층이 서로를 지우지 않고 비쳐 보입니다. 유리처럼 다른 투명 오브젝트와 섞여야 하는 표면도 이쪽입니다. 대신 카메라 깊이 텍스처에 들어가지 않아 위 세 모듈은 쓸 수 없습니다. 두 모드 모두 아웃라인을 유지할 수 있습니다.

### `양면 듀얼패스`

- `표면 렌더링`에 `양면 듀얼패스`가 생겼습니다. `표시할 면`이 `OFF (양면)`인 표면의 뒷면을 앞면보다 먼저 따로 그립니다. 치마 자락이 자기 위로 접히는 곳에서 생기던 삼각형 톱니가 사라지고, 뒷면이 알파대로 비칩니다.
- 대가는 정점 패스 1회와 SetPass 1회입니다. 픽셀 비용은 그대로입니다 — 양면 설정은 이미 앞뒤 양쪽을 셰이딩하고 있었습니다.
- `표면 모드`와 무관하게 켤 수 있습니다. 기본값은 꺼짐이라 기존 재질의 그림은 달라지지 않습니다.

### `투명 깊이 선기록` — 투명 재질의 아웃라인이 뚫고 나오지 않습니다

- `투명 (3000)` 재질은 색을 그릴 때 깊이를 기록하지 않아, 아웃라인이 표면을 뚫고 앞으로 비쳐 나왔습니다. `표면 렌더링`의 `투명 깊이 선기록`을 켜면 깊이만 기록하는 패스를 한 번 더 그려 그 아웃라인을 걸러냅니다.
- 깊이를 스스로 기록하는 `반투명 (2499)`에는 필요 없으므로 `투명 (3000)`에서만 동작합니다.
- 접힌 부분처럼 비스듬히 보이는 면에서 뒤쪽 아웃라인이 여전히 비쳐 나오면 `아웃라인 차단 여유 (기울기)`·`아웃라인 차단 여유 (고정)`를 조금씩 올리세요. 둘 다 기본값 0이며, 과하게 올리면 실루엣 아웃라인까지 함께 지워집니다.

### `알파 페이드` — 거리와 각도로 표면을 사라지게 합니다

- `알파와 컷아웃`에 `알파 페이드` 영역이 생겼습니다. `거리 페이드 사용`은 카메라와의 거리로 표면을 사라지게 합니다. 1인칭에서 자기 머리나 액세서리가 시야를 막지 않게 하거나, 멀어질수록 사라지게 할 때 씁니다. 가까운 쪽은 `가까운 쪽 · 완전히 사라지는 거리`와 `가까운 쪽 · 완전히 보이는 거리`, 먼 쪽은 `먼 쪽 · 옅어지기 시작하는 거리`와 `먼 쪽 · 완전히 사라지는 거리`로 지정하며(단위는 미터), 한 쌍의 두 값을 같게 두면 그 지점에서 딱 끊깁니다.
- `각도 페이드 사용`은 표면이 카메라를 향한 정도로 투명도를 바꿉니다. `정면 불투명도`와 `가장자리 불투명도` 두 값이 방향을 정하므로 별도의 모드 선택이 없습니다. 노멀맵이 아니라 메시 자체의 방향을 보므로 실루엣을 따라갑니다.
- 둘 다 기본 꺼짐이고, 켠 직후의 기본 범위는 아무것도 가리지 않으므로 거리와 불투명도를 직접 지정해야 합니다. `표면 모드`가 `불투명 (2000)`이면 결과가 보이지 않습니다.
- 두 가지 주의점이 있습니다. `투명 깊이 선기록`은 페이드를 반영하지 않으므로, 페이드로 사라진 자리가 뒤쪽 반투명을 계속 가릴 수 있습니다. 그리고 페이드로 사라져도 그림자는 그대로 남습니다 — 그림자는 카메라가 아니라 조명에서 그리는 것이라 그 패스 안에 잴 수 있는 카메라 거리가 없습니다. 먼 거리 페이드로 완전히 사라뜨릴 때는 렌더러의 그림자 설정도 함께 끄세요.

### `그라데이션 LUT`와 `색조 회전 방식`

- `기본 표면`에 `그라데이션 LUT 사용`이 생겼습니다. 베이스 맵의 색을 R·G·B 채널별 램프로 다시 매핑합니다. `그라데이션 LUT`에는 가로 방향 램프 텍스처를 넣고 sRGB로 임포트하세요. `그라데이션 강도`로 원래 색과 섞는 비율을 정하며, 기본값은 꺼짐이라 끄면 램프 텍스처를 읽지 않습니다.
- 같은 자리에 `색조 회전 방식`이 생겼습니다. 베이스맵 HSVG의 색조(H)를 어느 공간에서 돌릴지 고릅니다. `OKLab`은 색조만 돌리고 밝기와 선명도를 유지해 피부·머리색을 옮길 때 결과가 예측 가능하고, `HSV`는 지금까지의 방식입니다.
- **기존 재질은 저장된 HSVG 값을 보고 자동으로 방식이 정해집니다.** 이미 HSV로 색을 맞춰 둔 재질은 `HSV`에 남아 색이 달라지지 않습니다. 새로 색조를 돌릴 때만 `OKLab`을 쓰세요.

### VRChat·WARUDO 공용 빌드 깊이 라이트

- 새 Manager에서는 기본으로 켜지지만, 깊이 마스터와 실제 깊이 효과가 하나 이상 켜졌을 때만 빌드에 싣습니다.
- 깊이 기능을 쓰지 않으면 자동 제외되고, 깊이를 제공하는 월드·호스트 전용이면 직접 끌 수 있습니다.
- VRChat과 WARUDO가 같은 설정과 판정식을 쓰며, 씬·원본 프리팹·재질 값은 빌드 후 보존됩니다.
- 깊이 라이트는 `Not Important`(ForceVertex)로 실려 라이트 섀도우맵과 ForwardAdd를 만들지 않습니다. 이 동작은 에디터 실측 기준이며 실제 VRChat 클라이언트에서는 아직 검증하지 않았습니다. 이전 업로드본에 적용하려면 다시 업로드해야 합니다.

### 5. VRChat Expressions 메뉴 제작을 MLC 애드온으로 분리

- Manager의 VRChat Expressions 설치 항목을 통째로 제거했습니다. `Modular Avatar로 비파괴 설치`, 전체 메뉴와 가벼운 메뉴를 고르던 `전체 조정 메뉴 사용`, `Expressions 루트에 직접 배치`, 설치 버튼, 그리고 이 캐릭터의 재질 전부에 `VRC 런타임 제어 사용`과 `FX 메뉴로 그림자 투영 전환`을 한 번에 켜고 끄던 일괄 버튼이 모두 없어졌습니다.

- 이전 판에서 설치해 둔 항목은 아바타에 그대로 남습니다. 제거해 주던 경로도 함께 없어졌으니 필요 없으면 직접 정리하세요.
- 재질의 `VRC 런타임 제어 사용`과 `VRC Quality Tier`는 인스펙터에 그대로 있습니다. MLC를 쓰면 이 값을 아바타 메뉴에 연결하고, 쓰지 않으면 필요한 메뉴와 애니메이션을 직접 구성할 수 있습니다.
- 같은 판 안에서 정리를 마무리해, 예전 설치기의 소스(`MingVrcVirtualLightExpressionInstaller`·`MingVrcVirtualLightContract`·`MingVrcModularAvatarBridge`)와 Manager 설치 패널의 문구도 패키지에서 제거했습니다. 재질의 `VRC 런타임 제어 사용`이 베이크에서 유지하는 프로퍼티 목록과 셰이더 프로퍼티는 그대로이며, MLC가 그 프로퍼티를 구동합니다.

### 7. 인스펙터 섹션과 프레넬 영역 정리

- 림뿐 아니라 프런트 라이트와 그림자 내부 반사도 포함하는 상위 `림` 그룹을 `스타일 조명`으로 이름을 바꿨습니다.
- 조명 항목은 `기본 설정` 안의 `그림자` 섹션으로 옮겨 `형태 그림자`→`투영 그림자`→`그림자 색상`→`그림자 패턴` 순서가 됐습니다.
- 림 계열은 `림라이트`→`림 셰이드`→`프런트 라이트`→`백라이트`→`그림자 내부 반사`, 깊이 계열은 `깊이 효과 마스터`→`2D 림라이트`→`2D 투과광`→`2D 그림자`→`이너 아웃라인` 순서입니다.
- 프레넬 계열 영역은 `폭`·`부드러움`·`영역 반전`으로 통일했습니다. 폭 0은 없음, 1은 전체 영역을 사용할 수 있습니다. 부드러움은 폭의 바깥 경계를 움직이지 않고 선택한 폭 안쪽에서만 감쇠 비율을 바꿉니다. 폭 1·부드러움 1은 단색 채움이 아니라 전체 범위 그라데이션입니다.
- 림 라이트와 그림자 내부 반사의 기존 `광원 방향 영향`은 실제 동작에 맞춰 `광원측 강조`로 명확히 했습니다. 반대쪽에 남던 0.5 밝기 바닥을 제거해 메인·가상 광원을 돌릴 때 밝은 쪽이 즉시 바뀝니다. 림 위치는 별도 `시점 기준`으로 조절합니다.
- 프런트 라이트는 프레넬 계열에서 분리해 화면상 반지름에 가까운 전용 원형 캡으로 다시 만들었습니다. `영역 크기`·`부드러움`을 직접 조절하며, `광원 방향 영향`과 새 `시선 방향 영향`으로 주광·카메라 방향 가중치를 따로 정합니다. 시선 값을 0으로 두면 카메라를 돌려도 캡이 주광 축에 고정됩니다. 같은 반지름을 재사용하는 저비용 `하이라이트 중심 크기/강도`도 추가했습니다. 프레넬용 영역 반전은 사용하지 않습니다.
- 이전 프런트 라이트의 `Border`·`AreaInvert`·`Directivity`·`ViewStrength`는 자동 변환 없이 제거했습니다. 새 시선 제어는 과거 ID를 되살리지 않는 `_FrontLightViewDirectionInfluence`입니다. 올바른 새 기본값과 공장 프리셋으로 다시 작성했으며 이 항목 시점의 재질 속성 스키마는 15, 프리셋 스키마는 10입니다. 같은 판의 이후 변경으로 재질 속성 스키마는 17까지 올라갔고, 이 판이 출하하는 값은 17입니다.
- 이전 Power/Falloff 값 5개도 숨은 호환 저장값으로 남기지 않고 자동 마이그레이션 없이 제거했습니다. 백라이트는 기존 직렬화 `Border`를 유지한 채 인스펙터에서 `폭 = 1 - Border`로 표시합니다.
- `2D 림라이트`에도 선택형 프레넬 영역을 추가했습니다. 기존 2D 림라이트 결과에 곱해지며, 끄면 이전 출력과 정확히 같습니다. `영역 반전`에서는 카메라 정면 선택을 지우던 실루엣 기하 보호만 우회하고 깊이 비교·재질 마스크는 유지합니다.

### 8. `성능 부하` 미터가 베이크 후 값을 기본으로 표시

- 아무것도 안 했는데 숫자가 예전보다 낮게 보일 수 있습니다. 재질이 바뀐 것이 아니라 기준이 바뀐 것입니다. 실제로 업로드되는 것은 베이크된 셰이더라 그 값이 대표 숫자가 됐습니다. 편집 중인 재질의 값은 상세 항목에 그대로 있습니다.

### 9. `Overlay` + `Depth2D` 조합에 안내 표시

- `패턴 방식`을 `Overlay`로 두고 `패턴 적용 대상`을 `Depth2D`로 바꾸면 안내가 나옵니다. `Overlay`는 완성된 음영 위에 선을 얹는 방식이라 형태 그림자에서만 동작하고, 2D에서는 `Recolor`로 내려갑니다. 예전부터 그랬지만 아무 표시가 없었습니다.


### 투영 경계 페더 개편과 자동 변환

- `캐스트 경계 페더 품질`의 선택지가 다섯 개에서 세 개로 줄었습니다. 이제 `Light3Tap`·`Standard5Tap`·`High9Tap`이며, 중심 1탭에 황금각으로 배치한 디스크 탭을 픽셀별 노이즈 회전으로 섞는 하나의 방식으로 통일됐습니다. 예전 방식별 반경 상한(8/20/48px)도 함께 없어져, 세 등급 모두 슬라이더 전 범위를 그대로 씁니다.
- `투영 페더 반경`의 단위가 화면 픽셀에서 2D 림라이트와 같은 카메라 보정 월드 폭으로 바뀌었습니다. 범위는 0~400(기본 60)에서 0~20(기본 3.5)이 됐습니다.
- **재질을 열면 저장된 두 값이 자동으로 변환됩니다.** 값이 초기화된 것이 아니라 새 단위로 환산된 것입니다. 품질 대응은 `Premium25Tap`·`SoftBilinear9Tap` → `High9Tap`, `Fast5Tap`·`Smooth13Tap`·`StableVogel5Tap` → `Standard5Tap`, `DerivativeEdgeAA1Tap` → `Light3Tap`입니다. 반경은 각 등급이 실제로 낼 수 있던 픽셀 폭 기준으로 환산합니다.
- **이름의 숫자가 곧 픽셀당 읽기 횟수입니다.** 이미 읽어 둔 중심 1회에 디스크 2·4·8회를 더한 값이며, 디스크는 메인 디렉셔널 라이트의 섀도우맵만 읽습니다. 카메라 깊이 텍스처는 읽지 않으므로 이 항목 때문에 깊이 프리패스가 생기지는 않습니다.
- **URP에서 디스크 탭이 가벼워졌습니다.** 프로젝트의 소프트 섀도우가 켜져 있으면 디스크 탭마다 5×5 필터가 한 번 더 펼쳐져, 픽셀당 섀도우맵 읽기가 `Standard5Tap`에서 36회, `High9Tap`에서 72회까지 올라갔습니다. 이제 각 디스크 탭은 하드웨어 비교 1회만 하므로 4회·8회입니다. 디스크 자체가 경계를 부드럽게 하는 필터라 그 위에 필터를 겹치는 것은 같은 일을 아홉 배 값에 하는 것이었습니다. 중심 탭은 URP가 이미 계산해 둔 필터된 그림자 값을 그대로 쓰므로 소프트 섀도우의 부드러움은 남습니다. 스크린스페이스 그림자를 쓰는 구성은 원래 탭당 1회였으므로 달라지지 않고, Built-in도 달라지지 않습니다. 경계가 아주 미세하게 더 또렷해질 수 있습니다.
- **`성능 부하` 미터가 이 페더를 계산에 넣습니다.** 지금까지 이 모듈은 미터에서 0으로 나와, 픽셀당 읽기가 정직하게 잡히던 2D 그림자와 나란히 놓고 비교할 수 없었습니다. 이제 페더를 켜고 끄면 미터의 숫자가 실제로 움직입니다. 다른 모듈과 같은 규약을 따라 `그림자 투영`·`투영 경계 페더`가 켜져 있고 반경과 강도가 0보다 클 때만 세며, 탭 수는 고른 등급의 2·4·8을 씁니다. 섀도우맵 읽기는 깊이 읽기와 구분해 세므로 깊이 프리패스 항목이 잘못 늘지 않습니다.

### `2D 뎁스 림`이 `2D 림라이트`로 바뀝니다

- 인스펙터에 `2D 뎁스 림`·`뎁스 림`·`깊이 림`으로 나오던 이름을 `2D 림라이트`로 통일했습니다. `깊이 림 마스크` 같은 하위 항목도 `2D 림라이트 마스크`로 따라가고, `2D`가 빠져 있던 이름에도 접두어를 붙여 맞췄습니다.
- 이 항목은 표시 이름만 바뀐 것입니다. 2D 림라이트 계열의 재질 프로퍼티 이름은 하나도 바꾸지 않았으므로(`_DepthRimEnabled`·`_DepthRimMask`·`_DepthRimWidth` 등 그대로) 이 이름 변경 때문에 다시 연결할 것은 없습니다. 다만 이번 판에는 별개의 프로퍼티 ID 정규화가 함께 들어 있으니, 위쪽 업그레이드 경고의 `_Ming` 접두어 항목을 반드시 확인하세요.

### 별매 애드온이 필요한 버튼의 동작 통일

- Mask Maker · Face SDF Studio · Ming Light Controller가 필요한 자리는 애드온이 없어도 버튼이 그대로 보이고 눌립니다. 누르면 그 기능을 설명하는 매뉴얼 페이지로 이동하며, 구매 경로도 그 페이지에 있습니다.
- 예전에는 자리마다 달랐습니다. 마스크 제작 버튼과 버텍스 페인트 시작 버튼은 회색으로 비활성화돼 마우스를 올려야 이유를 알 수 있었고, Face SDF 버튼은 안내창만 띄우고 제자리에 머물렀습니다.
- 단, `마스터 조정` 탭과 `가상 조명`은 버튼이 아니라 값을 쓰는 자리라 규칙이 다릅니다. Ming Light Controller가 없으면 MLC가 담당하는 행 — `빛을 더하는 것 전부`·`그중 가장자리에 걸리는 것만`·`그림자 전부`·`최종 출력` 네 그룹과 `가상 조명` 그룹 — 을 그리지 않습니다. 잠금 안내나 회색 컨트롤을 남기지 않고 아무것도 그리지 않으며, 애드온 없이는 값을 확정할 수 없는 죽은 컨트롤을 보여 주지 않기 위한 것입니다.
- `마스터 조정` 탭 맨 아래의 `성능 거리` 그룹은 MLC와 무관하게 동작하므로 애드온이 없어도 항상 표시됩니다. MLC가 없는 프로젝트에서 이 탭에 남는 것은 이 그룹뿐입니다.
- 어느 쪽이든 재질에 저장된 값은 그대로 남아 있고 셰이더도 계속 그 값을 씁니다. MLC를 설치하면 같은 자리에 행이 다시 나타납니다.

### 투영 그림자 수광 구조 개편

- 투영 그림자가 어두워지는 방식을 다시 짰습니다. 그림자 감쇠는 직사광 항에만 곱하고, 환경광(SH)은 그 위에 가산 바닥으로 더합니다. 통합 그림자 모드에서 죽어 있던 `캐스트 간접광 보정`이 살아나, 환경광이 밝은 씬에서 투영 그림자가 검게 뚫리지 않습니다. 환경광이 없는 씬에는 아무것도 더하지 않습니다.
- **통합 그림자(출하 기본)를 쓰는 재질은 환경광이 있는 씬에서 투영 그림자가 이전보다 밝아집니다.** 레이어 모드에서 쓰이던 옛 감면식도 이 가산 바닥으로 대체됐습니다.
- `역광 실루엣 억제`가 투영 그림자를 지우기 시작하는 지점이 고정 각도에서 형태 그림자의 실효 경계 추종으로 바뀌었습니다. 새 `캐스트 억제 오프셋`(0~1, 기본 0.25)이 그 지점을 어두운 쪽으로 얼마나 밀지 정하고, 실제 밀림량에는 `1차 그림자 번짐`의 절반이 더해져 캐스트 그림자가 사라지는 경계가 형태 그림자 안쪽에 숨습니다. `투영 그림자` 탭의 `고급 설정` 안, `역광 실루엣 억제` 바로 아래에 있습니다. 형태 그림자를 끈 재질은 예전 창을 그대로 씁니다.
- `셀프 캐스트 섀도우 억제`의 캐스터 밀어내기가 역광에서 자동으로 약해져 접지 실루엣을 지키고, 디렉셔널 라이트에만 적용됩니다. 이 토글을 켠 재질만 해당하며, 스팟·포인트 라이트 아래에서는 바이어스가 걸리지 않습니다.

### 얼굴 전용 자기면 억제 행이 `수신면 밀기` 하나로 합쳐졌습니다

- `얼굴` 탭에 따로 있던 얼굴 전용 자기면 억제 행을 없앴습니다. 같은 일을 하는 값은 이제 `2D 그림자` 탭의 `수신면 밀기` 하나이며, 얼굴과 몸이 함께 씁니다. 이 재질이 기록하는 깊이를 뒤로 밀어 자기면 얼룩을 줄이는 값이고, 카메라 깊이(`2D 그림자`·`SSAO 사용`이 읽습니다)와 라이트 섀도우맵(`그림자 투영`이 비교합니다) 양쪽에 같은 값으로 걸립니다.
- `얼굴 2D 그림자 어시스트`와 무관하게 동작합니다. 예전에는 어시스트가 켜져 있을 때만 걸려서, 출하 기본값인 어시스트 꺼짐 상태에서는 인스펙터에 보이는 슬라이더가 조용히 죽어 있었고 코 능선에 각진 그림자 덩어리가 남았습니다. 이제 `전체 효과`와 `깊이 효과 마스터`가 켜져 있고 `2D 그림자`나 `SSAO 사용` 중 하나가 켜져 있으면 그대로 듣습니다.
- 시야각 가중이 붙었습니다. 카메라를 향한 릴리프(코·뺨·이마)만 뒤로 밀려 자기 얼룩이 빠지고, 스침각으로 누운 면(턱 밑)은 실제 깊이를 유지해 턱에서 목으로 지는 그림자의 분리가 그대로 남습니다.
- **재질을 열어 `2D 그림자` 탭의 `수신면 밀기` 값을 확인하세요.** 그림자를 받는 얼굴·몸 재질에만 쓰고, 그림자를 드리우는 머리카락·의상은 0으로 두는 것이 기준입니다. 새로 만드는 재질의 기본값은 0이고, 동봉 팩토리 룩은 얼굴 슬롯에만 0.01을 씁니다.
- **슬라이더의 상한이 1에서 0.1로 내려갔습니다.** 0.1은 10cm이고, 이 지점이 효과가 끝나는 자리입니다 — 2D 그림자가 앞뒤를 판정하는 간격이 10cm에서 잘리고 SSAO 반경은 그보다 훨씬 작아, 그 위의 값은 어떤 픽셀도 바꾸지 않았습니다. 슬라이더가 효과가 끝나는 곳에서 끝나도록 맞춘 것으로, 이번 판의 `2D 그림자 바이어스` 척도 정리와 같은 정리입니다. 실제로 쓰이던 구간(기본 0, 팩토리 얼굴 0.01)은 그대로이므로 그림은 달라지지 않습니다. 재질에 0.1보다 큰 값이 저장돼 있어도 결과는 같고, 슬라이더를 한 번 움직이면 새 상한으로 정리됩니다.

### 얼굴 보정과 투영 그림자가 함께 그려집니다

- `얼굴 2D 그림자 어시스트`가 얼굴 영역에서 투영 그림자를 빼던 배타를 없앴습니다. 어시스트를 켜면 얼굴에서만 씬 그림자가 사라지던 것이 이 배타였고, 이제 얼굴에도 투영 그림자와 2D 그림자가 함께 집니다.
- 배타가 감추고 있던 정면광 자기 그림자는 원인 쪽에서 없앴습니다. Built-in에서는 얼굴의 그림자맵 기록을 카메라 깊이 밀기와 같은 양·같은 영역·같은 조건으로 광원 방향으로 함께 밀어(디렉셔널 라이트 한정), 자기 비교가 구조적으로 성립하지 않게 했습니다. 손이나 모자 같은 외부 캐스터는 원래 깊이를 유지하므로 얼굴에 정상적으로 집니다. URP는 그림자맵을 래스터 위치에서 직접 읽으므로 애초에 이 문제가 없었습니다.
- 근거가 사라진 인스펙터 경고(`2D 그림자 얼굴 보정은 Shadow Projection이 필요합니다`와 함께 있던 `Shadow Projection 켜기` 버튼)를 제거했습니다. `그림자 방식`에서 `2D 그림자 (얼굴 보정)`를 고를 때 `그림자 투영`을 강제로 켜던 동작도 없앴습니다 — 이제 그 선택은 투영 마스터를 건드리지 않습니다.

### `가산광 최종 밝기 상한`의 의미 재설계

- 이 값이 이제 HDR 인텐시티처럼 읽힙니다. 가산 효과까지 더한 **최종 출력 피크의 절대 상한**이며, 1이면 블룸 임계 1에 걸리지 않는 만큼까지만 밝아지고 1.1이면 블룸이 붙습니다. 예전에는 베이스 색 밝기의 배수로 최종 색 전체를 눌렀기 때문에, 검은 옷에서는 글리터와 림이 통째로 사라지고 상한을 올리면 장면광까지 함께 풀려 허옇게 날아갔습니다.
- 같은 값이 **가산 효과에 들어가는 조명 인텐시티도 함께 제한합니다.** 1이면 인텐시티 1까지, 3이면 3까지만 림·백라이트·프런트 라이트·투과광·맷캡·발광·글리터에 반영됩니다. 인텐시티가 큰 디렉셔널 라이트 아래에서 이 효과들이 흰색으로 타던 것이 이 제한으로 잡힙니다.
- **저장된 숫자는 그대로여도 뜻이 달라졌으므로 밝기가 달라집니다.** 검은 옷에서도 가산 효과가 보이는 쪽으로 밝아지고, 강한 조명 아래에서는 예전보다 눌립니다. `림·추가광도 상한 적용`을 끄면 두 제한이 모두 풀립니다.
- 장면광 자체의 노출은 예전처럼 `최종 최대 밝기` 소관입니다.

### SSAO 색상 조정과 색 순도

- SSAO에 `색 순도`(0~10, 기본 1), `색상 밝기`, `색상 감마`가 추가됐습니다. 기본값 1은 기존 합성 색을 유지하며, 밝기와 감마는 색상 조정 단계에서 적용됩니다. 이전 문서의 `SSAO 순도`라는 프로퍼티명은 실제 셰이더에 존재하지 않습니다.
- 림 라이트·백라이트·프런트 라이트·그림자 내부 반사·2D 림라이트·2D 투과광의 `색 순도`도 같은 0~10 범위입니다. 0은 무채색, 1은 합성된 색 그대로, 1을 넘으면 과채도입니다.
- 상한만 넓힌 것이라 저장된 값의 뜻은 그대로이고 룩도 달라지지 않습니다.

### 메뉴 경로 정리

- MingToon 메뉴가 `Tools` 아래에서 최상위 `StudioRaming > MingToon`으로 옮겨졌습니다. 이 문서의 다른 항목에 `Tools / Studio Raming / MingToon …`으로 적힌 경로도 모두 새 루트에서 찾으세요.
- 우클릭 메뉴는 루트가 `MingToon` 하나로 통일됐습니다. 하이어라키에서는 `MingToon > Add MingToon Manager`·`MingToon > Create Look Preset From Character`, 프로젝트 창에서는 `MingToon > MingToon Manager`·`MingToon > Ming Light Controller`·`MingToon > Create Look Preset From Prefab`입니다.
- 프로젝트 창에서 프리팹을 우클릭해 `MingToon > MingToon Manager`를 고르면 씬에 꺼내지 않고 바로 Manager를 붙입니다. 여러 개를 한 번에 처리하며, FBX 같은 임포트 원본은 이유를 알려 주고 건너뜁니다.
- Ming Light Controller는 `StudioRaming > Ming Light Controller > Open`과 `> Avatar Attachment`로 이관했습니다. 예전에는 같은 이름이 항목이자 하위 메뉴를 겸해 메인 창이 열리지 않았습니다.

### `얼굴 프록시 뎁스` 제거

- 실험 기능이던 `얼굴 프록시 뎁스`를 제거했습니다. 셰이더에서 기본으로 꺼진 채 컴파일에서 빠져 있어 켤 방법이 없던 기능이라 결과 화면은 달라지지 않습니다.

### `VRChat Preview` 제거

- 0.1.5에서 안내한 `Tools / Studio Raming / MingToon / VRChat Preview` 메뉴를 제거했습니다. `Authoring` / `VRChat - no camera depth` / `VRChat - camera depth available` 세 가지 화면 전환은 더 이상 없고, 대체 수단도 없습니다. 메뉴 경로가 바뀐 것이 아니므로 찾지 마세요.
- 깊이가 실제로 공급되는지 확인하려면 재질 인스펙터의 `깊이 샘플링` > `깊이 가용성`을 `Diagnostic`으로 두세요. 판정 상태가 화면에 표시됩니다.

### 포인트·스폿 조명이 `림 라이트`에 실립니다

- 추가 조명(포인트·스폿)의 색과 세기가 프레넬 림에 얇게 더해집니다. 지금까지 림은 주광에만 반응해서, 색등이 옆에서 비추는 씬에서도 실루엣 가장자리가 주광 색으로만 남았습니다. **`프레넬 림 사용`이 켜진 재질은 추가 조명이 있는 씬에서 가장자리 색이 달라집니다.**
- 더해지는 양은 `림 라이트`의 색과 `블렌드 불투명도`에 묶여 있어 조명이 여러 개여도 흰색으로 날아가지 않습니다. `프레넬 림 사용`을 끄거나 `강도`를 0으로 둔 재질에는 아무것도 더하지 않고, `성능 거리`의 원거리 구간에서는 이 항목이 통째로 빠집니다. 텍스처를 더 읽지 않습니다.
- URP에서 프레넬 림이 추가 조명을 두 번 받던 것을 BRP와 같게 맞췄습니다. 이제 두 백엔드 모두 주광은 곱셈, 추가광은 가산 한 가지 방식입니다. **URP 재질은 추가 조명이 있는 씬에서 림 색이 달라집니다.**

### 팩토리 룩의 `림 라이트` > `색 순도` 기본값이 1로

- 동봉 프리셋에 저장돼 있던 값이 10에서 1로 내려갔습니다. 순도 상한을 0~10으로 넓힐 때 프리셋 값이 상한에 붙어 저장돼, 팩토리 룩을 적용하면 림 색이 과채도로 튀었습니다. 1은 합성된 색 그대로라는 뜻이며 셰이더 기본값과 같습니다.
- 프리셋을 새로 적용할 때만 반영됩니다. 이미 만들어 둔 재질에 저장된 값은 건드리지 않습니다.

### 재질 버전이 프리셋과 JSON을 막지 않습니다

- 룩 프리셋 적용, 프리셋 저장, JSON 적용이 재질에 저장된 버전과 상관없이 그대로 동작합니다. 이전에는 이 세 경로가 구버전 재질을 거절하고 프로젝트 마이그레이션을 먼저 돌리라는 오류를 냈습니다. 그 검사와 오류, 마이그레이션을 권하던 다이얼로그를 모두 없앴습니다.
- 0.1.6에서 올라오는 공식 경로는 `Assets/StudioRaming/MingToon` 폴더를 지우고 0.1.7을 새로 임포트하는 것입니다. 프로퍼티 이름이 대폭 바뀌어 옛 값은 이어지지 않으므로, 재질은 새 기본값에서 다시 잡고 필요하면 룩 프리셋으로 되돌리세요. 베이크 산출물도 다시 구워야 합니다. 마이그레이션을 요구하는 기능은 이제 없습니다.

**개선**

### 10. 맷캡을 쓰는 아바타가 가벼워집니다

- 맷캡을 여러 장 얹은 재질일수록 차이가 큽니다. 다시 구운 뒤 `성능 부하` 미터에서 바로 보입니다. 맷캡을 쓰지 않는 재질은 그대로입니다.
- VRChat·WARUDO에 올리는 재질이 URP와 같은 비용이 됐습니다. 지금까지는 똑같이 설정한 재질이 Built-in 쪽에서만 더 무거웠습니다.

### Manager에 `최적화` 탭·예상 사양 카드·재질 선택 행

- 툴바가 다섯 탭이 됐습니다. `최적화` 탭은 텍스처 최적화와 유형별 해상도 상한을 모으고, 자동 빌드·플레이 모드 훅은 `업로드`에서 설정합니다. `최적화`의 `분석` 버튼은 이 아바타에 맞는 제안 네 가지 — 같은 설정 재질 묶어 굽기, 단색 텍스처 상수화, 마스크 텍스처 합치기, 효과 없는 모듈 끄기 — 를 보여 줍니다. 모두 기본 꺼짐이고, 선택은 이 컴퓨터의 사용자 설정에 아바타별로 기억됩니다.
- 툴바 아래의 접힌 재질 선택 도구를 열면 `모두`·`얼굴`·`얼굴·피부`·`공통`·`얼굴 제외`를 사용할 수 있습니다.
- `요약`은 현재 아바타 상태와 다음 행동을 먼저 보여 줍니다. 접힌 예상 사양 카드를 열면 머티리얼 슬롯, 예상 드로우콜(편집본/베이크본), 최대 텍스처 바인딩, 픽셀당 최대 깊이 읽기, 텍스처 메모리와 VRChat 퍼포먼스 랭크를 확인할 수 있습니다. 근사치이며 최종 수치는 SDK 빌드 패널이 기준입니다.
- 같은 화면에서 `깊이 효과`·`2D 그림자`·`SSAO 사용`·`그림자 투영`·`아웃라인`을 아바타 전체에 한 번에 켜고 끌 수 있습니다. 되돌리기가 듣습니다.

### Manager에 `투명 파츠 그리는 순서`

- Manager의 `룩·베이크` 탭 `3 · 세부 설정`에 `투명 파츠 그리는 순서`가 생겼습니다. 투명 파츠는 카메라와의 거리 순으로 그려지는데, 아바타의 스킨 메쉬는 보통 하나의 큰 공용 바운즈를 쓰기 때문에 파츠가 전부 같은 거리로 보고됩니다. 그러면 순서는 Sorting Order 값만으로 정해지고, 값이 같은 파츠끼리는 순서가 정해지지 않아 리본이 옷 뒤로 들어가는 식의 문제가 생깁니다.
- `순서가 정해지지 않은 파츠 찾기`를 누르면 거리로 구분되지 않는 묶음을 공유 머티리얼별로 찾아 줍니다. 목록에서 ▲▼로 순서를 직접 정하며, 위가 뒤·아래가 앞입니다.
- 순서를 정하지 않고 두면 Unity가 임의로 고르며, 씬을 다시 열거나 빌드할 때마다 달라질 수 있습니다.

### 베이크가 텍스처와 드로우콜을 더 줄입니다

- 마스크 없이 더해지기만 하는 맷캡 레이어를 굽는 시점에 한 장으로 합칩니다. 레이어 수와 키워드가 함께 내려갑니다.
- 슬롯이 비어 있거나 텍셀이 전부 같은 색인 텍스처는 상수로 접힙니다. 텍스처 읽기와 바인딩이 동시에 사라집니다.
- 아웃라인을 꺼 둔 재질에서 아웃라인 헐 패스를 더 이상 제출하지 않습니다(아웃라인 관련 프로퍼티에 애니메이션이 걸려 있지 않을 때). 슬롯마다 패스가 하나씩 줄어듭니다.
- `깊이 효과 마스크`와 `아웃라인 폭 마스크`가 기존 마스크 팩에 편입돼 텍스처 두 장이 줄어듭니다.
- 모두 다시 구워야 적용됩니다.

### 인스펙터와 Manager 정리

- `간단` 모드가 6그룹 22섹션으로 재편됐습니다. 형태 그림자·노멀 아웃라인·얼굴 셰이딩·깊이 효과 공통·내부 2D 경계·SSAO가 간단 모드로 들어왔고, 마스터 조정·스텐실·글리터는 `전체 설정`으로 갔습니다. 간단 모드는 섹션은 그대로 두고 실제로 자주 조정되는 값만 보여 줍니다.
- 얼굴 경계 표시는 몸의 경계와 같은 0~1 정규화 척도로 통일됐고, 얼굴 재질에서는 `형태 그림자` 탭에도 나타납니다. `마스터 조정`에는 `가장자리 림 최저 배율`이 추가됐으며, 처음 선택한 재질은 빠른 설정만 열고 나머지 섹션은 접힌 상태로 시작합니다. `2D 그림자 바이어스` 상한은 10에서 1로 정리됐습니다.
- 섹션 헤더의 `?` 버튼을 누르면 인스펙터 언어에 맞는 온라인 문서 페이지가 열립니다. 섹션 33곳이 문서 22페이지로 이어지고, Manager와 Validator 경고에서도 같은 방식으로 연결됩니다.
- 속성 툴팁을 크게 늘렸습니다. 인스펙터에 나오는 셰이더 속성 중 툴팁이 붙은 비율이 30.7%에서 41.8%가 됐고(160개 증가), 세 언어를 모두 채웠습니다.
- Manager가 `요약`·`준비`·`룩·베이크`·`업로드`·`최적화` 다섯 탭으로 정리됐습니다. `요약`에는 현재 상태와 실제 다음 버튼이 보이고, `준비`는 변환 입력을, `룩·베이크`는 변환 후 룩 재적용·재베이크를, `업로드`는 일반 자동 경로에서 현재 아바타 점검 후 고급 수동 베이크로 이어지는 흐름을, `최적화`는 중복 자동 훅 안내 없이 프로젝트 최적화를 담당합니다.
- 섹션 헤더 높이를 34에서 22로 줄이고 섹션 사이 여백도 좁혔습니다. 마스터 토글은 폭이 들쭉날쭉하던 알약 버튼에서 체크박스가 됐고, `?`·즐겨찾기·초기화 아이콘이 모든 섹션에서 같은 자리에 섭니다.
- `전부 접기`·`전부 펼치기` 버튼이 인스펙터 상단과 스크롤 고정 바 양쪽에 있습니다. 접어도 워크플로 그룹 배너는 펼쳐진 채 남아 탭 목록이 한눈에 보입니다.
- 스크롤 고정 바에 `변경값만` 보기, 부하 등급과 그 원인 모듈, 워크플로 그룹 이동 버튼, 지금 보고 있는 섹션 이름 줄(누르면 그 섹션이 접힘)이 추가됐습니다. 전체 모드에서는 검색 행의 `즐겨찾기만` 옆에도 같은 `변경값만` 버튼이 인라인으로 표시됩니다. 200% 배율에서 고정 바가 스크롤을 따라오지 않던 것도 고쳤습니다.

### VRC 라이트 볼륨은 업로드할 때 자동으로 켜집니다

- `VRC 라이트 볼륨 (테스트용)`은 에디터 확인용 토글입니다. VRChat 아바타 업로드에서는 이 값과 상관없이 켜져서 월드가 배치한 Light Volume을 라이트 프로브 대신 읽고, 업로드가 끝나면 재질에 저장된 값이 그대로 복원됩니다. 볼륨이 없는 월드에서는 프로브로 되돌아가 그림이 바뀌지 않습니다.
- 월드 빌드에서는 씬에 Light Volume 컴포넌트가 있을 때만 켭니다. 에디터에서 켜면 변형이 하나 더 컴파일되고 Texture3D를 한 번 더 읽으므로, 볼륨 월드의 룩을 미리 볼 때만 켜세요. Built-in 전용이라 URP 재질에는 이 줄이 없습니다.

### 콘솔이 조용해집니다

- 패키지에 들어가는 소스에서 개발용 콘솔 로그를 걷어냅니다. 셰이더 워밍업 진행 상황이나 베이크 내부 태그 같은 로그 27줄이 더 이상 뜨지 않습니다.
- 경고와 오류는 하나도 지우지 않았고, 작업 결과를 알려 주던 로그도 그대로 남습니다.

### 베이크 전용 매트캡 값이 남은 재질에 경고

- 베이크된 재질의 셰이더를 손으로 편집용 셰이더로 되돌리면 맷캡 아틀라스 값만 남고 레이어별 맵은 비어 있게 됩니다. 이제 이 상태에서 `맷캡 레이어` 탭 맨 위에 노란 경고 —「베이크 전용 매트캡 아틀라스 값이 남아 있어 매트캡 층이 비어 보입니다. 원본 재질을 쓰거나 다시 베이크하세요.」— 가 뜹니다.
- 맵을 되살리는 자동 복구는 없습니다. 없던 내용을 지어내는 셈이 되기 때문에 안내만 합니다 — 복원 버튼으로 원본 편집용 재질을 쓰거나 다시 구우세요. 복원·정리·백엔드 전환·마이그레이션은 베이크 사본의 셰이더를 건드리지 않으므로, 정상 경로에서는 이 경고가 나오지 않습니다.

### 성능 거리가 0인 재질을 검증기가 잡습니다

- `성능 거리 (m)` × `성능 거리 배율`이 0이면 모든 거리에서 가장 가벼운 티어로 렌더되고 깊이 효과·PBR·매트캡 2층 이상·노멀 추가 층·툰 스페큘러·글리터·스크린톤이 그려지지 않습니다. 검증기가 이 상태를 `MING-MAT-PERF-DISTANCE-ZERO`으로 보고합니다.
- 에러가 아니라 경고입니다. 0은 정상적으로 저작할 수 있는 값이고 MLC가 인게임에서 내리는 쪽 끝이기도 하므로, 의도적으로 배율을 0에 둔 재질은 그대로 두면 됩니다. 그렇지 않다면 `마스터 조정` 탭에서 `성능 거리 배율`을 올리라는 안내가 함께 나옵니다.

### 목록에서 빠져 있던 항목 정리

- 여러 재질을 한 번에 고치는 일괄 편집 패널에 `베이스맵 불투명도` 행이 생겼습니다.
- 마스크 제작 버튼이 발광 레이어 1·2의 블렌드 마스크 슬롯도 지원합니다. 이 두 슬롯만 목록에서 빠져 있었습니다.
- 유형별 텍스처 해상도 상한이 분류하지 못하던 슬롯 7개 — `반사 색상 맵`·`반사 큐브맵`·`그라데이션 LUT`과 맷캡·발광 마스크 슬롯 — 를 제자리에 넣었습니다. 상한을 걸어도 이 텍스처들만 원본 해상도로 남던 것이 없어집니다.
- 모듈 목록에 `아웃라인 마스터`가 등록됐습니다.
- 은퇴한 프로퍼티 `_DepthShadowDistanceReach`·`_SsaoQuality`·`_SsaoFarDistance`가 은퇴 목록에 없어 재질에 저장된 값이 정리되지 않고 남던 것을 고쳤습니다. `Migrate Project To Current Schema`를 돌리면 이제 함께 걷어냅니다. 이 명령은 선택 사항이며, 값이 남아 있어도 룩에는 영향이 없습니다.

### 설치·변환 후 워밍업 대기가 첫 화면에 필요한 변형까지만 기다립니다

- 설치 대기는 기본 씬이 처음 그리는 데 필요한 변형(첫 화면 예측 요청과 그 조명에 맞는 기록 변형)만 기다리고 바로 에디터를 돌려줍니다. 나머지는 Progress 창 뒤에서 같은 비동기 작업으로 계속 컴파일되며 에디터 포커스에 묶이지 않습니다.
- 첫 컴파일이 오래 걸려도 멈춤으로 오인해 순차 컴파일로 떨어지지 않도록 대기 한도를 늘렸습니다. 변환의 사전 워밍업도 진행 중인 비동기 작업에 합류합니다.
- 변환 시 메쉬 채널을 하나도 고르지 않으면 메쉬 베이크 단계를 통째로 건너뛰고, 재고정·저장 단계는 자체 진행 문구를 표시합니다.

### 얼굴용 팩토리 룩 프리셋의 2D 그림자 값 조정

- 모든 Face 프리셋의 `소프트니스`를 0.001로 통일했습니다. 2D 그림자가 켜진 세 프리셋은 `수신면 밀기`·`깊이 늘림`을 0으로 두고 `얼굴 2D 그림자 어시스트`를 끈 채 `2D 그림자 바이어스` 0.15를 씁니다. 새로 적용하는 프리셋에만 반영되며 기존 재질은 바뀌지 않습니다.

- 되돌리기 버튼이 항목 상자 밖으로 떨어져 보이고 오른쪽 여백이 과하게 넓던 것 — 버튼이 상자 안에 맞춰 붙습니다.

### 16. Face SDF Studio를 먼저 열면 밍툰 인스펙터까지 한국어로 고정되던 것

- 한국어 사용자가 아니면 영어·일본어로 되돌릴 방법이 없었습니다. 이제 시스템 언어를 따릅니다.

### 17. 얼굴 프록시 노멀이 정면광에서도 뒤집히거나 너무 좁게 반응하던 것

- 프록시 중심이 얼굴 앞쪽에 놓여도 목표 노멀이 얼굴 뒤쪽 반구를 향하지 않도록 보정했습니다.
- 별도의 평면 노멀을 섞던 `노멀 방식`을 제거했습니다. 이제 `프록시 노멀 강도` 하나만 원래 노멀과 프록시 모양 노멀을 섞습니다.
- 반지름이 실제 노멀 곡률을 정하도록 바꿨습니다. 작은 구·원기둥·캡슐은 더 둥글게, 큰 프록시는 더 완만하게 전이됩니다.
- 씬뷰 왼쪽 위 패널에서 노멀 선·프록시 볼륨 표시를 각각 끄고 켤 수 있고, 선 길이와 밀도도 실제 조명과 독립적으로 조정할 수 있습니다.
- 텍스처 얼굴 영역 마스크를 쓰는 재질은 씬뷰 노멀 선도 실제 UV·채널·반전·리맵을 따릅니다. 샘플할 수 없으면 잘못된 선을 그리지 않고 이유와 함께 숨깁니다.

### 18. 업로드·변환 중단 복구 강화

- VRChat 얼굴 노멀 베이크는 빌드용 Face 슬롯을 임시 재질로 격리해 처리합니다. 씬의 원본 Mesh·재질과 다른 아바타가 공유하는 재질은 수정하지 않습니다.
- 얼굴 노멀 최적화 대상 build root에서 Mesh가 연결된 모든 Renderer의 원래 Mesh·재질 슬롯을 먼저 기록합니다. 후속 업로드 변환이 비-Face Renderer의 Mesh를 바꿔도 복원하며, 스크립트 리로드나 에디터 재시작 뒤에도 저널과 임시 재질 소유권을 이어서 복구합니다.
- 일반 변환은 Renderer·Mesh·재질·Prefab override·dirty 상태를 변경 전에 먼저 기록합니다. 저널은 `ProjectSettings`에 원자적으로 저장하고 손상된 주 파일은 백업에서 복구하며, 이전 `Library` 저널은 한 번만 이관합니다. 자동 복구가 8회 실패하면 Advanced 메뉴에서 다시 시도하거나, 내용을 확인한 뒤 복구 저널만 폐기할 수 있습니다.

### 에디터를 켤 때마다 `Startup recovery is incomplete` 오류가 반복되던 것

- 빌드가 중단된 뒤 그 재질이 삭제되면 복구가 영원히 끝날 수 없는데, 도메인 리로드마다 다시 시도하며 빨간 오류를 새로 찍었습니다. 스크립트를 다시 컴파일하거나 플레이 모드에 들어갈 때마다 나던 것이 이 원인입니다.
- 이제 첫 시도는 임포트가 끝나기를 기다리고, 프로젝트에서 사라진 재질의 기록만 이름과 함께 한 번 정리합니다. 세 번까지 되돌리지 못했을 때만 어떤 재질이 남았는지와 조치 방법을 경고 한 줄로 알리고 그 뒤로는 조용합니다. 빌드·업로드 도중의 복구 실패는 예전처럼 빌드를 막습니다.

### 노멀·깊이 계산의 정밀도와 백엔드 불일치 네 건

- 노멀 레이어를 반전과 최대 강도로 겹친 픽셀에서 계산이 넘쳐 노멀 스택이 통째로 사라질 수 있던 것을 고쳤습니다. 2D 그림자와 2D 림라이트가 쓰는 방향 벡터에서도 같은 한계를 함께 고쳤습니다.
- 탄젠트가 거의 0인 픽셀에서 BRP와 URP가 서로 다른 탄젠트 프레임을 만들던 것, 2D 그림자의 깊이 배치 폴백이 한쪽은 앞을 다른 쪽은 뒤를 향하던 것을 양쪽 같은 식으로 맞췄습니다.
- 앞의 두 건은 half 정밀도를 실제로 쓰는 GPU에서만 드러나는 방어적 수정이고, 뒤의 두 건은 PC에서도 나던 BRP·URP 결과 차이입니다. 셰이더 컴파일 게이트로 확인했으며 실기 렌더 검증은 하지 않았습니다.

### `한 슬롯 / 타일 지역` 창에서 지역을 되돌릴 수 없던 것

- 지역 체크를 끄고 적용해도 이미 쓴 슬롯이 그대로 남아, 한 번 적용한 지역은 이 도구로는 지울 방법이 없었습니다. 이제 적용이 네 슬롯 전부에 반영되어 꺼 둔 지역은 재질에서 실제로 빠집니다.
- **이 창은 재질의 현재 값을 읽어 오지 않습니다.** 스택·노멀·맷캡 슬롯이 이미 채워진 재질에 빈 창 상태로 적용하면 그 슬롯이 비워지므로, 적용 전에 창의 지역 구성을 먼저 맞추세요. 되돌리기(Ctrl+Z)는 듣습니다.

### `그라데이션 LUT 사용`을 켜도 아무 일이 없던 것

- 이 모듈의 셰이더 키워드가 BRP·URP 어느 쪽에도 선언돼 있지 않아, 켜도 램프가 적용되지 않고 컴파일에서 통째로 빠졌습니다. 이제 실제로 동작합니다.
- **`그라데이션 LUT 사용`을 이미 켜 둔 재질은 룩이 달라집니다.** 지금까지 무시되던 램프가 이제 베이스 색에 적용되기 때문입니다. 예전 그림이 필요하면 이 항목을 끄세요.
- UV 스크롤·회전·아틀라스 애니메이션을 쓰는 재질에서 Built-in만 램프를 건너뛰던 것도 함께 맞췄습니다.
- 다시 구워야 적용됩니다.

### `렌더 비활성화`가 투명 깊이 선기록 패스를 끄지 못하던 것

- `렌더 비활성화 (이 재질을 그리지 않음)`는 화면 패스의 드로우를 막고, Built-in·URP의 깊이·그림자 패스도 정점 단계에서 제거합니다. 따라서 숨긴 재질은 카메라 깊이·라이트 섀도우맵에 기록되지 않아 2D 그림자, SSAO, 투영 그림자를 만들지 않습니다. 숨겨 둔 이전 재질은 다음 선택 또는 프로젝트 마이그레이션 때 자동으로 치유됩니다.

### 프리팹에서 룩 프리셋을 만들면 다른 작업까지 함께 저장되던 것

- 프로젝트 창의 `MingToon > Create Look Preset From Prefab`이 저장 시점에 프로젝트 전체의 저장하지 않은 변경까지 디스크에 썼습니다. 이제 이 작업이 실제로 만들거나 덮어쓴 프리셋 에셋만 저장합니다.

### 얼굴 프록시 씬뷰 미리보기가 만들어지지 않던 것

- 미리보기가 자기 임시 재질을 읽고 "얼굴이 없다"고 판정해, 노멀 선을 그릴 데이터를 아예 만들지 않았습니다. 이제 원본 재질 값을 기준으로 판정합니다.

### lilToon 변환에서 발광 채널 설정이 이전 값으로 남던 것

- 변환이 발광 맵과 마스크는 새로 쓰면서 `채널 소스`·`소스 색 반전`과 블렌드 마스크의 채널·반전은 변환 전 재질 값을 그대로 두어, 두 발광 레이어의 결과가 원본과 달라질 수 있었습니다. 이제 변환이 이 값들을 함께 초기화합니다.

### Ming Light Controller — 포토 룩 비트를 고정한 구성이 설치에서 거부되던 것

- 포토 룩 비트를 고정값으로 잠근 구성이 설치 단계에서 "대상 바인딩 없음" 오류로 거부되던 문제를 수정했습니다.

### Face SDF 자동 갱신 중 수동으로 바꾼 맵 보존

- Face SDF Studio의 자동 갱신이 대기 중일 때 사용자가 외부 또는 공유 Face SDF 맵을 연결하면, 이전 자동 작업이 그 맵을 덮어쓰지 않도록 적용 직전에 연결 상태를 다시 확인합니다.

### 0.1.6 생성 프로필 정리의 재질 참조 확인

- 하나의 에셋 파일에 포함된 여러 재질까지 확인해 현재 셰이더로 전환합니다. 먼저 저장 가능한지 검사하고, 변경 후에는 저장된 참조를 다시 읽어 확인합니다. 저장할 수 없거나 결과를 확인하지 못하면 기존 생성 프로필을 남겨 두고 정리를 미완료로 유지합니다.

### 자동 카메라 설정 해제와 기존 설정 보존

- 인스펙터에서 자동 카메라 설정을 꺼도 자동으로 적용한 설정이 해제됩니다. 기존 후처리 레이어를 사용한 경우에는 사용자가 나중에 변경한 레이어 마스크와 볼륨 기준 설정을 덮어쓰지 않습니다.

### 컴파일 실패를 웜업 완료로 기록하던 문제

- 셰이더 변형을 웜업한 뒤 컴파일 오류를 확인합니다. 오류가 있는 변형은 준비 완료로 기록하지 않고 실패 원인을 알립니다.

### 에디터 재시작 후 같은 마스크 팩 재사용

- 프로젝트에 저장된 원본 마스크와 설정이 같으면 에디터를 다시 열어도 같은 마스크 팩을 재사용합니다. 기존 팩은 삭제하거나 이름을 바꾸지 않으므로, 이 변경을 처음 적용할 때는 새 팩이 한 번 생성될 수 있습니다.

### 알파 마스크·영역 마스크 재질의 빌드용 셰이더가 컴파일에 실패하던 문제

- 알파 마스크나 영역 마스크를 쓰는 재질의 베이크된 프로파일이 D3D11에서 컴파일에 실패해, 빌드 훅이 그 재질을 편집용 셰이더로 남긴 채 업로드하던 문제를 고쳤습니다. 편집용 셰이더의 변형 전체가 아바타 번들에 들어가 업로드가 약 5분 길어지던 원인입니다.
- 이미 올린 아바타는 재업로드해야 이 수정을 받습니다.

### 변환 완료 창의 NullReferenceException

- 메쉬 채널을 고르지 않아 메쉬 베이크를 건너뛴 변환에서, 변환 자체는 끝났는데 완료 창 제목을 만들다 NullReferenceException이 나던 문제를 고쳤습니다.

### NDMF 생성 클론의 레코드가 남아 VRChat 빌드가 계속 막히던 문제

- NDMF가 빌드 후 지우는 `Packages/nadena.dev.ndmf/__Generated/` 클론 머티리얼의 복구 레코드가 저널에 남아, 이후 모든 VRChat 빌드가 `Material recovery is incomplete`로 막히던 문제를 고쳤습니다. 머티리얼 소실 판정이 GUID 매핑만 보던 것을 실제 파일 존재로 바꿨고, 그런 레코드는 다음 복원 시점에 경고 한 줄과 함께 정리됩니다.
- 이미 이 상태에 빠진 프로젝트도 업데이트 후 첫 빌드나 에디터 재시작 때 자동으로 정리됩니다.
