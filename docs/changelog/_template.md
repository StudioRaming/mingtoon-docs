  2. 아래 섹션 순서를 지킵니다. 해당 없는 섹션은 통째로 지웁니다.
     순서는 한 줄 요약, 업데이트 전 확인, 새 기능, 바뀐 기본값과 룩 변화,
     수정된 문제, 알려진 제한, 하단 링크입니다.
  3. 각 항목은 사용자에게 보이는 변화로 시작합니다.
     캐시·계산 공유·코드 정리처럼 화면에 결과가 없는 변경은 쓰지 않습니다.
       나쁨: 반복 계산 감소 — 재사용할 수 있는 조명·노멀 계산을 공유하고…
       좋음: 같은 아바타를 다시 베이크할 때 대기 시간이 줄어듭니다.
  4. `새 기능` 항목은 인스펙터 라벨로 시작합니다. 라벨이 없으면 새 기능이 아닙니다.
  5. `수정된 문제`는 증상으로 씁니다.
       나쁨: 복원 안정성 개선
       좋음: 베이크를 취소하면 재질이 편집용으로 돌아오지 않던 문제
  6. 성능 변화는 숫자 없이 쓰지 않습니다. 없으면 "체감 차이는 환경마다 다릅니다"만 붙입니다.
  7. 면책 문단을 본문 사이에 끼우지 않습니다. `알려진 제한`으로 모읍니다.
  8. UI 라벨은 인스펙터 문구 그대로 굵게, 백틱은 메뉴 경로와 파일 이름에만 씁니다.
     라벨 정본: MingToon 소스의 Editor/InspectorUx/MingInspectorText.cs
  9. 앵커는 한국어 원본 그대로 세 언어에 씁니다. 없는 앵커를 쓰면 빌드가 실패합니다.
 10. Admonition은 v3 문법만 씁니다. `:::warning[제목]` — 대괄호 필수.
     `:::warning`은 상단 "업데이트 전 확인" 하나만 씁니다.
 11. 한 문장 60자 이내, 한 페이지 80줄 이내, 이모지 금지.
