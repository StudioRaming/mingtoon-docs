*클로즈 베타 · 2026-08-09*

## 업그레이드 시 확인할 것

:::caution[VRChat 아바타 재업로드 필요]
**이번 업데이트 후 VRChat 아바타를 재업로드해야 수정이 반영됩니다.** 셰이더가 아바타 에셋번들에 동봉되므로, 이미 업로드된 아바타는 구버전 셰이더를 계속 사용합니다.
:::

## 버그 수정

- **업로드 최적화 결함으로 아바타가 새하얀 현상이 사라집니다** — 업로드 최적화(베이크) 시 꺼놓은 모듈이 강제로 켜지던 결함을 고쳤습니다. 이전에는 `이미션 사용`을 껐는데 기본 흰 맵으로 전면 발광하거나, `2D 그림자 마스크` 같은 모듈이 꺼져 있는데도 작동하는 현상이 일어났습니다. 이것이 거울이나 포스트 없는 카메라에서 아바타가 "새하얗게 빛나는" 신고의 근본 원인이었습니다. → [문서](/workflow/build-optimization)
  - 이미 생성된 베이크 셰이더는 재생성되므로, 이 수정을 적용받으려면 **아바타를 재업로드해야** 합니다.
- **거울 안에서 깊이 효과가 정상화됩니다** — VRChat 거울 안에서 `2D 그림자`와 `깊이 림`이 플레이어 고개를 돌릴 때마다 몸을 따라오지 않고 미끄러지던 문제를 고쳤습니다. → [문서](/guides/depth-effects#플랫폼별-깊이-확보)
  - 거울 카메라는 자기 깊이 텍스처를 렌더하지 않는데, 플레이어 카메라의 깊이 버퍼가 계속 바인드되어 있어 셰이더가 남의 실루엣을 읽고 있었습니다. 이제 거울 안에서는 깊이 관련 모듈이 자동으로 내려갑니다.
  - `깊이 가용성`의 의미가 조금 달라집니다. `Force On`은 이제 "호스트가 보고하지 못하는 경우까지 켠다, **단 거울은 제외**"를 뜻합니다.
- **무광 월드와 Disable Pixel Lights 거울에서 명암이 정상입니다** — 리얼타임 디렉셔널 라이트가 없는 월드나 Disable Pixel Lights 거울에서 아바타의 명암 구조가 무너지고 창백하게 뜨던 문제를 고쳤습니다.
  - 이제 앰비언트 프로브에서 키 라이트(방향과 색)를 합성하여 어디서나 정상적인 셰이딩을 유지합니다. 디렉셔널 라이트가 있는 월드에서는 변화가 없습니다.
- **lilToon 변환이 옮겨온 데이터의 토글을 이제 켠다** — lilToon의 `PBR 표면 사용`, `이미션 사용`, `서페이스 스택 사용`, `아웃라인 마스터`, `클래식 헐` 토글이 켜져 있던 머티리얼을 변환할 때, 값은 받았는데 모듈이 꺼진 채로 나오던 문제를 고쳤습니다. → [문서](/workflow/liltoon-conversion)
  - lilToon의 `_UseReflection`(반사)이 켜져 있었으면 MingToon의 `PBR 표면 사용`도 켜서 나옵니다. 이미션 텍스처 없이 색만으로 발광하던 머티리얼도 그대로 재현됩니다. 스택의 2단·3단 레이어 데이터도 받습니다. 아웃라인은 방향과 두께를 정확히 받습니다.
  - `헐 두께` 기본값도 작가가 설정한 값을 받습니다. lilToon에서는 아웃라인이 없던 머티리얼까지 두께 1로 켜져 나오던 일이 없습니다.
- **`노멀 소스`를 `VertexColorTS`로 두면 아웃라인이 정상입니다** — 아웃라인의 `노멀 소스`를 `VertexColorTS`로 고르면서 메시에 버텍스 컬러가 없을 때 아웃라인이 대각선 방향으로 통째로 밀려 나가던 문제를 고쳤습니다. 이제 메시 노멀로 내려가서 툴팁의 설명대로 동작합니다. → [문서](/guides/outline#노멀-아웃라인)
- **탄젠트 없는 파츠 하나가 얼굴·높이 베이크까지 망치던 것이 고쳐집니다** — 변환 중 메시에 탄젠트나 노멀이 없으면 아웃라인, 얼굴, 높이 3단계가 한꺼번에 실패하던 것을 고쳤습니다. 이제 그 렌더러만 건너뛰고 어느 메시인지 콘솔에 알려줍니다.
- **여러 렌더러가 공유하던 메시가 베이크에서 제대로 합쳐집니다** — 같은 메시를 N개 렌더러가 공유할 때 베이크가 사본 N개를 따로 만들던 것을 고쳤습니다. 이제 소스 메시마다 에셋 하나를 만들고 모든 렌더러가 그것을 공유합니다.
- **변환이 사용자 모델의 UV8을 확인 없이 덮어쓰던 것이 고쳐집니다** — 변환이 원본 모델의 UV8을 `기존 채널 덮어쓰기` 옵션과 무관하게 지웠습니다. 옵션이 꺼져 있으면 이제 건너뛰고 보고합니다.
- **아웃라인 UV8 베이크가 이미 구운 캐릭터를 거절하지 않습니다** — 하위 메시 중 하나라도 UV8을 가지면 캐릭터 전체가 실패하던 것을 고쳤습니다. 이제 MingToon이 구운 UV8은 건너뛰고, 사용자 모델의 원래 UV8만 거절하며 어느 메시인지 이름으로 알려줍니다. → [문서](/guides/mesh-bakes#아웃라인-스무스-노멀-uv8)
- **`Unified Shadow Color Map` 토글이 모든 모드에서 동작합니다** — `Unified Shadow Color Map`을 끄면 이제 어떤 컴파일 모드에서도 확실히 꺼집니다. 이전에는 광역 컴파일 모드가 켜져 있으면 이 행이 동작하지 않던 경우가 있었습니다.
- **월드 제작 프로젝트에서 임포트가 컴파일 에러로 깨지던 문제 수정** — 아바타 SDK가 없는 VRChat 월드 프로젝트에 MingToon이나 변환된 아바타를 넣으면 `VRCExpressionsMenu` 컴파일 에러(CS0246)로 프로젝트 전체가 깨지던 문제를 고쳤습니다. 표현식 메뉴 설치기는 아바타 업로드 전용 기능이므로, 월드 프로젝트에서는 자동으로 컴파일에서 제외됩니다.
- **머티리얼을 선택하면 아웃라인만 보이던 현상이 근본적으로 사라집니다** — Unity 2022 프로젝트에서 머티리얼을 선택하거나 편집하는 순간 베이스가 사라지고 아웃라인만 남던 현상의 근본 원인을 찾아 고쳤습니다. 컴파일을 아무리 기다려도 재발하던 환경에서도 더 이상 나타나지 않습니다. → [문서](/guides/texture-modules#마스크-세부-설정)
  - 이를 위해 레이어 마스크(서페이스 스택·노멀·매트캡)가 내부적으로 통합 텍스처로 자동 합성됩니다. 마스크를 슬롯마다 넣는 사용법과 채널 선택·반전·리맵 등 모든 조절값은 그대로이며, GPU가 읽는 텍스처 수가 줄어 렌더링도 가벼워집니다. 합성본은 `MingToonGenerated/MaskPacks` 폴더에 자동 생성·공유되므로 직접 관리할 필요가 없습니다.
- **변환할 때 선택한 룩 프리셋이 그대로 적용됩니다** — 프리셋을 골라 놓아도 첫 변환에서 목록 맨 위의 프리셋(하드 툰)이 적용되던 문제를 고쳤습니다. 스크립트 리로드나 오브젝트 재선택 뒤에도 골라 둔 프리셋이 유지됩니다.
- **룩 프리셋이 변환으로 옮겨온 레이어 콘텐츠를 건드리지 않습니다** — 변환이 옮겨온 매트캡·노멀 레이어·서페이스 스택이 룩 프리셋 적용과 함께 꺼지거나, 합성 모드가 전부 `Add`로 바뀌어 곱하기 매트캡이 빛나던 문제를 고쳤습니다. → [문서](/workflow/character-manager#1--변환)
  - 룩 프리셋은 이제 그림자·림 같은 "룩"만 다루고, 캐릭터가 가진 레이어 콘텐츠(활성 여부·합성 모드·강도 포함)는 그대로 둡니다. 해당 탭 전용으로 저장한 탭 프리셋만 그 값을 바꿀 수 있습니다.
- **VRChat 빌드 훅 등록 로그가 실제로 표시됩니다** — 매뉴얼에 안내된 `[MingToon] VRChat build hook compiled and registered.` 확인 로그가 사용자 환경에서 표시되지 않던 문제를 고쳤습니다. 이제 에디터 세션당 한 번 콘솔에 표시되어, 업로드 최적화 훅이 살아 있는지 바로 확인할 수 있습니다. → [문서](/workflow/build-optimization#제대로-걸렸는지-확인하기)

## 작업 경험 — 컴파일 대기 제거

- **인스펙터 토글이 더 이상 셰이더 컴파일을 기다리지 않습니다** — `글리터 마스크 사용`, `마스크 사용`(그림자 반사), `2D 그림자 마스크`, `깊이 림 마스크`, `내부 경계 마스크`, `영역 마스크 사용`, `2차 그림자 사용` 등 인스펙터의 7개 토글을 켜고 끌 때 인스펙터가 멈추던 셰이더 재컴파일(토글당 2~6초)이 사라졌습니다.
  - 레이어 드롭다운도 마찬가지입니다. 컴파일 대기 없이 즉시 값을 바꿀 수 있습니다.
  - `Base Tint After HSVG` 행도 마찬가지입니다. 키워드 대신 float 분기로 제어하도록 바뀌어, 토글하는 순간 바로 적용됩니다.
  - `Face Shading Module` 토글(얼굴/일반 역할 전환)도 다른 토글처럼 재컴파일 없이 즉시 적용됩니다.
  - 편집용 셰이더에서 관련 키워드를 항상 켜 두고, 실제 on/off는 float 값으로 결정하므로 그려지는 그림은 전혀 바뀌지 않습니다. 인스펙터 기본값과 베이크 동작도 그대로입니다.
  - 이를 위해 `Compile All Modules While Authoring` 설정이 기본 켜짐으로 바뀌었습니다. 처음 켜질 때 콘솔에 한 줄 안내가 나오며, 원치 않으면 MingToon 인스펙터의 일괄 편집 패널에서 끌 수 있습니다. 켜 둔 채 빌드/업로드해도 불필요한 키워드는 자동으로 정리되어 나가므로 결과물 부담이 없습니다.
- **셰이더 컴파일이 패키지 설치 시 한 번에 끝납니다** — 패키지를 임포트하면 설치 컴파일이 곧바로 실행됩니다(취소 가능한 진행바 표시). 병렬 컴파일로 처음 설치가 수 분 안에 끝나며, 이후 변환·머티리얼 선택·편집 중에 컴파일 창이 뜨거나 아웃라인만 보이는 대기 구간이 없습니다. "기다림은 설치 때 한 번"이 이번 버전의 컴파일 모델입니다.
  - 변환 결과물이 쓰는 조합(컷아웃, 매트캡·노멀·스택이 켜진 상태 포함)까지 설치 시점에 미리 컴파일됩니다. 머티리얼을 선택해도 그리는 조합이 바뀌지 않도록 저장 상태와 표시 상태가 항상 일치합니다.
  - 워밍업 상태는 `Library/StudioRaming/MingToon.warmup`에 기록됩니다. 셰이더 소스나 유니티 버전, 그래픽 API가 바뀌면 자동으로 무효가 되어 재컴파일되고, 취소한 지점부터 다음 실행이 이어받습니다.
  - 수동 메뉴도 유지됩니다. `Tools > Studio Raming > MingToon`의 `Warm up shader variants`(설치 플랜), `Warm up selected materials`, `Verify warm-up`, `Warm-up status`, `Measure warm-up cache effect`.
- **변환 진행 상황이 단계별로 표시됩니다** — 변환 버튼을 누른 뒤 "Hold on (busy)"만 뜨던 구간에 단계별 진행바(머티리얼 변환 → 룩 프리셋 → 메시 베이크)가 표시됩니다.
  - 변환 완료 시 단계별 소요 시간이 콘솔 한 줄로 기록되어, 변환이 오래 걸리는 경우 어느 단계가 원인인지 바로 확인할 수 있습니다.
- **아웃라인 UV8 베이크가 필요할 때 알려주고, 범위와 결과를 미리 밝힙니다** — `노멀 소스`가 `UV8TS`(기본값)인데 메시에 UV8이 없으면 MingToon Manager 최상단에 경고 메시지와 베이크 버튼이 나타납니다. 조건에 맞지 않는 캐릭터에게는 아무것도 그려지지 않습니다. → [문서](/guides/mesh-bakes#아웃라인-스무스-노멀-uv8)
  - 베이크 버튼 위에 "어디에 새 메시를 만들고, 원본 FBX는 수정하지 않으며, 몇 개 렌더러를 처리할 것인지"를 표시합니다. 결과 메시지에는 탄젠트 없어서 메시 노멀로 남은 정점 수도 보고합니다.
- **프로젝트 전체 머티리얼 키워드 정리 메뉴가 추가됩니다** — `Tools > Studio Raming > MingToon > Heal Material Keywords (Project)` 메뉴가 새로 생겼습니다. 프로젝트의 모든 MingToon 머티리얼의 저장된 키워드와 패스 상태를 인스펙터 값과 일치시킵니다. 실행 전 확인 후 변경 파일은 `TempBackups/MingToonKeywordHeal/`에 백업되고, 취소할 수 있으며, 결과는 콘솔에 한 줄 기록됩니다.

## 기능 추가·제거

- **VRC Light Volumes 월드의 간접광을 읽습니다 (기본 꺼짐)** — `VRC 라이트 볼륨`이라는 새 행이 추가되었습니다. VRC Light Volumes를 쓰는 월드에서 아바타의 `간접광 보정`과 그림자 색조가 유니티 프로브 대신 방의 Light Volume을 따릅니다. Built-in 셰이더에만 적용됩니다.
  - 기본값은 꺼짐입니다. 켜도 Light Volume이 없는 환경에서는 프로브로 되돌아가므로, 어디서나 그림이 달라지거나 깨지지 않습니다.
- **`깊이 가용성`에 진단 모드 추가** — `깊이 가용성`에 `Diagnostic`이라는 네 번째 선택지가 추가되었습니다. VRChat에서 깊이 효과가 아바타 전체에 번지는 현상을 신고할 때, 이 모드로 셰이더가 실제로 읽는 깊이 텍스처를 단색으로 칠해 진단할 수 있습니다. → [문서](/guides/depth-effects#플랫폼별-깊이-확보)
  - 색상 판독표는 다음과 같습니다. 검정은 깊이 텍스처가 없음, 빨강은 텍스처가 있으나 이 화면의 버퍼가 아님(크기가 다르거나 거울), 노랑은 있고 크기도 맞음, 파랑 채널은 호스트가 직접 깊이 가용을 보고함을 뜻합니다. 이 모드는 **버그 신고 때만 쓰는 진단용**이므로 일반 사용에는 적합하지 않습니다.
- **일괄 편집 패널에 그림자 컬러맵 두 줄이 추가됩니다** — `그림자 컬러맵 사용`과 `컬러맵 적용량` 두 행이 일괄 편집 패널에 나타났습니다. 일반 인스펙터에서는 이미 그려지던 것이 일괄 편집에도 추가되어, 여러 머티리얼을 선택하고 한 번에 이 값을 설정할 수 있습니다. → [문서](/guides/bulk-editing#일괄-설정-패널)
- **Missing Depth Fallback(프레넬 폴백) 기능이 제거됩니다** — 깊이가 없을 때 `깊이 림`이 프레넬 림으로 자동 폴백되던 기능이 제거되었습니다. 깊이 모듈은 이제 깊이 데이터가 없으면 조용히 내려갑니다. Fresnel Rim을 쓰던 재질은 해당 림이 사라집니다. → [문서](/guides/depth-effects#깊이-림-2d-림)
- **아웃라인이 훨씬 가벼워집니다** — 아웃라인(클래식 헐)의 픽셀 비용이 약 1/3로 줄었습니다. 아웃라인은 이제 베이스 맵 색과 조명 응답만으로 그려지고, 본체의 그림자 패턴·투사 그림자·깊이 효과를 아웃라인 위에 다시 그리지 않습니다. → [문서](/guides/outline#아웃라인-색이-조명을-따라가게)
  - `Outline Include Shading`은 유지되지만 동작이 바뀝니다. 켜면 본체의 폼 섀도 색을 따르는 가벼운 명암 밴드가 아웃라인에 적용되고, 이전처럼 본체 셰이딩 전체를 복제하지는 않습니다. 굵은 아웃라인의 명암 인상은 유지하면서 비용만 내려갑니다.
