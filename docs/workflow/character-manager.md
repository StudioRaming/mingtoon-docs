# 밍툰 매니저

**이 문서를 읽으면** 아바타 하나를 처음부터 끝까지 — 변환 · 룩 · 메시 베이크 · 최적화 · 업로드 점검 — 한 컴포넌트에서 진행할 수 있습니다.

재질 하나씩이 아니라 **아바타 단위 작업**은 전부 여기서 합니다.

## 붙이기

변환할 캐릭터의 **루트 오브젝트**를 선택하고

`GameObject > Studio Raming > MingToon > Add MingToon Manager`

Add Component에서 `MingToon Manager`를 찾아 붙여도 됩니다. **루트에 붙인 다음 변환을 진행하면 됩니다.**

<!-- SCREENSHOT: 밍툰 매니저 인스펙터 전체 -->

## 인스펙터 구성

| 단계 | 하는 일 |
|---|---|
| **1 · 변환** | 다른 셰이더 → MingToon, Face / Skin / Common 역할, 변환 룩 |
| **2 · 설정** | 캐릭터 범위, 에디터·Warudo 미리보기, 런타임 얼굴 방향 |
| **3 · 세부 설정** | 룩 재적용, 얼굴 SDF 연결, UV4·UV8 메시 베이크, Live 얼굴 노멀 복귀 |
| **4 · 출하** | 경량 셰이더, 텍스처 상한, VRC 메뉴, 업로드 준비·플랫폼 점검 |

위쪽 상태 패널은 현재 재질 구성에 맞춰 다음 단계를 안내합니다. `텍스처 최적화`는 캐릭터가 아니라 프로젝트 전체에 적용되는 별도 설정입니다.

위쪽에 **자주 쓰는 기능**과 **상태 패널**이 항상 떠 있습니다.

---

## 상태 패널 {#상태-패널}

매니저를 열면 지금 상태가 먼저 보입니다. `새로고침`으로 다시 셉니다.

| 표시 | 의미 |
|---|---|
| `MingToon N · 변환 가능 N · 변환 제외 N · 기타 N` | 재질 구성 |
| `셰이딩 상태` — `편집용 N · 베이크됨 N` | 어떤 재질이 베이크되었는지 |
| `얼굴 슬롯` | 아래 참고 |
| `빌드/업로드 시 자동 최적화` | 훅이 켜져 있는지 |
| `최적화 범위` | 아래 참고 |

:::danger[얼굴 모듈 키워드가 어긋났다면]
`얼굴 슬롯 N개 중 M개의 얼굴 모듈 키워드가 재질 값과 어긋나 있습니다. 이 상태로 베이크하면 얼굴 셰이딩이 빠집니다.`

`얼굴 모듈 동기화` 버튼을 누르면 맞춰집니다. **베이크 전에 반드시 해소하세요.**
:::

:::caution[최적화 범위가 오래됐다면]
`최적화 범위가 렌더러 N개 중 M개뿐입니다. 캐시가 오래되어 나머지는 최적화 없이 업로드됩니다.`

의상을 붙이거나 뺀 뒤에는 `하위 렌더러 다시 찾기`를 눌러 주세요.
:::

## 1 · 변환 {#1--변환}

### 어떤 셰이더에서 옮길 수 있나

**lilToon 재질이 가장 완전하게 옮겨집니다.** Standard, URP Lit 등 다른 셰이더도 변환할 수 있으며, 이 경우 베이스 색·텍스처·노멀·이미션·오클루전과 렌더 상태가 옮겨지고 나머지는 MingToon 기본값이 됩니다.

인스펙터가 어떤 규칙으로 읽는지 표시합니다 — `원본 스키마: lilToon` 또는 `원본 스키마: Unity 표준 재질 규칙`.

### 변환되지 않는 슬롯 {#변환되지-않는-슬롯}

일부 재질은 **일부러 건드리지 않고 원본 그대로 둡니다.**

| 계열 | |
|---|---|
| 파티클 / VFX | 굴절 / 보석 |
| 퍼 / 쉘 | 오디오 반응 |
| 플립북 / 스크롤 / 시간 애니메이션 | 외곽선 전용 / 오버레이 / 보조 패스 |

MingToon이 그대로 옮길 수 없는 표현이기 때문입니다. 상태 패널의 `변환 제외` 개수로 확인할 수 있습니다.

:::caution[전부 제외 대상이면 버튼이 아무 일도 안 합니다]
`읽을 수 있는 슬롯 N개가 모두 변환 제외 대상입니다.` 가 뜨면 변환 버튼을 눌러도 바뀌는 것이 없습니다.
:::

### 얼굴 · 피부 지정 — 가장 중요한 단계 {#얼굴--피부-지정--가장-중요한-단계}

:::danger[Auto는 이름으로 추측하지 않습니다]
`Auto`는 **원본 재질이 직접 가진 얼굴 플래그만** 읽습니다.

따라서 **플래그가 없는 셰이더에서 변환하면 전부 `Regular`로 남습니다.** 얼굴로 쓸 슬롯은 **직접 `Face`로 지정해야 합니다.**
:::

슬롯마다 `Auto` / `Face` / `Skin` / `Regular` 를 고정할 수 있고, 한 렌더러 안의 얼굴·눈·속눈썹도 따로 지정할 수 있습니다. 미리보기에 `얼굴 셰이딩` · `피부 룩` · `일반 셰이딩` 중 무엇이 적용될지 표시됩니다.

렌더러 단위로 한 번에 지정할 수도 있습니다.

- `얼굴 렌더러 직접 지정`
- `피부 렌더러 직접 지정` — 여기 지정한 렌더러의 재질은 룩 프리셋의 **Skin 값**을 받습니다. **맨살 전용**입니다.
- `지정한 렌더러에 역할 표시`

:::caution[옷과 머리카락이 같은 렌더러에 있다면]
피부 렌더러로 지정하면 옷까지 Skin 값을 받습니다. 변환한 뒤 슬롯별 목록에서 **옷 슬롯을 `Regular`로 되돌리세요.**
:::

:::note[밍툰 매니저를 여러 개 선택하면]
슬롯별 판정이 비활성화됩니다. **한 번에 하나만** 선택하세요.
:::

### 변환 시 룩 프리셋 {#변환-시-룩-프리셋}

변환과 동시에 룩 값을 채워 넣습니다.

:::danger[프리셋은 약 500개 값을 덮어씁니다]
`프리셋은 변환 직후 재질의 수치와 색상 약 500개를 한꺼번에 덮어씁니다. 변환 전에 손본 값이 있다면 None을 고르세요.`
:::

얼굴로 판정된 재질에는 얼굴용, 피부로 판정된 재질에는 피부용, 나머지에는 공용 값이 들어갑니다. SDF 프레이밍·베이크 결과·텍스처 유무처럼 **캐릭터마다 다른 값은 프리셋에 없습니다.**

`이 에디터에서 마지막으로 적용한 프리셋`이 표시되므로 무엇을 씌웠는지 나중에 확인할 수 있습니다.

### 함께 구울 메시 채널 {#함께-구울-메쉬-채널}

변환 직후 필요한 정적 채널만 굽습니다.

| 채널 | 무엇을 위해 |
|---|---|
| `아웃라인 스무스 노멀 (UV8)` | 각진 부분에서 아웃라인이 끊기지 않게 |
| `캐릭터 높이 그라데이션 (UV4)` | 루트 기준 높이 그라데이션 |
| `이미 사용 중인 UV 채널 덮어쓰기` | 소유권을 확인한 재변환에서만 사용 |

0.1.7의 얼굴 노멀은 편집 중 Live로 계산하므로 **변환 단계에서 UV7을 기본 베이크하지 않습니다.** VRChat 업로드 때 업로드 복사본에만 자동 베이크합니다. 텍스처 얼굴 영역 마스크 또는 Face SDF가 UV7을 소유하면 결과를 보존하기 위해 Live 경로를 유지합니다.

`UV 채널 사용 현황`에서 UV4·UV7·UV8의 소유권을 먼저 확인하세요. → [메시 UV 베이크](/guides/mesh-bakes)

### 복구

변환은 Renderer·Mesh·재질·Prefab override·dirty 상태를 영속 저널로 기록합니다. 각 영속 변경 직전에 계획 상태를 먼저 저장하므로, 변경 직후 에디터가 종료되는 구간도 복구할 수 있습니다. 저널은 `ProjectSettings`에 원자적으로 기록되고 손상된 주 파일은 백업에서 복구하며, 이전 버전의 `Library` 저널은 한 번만 이관합니다. 사용자가 나중에 바꾼 상태는 덮어쓰지 않고 보류하고, 자동 복구가 8회 실패하면 `Tools > Studio Raming > MingToon > Advanced`에서 다시 시도할 수 있습니다.

`원본 머티리얼 복구`는 **현재 슬롯만** 원본 재질로 되돌립니다. 변환 재질이나 메시 UV 베이크는 삭제하지 않습니다.

:::caution[복원은 하나의 Undo 단계입니다]
되돌리면 **직전에 직접 수정한 내용까지 함께 사라질 수 있습니다.**
:::

`변환 짝 검사`로 변환 재질과 원본의 짝을 확인할 수 있습니다. 원본 기록이 없는 재질은 프로젝트 전체를 훑기 때문에 시간이 걸려서, **버튼을 눌렀을 때만** 실행됩니다.

| 항목 | 하는 일 |
|---|---|

### 에디터 런타임 미리보기

:::caution[VRChat에는 실리지 않습니다]
이 두 그룹은 에디터와 Warudo처럼 스크립트를 유지하는 환경에서만 동작합니다. VRChat에서는 컴포넌트가 `IEditorOnly`로 표시되지만 자동 삭제는 보장되지 않습니다. SDK 처리 뒤 실제 build clone에서 MingToon 런타임 컴포넌트가 0개인지 검증하고, 이 그룹의 런타임 결과를 아바타 외형으로 기대하지 마세요.
:::

`룩 프로필 사용` · `에디트 모드에서도 미리보기` · `룩 프로필`

### 런타임 얼굴 방향

`머리 방향 전달`을 켜면 머리 본의 방향을 셰이더에 넘겨 얼굴 셰이딩이 머리를 따라갑니다.

- `머리 본` — 비우면 자동 판정
- `머리 축 자동 판정` · `머리 로컬 정면` · `머리 로컬 위쪽`

:::note[Warudo에서는 별도 Runtime Root가 필요하지 않습니다]
Warudo 모드에서는 밍툰 매니저 컴포넌트가 그대로 유지됩니다. 별도 Runtime Root를 프리팹에 붙이지 마세요. 2D 림·2D 그림자·SSAO처럼 카메라 깊이가 필요한 효과는 캐릭터 컴포넌트가 아니라 전역 Playground 플러그인 `MingToonWarudoDepthBridge.cs`를 설치해야 합니다. → [Warudo Depth Bridge](/platforms/warudo#warudo-depth-bridge)
:::

## 3 · 세부 설정

`개별 메시 베이크` — 1단계 변환의 체크박스를 껐거나 그 베이크가 실패했을 때만 필요합니다. 이미 채워진 채널에는 `덮어쓰기`를 켜지 않는 한 거부합니다.

`캐릭터 높이 UV4`와 `아웃라인 스무스 노멀 UV8`을 개별로 실행할 수 있습니다. 얼굴 노멀은 Live가 기본입니다. 예전 변환에서 `_FaceNormalBaked`가 남아 프록시 조정이 반영되지 않으면 `얼굴 노멀 실시간으로 되돌리기`를 실행하세요. 이 작업은 재질의 baked 플래그와 잘못된 Face SDF UV7 선택을 한 Undo 단계로 정리합니다. → [메시 UV 베이크](/guides/mesh-bakes)

## 룩 / 얼굴

변환된 재질에 룩 프리셋을 적용합니다.

아직 변환 전이면 `아직 MingToon 재질이 없습니다. 2단계 변환을 먼저 실행하면 여기서 룩 프리셋을 적용할 수 있습니다.` 가 표시됩니다.

### 얼굴 SDF

`프론트뷰 SDF TEXCOORD6 (Unity UV7) 베이커 열기`

:::note[Face SDF Studio는 별도 제품입니다]
설치돼 있으면 이 버튼이 Studio를 엽니다. 설치되지 않았다면 구매·설치 안내가 표시됩니다. Studio가 없어도 MingToon의 페이스 셰이딩과 Base UV 얼굴 SDF는 사용할 수 있습니다.
:::

→ [얼굴 SDF 오소링](/guides/face-sdf)

## 4 · 출하 {#4--출하}

### 최적화 / 베이크

:::tip[대부분의 경우 건너뛰어도 됩니다]
VRChat 업로드와 Warudo 모드 빌드에서는 [빌드 시 자동 최적화](/workflow/build-optimization)가 알아서 걸리고, 재질은 편집 가능한 상태로 남습니다.
:::

`경량 셰이더 베이크 (에디터 전용)` · `애니메이션 가능 패스 보존 (안전)`

:::caution[텍스처 최적화는 프로젝트 전체 설정입니다]
베이스·노멀·마스크 등 슬롯 종류별 업로드 해상도 상한과 `업로드 시에도 텍스처 재작성 (옵트인)`은 에디터 환경설정에 저장됩니다. 씬·프리팹에는 들어가지 않고 이 프로젝트에서 출하하는 모든 캐릭터에 적용됩니다. 업로드 복사본만 바꾸며 원본 텍스처는 보존합니다.
:::

→ [수동 Bake와 복원](/workflow/bake-and-restore)

### VRChat 표현식 메뉴 {#vrchat-표현식-메뉴}

Unity 2022.3 VCC 프로젝트에서 `밍툰 매니저`가 Virtual Light와 품질 메뉴를
준비합니다. 기본 전체 메뉴에는 Palette, Master Adjust, Photo Looks도 포함됩니다.

1. Avatar Root 아래의 `MingToon Manager`를 선택합니다.
2. `Modular Avatar로 비파괴 설치`를 켭니다. 기본값은 켜짐입니다.
3. `전체 조정 메뉴 사용`을 고릅니다. 켜면 전체 77비트, 끄면 가벼운 31비트입니다.
4. 메뉴 위치를 고르고 Scene 또는 Prefab을 저장한 뒤 Manager Inspector를 다시 엽니다.
5. Gesture Manager에서 선택한 `MingToon Controls` 구성을 확인합니다.
6. VRChat SDK Builder에서 업로드합니다. 메뉴·파라미터·FX는 build clone에 합쳐집니다.

Modular Avatar가 없어도 MingToon은 컴파일됩니다. 직접 병합하려면 토글을 끈 뒤
`원클릭으로 VRC 메뉴 등록`을 사용합니다.

:::caution[Expression Parameters 예산]
- **전체 메뉴(기본):** 총 28개 / 동기화 21개·77비트 / 로컬 명령 7개·0비트
- **가벼운 메뉴:** 총 12개 / 동기화 10개·31비트 / 로컬 명령 2개·0비트

기존 아바타와 합친 타입 충돌, 256비트 예산, 메뉴당 8칸을 검사하고 실패하면
변경을 되돌립니다.
:::

두 프로필 모두 Virtual Light 핵심, High/Mid/Low, Shadow Projection, Reset을
유지합니다. 전체 메뉴만 8색×4채도 Palette, Highlight / Shadow / Final Output의
독립 Intensity·Tint 양, Photo Looks 8종을 추가합니다. 프로필을 바꿔 다시 설치하면
더 이상 쓰지 않는 MingToon 파라미터·FX 레이어·생성 메뉴를 정리합니다.

`Expressions 루트에 직접 배치`를 켜면 전체 메뉴는
`Virtual Light`·`Master Adjust`·`Reset All`, 가벼운 메뉴는
`Virtual Light`·`Quality`·`Reset All`을 루트에 둡니다. Photo Looks는 자기
아바타 결과만 동기화합니다. 내 화면의 다른 아바타를 일괄 제어하려면 월드/Udon이
필요해 이번 아바타 설치에는 포함하지 않습니다.
### 내보내기 / 검증 {#내보내기--검증}

#### 업로드 준비 점검 {#업로드-준비-점검}

`준비 상태 검사` — 계층과 Manifest를 모두 훑기 때문에 **버튼을 눌렀을 때만** 실행됩니다.

결과는 `업로드를 막는 문제는 없습니다. 경고 N건.` 또는 `업로드를 막는 오류가 N건 있습니다.` 로 나오고, 검사 범위(`렌더러 · 재질 · 편집용 · 베이크됨`)가 함께 표시됩니다. 각 항목의 `위치` 버튼으로 해당 오브젝트를 바로 찾아갈 수 있습니다.

주요 진단 항목:

| 분류 | 항목 |
|---|---|
| **베이크** | 베이크 Manifest가 없음 · Manifest에 기록 없음 · 이전 Generator 버전 · 베이크 이후 원본이 바뀜 · 원본 재질을 찾을 수 없음 |
| **베이크 문맥** | 캐릭터 의존성 추적 이전 버전 · 베이크 이후 애니메이션이나 룩 프로필이 바뀜 · 베이크한 매니저를 찾을 수 없음 |
| **생성 셰이더** | 없음 · 기록과 다름 · 컴파일 오류 |
| **컴포넌트** | MingToon 런타임 컴포넌트가 있음 · 스크립트가 깨진 컴포넌트가 있음 |
| **얼굴 SDF** | SDF용 UV가 없음 · SDF 텍스처가 없음 · 준비됐지만 얼굴 모듈이 꺼짐 |
| **기타** | 호스트의 깊이 텍스처가 필요함 · 예전 이름으로 걸린 애니메이션 바인딩 |

`프로젝트 설정 검사`로 [Validate Project](/reference/validator)도 여기서 실행할 수 있습니다.

:::note[깊이 Auto는 업로드에서 바뀌지 않습니다]
`Auto`는 바인딩된 깊이 텍스처와 Photo Camera 상태를 직접 읽으며 업로드에서 `Force On`으로 승격되지 않습니다. 일반 화면 깊이가 필요하면 별도 옵트인 `업로드 시 깊이 라이트 싣기`의 비용을 확인하세요. → [빌드 시 자동 최적화](/workflow/build-optimization#vrchat-깊이-자동-승격)
:::

#### VRChat 사전 점검

`규칙 버전 · 검증된 Unity` 가 표시되고, 아래를 검사합니다.

- **없는 표준 프로퍼티** — fallback이 값을 이어받는 데 필요합니다. `폴백 프로퍼티 동기화`로 갱신할 수 있습니다.
- **VRChat이 허용하지 않는 컴포넌트** 개수

→ [VRChat 호환성 규칙](/internals/vrc-rules)

#### Quest / Android

`MingToon은 Quest(Android) 빌드를 지원하지 않습니다.` Quest용 변형을 만들 계획이라면 **아래 기능은 모두 빠진다고 보세요.**

`Quest에서 잃는 항목` — `아웃라인 N · 반투명 N · 깊이 효과 N` 으로 실제 개수를 세어 줍니다.

#### 스크립트 제거 점검

:::danger[MingToon 컴포넌트는 직접 지우지 마세요]
저작 씬의 MingToon 컴포넌트는 직접 지우지 마세요. 매니저를 지우면 캐시된 렌더러 목록이 사라져 업로드 최적화가 범위를 잃습니다. 이 컴포넌트들은 `IEditorOnly`로 표시되지만 자동 삭제는 보장되지 않으므로, SDK 처리 뒤 실제 build clone에서 `RuntimeComponentCount = 0`인지 검증하세요.

Warudo 모드는 **스크립트를 유지하는** 별도 규칙을 따릅니다. 이 패널은 검사만 합니다.
:::

## 전체 흐름 요약

```text
루트에 밍툰 매니저 붙이기
        ↓
1 · 변환      역할 지정 → 변환 룩 선택 → 변환 → 손실 보고서 확인
        ↓
2 · 설정      범위 갱신 → 에디터·Warudo 미리보기와 얼굴 방향
        ↓
3 · 세부 설정 룩 재적용 → SDF 연결 → 필요할 때 UV4·UV8 베이크
        ↓
4 · 출하      텍스처 상한 → VRC 메뉴 → 자동/수동 베이크 → 준비 상태 검사 → 업로드
```

Warudo로 내보낼 때 별도 Runtime Root는 필요하지 않습니다. 깊이 효과를 쓴다면 [Warudo Depth Bridge](/platforms/warudo#warudo-depth-bridge)를 Playground에 설치하세요.
