# MingToon Manager

**이 문서를 읽으면** 아바타 하나를 처음부터 끝까지 — 변환 · 룩 · 메시 베이크 · 최적화 · 업로드 점검 — 한 컴포넌트에서 진행할 수 있습니다.

재질 하나씩이 아니라 **아바타 단위 작업**은 전부 여기서 합니다.

## 붙이기

아바타 최상위 GameObject를 선택하고 `GameObject > Studio Raming > MingToon > Add MingToon Manager`.

{/* SCREENSHOT: MingToon Manager 인스펙터 전체 */}

인스펙터가 5단계로 나뉩니다. 위에서 아래로 진행하면 됩니다.

| 단계 | 하는 일 |
|---|---|
| **1 · 설정** | 캐릭터 범위와 렌더러 파악 |
| **2 · 변환** | lilToon → MingToon, 얼굴 판정, 메시 채널 베이크 |
| **3 · 룩 / 얼굴** | 얼굴 SDF UV 준비 |
| **4 · 최적화 / 베이크** | 경량 셰이더 베이크 |
| **5 · 내보내기 / 검증** | 스크립트 제거 점검 |

---

## 1 · 설정

| 항목 | 하는 일 |
|---|---|
| `캐릭터 범위` | 어디까지를 이 캐릭터로 볼지 |
| `캐시된 렌더러` | 찾아낸 렌더러 수 |
| `MingToon 재질 슬롯` | 관리 대상 슬롯 수 |
| `하위 렌더러 다시 찾기` | 의상을 붙이거나 뺀 뒤 실행 |
| `모든 MingToon 재질 선택` | 하위 재질을 전부 선택해 [일괄 편집](/guides/bulk-editing)으로 넘김 |
| `프로필 지금 적용` / `프로필 미리보기 해제` | 룩 프로필 적용/해제 |

:::tip 의상을 갈아입힌 뒤에는
`하위 렌더러 다시 찾기`를 먼저 누르세요. 캐시가 낡으면 새 파츠가 변환·베이크에서 빠집니다.
:::

### 캐릭터 높이 UV4

| 항목 | 하는 일 |
|---|---|
| `선택 캐릭터 전체 UV4 베이크` | 캐릭터 **전체**의 루트 기준 높이를 모든 메시 UV4.x에 굽습니다 |
| `기존 UV4 덮어쓰기` | 이미 UV4를 쓰는 메시가 있을 때만 필요 |
| `하위 모든 MingToon 재질에 일괄 적용` | 구운 뒤 재질들의 높이 설정을 한 번에 맞춥니다 |

상태 표시가 `일부 메시의 UV4가 이미 사용 중입니다.` 이면 덮어쓰기를 켤지 판단하고, `모든 메시에 UV4 높이를 베이크할 준비가 됐습니다.` 이면 그대로 진행하면 됩니다.

→ [캐릭터 높이 그라데이션](/guides/character#캐릭터-높이-그라데이션)

## 2 · 변환

### lilToon 빠른 변환

새 **편집용** MingToon 재질을 만들고 원본 lilToon 재질은 **보존**합니다.

:::note 전부 성공해야 교체합니다
모든 변환이 성공한 뒤에만 하위 렌더러 슬롯을 교체합니다. 중간에 실패하면 아무것도 바뀌지 않습니다. MingToon 그림자·아웃라인 기본값은 유지됩니다.
:::

| 항목 | 하는 일 |
|---|---|
| `변환 재질 저장 폴더` | 비워 두면 원본 재질이 있던 폴더 아래 `MingToon` 폴더에 저장 |
| `하위 lilToon 재질을 MingToon으로 변환` | 실행 |

### 얼굴 슬롯 판정 — 가장 중요한 단계

:::danger 여기를 대충 넘기면 얼굴이 몸 규칙으로 셰이딩됩니다
`재질 슬롯별 얼굴 판정`에서 **슬롯마다** `Auto` / `Face` / `Regular`를 고정할 수 있습니다. 한 렌더러 안의 얼굴·눈·속눈썹을 각각 다르게 지정할 수 있습니다.
:::

`Auto`는 재질/렌더러 이름과 원본 플래그로 판정하며, 각 슬롯 옆에 **판정 근거**가 표시됩니다.

| 표시 | 의미 |
|---|---|
| 오브젝트/렌더러 지정 | `얼굴 렌더러 직접 지정`·`얼굴 오브젝트 직접 지정`으로 사람이 지정 |
| 재질 직접 지정 · 재질 슬롯 지정 | 슬롯 단위로 사람이 고정 |
| 원본 얼굴 플래그 | 원본 셰이더가 얼굴이라고 표시 |
| 재질 이름 판정 · 렌더러 문맥 판정 | **이름 기반 추측** |
| 전체 변환 모드 · 일반 기본값 | 판정 근거 없음 |

**"재질 이름 판정"이나 "일반 기본값"으로 뜬 슬롯은 직접 확인하세요.** 미리보기에 `얼굴 셰이딩` / `일반 셰이딩` 중 무엇이 적용될지 표시됩니다.

:::caution 여러 캐릭터 루트를 함께 선택하면
슬롯별 얼굴 판정이 비활성화됩니다(`여러 캐릭터 루트가 선택되어 있습니다.`). **한 번에 한 루트만** 선택하세요.
:::

### 변환 시 룩 프리셋

변환과 동시에 룩 값을 채워 넣습니다.

| 옵션 | 범위 |
|---|---|
| `적용 안 함` | 변환만 |
| `그림자 색상까지 덮어쓰기` | |
| `프레넬 설정까지 덮어쓰기` | |

얼굴로 판정된 재질에는 얼굴용 값이, 나머지에는 공용 값이 들어갑니다.

:::note 프리셋에 없는 것
SDF 프레이밍, 베이크 결과, 텍스처 유무처럼 **캐릭터마다 다른 값**은 프리셋에 들어 있지 않습니다.
:::

나중에 `선택 프리셋을 현재 MingToon 재질에 일괄 적용`으로 다시 씌울 수 있습니다. **텍스처·UV·베이크는 유지한 채 룩 값만** 바뀝니다.

### 함께 구울 메쉬 채널

변환 직후 체크한 채널을 자동으로 굽습니다.

| 채널 | 무엇을 위해 | 문서 |
|---|---|---|
| `아웃라인 스무스 노멀 (UV8)` | 각진 부분에서 아웃라인이 끊기지 않게 | [메시 베이크](/guides/mesh-bakes#아웃라인-스무스-노멀-uv8) |
| `얼굴 프론트뷰 노멀 (UV7)` | 셰이더만으로 얼굴 SDF | [메시 베이크](/guides/mesh-bakes#얼굴-프론트뷰-노멀-uv7) |
| `캐릭터 높이 그라데이션 (UV4)` | 높이 기반 색 그라데이션 | [메시 베이크](/guides/mesh-bakes#캐릭터-높이-uv4) |
| `이미 사용 중인 UV 채널 덮어쓰기` | | |

:::tip 변환 직후에 굽는 이유
재질 변환이 끝난 뒤 실행되므로 **얼굴 노멀 베이커가 어떤 서브메시가 얼굴인지 알 수 있습니다.** 나중에 따로 굽는 것보다 정확합니다.
:::

:::caution 선택한 UV 데이터는 렌더러마다 하나의 통합 메시 에셋에 함께 저장됩니다
채널을 나눠서 여러 번 구울 계획이라면 이 점을 염두에 두세요.
:::

UV4를 굽지 않으면 높이 그라데이션이 자동으로 꺼집니다 (`UV4를 굽지 않아 재질 N개에서 높이 그라데이션을 껐습니다.`).

### 원본으로 되돌리기

`원본 lilToon 머티리얼 복구`는 **현재 슬롯만** 원본 재질로 되돌립니다. 변환 재질이나 메시 UV 베이크는 **삭제하지 않습니다.**

변환 재질이 원본 lilToon GUID를 저장하고 있어서 가능한 동작입니다. 결과에 `정확한 원본 GUID가 없거나 원본을 찾지 못한 슬롯: N개` 가 나오면 그 슬롯은 수동으로 되돌려야 합니다.

### 변환 결과 읽기

완료 시 Console에 이렇게 남습니다.

```text
MingToon lilToon 변환 완료: 슬롯 12개, 머티리얼 8개, 손실·미지원 기능 5건. 원본은 그대로 보존했습니다.
```

**`손실·미지원 기능` 건수가 0이 아니면 Console 보고서를 끝까지 읽으세요.** 무엇이 옮겨지지 않았는지 항목별로 나옵니다. → [lilToon 변환](/workflow/liltoon-conversion)

## 3 · 룩 / 얼굴

### 얼굴 SDF UV 준비 (WARUDO / VRC)

현재 씬의 **프론트뷰를 복제 메시의 TEXCOORD6 (Unity UV7)에 투영**합니다.

셰이더만으로 4방향 얼굴 SDF가 동작하므로, **런타임 노멀 공급자 컴포넌트 없이** WARUDO와 VRChat에서 안정적으로 동작합니다. 스크립트를 제거해야 하는 배포에서 중요합니다.

1. `프론트뷰 SDF TEXCOORD6 (Unity UV7) 베이커 열기`
2. 씬 뷰에서 얼굴을 정면으로 잡습니다.
3. 굽습니다.

`원본 메시 복원`으로 되돌릴 수 있습니다.

→ [메시 베이크](/guides/mesh-bakes#얼굴-프론트뷰-노멀-uv7)

## 4 · 최적화 / 베이크

:::tip 대부분의 경우 이 단계를 건너뛰어도 됩니다
VRChat 업로드와 Warudo 모드 빌드에서는 [빌드 시 자동 최적화](/workflow/build-optimization)가 알아서 걸리고, 재질은 편집 가능한 상태로 남습니다. 여기 있는 **경량 셰이더 베이크는 재질을 실제로 교체**하므로 되돌리는 작업이 따릅니다.
:::

`경량 셰이더 베이크 (에디터 전용)` — 베이커와 Manifest 코드는 에디터에서만 실행되고, 생성 결과는 Shader / Material / Texture만으로 렌더링됩니다.

:::danger 애니메이션이 있으면 `애니메이션 가능 패스 보존 (안전)`을 켜세요
베이크는 **현재 레이어 수와 Alpha Mask / Emission / Occlusion 활성 상태를 기준으로** 코드를 제거합니다. Animator나 AnimationClip이 나중에 그 기능을 켜는 재질 애니메이션은 베이크 결과에서 **동작하지 않을 수 있습니다.**
:::

완료 로그:

```text
MingToon 베이크 완료: 렌더러 12개, 슬롯 18개, 머티리얼 8개, 생성 셰이더 5개.
```

→ [수동 Bake와 복원](/workflow/bake-and-restore)

## 5 · 내보내기 / 검증

`스크립트 제거 / 업로드 점검`

| 표시 | 의미 |
|---|---|
| `하위 MingToon 런타임 컴포넌트: 0` + `스크립트 없이 동작 가능한 상태입니다.` | ✅ 업로드 가능 |
| 컴포넌트가 남아 있음 | ⚠️ 아래 참고 |

:::caution 이 패널은 검사만 합니다
`VRC 또는 명시적으로 스크립트를 제거하는 배포에서는 이 컴포넌트들을 build clone에서 제거하세요.` — **원본 Hierarchy를 삭제하지 않습니다.** Warudo 모드는 별도 플랫폼 규칙을 따릅니다.
:::

→ [VRChat 업로드 체크리스트](/platforms/vrchat#업로드-체크리스트)

## 전체 흐름 요약

```text
1 · 설정            렌더러 다시 찾기
        ↓
2 · 변환            얼굴 슬롯 판정 확인 → 룩 프리셋 → UV8/UV7/UV4 함께 굽기 → 변환
        ↓           손실 보고서 읽기
3 · 룩 / 얼굴       재질별 룩 조정 (룩 만들기 문서)
        ↓           필요하면 얼굴 SDF 프론트뷰 베이크
4 · 최적화          보통 건너뜀 — 빌드 시 자동 최적화로 충분
        ↓
5 · 검증            런타임 컴포넌트 0개 확인 → 업로드
```
