0.1.13

정식 배포 · 2026년 10월 11일

이 글은 0.1.13 정식 버전의 변경 내역입니다.

한 줄 요약​

업데이트 뒤 검게 나오던 셰이더 문제와 다른 아바타 도구 연동 문제를 고쳤습니다.

업데이트 전 확인
  • 백업: 중요한 프로젝트는 먼저 백업하고, 별도 사본에서 확인하세요.
  • 재베이크: 생성기 버전이 104로 올랐습니다. 기존 베이크는 오래된 베이크로 표시되니 복원 후 다시 베이크하세요.
  • 재업로드: 변환한 아바타는 새 버전으로 다시 변환하고 다시 업로드해야 반영됩니다.
  • 맷캡 캐시: 맷캡 생성 캐시가 텍스처 샘플러 설정을 구분하도록 바뀌어, 업데이트 뒤 기존 맷캡 생성 캐시가 한 번 다시 만들어집니다.
  • 첫 실행: 업데이트 뒤 첫 실행에서 MingToon 폴더를 한 번 다시 임포트하므로 시간이 걸릴 수 있습니다. 진행 중에는 Unity를 닫지 마세요.

바뀐 기본값과 룩 변화​

  • 깊이 라이트는 VRChat 업로드에서 기본 꺼짐으로 실리고, 본인과 친구에게만 켜집니다. 보는 사람의 안전 설정 등으로 애니메이션이 막혀도 비친구에게는 꺼진 채로 남습니다. 비친구에게도 깊이 효과 보이기를 켜면 이전처럼 모두에게 켜집니다.
  • NDMF를 쓰는 프로젝트에서는 업로드 준비를 NDMF 빌드 안에서 실행하며, 다른 도구가 아바타를 바꾼 뒤의 모습을 기준으로 준비합니다. NDMF가 없는 프로젝트는 VRChat SDK 빌드 단계에서 실행합니다.
  • VRC Light Volumes v3.0.0-dev.21에 대응합니다. v2 월드도 v3 경로로 받으며, 볼륨에 구운 포인트 라이트 차폐가 더 이상 반영되지 않아 벽 너머의 포인트 라이트가 비쳐 보일 수 있습니다. v3 월드와 Light Volumes가 없는 월드는 그대로입니다.
  • 점 그림자 다이얼을 인스펙터에서 제거했습니다.

수정된 문제​

  • 업데이트 뒤 아바타가 검게 나오거나 셰이더 오류가 나던 문제를 고쳤습니다. 업데이트된 셰이더 파일이 변경으로 인식되지 않아 예전 셰이더와 섞여 컴파일되던 것이 원인이었고, 패키지 파일 시각이 버전마다 달라지도록 했습니다.
  • 설치 뒤 셰이더 준비가 에디터를 멈추게 하던 동기 대기 창을 없앴습니다. 준비는 지금 쓰는 렌더 파이프라인만 컴파일하며, 진행 상황은 Unity 오른쪽 아래 Background Tasks에 나옵니다.
  • Unity 2021.3 초기 버전(예: 2021.3.18f1)에서 MingToon을 임포트하면 C# 컴파일 오류가 나던 문제를 고쳤습니다. VRChat(2022.3)과 WARUDO(2021.3.45f2) 환경에는 변화가 없습니다.
  • 경량화 도구(AAO, LAC 등)가 준비 뒤 재질을 바꿔 영수증이 맞지 않아도 업로드를 막지 않습니다. 경고를 남기고 그 재질을 일반 경로로 처리합니다.
  • 폴더 이름이 정확히 lilToon이 아니어도(버전이 붙은 이름 등) lilToon 재질을 변환 대상으로 인식합니다.
  • 메쉬를 교체할 때 블렌드셰이프 값을 유지합니다. 이름이 맞지 않으면 경고합니다.
  • 변환 복사본에 Missing Script가 있으면 변환이 멈추던 문제를 고쳤습니다. 복사본에서만 Missing Script를 지우며 원본은 바뀌지 않습니다. 프리팹 저장에 실패해도 변환된 오브젝트와 새 재질은 씬에 남으니 결과 화면의 안내대로 씬을 저장하세요.
  • 머티리얼을 바꾸는 토글 애니메이션이 변환 후에도 lilToon 재질을 가리키던 문제를 고쳤습니다. 업로드용 빌드 복사본에서만 클립의 재질 참조를 변환된 MingToon 재질로 바꾸며, 원본 애니메이션 클립과 컨트롤러는 바뀌지 않습니다. Auto Optimize를 켜도 꺼도 적용됩니다. 변환 기록이 없는 재질이나 하나의 원본에 변환 재질이 둘 이상인 경우는 건드리지 않고 경고합니다. 변환 기록이 생기기 전에 마법사로 만든 복사본은 구조가 같으면 같은 방식으로 바꿉니다.
  • 업로드 뒤 복원 때 "Preserved a user keyword edit" 거짓 경고가 뜨고 일부 키워드가 원래대로 돌아오지 않던 문제를 고쳤습니다.
  • VRCFury Build an Editor Test Copy를 d4rkAvatarOptimizer나 TexTransTool과 함께 쓸 때, 사본이 빌드 전 재질로 되돌아가 머리카락이 안 그려지거나 텍스처가 어긋나던 문제를 고쳤습니다.
  • Test Copy나 수동 베이크 사본이 남아 있는 동안 그 사본이 쓰는 빌드 파일을 지우지 않으며, 사본을 지우면 정리합니다.
  • 수동 베이크 사본이 원본 MingToon 재질의 깊이 앵커 값을 바꾸던 문제를 고쳤습니다.
  • d4rkAvatarOptimizer의 Write Properties as Static Values를 켜면 d4rk가 만든 MingToon 셰이더 사본에 컴파일 오류가 나던 문제를 고쳤습니다. 다른 도구가 MingToon 셰이더를 고쳐 쓴 사본은 업로드 때 경고합니다. 그 사본의 모양은 MingToon이 보장할 수 없습니다.
  • TexTransTool 아틀라스 뒤에도 텍스처가 어긋나지 않도록, MingToon 텍스처마다 쓰는 UV를 TexTransTool에 알려 줍니다.
  • 메쉬를 다시 만드는 도구가 MingToon이 메쉬에 구운 UV 데이터(아웃라인 등)를 지우면, 업로드 때 경고하고 그 데이터를 쓰는 효과를 안전한 값으로 돌립니다.
  • 업로드 끝에 MingToon 재질이 제대로 남았는지 다시 검사하고, 다른 도구가 재질이나 셰이더를 바꾸면 어느 슬롯인지 콘솔에 알립니다.
  • 한 오브젝트에 MingToon 재질이 여러 개일 때 인스펙터 상단 고정 탭이 깨지던 문제를 고쳤습니다. 고정 탭과 이동 목록은 에디터마다 따로 동작합니다.
  • 빌드 요약 로그의 "depth availability promotion" 표기를 "VRC Light Volumes를 켠 재질 수"로 고쳤습니다.
  • 설치 워밍업 뒤 첫 변환에서 셰이더를 하나 더 컴파일하던 문제를 고쳤습니다.

Ming Light Controller 0.1.4​

Ming Light Controller 0.1.4는 0.1.13과 함께 나옵니다. MLC는 별도 제품입니다.

  • NDMF 1.14 이상이 설치된 경우, Modular Avatar나 FaceEmo 등 다른 도구가 추가한 파라미터도 예산·검증 패널의 예산에 포함합니다.
  • NDMF가 보고하지 않는 동기화 메뉴 항목도 파라미터 이름으로 계산에 포함합니다.
  • NDMF 기준 계산과 아바타 디스크립터만의 계산이 다르면 예산·검증 패널에 두 숫자를 모두 표시합니다.
  • 다른 도구가 파라미터를 추가하기 전에 빌드가 먼저 실패하지 않습니다. 최종 예산은 모든 도구가 실행된 뒤 다시 확인합니다.
  • 최종 예산 초과 메시지에 특정 도구 이름을 표시하지 않습니다.
  • 이전의 소스 코드 방식 MLC 설치에서 DLL 패키지로 업데이트하면, 설정 Inspector가 Unity 기본 Inspector 대신 MLC 패널을 표시합니다.
  • 머티리얼 그룹 템플릿이 NaN이나 무한대 값을 거부합니다.
  • 0.1.2 또는 0.1.3에서 업데이트하는 경우, unitypackage를 기존 폴더 위에 Import All로 임포트합니다. 설정은 유지됩니다.

알려진 제한​

  • MMD 월드에서 입만 움직이지 않는다는 보고가 있습니다. 원인은 확정하지 못했고, 깊이 라이트를 켜고 끄는 FX 레이어를 MMD 월드가 끄는 FX 1·2번 레이어 뒤에 넣는 방어 수정을 넣었습니다. MMD 월드에서는 아직 직접 확인하지 못했으니, 같은 증상이 계속되면 알려 주세요.
  • 라이트와 림을 끈 상태에서 위를 보면 피부가 번쩍인다는 보고가 있습니다. 최신 버전으로 다시 변환하면 해결되는 경우가 있습니다.
  • 다른 사람의 시점에서 그림자가 어긋나 보인다는 보고가 있습니다. 원인은 확인 중입니다.
  • 몸 재질 슬롯이 사라진다는 보고가 있습니다. 확인 중입니다.
  • 설치나 업데이트 직후 캐릭터가 분홍색이면, 워밍업 중 셰이더 컴파일이 Unity 제한 시간을 넘긴 경우입니다. Project 창에서 MingToon 셰이더를 오른쪽 클릭해 Reimport하면 돌아옵니다. 느린 PC에서 생길 수 있으며, 자동 복구는 다음 버전에 넣습니다.
  • 다른 도구와의 호환 확인은 PC(Windows) 빌드 기준입니다. VRCQuestTools가 붙은 아바타도 PC 빌드에는 영향이 없음을 확인했습니다. Quest판의 모양은 확인 범위가 아닙니다.
  • VRM 내보내기(NDMF VRM Exporter)는 VRM 셰이더로 바뀌므로 MingToon 모양이 남지 않습니다. 내보내기가 오류 없이 끝나는 것만 확인했습니다.
  • TexTransTool 아틀라스에서 타일링·오프셋·스크롤이 있는 텍스처는 넣지 않고 경고합니다. 2×2 같은 아주 작은 단색 텍스처를 쓰는 재질은 아틀라스 가장자리에서 색이 어긋날 수 있으니 아틀라스 대상에서 빼 주세요(lilToon 재질도 같습니다).
  • Manager의 Play 모드에서 빌드 훅 실행은 Play 중 아바타를 직접 수정할 수 있으니 꺼 두세요. 기본값은 꺼짐 그대로입니다.
